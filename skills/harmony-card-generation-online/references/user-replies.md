# 回复占位符补充示例

固定模板、发送时点、合法组合及禁止输出的信息统一见 [SKILL.md](../SKILL.md) 的“用户回复”。
本文仅在不确定如何填写时查阅，不另设话术或执行规则。下例都以相应真实结果已确认且允许回复为前提。

## 使用条件与权限引导

- 若实际采用的能力明确要求手动开启“健康使用设备”，R15 可填为：
  “请注意，应用使用时长数据需要你手动开启设置中的「健康使用设备」，未开启时卡片将无法获取应用使用时长数据。”
- 若限制只对特定连接或设备成立，保留“使用某种连接时”或“非某类设备时”等条件，不猜用户当前状态。
- 权限结果只给出授权项名称时使用 R12；确有设置路径才用 R11，不能根据常识补路径。

提醒使用条件不代表权限通过，也不代表已替用户开启设置。

## 澄清与不支持

| 情况 | 填写示例 |
| --- | --- |
| 个人事件日期未明确 | R05：“请补充婚礼的具体日期。” |
| 修改内容不明确 | R05 只问一个必要信息，不询问内部字段 |
| 请求删除已有日历数据 | R10：“当前连续编辑暂不支持删除卡片中的日历数据，这次先不修改。” |

R06/R07 可在已有充分依据时追加 R23；R10 仅在已有依据确认创建支持时追加 R24。
存在会改变主要用途的已确认可用替代时，按 R09 等待决定，不再叠加其它问题。

## 外部事实

R16/R16W 填本轮选定、已核验且尚未告知的完整事实，保留名称、日期、地点、数值、单位及限定。
不加“查到”“根据搜索”等过程开头，不携带来源链接；末尾句号由模板补齐。
已告知事实不再发送，但请求仍从完整清单包含本轮采用的全部外部静态展示事实。

## 部分满足与成功概括

| 已知情况 | 回复选择 |
| --- | --- |
| 明确缺少数据、操作或必需素材 | R18C/R18E 后追加一句对应 R19D/R19A/R19M |
| 多类缺失 | 按原顺序去重合并，以 R19X 说明 |
| degraded 不适用 R19E，且没有缺失明细或其它确定依据 | R19X 的缺失内容填“相关内容”，不从候选猜测 |
| 创建成功，但未确认具体组件 | 概括用途，不声称所有候选都已显示 |
| 编辑成功 | 只概括本轮有依据的修改，不复述整张卡片或查询读数 |

生成成功不代表已添加桌面。没有生成后的文本机会时，不为补回复再次生成。

### 二次编辑部分完成

按 SKILL.md 的 R18E 加 R19E，例如：“卡片已修改，本次完成了部分视觉调整。
字号目标尚未完全满足，已保留本次可用的修改。”只说明真实反馈确认的目标，不声称全部完成。

## 下一步引导示例

以下只示范 SKILL.md 的合法组合，示例中的能力和结果必须在实际任务中已有依据。

| 已确认情况 | 示例 |
| --- | --- |
| 已交付部分修改，字号目标未完全满足 | 卡片已修改，本次完成了部分视觉调整。字号目标尚未完全满足，已保留本次可用的修改。你可以继续告诉我，最希望优先调整哪一处。 |
| 本轮已确认能展示日程名称与时间，交付结果缺少某项操作，下一轮表达仍在当前编辑范围内 | 在真实结果与缺失说明后追加：你可以这样描述需求：“突出下一场日程的名称和时间”。 |
| 当前编辑不支持新增数据，但已有有效依据确认创建支持该新需求 | 当前连续编辑暂不支持新增这类数据，这次先不修改。是否按这个新需求另建一张卡片？ |
| 没有已确认可用的替代 | 只使用对应边界话术，不追加“换个说法试试”或虚构需求示例。 |
| 正等待用户补充必要信息或授权 | 保留原问题或授权引导，不再追加下一步问题。 |

已有合法新产物时，先保存新来源并结束本轮生成；引导不触发自动修改。新建询问须等用户明确
同意后再按创建流程处理，不覆盖原卡。宿主没有生成后文本机会时，不为发送引导重新调用工具。
