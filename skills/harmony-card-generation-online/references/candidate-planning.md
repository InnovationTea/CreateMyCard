# 候选规划

把用户需求转换成微服务可裁决的候选计划。候选只表达用户可能需要的内容，不代表设备最终可用，也不是最终 CardSpec。

## 生成前决策

先区分核心与次要内容：

- 缺失后会改变卡片主要用途的数据或动作是核心；“必须”“只要”“一键”等明确约束、主要动态数据和主要动作默认属于核心。
- 素材默认是次要内容，只有用户明确要求必须使用时才作为核心硬约束。
- 静态入口或动作本身就是用户核心目标时，即使没有数据候选也可以继续。

据此选择四种决策：

| 决策 | 条件 | 后续 |
| --- | --- | --- |
| 继续生成 | 核心内容可满足，或静态/入口卡本身保持原意图 | 继续 |
| 调整后生成 | 核心可满足，仅次要内容不可用 | 记录缺失与保留项，先说明后自动继续 |
| 追问 | 缺少会改变核心意图或候选的用户可回答信息 | 只追问最小必要内容并等待 |
| 结束并引导 | 核心无法满足且静态/入口卡不能保持原意图 | 停止后续工具并提供相近需求 |

用户明确“必须包含，否则不要生成”的能力不可用时直接结束，不生成降级版本。工具失败或 payload 非法属于工程异常，不据此推荐能力。

## 用户确认门禁

每次工具调用前重新检查：

- 核心对象、应用、联系人、地点、日期/时间范围或设备是否明确。
- 多个互斥选择是否会改变核心候选。
- 能力 `inputSchema` 的必填业务参数能否从用户原话、可信会话上下文或明确默认值安全取得。
- 拨号、导航、入会、切换设置等动作的目标和范围是否明确；高风险动作是否由用户明确要求。

以下内容不追问：

- 可按稳定规则生成的 `size`、`title`、`description`。
- 设备是否支持能力、应用是否安装或是否有数据权限。
- 能力 ID、schema、写入路径、协议版本等内部字段。
- 仅影响非核心可选内容的缺失项；可以删除该候选。

edit 未指定目标时默认最近有效卡片，不追问；明确目标无法与会话结果对应时才追问。

## 能力概述筛选

先从用户 query 抽取核心场景、动态数据、动作和素材意图，再从本轮概述选择：

- 数据能力只从 `dataCapabilities` 选择，最多 2 个核心候选。
- `unavailableCapabilities` 仅记录本地不可用的数据能力 ID，不加载 schema、不进入候选；字段非字符串数组时按 payload 非法处理。
- 事件能力最多 2 个主动作，只选择描述与用户目标强相关、参数可安全补齐的候选。
- 素材只保留 1～4 个强相关 ID；没有强匹配时使用空数组。
- 不因名称相似选择会改变用户意图的能力，不编造数据、事件或素材。

能力概述或 schema 无法覆盖核心数据、核心动作或必需素材时，重新执行生成前决策。结束并引导时：

- 已有合法概述：优先从同领域、低风险且有完整卡片价值的能力描述生成 1～3 条建议。
- 尚无合法概述：只使用天气、日程、运动、设备电量或系统状态等通用示例。
- 建议只写用户可复述的自然语言需求，不输出技术字段，也不承诺当前设备一定支持。

## 尺寸与展示内容

- 用户明确指定 `2x2` 或 `2x4` 时优先尊重。
- 未指定时从 `2x2` 开始；先移除非核心可选信息、摘要列表或只保留首项。
- 只有必须保留的核心内容、受保护文本、必要热区、必须同屏理解的并列关系或关键媒体无法在 `2x2` 成立时，才选择 `2x4`。
- 信息较多、横版更舒展、视觉更丰富、天气加日程或存在两个数据能力都不是升级理由。
- 主要展示数据项合计不超过 4 项；无法判断取舍且用户要求全部保留时再请求用户确认。

create 必须提供稳定、静态的 `title` 和 `description`：

- `title` 尽量不超过 8 个字；无法提炼时使用“桌面卡片”。
- `description` 尽量不超过 12 个字；无法提炼时使用“信息速览”。
- 不写动态值、隐私内容、设备状态或能力可用性承诺。
- edit 只有用户明确修改时才传对应字段，否则省略并继承。

## 候选数据、事件和素材

### 数据候选

- 先确认运行时 schema 声明 `candidateDataBindings`。
- `capabilityId` 必须来自本轮已加载的数据 schema。
- `arguments` 只包含对应 `inputSchema.properties` 声明字段，始终放在 binding 的 `arguments` 对象内。
- 核心必填参数缺失且用户可以回答时先追问；不要编造或静默删除核心候选。
- `writeResultTo` 优先使用 schema 的默认值；没有时使用不冲突的 `/data/{semanticKey}`。多个路径不得相同、互为父子或互相覆盖。
- `candidateOutputFields` 可省略。需要投影时只传能从对应 `outputSchema` 推导的叶子 JSON Pointer，数组元素 schema 使用 `/0`，去重后所有候选合计不超过 4 项。
- 不传 `required`、`inputSchema`、`outputSchema`、`updateModel` 或其它未声明字段。

结构以 [`tool-contracts.md`](tool-contracts.md) 的 `CandidateDataBinding` 为准；实际字段仍以当前运行时 schema 为唯一依据。

### 事件候选

- 使用单数组 `candidateEventCandidates`，每项同时包含 `capabilityId` 和完整 `action.call/action.args`。
- ID、函数与参数结构必须来自本轮 overview 的事件描述或 `actionTemplate`；用户只补充业务值，Agent 不编造 deeplink、intent、包名、ability、号码或参数名。
- 参数无法安全填齐时移除整个事件候选；核心动作因此缺失时重新执行生成前决策。
- 高风险或不可逆动作仅在用户明确要求且 overview 明确支持时选择。
- 候选 action 不是最终 DSL `onClick`，最终过滤和写入由微服务负责。

### 素材候选

- 只传 overview 返回的 `candidateAssetIds`，不传自造路径。
- 素材必须与场景、状态或动作有明确语义关系；没有匹配时传空数组。

本版不传 `slots`、`options`、`locale`、`uid`、`device` 或运行时 schema 未声明的其它字段。

## 编辑规划

edit 先取得目标卡片最近一次业务 payload 的真实 `artifactUrl`，并确认运行时 schema 声明 `sourceArtifactUrl`。无法取得时停止，不改走 create。

| 修改类型 | 请求构造 |
| --- | --- |
| 纯视觉或布局 | `userQuery` + `sourceArtifactUrl` |
| 标题、说明或尺寸 | 再传用户明确修改的字段 |
| 删除数据能力或修改已有数据参数 | 再传编辑后的完整 `candidateDataBindings` |
| 新增数据能力、修改事件或素材 | 不调用 edit，引导重新创建 |

恢复完整数据候选集合：

1. 沿当前卡片会话链找到最近一次显式提交的完整 `candidateDataBindings`。
2. 根据后续有效业务结果排除已被微服务移除的数据能力。
3. 删除用户要求移除的 binding，或只修改目标 binding 的 `arguments`；保留其它 binding。
4. 重新获取能力概述并只保留当前可用能力，再加载所需 schema。
5. 重新校验全部参数、写入路径和字段投影后，显式传完整数组；删除全部动态数据时传 `[]`。

无法可靠恢复时停止编辑，不传不完整数组，不下载来源 artifact 猜测。

## 权限集合

每次 `generateWidgetCard` 前确定并去重最终数据能力 ID：

- create：最终 `candidateDataBindings[].capabilityId`。
- 删除数据或修改参数 edit：编辑后完整 binding 的能力 ID。
- 纯视觉、布局、文案或尺寸 edit：优先使用目标卡片最近一次 `effectiveCapabilities.data`；缺失时才从同一会话完整候选链扣除已移除能力后恢复。

无法可靠恢复 edit 的集合时停止编辑。集合为空时跳过 `RequestDataPermission`；非空时完整传入。权限通过后若集合或 binding 发生变化，必须重新检查。
