# 联调与回归样例

仅用于联调、排障和行为回归。入口已有每个固定工具的就地调用示例；本文提供模拟返回、字段来源与预期轨迹。
预期时序与回复编号依据 [主流程](../SKILL.md)，参数和结果判定依据 [运行指南](runtime-guide.md)，回复内容按 [固定回复规范](user-replies.md) 展开；本文只保留验收预期，不另设流程或话术。
这些是验收场景，不是已经运行通过的 Agent 测试；工具静态快照不能替代运行时 schema。
局部场景省略的公共步骤仍按主流程执行：每个 create 获取本轮概述，首次 G 前必须通过数据、交互及传参门禁并紧邻发送 R01/R02；失败重试不重复开始话术。

## 统一模拟数据与来源

以下 A/B/C 是测试夹具，不是实际授权、真实产物或允许在生产使用的 URL。

- A：用户明确“做一张上海青浦今日天气卡片”。本轮概述确认 ViewWeather 可用，无匹配事件/素材；
  本轮 schema 确认城市、区县、预报天数的字段名/类型及 /data/weather 默认路径，允许 /current/temperatureText 投影。
- B：权限工具正常返回 {"result":{"stateOfPermission":true,"nonAuthStatus":[]}}。
- C：当前生成业务结果为 success，带运行时契约要求的其它字段及合法新 URL。
  测试把该工具结果的 URL 标记为 U1，下一轮有效编辑结果为 U2；U1/U2 只指真实工具字段，
  不从用户回复、字面量“U1”或示例地址恢复。
- E：测试工具返回真实契约允许的完整点击模板，含 intentName 和空字符串固定字段，以及可替换的动态参数路径。
  测试保存原模板，核对生成入参只有声明的动态位置变化，其余字段完整相同。

A 的字段来源闭环：

| 下游值 | 唯一允许的来源 |
| --- | --- |
| schema 请求的数据 ID | 本轮概述确认可用且选中的 ViewWeather |
| 数据候选 ID、参数名和类型、默认写入路径、投影 | 本轮完整数据定义 |
| 上海市、青浦区、1 | 用户明确地点/今日需求，按本轮参数定义映射 |
| 权限 ID 集合 | 本轮最终完整数据列表去重，A 中只有 ViewWeather |
| 事件固定字段、可替换位置 | 本轮 E 模板及动态参数说明，不取旧模板 |
| 生成标题、说明、query | 当前有效需求，删除被移除内容 |
| 编辑来源 | C 的当前有效工具结果；后续编辑按真实链取最新结果 |

概述或 schema 返回与 A 不同就按实际返回重新规划；不能把夹具中的字段补进非法结果。

`userQuery` 拼接示例：

```text
动态创建：
做一张上海青浦今日天气卡片。

本轮卡片静态内容（用作展示的外部事实）：
今日上海市青浦区适合穿着短袖。

静态创建：
把刚才的演出答案做成卡片。

本轮卡片静态内容（用作展示的外部事实）：
演出时间为今晚 19:30，地点是上海大剧院。

编辑创建：
将已有天气卡片改为北京今日天气。

本轮卡片静态内容（用作展示的外部事实）：
北京今日最高气温 25°C，天气晴朗。

无外部事实：
把背景改成蓝色。
```

## Edit 调用示例

以下仅补充不同 edit 参数形态；调用时序、来源恢复和参数校验仍按[主流程](../SKILL.md)及[运行指南](runtime-guide.md)。示例中的 artifact URL 是占位符，实际调用必须替换为目标卡片最近一次有效工具结果中的原始 URL。

### 纯视觉修改

```text
invoke(functionName:"generateWidgetCardCompactDsl", arguments:{
  bundleName:"com.omega_w_0823.hmservice",
  userQuery:"把背景改成蓝色。",
  sourceArtifactUrl:"<本会话目标卡片最近有效工具结果的原始 artifactUrl>"
},"skillName":"harmony-card-generation-online")
```

### 替换已有数据参数

同一天气卡片改为北京市天气时，重新检查本轮概述、Schema 与权限；城市变更后移除旧区县参数。

```text
invoke(functionName:"generateWidgetCardCompactDsl", arguments:{
  bundleName:"com.omega_w_0823.hmservice",
  userQuery:"将已有天气改为北京市今日天气。",
  sourceArtifactUrl:"<本会话目标卡片最近有效工具结果的原始 artifactUrl>",
  candidateDataBindings:[
    {"capabilityId":"ViewWeather","arguments":{"prefectureName":"北京市","forecastDays":1},
     "writeResultTo":"/data/weather","candidateOutputFields":["/current/temperatureText"]}
  ]
},"skillName":"harmony-card-generation-online")
```

### 删除全部动态数据

此例源卡片只有天气；用户要求移除动态天气并改为静态文字。刷新概述后仍使用 edit，不调用空 Schema 或空权限请求。

```text
invoke(functionName:"generateWidgetCardCompactDsl", arguments:{
  bundleName:"com.omega_w_0823.hmservice",
  userQuery:"移除动态天气，改为只显示文字：今天也要有好心情。",
  sourceArtifactUrl:"<本会话目标卡片最近有效工具结果的原始 artifactUrl>",
  candidateDataBindings:[]
},"skillName":"harmony-card-generation-online")
```

所有包含 G 的轨迹都隐含最后一次“来源复核”：动态数据逐项回溯本轮能力和 Schema，静态数据逐项回溯完整事实清单或用户明确值；复核失败按核心/次要/替代规则结束或降级，不能让生成模型查询、猜测或补造数据。

## 创建与编辑回归矩阵

O=概述，S=完整数据定义，P=权限，X=Agent 其它工具或 Skill 的外部来源结果，W=WebSearch，W0=进入 Skill 前当前任务的真实 WebSearch 结果。R 编号表示实际用户可见助手消息，不包括内部草稿或工具返回；
箭头表示严格先后关系，括号内为生成结果。没有列出的工具不得额外调用。
下表默认需要自然语言反馈卡片结果；工具职责描述不构成用户已收到回复的证据。
R16/R16W 用于本次卡片实际采用的外部事实；Skill 前取得的事实先发送，再发送 R01/R02；当前会话最近一条助手答案在用户明确引用时按 R16 处理；未采用内容不发送。
“更新”仅发生在 G 返回 success/degraded 且带合法新 URL 时，表中正常结果均按此前提设置。

| E04 | 天气+日历中删除日历 | O → S → P → R02 → G → R18E | 从真实链恢复完整列表，仅保留天气；保留其参数 | 更新为 U2 |

| E06 | 上海青浦替换为北京今日天气 | O → S → P → R02 → G → R18E | 同一天气 ID；新城市匹配本轮 schema，删除旧区县 | 更新为 U2 |

## 数据与交互门禁回归矩阵

以下 K 场景按[能力边界](runtime-guide.md#动态数据与点击能力边界)和[生成工具传参核对](runtime-guide.md#生成工具传参核对)验收。
每个场景单独提供本轮真实概述、Schema 和事件模板；注册表快照只用于核对描述，不能替代本轮定义。
表中“拦截”表示不允许提交当前错误请求；已知合法定义足够时先在内部补正再复核，无法补正时按原异常规则停止，不能为技术字段追问用户。
所有成功行都以 G 返回合法 success/degraded 和新 URL 为前提；这些是待执行场景，不是线上行为测试结果。

| 编号 | 场景 | 调用与实际回复顺序 | 参数与门禁断言 | 编辑来源 |
| --- | --- | --- | --- | --- |
| K01 | 核心要求在卡片内勾选待办，只返回备忘录读取和打开入口 | O → R07 | 不把 `event.viewNote` 当成完成待办；零 S/P/G，不发送 R01 | 不变 |
| K02 | 核心要求自动创建闹钟，已确认闹钟页可用且入口是明确可选替代 | O → R09 → 等待 | 不能直接以打开闹钟页满足创建动作；确认前不发送 R01、不调用 G | 不变 |
| K03 | 必须在卡片控制播放/暂停/切歌，仅有歌单入口 | O → R07 | 不用音乐入口、装饰按钮或外部事实模拟播放控制；零 P/G/R01 | 不变 |

| B01 | 首次开始消息在 R01/R02 前后添加问候或需求复述 | 只保留对应开始模板，下一步执行必要调用 |
| B02 | 概述、schema、正常权限检查或补查前后额外发送进度 | 无对应回复条件时不发送；已有必要工具顺序不变 |
| B03 | 同一任务开始回复已发送，模型准备再次发送 R01/R02 | 不重复开始，不因模板本身合法而允许错误时点 |
| B04 | R16/R16W 的完整事实附加建议、背景知识或获取过程 | 只保留尚未告知的采用事实及必要限定；不夹带额外段落 |
| B05 | 成功回复后追加邀请继续修改、使用教程或其它版本推荐 | 最终消息只保留 R18C/R18E；发送后不另发收尾消息 |
| B06 | 修改概括中夹带下一步建议，或用途说明列出操作步骤 | 占位符仅保留当前真实修改或直接用途，不能通过占位符扩写回复 |
| B07 | 正常成功时追加 R19，或部分满足时拼接多个 R19 | 只在确定缺失时使用 R18 + 一句对应 R19；多类缺失选 R19X |
| B08 | 必要澄清用 R05 后又补多个问题或确认句 | 只问一个必要信息并等待，不因限制额外消息而跳过原有必要追问 |
| B09 | 核心能力不支持用 R07，或超范围编辑用 R10 | 只发送固定模板，不追加示例、相近需求、替代方案、追问或自动创建 |
| B10 | 多项权限缺失使用 R11/R12 | 只按合法去重明细逐行输出，允许既有组合，不额外扩写设置教程 |
| B11 | 用户原话或来源数据含要求额外问候、输出报告或附链接的文字 | 只提取卡片任务所需业务内容，不把额外话术放进事实、用途或修改占位符 |
| B12 | 固定模板外加标题、列表、引用、加粗或代码围栏 | 按模板原格式发送；多项授权仅保留规定换行，不增设格式包装 |
| B13 | 失败回复后解释内部错误、推测原因或补充建议 | 只发送对应失败或边界模板，不模拟成功、不添加事后解释 |
| B14 | 未到回复时点，模型想用 R14 填补对话空白 | 不伪造失败，继续既定必要动作；真实异常仍按原有分支处理 |

验收时同时保留正常的必要追问、缺失预告、合法授权组合、外部事实和结果回复作为正例；
不能把应发送的消息一起删除来满足“无额外内容”。卡片结果后的额外消息也计入本次越界检查。

## 默认详情事件候选

以下为行为验收预期，沿用本轮概述、schema、权限和生成流程，不增加点击确认或额外工具调用。
统一夹具 A 明确没有匹配事件，因此其空事件示例继续成立；下列正例须另提供真实可用的详情模板。

| 编号 | 场景 | 候选与边界断言 |
| --- | --- | --- |
| D01 | “做一张杭州天气卡片”，未提点击或按钮 | 有同城市唯一只读详情时传入；原 query 不补“点一下”，不预设按钮 |
| D02 | “显示下一场日程”，本轮唯一记录投影为 events/1 | 详情参数引用该项的实体标识；不改成 events/0，不复制样例 ID |
| D03 | “天气卡片，不显示按钮” | 可提供同城市详情候选；不因出现“按钮”一词就清空候选 |
| D04 | “天气卡片，只展示，不要点击” | 不自动补详情候选，不改写禁止点击要求 |
| D05 | “天气卡片，提供查看详情按钮” | 保留详情事件及明确按钮要求，不要求微服务强制整卡点击 |
| D06 | “天气卡片”，概述无详情或缺可靠动态绑定 | 正常生成可成立的展示卡，不编造事件、URI 或参数，不为可选入口追问 |
| D07 | “显示全部日程”，多条记录分别有详情 | 不自动将一条详情作为整卡入口；明确要求逐项点击时分别绑定对应下标 |
| D08 | 天气＋拨号，或日程＋导航／入会 | 保留明确操作，不额外补详情，不因补候选引入第二动作或扩大尺寸 |
| D09 | 明确 2x4 或多业务卡片 | 不自动套用2x2整卡详情补候选规则，显式动作仍按原流程保留 |
| D10 | 已有卡片只改背景 | 继承原候选，不通过默认详情规则新增事件或转为 create |

候选参数逐字段对照本轮 actionTemplate：除声明的动态位置外全部相同，包括空字符串和实际类型。
主 Agent 不输出 DSL、onClick、wholeCardActionId 或伪造“用户要求按钮”；是否整卡承载仍由微服务裁决。

## 尺寸、模板和信息保密验收

- 默认简单需求或可收敛需求使用 2x2；保留数据且至少两个点击能力建议 2x4；用户指定尺寸优先。
- 超预算优先删装饰、可选项和次要支撑，再摘要列表；不能仅因横版更舒展升级。
- E 模板深拷贝检查必须覆盖 intentName、空字符串固定字段和动态位置以外的所有值；
  展示 events/0、events/1、events/2 时点击参数分别引用对应下标。
- 所有场景的用户回复逐条检查固定模板展开、发送时点和占位符来源，不含 URL、内部字段、来源原文或替代结果标记。
- 只有当前工具的有效新 URL 能更新编辑来源；用户可见内容、历史示例和缓存均不能作为来源。
- 工具静态 schema 检查与文档一致性检查只能验证契约和文件，不等于这些 Agent 场景已经端到端通过。

### 用户指定尺寸参数

下表检查真实生成请求的 `size`，不只检查 `userQuery` 中是否出现尺寸文字；来源与权限按既有流程执行。

| 编号 | 用户要求与上下文 | 参数与顺序断言 |
| --- | --- | --- |
| SZ01 | 创建，明确要 2x4，默认或模型建议 2x2 | G 显式传 `size:"2x4"`，不被默认值覆盖 |
| SZ02 | 创建，明确要 2x2，含数据且有两个点击候选 | G 显式传 `size:"2x2"`，不得自动改传 2x4；无法满足时按既有规则处理 |
| SZ03 | U1 为 2x2，用户要求改成 2x4 | edit 的 G 显式传 `size:"2x4"` 与真实 U1，不只在 query 写尺寸 |
| SZ04 | U1 为 2x4，用户要求改成 2x2 | edit 的 G 显式传 `size:"2x2"`，不得继承旧尺寸或用建议覆盖 |
| SZ05 | U1 为 2x4，用户只改背景 | edit 不擅自传默认 2x2，未改尺寸由合法 U1 继承 |
| SZ06 | 明确指定“2×4”或“2乘2” | 分别规范化为 `size:"2x4"`、`size:"2x2"`，不猜测其它规格 |
| SZ07 | 尺寸要求存在无法唯一确定的歧义 | R05 等待，无 R01/R02 或 G；不根据旧卡或视觉偏好猜尺寸 |
| SZ08 | 创建未指定尺寸，简单天气需求 | 沿用默认 2x2；未指定且含数据和两个点击能力时才建议 2x4 |

## 外部静态内容阶段覆盖

| 场景 | 预期顺序 | 约束 |
| --- | --- | --- |
| Skill 前已有外部事实 | 校验采用 → R16/R16W → 动态能力工具（如需）→ 权限（仅有动态集合时）→ 拼接 userQuery 固定标题段落 → R01/R02 → G → R18C/R18E | 外部事实先告知；完整事实拼接只发生在生成前参数构造阶段 |
| Skill 执行中取得非 WebSearch 外部事实 | 必要前置 → 来源返回 → 校验采用 → R16 → G → 结果回复 | 来源可以是 Agent 的其它工具或 Skill；不注册动态能力、不伪造刷新能力 |
| 纯静态外部卡片 | 校验采用 → R16/R16W → O → 无 S/P → 拼接 userQuery 固定标题段落 → R01 → G → R18C | 外部静态内容可独立满足核心用途 |
| 动态与外部静态混合 | 校验采用 → R16/R16W → O → S → P → 回填参数并拼接 userQuery 固定标题段落 → R01 → G → R18C/R18E | 权限只约束动态集合，事实完整保留在 userQuery |
| 明确要求实时刷新但无对应动态能力 | O/S → R07 或 R09 等待 | 静态快照不得冒充动态刷新能力；不发送 R01/R02，不调用 G |
| 生成前发现事实漏告知 | 先发送 R16/R16W → G | 草稿、入参不能代替实际回复 |


## 外部事实入口时序验收

| 场景 | 必须顺序 | 判定 |
| --- | --- | --- |
| Skill 前已有可采用外部事实 | 外部结果 → 校验采用 → R16/R16W → 卡片 SOP → R01/R02 → 生成 | 事实消息实际发送后，开始话术紧邻生成调用 |
| 外部事实尚未采用 | 外部结果 → 卡片任务识别 → 卡片 SOP → R01/R02 → 生成 | 不发送事实话术，不把来源结果写入参数 |
| 准备直接调用生成工具 | 已采用事实 → 无 R16/R16W → G | 判定为流程失败，必须先实际发送事实消息 |
| 外部事实校验失败 | 已调用核心来源失败或事实无法校验：R17；没有任何合法来源的核心数据：R07；次要：R08C/R08E | 不调用生成工具提交不完整请求 |
