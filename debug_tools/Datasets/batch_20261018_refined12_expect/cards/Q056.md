# Q056 · 客户现场（精致版期望输出）

> 身份：**期望输出**，供「导入期望输出」页手工录入。底稿是批跑 `batch_20261018_160124_3f440556` 里同 ID 的模型 DSL，入参（Query、候选字段、候选事件、候选素材、声明尺寸）完全沿用，只重做了版式与信息层次。

## 卡片信息

- Query：今天上午要去北京朝阳区客户现场，帮我做个卡片，看当地当前天气、气温和今天第一件日程的开始时间、地点，点一下查看北京天气详情。
- 尺寸：2x4（与入参一致，root 用 W- 系列布局）
- 布局：W-split-panels
- 版面验算：展开后纵向实算 110vp／预算 110vp（几何取自 `convert_compact_dsl_to_a2ui` 展开的 `styles.height`、`padding`、`itemMargin`；同排分支 weather_panel 110vp、calendar_panel 76vp）
- 分类：日程（导入页可按这个分类建组）
- 已通过 `convert_compact_dsl_to_a2ui` 严格转换，可直接贴进「卡片渲染」页预览。

## 比批跑原文精致在哪

- 左右两区各自带准确图标，日程区地点用 `location` 承载、天气区把气温收进同一核心语义的次文本。
- 入参候选字段 5 项，本卡实算命中 5 项；批跑原文实算 5 项。
- 图标实例 2 个（2x4 按语义增益取用）。

- 候选 `sun_max`／`icon_schedule` 未用：太阳会静态断言天气现象，两个日历素材里只留语义最直白的 `calendar_fill`。

## 与批跑实际输出对比时

- 原版实算数据 ["/data/calendar/events/0/dtStart", "/data/calendar/events/0/eventLocation", "/data/weather/current/condition", "/data/weather/current/temperatureC", "/data/weather/location/cityCode"]
- 所以把本条当期望、把 batch_20261018_160124_3f440556 当实际侧按 ID 配对时，启用「数据」维度会因原版少绑的字段判未匹配，这正是精致版补出来的信息量。
