# Debug Tools 调试平台运行规范

本文维护 Debug Tools 的页面交互、批跑、后处理、渲染、评分及开发调试 Trace 的运行与验收规则。
平台架构与代码组织见[调试平台技术方案](调试平台技术方案.md)，启动与使用见[工作台说明](README.md)。
云侧业务接口、协议、产物、校验与降级仍以[云侧方案设计](../docs/云侧方案设计.md)为准；
调试平台专属变更直接更新本目录文档。本文收纳原云侧方案中的调试规范，保持既有行为与约束。

批跑结果排查按[批跑失败案例分析指南](批跑失败案例分析指南.md)组织证据、统计和归因；
该指南提供分析方法，不替代本文运行规则或云侧校验合同。

## 主题图片开发诊断

主题图片测量仅用于开发态诊断。调用 `render/genui-sdk/test-renderer/src/measure-theme.tsx` 时必须
显式提供测试视口；工具不从2x2/2x4推导卡片像素宽高。结果标记 `basis=explicit-test-viewport`、
`deviceGeometryKnown=false`，不能作为云侧线上图片主体避让通过的证据。文字实际字形加动态余量、
完整按钮和图标的诊断算法保留；测试视口与最终真机显示均不决定线上主题配置的卡片宽高。

## 页面切换与会话保留

端到端调试在首次进入后，由工作台主框架保留页面实例和 Agent 连接。在同一工作台内切换接口调试、
卡片渲染、批量测试、质量评分或连接配置时，仅隐藏端到端页面，保留对话、运行轨迹、输入草稿及会话上下文；
运行中的回合和浏览器工具调用继续执行，返回端到端页面后显示期间收到的结果。未进入端到端页面时不提前
创建 Agent 会话。点击“新建会话”仍显式清空当前上下文。

本阶段仅覆盖工作台主导航内的页面切换；刷新或关闭浏览器页面、离开工作台主框架及服务重启后的会话恢复
不在本次范围内。回归须覆盖切换往返后的消息与草稿保留、隐藏期间接收结果、工具调用不中断、连接不重复
创建，以及退出工作台时释放连接。

## Trace 语义与查看

Trace v2 的语义埋点版本为 `instrumentationVersion: 2`。Span 必须来自明确作用域或显式步骤，普通事件
使用独立 `eventId` 并通过 `spanId` 归属执行区间；不根据事件是否携带耗时自动创建 Span。Span 使用稳定
`operation` 和 `kind: group/step/model`，业务失败、恢复、跳过和取消必须记录真实状态。
批跑归一化为 `trace-view-v2`，默认展示请求准备、生成计划、生成 DSL、转换与校验、质量修复、保存产物、
返回结果；内容引用标记所属步骤，阶段容器仅聚合内容索引。运行级 `trace_blob_manifest.json` 登记
无扩展名 `trace_blobs/<sha256>` 文件，读取与前端加载均校验字节数和 SHA-256。旧埋点仅提供原始查看。

批跑平台的单样本 Trace 从样本详情入口在新标签页打开独立页面，地址包含运行和样本标识，可刷新和直接访问。
独立页面使用整个浏览器视口，桌面端并排展示时间瀑布与节点详情，窄屏端上下排列，保留 attempt 切换与附件按需加载。

## 批跑任务与队列

批跑入口使用后台任务中心。数据集来自 `debug_tools/Datasets` 的直接子文件夹，任务保存样本选择、公共请求
字段覆盖、运行参数和非敏感后端配置快照；新建任务落盘后必须立即创建首个执行并加入队列，不要求用户再次
点击启动。任务可重复运行，后续再次执行均生成独立结果。调试后端使用持久化单消费者队列保证同一时刻
只执行一个任务；调度器繁忙时新执行保持 `queued` 并在页面显示“排队中”，任务内部仍可配置样本并发。浏览器生命周期不影响执行；调试
后端重启时活动执行标记为中断，等待队列保持暂停，需显式恢复。

## 批跑生成指标

批跑详情的“本次批跑重试参数”常显批跑、整接口及每轮质量 repair 预算，展开后查看 Plan、主备模型
调用失败重试、备用模型切换及生成参数修复的开关与次数。次数明确区分额外次数、含首次的完整生成轮数
和不含首稿的 repair 次数；通过即停止，理论累计上限不表示已经执行的次数。
微服务在 `retry.policy.configured` 开发 Trace 中仅记录重试配置白名单，不改变业务响应或执行策略。
页面只展示该次 Trace 中服务实际加载的参数，列名为“实际配置”；历史 Trace 可从 `interface.attempt.started`、`plan.attempt`
确认当次预算上限，不根据实际只执行几次来反推配置。缺失参数显示“未知”，不读取当前 `.env` 或默认值填补历史。
同一批次跨请求出现不同参数时保留并展示所有观测值，不能取最大值伪装成统一配置。
受管任务在入队及启动时保存重试参数白名单快照，供执行记录留存；页面不展示快照，也不使用快照补齐
实际配置或计算理论累计上限。已部署后端不使用调试平台的受管默认值解释其参数；旧微服务没有配置埋点时相关字段保持未知。

受管微服务默认关闭模型 Mock，使用真实模型；批跑不额外重试（每个样本仅 1 次外部请求），整接口重试开启并
额外重试 1 次（每次外部请求最多 2 轮完整生成），质量 repair 开启且每轮上限 5 次，不含首稿。
预算耗尽时每个样本最多 2 轮完整生成、10 次 repair，成功或不可重试错误会提前结束。
模型调用失败重试默认开启，主模型和备用模型均保留额外重试 1 次；这些物理调用不计入质量 repair 次数。
页面在开关关闭时明确显示不进行整接口重试或允许 0 次修复，详细表格保留记录的次数并标注“开关关闭，不生效”。
已部署微服务读取自身配置，受管微服务读取任务配置快照；默认值变更不改写正在执行或历史任务。

批跑详情同时显示首稿校验、首次请求交付、最终交付、内部修复与批跑重试挽救率，以及 P95 总耗时。
展开统计区可查看调用计数、信息缺失告警、证据覆盖数和按请求尺寸的分组；样本表提供首稿状态及质量筛选。
所有比率显示分子与分母，没有分母时显示“—”，不以零成功率替代未知。具体口径如下：

| 指标 | 口径 |
| --- | --- |
| 首次成功率（首稿校验） | `attempt_000` 第一次 `validation.evaluate` 成功数 / 存在该评估终态的样本数；包括当轮转换及产物校验，不包含修复后的评估 |
| 首次请求交付率 | 首次请求成功或降级交付数 / 首次请求已结束数；包含内部修复，不含批跑重试 |
| 最终交付率 | 最终成功或降级数 / 最终成功、降级、失败及不支持的样本数；不混入取消和未完成样本 |
| 生成前失败 | 首次请求有完整 Trace 终态、没有 DSL 评估且请求失败或不支持；缺少 Trace 不据此推断生成前失败 |
| 首稿证据缺失 | 首次请求已结束或样本最终已结束，但缺少首稿评估及明确生成前失败证据 |
| 内部修复挽救率 | 首稿失败而首次请求交付数 / 首稿失败且首次请求已结束数 |
| 批跑重试率及挽救率 | 进入额外批跑尝试数 / 首次请求已结束数；重试后最终交付数 / 已结束的重试样本数 |
| 内部修复尝试、模型物理调用 | 累计所有批跑尝试的 Trace 终态计数；同时展示有计数证据的请求数，部分证据不得冒充完整累计 |
| 交付信息缺失告警 | 最终成功或降级样本的最后一次 Plan 覆盖检查中，存在动态事实或静态原文缺失告警的样本数；同时展示已检查交付样本数 |
| P95 总耗时 | 最终非取消、已结束样本的累计 `elapsedMs`，包含批跑重试；采用最近秩分位数 |

同一请求内部的接口重跑不等于批跑重试；首稿始终取首次请求的第一次评估。缺失告警仅表示已有 Plan
的可见覆盖检查结果，不证明用户需求全量覆盖、视觉合格或真机通过。分组尺寸优先使用首次请求落盘的尺寸
（包含公共字段覆盖），缺失时回退样本尺寸，不用主题扩展后的最终尺寸重新解释生成难度。

新运行在终态统计快照和 Markdown 汇总中保存指标；运行中及历史运行在读取详情时从原始请求尝试及 Trace 按需补充，
不改写旧汇总或重新导入 Trace。读取缓存依据文件修改时间及大小失效；覆盖附件还核对字节数与 SHA-256。
Trace 视图为 invalid 但原始记录可读时仍可利用其明确证据；缺失、损坏或无法解释的证据保持未知。

任务列表、执行记录选择器及调度状态只读取执行摘要，不扫描历史 Trace、画廊或真机截图逐样本结果，
也不携带逐样本结果或详细生成指标；已执行插件仍保留其状态和看板入口。
任务列表只补齐每个任务最新执行的进度与插件状态，不逐个加载其全部历史执行；后台运行中的进度落盘不触发整批
指标重算。前端列表与调度状态分别在各自返回后显示，同一页面只允许一组刷新请求在途，避免慢请求与定时轮询叠加。
首次加载时明确显示加载提示，不能短暂显示“暂无任务”误导用户。

## 后处理插件与执行历史

正常完成的批跑不会自动启动后处理。新执行统一采用 `batch-postprocess-v2` 插件依赖图：插件由项目固定
目录中的 `plugin.json` 清单注册，用户在批跑详情页选择一个或多个插件并手工启动。清单通过 `dependence`
列表声明当前插件运行前必须依次完成的插件名称；宿主自动补齐依赖、拒绝缺失或循环依赖，并让无依赖关系
的插件并行执行。插件只能读取其直接依赖的规范化结果，不再以用户选择顺序建立隐式上下游关系。自定义 Python 插件在独立子进程中逐样本调用
`process_sample(context)`，再调用可选的 `process_dataset(context)`，最后调用可选的 `finalize(context)`；收尾函数可在基础结果可见后执行截图、汇总画廊等长耗时任务，并按样本标识替换需要回填的结果。函数必须返回只包含状态、摘要、可索引
事实与声明式产物的 JSON 对象。清单通过 `outputs` 规定样本级和数据集级产物，通过受限 `presentation`
描述默认表格或画廊模式及样本索引字段。插件不得携带或返回 React、HTML、JavaScript 等可执行前端内容。

用户点击“开始后处理”时，仅调度本次勾选且尚无执行历史的插件；已经成功、部分成功、失败或跳过的插件
均不自动重复运行。新增插件依赖已执行插件时，宿主复用该依赖的最新规范化结果，不为满足依赖而重复运行；
尚未执行的依赖仍按 `dependence` 补齐。已执行插件只允许由用户在插件结果区域点击“再次运行”显式触发，
再次运行生成新的执行历史并保留旧记录，已执行依赖仍复用最新结果。

声明式产物的数据类型固定为 `metrics/records/matrix/image/json/text/code/diff/issues/file/link`；图表仅是
`records` 或 `matrix` 的受控展示提示。`image` 画廊项可引用受限图片 URL，也可携带 DSL 交由调试平台现有
CardRenderer 渲染，不允许携带自定义前端代码。宿主校验产物是否已声明、必选产物是否齐全、内联数据是否可 JSON
序列化，以及文件是否位于插件专属输出目录。清单标记为 `deferred` 的必选产物允许在基础阶段暂缺，但必须在
`finalize` 完成后通过最终校验。单样本失败继续处理其它样本，不改变原批跑业务状态；收尾失败时保留并展示
已经持久化的样本与数据集结果，但插件最终状态记为失败，依赖该插件的后续插件不再执行。

每次手工执行生成不带 `post_` 批次语义的执行标识，状态和结果写入
`batch_output/<runId>/postprocess/<executionId>/`。每个插件保留全部执行历史，界面按插件从历史中选择最新
结果；重新执行不覆盖历史产物。执行总览只保存插件状态和计数；数据集结果、逐样本结果与
`dashboard.json` 索引分别落盘，批跑详情接口不内联全部大产物。插件启动时立即创建运行中看板，并在每个
样本、数据集和收尾阶段完成时原子更新结果与结构化进度，因此插件未结束时也可进入看板查看已有内容。插件只可将文件写入自己的执行目录，返回
文件路径必须通过目录边界校验后才由受限接口读取。后处理使用独立单消费者队列，不占用批跑队列；后端
重启将活动执行标记为中断。批跑详情使用同一个界面展示可选插件与已选插件的最新结果，不再拆分“插件配置”
和“执行结果”，也不提供用户拖拽排序。任务列表展示该运行中所有已执行插件，而不是只展示最近一次提交。
每个已执行插件自动获得独立看板路由，看板按时间切换该插件的历史执行，并在运行中展示样本处理、数据集汇总、
收尾三个阶段的状态和可用结果；前端按产物类型统一渲染指标、表格、图表、热力矩阵、图片画廊、问题、JSON、
代码、差异和下载入口。样本表格的全量排序由服务端完成，排序入口位于可排序列的表头。多图片默认单张轮播，
并可切换缩略图导航。插件配置由清单中的受限 JSON Schema
描述，在提交前后分别校验。历史 `batch-postprocess-v1` 执行只读兼容，新执行不得继续写 v1。

## 本地转换与 Web 渲染

调试工作台所有 Compact DSL 和 Design Compact DSL 预览统一通过本地调试接口
`POST /debug/renderer/convert` 调用 `compact_dsl_a2ui_converter.py`，不在前端复制其转换规则。
独立 `render/platform` 的默认视觉验收模式同样通过同源代理调用该接口；本地 TypeScript
转换只作为显式离线对照模式，正式转换失败时不得静默回退。两个入口的卡片绘制都以
`render/genui-sdk` 为唯一视觉源；Debug Tools 的 workspace Runtime 由同步脚本确定性生成，测试前校验
除已登记的图片代理适配外不存在源码漂移。
自动渲染、手工渲染、批跑详情、后处理 DSL 画廊、批跑截图和校验失败截图使用同一异步解析入口。
已有 A2UI 和 Graph JSONL 在前端直接解析，不调用转换接口；转换失败不得回退为前端转换。
云侧 A2UI 的 `onClick` call/args 列表在 Web 绘制适配层映射到既有 interactionHost 的
functionCall action，保留参数和点击时求值语义，不修改导出的 A2UI，不执行外部跳转。
请求包含 `source`、`size`（`auto/2x2/2x4`）和可选 `appVersion`（客户端版本）。版本优先取原产物
`TaskSpec.appVersion`，其次取同次请求的 `deviceInfo.prdVer`；手工粘贴裸 DSL 时由版本输入框指定。
批跑详情、画廊与校验失败历史截图保留各执行尝试自己的版本，不使用当前工作台版本替换历史版本。
转换接口将版本传给 Python 转换器的 `protocol_profile.appVersion`，保留融球的版本门禁；
缺失、非法或过低版本不得被替换为高版本来开启背景。自动尺寸沿用 Compact 预览的几何推断，
宽度不小于 240 的组件选择 2x4，否则选择 2x2。响应返回 `genui` 和实际 `size`，
页面用该尺寸渲染。普通渲染保留原始输入；显式“Python 转换并渲染”操作额外将编辑器内容
更新为返回的 A2UI，供复制和检查。公共 `parseInput` 返回 `Promise<RendererDocument>`。
非法输入返回 422 和明确错误，转换失败保留原输入；转换期间修改输入、尺寸或版本时取消旧请求，
旧结果不得覆盖新输入。手动调整容器宽高时，同时取消旧请求和等待启动的自动渲染定时器，
保留用户设置的尺寸。frontend/full 两种调试模式均支持，工作台和独立渲染器的 Vite
开发模式均代理该接口；Compact 预览要求启动 Python 调试后端。
此接口仅用于本地调试，不调用模型、不生成或保存正式 Artifact，也不执行点击事件。

Web 文字组件在 `maxLines: 1` 时禁止换行，保留已有文字框高度和布局预算，避免固定高度中露出
第二行字形残片。单行裁剪按实际字体和可用宽度保留能完整显示的字符前缀；无法完整容纳的字符整体
隐藏，不显示半个字形，也不拆开组合字符或 emoji。尺寸、绑定内容或字体加载状态变化时重新计算。
显式省略模式保留省略号，多行文字继续使用多行截断，未声明行数限制的文字保留自然换行。

### 区域适配与共享实现

云侧转换器与两个浏览器预览入口都在高阶组件展开后执行区域适配、在融球背景展开前执行。
浏览器共用 `render/shared/compact-region-layout.ts`；旧平台入口保留兼容导出，新调试工作台
复用同一实现，不能各自维护缺省固定画布。原始Compact与标准A2UI预览应得到相同的区域关系。

## 浏览器画廊与预览尺寸

画廊和真机截图作为内置 v2 插件接入同一注册、调度、状态与结果协议；旧按钮和读取接口保留兼容。画廊插件
同时输出逐样本图片产物与独立 `gallery.html`。画廊按样本原始顺序复用调试平台
CardRenderer 生成 Web 渲染截图，将 PNG 以内联 data URI 写入单个可离线打开的 HTML，并同时展示全部
成功、降级、失败、不支持和取消样本；没有有效 DSL 或渲染失败的样本展示原因占位，不伪造截图。画廊生成
使用独立 `not_started/generating/ready/failed` 状态，失败不改变批跑业务状态，也不阻塞下一任务执行，
任务中心允许对已有结果手动重试、重新生成或打开画廊。该截图仅用于开发调试，不替代真实 HarmonyOS 端侧验收。
调试渲染尺寸优先采用最终 CardSpec 的 `suggestSize`，CardSpec 缺失时再从用户 query 中识别明确尺寸，
最后回退到批跑样本保存的 `size`；三者均无有效值时才允许由 DSL 几何推断。任务详情和画廊截图必须复用
同一解析逻辑，不能因 GenUI 的 `createSurface` 未声明宽高而默认按 `2x2` 渲染。

## 质量评分与跨批次比较

单批质量评分插件 `quality-score` 依赖 `browser-gallery`，不执行 DSL 修复；跨批次比较由宿主只读接口提供。
评分支持 Web 批跑和用户导入的 DSL、截图、Query、尺寸两种输入。外部输入通过
`POST /debug/batch/quality/import` 保存为独立 `sourceType=external-quality` 批次，
导入后须确认样本并点击运行评分。导入来源跳过 browser-gallery，使用离线结构、内容检测及可选 OCR，
再调用相同评分模型；截图关联保留用户提供的配对。缺 OCR、未支持结构或检测异常显示待评。
单条与批量导入共用接口，校验样本数、请求字节、图像格式/像素、ID、哈希及输入深度。
PNG/JPEG 损坏（包括 PNG CRC 校验失败）返回 422；批次全部验证及写入成功后才发布，失败清理临时目录。
单条对比通过 leftSampleId/rightSampleId 显式配对，允许不同 ID；并排展示左右原图、分数上下界和问题差异。
计算分差要求 Query、尺寸、客户端版本、评分策略及检测范围一致；外部检测另核对 OCR/检测器版本、
图片来源和显式动作要求。不同范围仍展示两边结果及差异原因，分差留空。

画廊截图同步采集 Web 文字边界、裁剪、疑似内容重叠、图片加载及解析诊断，并绑定最终 GenUI
规范化换行后的 SHA-256、渲染上下文和 PNG SHA-256。证据写入插件执行目录以保留历史。
评分沿用 consequence-comparison-v2 的四类权重与去重扣分，不把 Web 几何结果等同于端侧结果。
缺失、过期或无法解释的证据不得冒充满分；确认问题与待确认问题分别形成得分上下界。
插件执行状态与质量结论分离，100 分仅表示声明检查范围内未扣分，不代表功能、审美或训练验收通过。
旧画廊没有检测证据时，须先显式再次运行画廊，再运行评分；依赖历史不被自动覆盖。

平台主导航提供质量评分入口。选择已完成批次、确认样本导入后，只有用户点击运行才提交评分。
`quality-score` 配置允许互斥的 `sampleIds` 或 `count`（原批次顺序前 N 条）；空集、重复、未知 ID、
非正整数或超出批次数量均拒绝。宿主将选择固化为 ID 列表，只对所选样本调用评分并汇总，
新执行不覆盖历史。画廊依赖仍保持原有整批采集/历史复用行为，未选样本不进入评分分母。
看板同时记录来源总量、所选 ID、query/size 快照及配置；再次运行保留原选择。

`quality-score/EVALUATION.md` 内的受控 JSON 块是权重、严重度和规则表的唯一参数来源。
评分计算仍为标准库纯计算；方案接口由同一参数块生成 Markdown 表格，结果保留参数快照与哈希。
历史结果的参数以执行快照为准，不因当前文档更新而被改写。
只读接口 `/debug/batch/quality/evaluation` 返回当前方案；`/debug/batch/quality/compare` 接收两个
runId，可指定各自 executionId，否则使用各自最新已完成评分产物（含部分完成状态）。缺少结果返回
明确错误，不自动补跑、不把缺结果记为零。同一 ID 仅在 query 与 size 快照一致、参数口径一致且
两边有分时计算差值；新增/缺失、上下文不一致、待评分别展示。问题分布按每卡独立规则 code 计数，
疑似问题与确认问题保留区别。通过率定义为无确认/待确认问题且有完整评分的样本数除以本次所选总数，
待评不计通过；它仅表示 Web 范围内无问题，不能替代训练验收。总体通过率差仅在所选 ID 集合、
上下文及参数均一致时计算；否则只展示两边指标与不可直接比较原因。

## 期望对比

期望对比是独立模块，主导航入口只有「期望对比」对应页面 `/debug/expect`；期望数据画廊
`/debug/expect/gallery` 通过对比页页内跳转进入，不占左侧主导航。该模块不与质量评分共用子导航：
质量评分页不再把期望对比列为子页面，期望对比页也不再出现评分子页链接。模块自有页面为对比页
`/debug/expect`、导入期望输出页 `/debug/expect/import`、导入实际输出页 `/debug/expect/actual-import`
与期望数据画廊 `/debug/expect/gallery`；导入组件同时保留
质量评分侧入口 `/quality/import` 与画廊侧入口 `/expect/gallery/import`，复用同一组件，仅导入完成后的
落地位置与按钮语义不同（期望对比侧带 `importRunId` 跳到对比页预选，画廊侧回到 `/expect/gallery`，
评分侧仍跳到 `/quality?runId=` 选择评分样本）。旧地址 `/debug/quality/expect` 重定向到 `/debug/expect`
并保留查询参数，不静默丢弃批次。对比页页内保留「导入期望输出」「导入实际输出」与「期望数据画廊」跳转，模块之间
（质量评分、批量测试、端到端调试）一律通过左侧主导航进入，不在页面里放重复入口；导入页页内跳转只保留
「期望对比」与「期望数据画廊」（画廊入口进入时额外给出「返回画廊」），不再出现质量评分链接。
对比页在表单上方常驻「真实输出与期望输出是怎么比的」，写明期望需求项来源优先级（显式填写 →
CardSpec → 导入 DSL）、实际指纹提取口径、启用维度的包含式筛选与五个层级含义；出结果后汇总区给出
「配对明细表」，逐行写明期望样本、匹配到的实际样本、层级与两侧尺寸。
结果区只有匹配上的期望才按真实输出样本成组，且每组默认折叠（筛选区提供全部展开／全部收起）；未匹配的期望不渲染卡片，
统一由汇总区的配对明细表给出 期望样本／匹配到的实际样本／层级／缺项与多出／两侧尺寸（仅展示）。
数据、动作与图标 token 一律并排展示中文名与原始写法（路径、`函数:目标`、素材名），
中文名只用于阅读，匹配始终按原始 token 比较。
对比页把「实际来源 + 选中的批跑运行 + 勾选的会话记录 + 启用维度 + 三个筛选条件」持久化到浏览器本地（`localStorage` 键 `ai-widget-expect-compare:v1`，带版本号），回到页面时恢复并自动重跑一次；写读失败（隐私模式／配额）只影响记忆能力，不影响对比。页面上提供「清除记忆」回到默认；上次的批跑运行已不存在时不再自动重跑并给出提示。
对比页两侧在卡片上直接标出身份：左侧「期望输出」、右侧「真实输出」；汇总与明细表同样以「期望输出／真实输出」表述。配对前先做同一用例判定，判据三条（满足其一）：样本 ID 同名；Query 完全相同（非空）；「数据分类＋数据＋动作」强绑定全部成立（期望声明的分类要与实际相同，期望的数据与动作要被实际指纹包含；三项全空的期望不算强绑定，避免无关卡片硬配）。配对前先做同一用例判定：实际样本必须与期望同名（样本 ID 不区分大小写），或 Query 完全相同（非空），
否则记 `no-actual`（「没有对应的实际输出」）并在汇总里给出条数与样本 ID；候选内才按缺失最少、
同 ID、同 Query 排序挑选（尺寸不参与），因此不存在"无关卡片被拿来对比"的路径。

后端正式路径为 `/debug/expect/*`：`POST /debug/expect/compare-live` 用前端提交的本会话真实输出完成配对，
`GET /debug/expect/compare?importRunId=&runId=&dimensions=` 用已落盘批跑运行每个样本的最终 GenUI 完成配对，
两个接口的指纹口径与配对规则完全一致，`dimensions` 缺省时三个维度全启用。页面在「实际来源」
里二选一：默认本次会话的真实输出，另一个是已落盘的批跑运行，选哪个都走上面的同一套规则。
期望侧不要求挑批次：`importRunId` 留空时后端汇总 `purpose=expect` 的期望批次
（按 `startedAt` 新的在前，逐批读样本并按样本 ID 去重，同一 ID 取新批次），页面只显示已导入的条数与批次名；
实际输出批次（`purpose=actual`）不进期望池，避免自己和自己配对。
导入只强制截图。导入页有「使用自定义样本 ID」复选框，**默认不勾选**：此时不采用人工 ID（批量导入连清单／文件名主干也不用），由后端按内容（Query＋DSL＋期望项＋截图）生成 `H-<sha256 前 12 位>`——同内容必得同一个 ID，同批同内容撞车才加 `-2` 后缀并在 `sizeWarnings` 里提示。勾选后使用人工 ID，ID 唯一：人工重名直接 422 拒绝并提示可以留空。**ID 只是标识，不参与配对**——配对与筛选由数据分类、数据、动作决定；`ImportSample.dsl` 可留空（空 DSL 不再报错，尺寸改由截图比例或契约缺省判定）。`POST /debug/expect/import` 执行导入，`purpose` 取 `expect` 或 `actual`，缺省按期望处理，
历史导入批次落盘时没有 `purpose` 字段，读取侧统一按期望回填，不做数据迁移。
导入页不由人工填批次名：后端 `name` 仍必填，由页面按用途与导入时间生成（`期望导入 · YYYY/MM/DD HH:mm`／
`实际导入 · YYYY/MM/DD HH:mm`），只服务批次分组与整批删除。`GET /debug/expect/options` 返回导入页可选的期望项（能力声明的出参路径、事件与素材，均带中文标签，
数组字段的数组标记归一为 0 号槽位），页面据此做下拉与模糊提示，候选之外仍可手写。
`POST /debug/expect/detect` 按内容结构识别 genui DSL 还是 CardSpec，返回指纹与尺寸但不落盘；
`query` 与截图都是可选项：没填 `query` 的样本只按样本 ID 与另一侧配对，声明了 `imageSha256`
却没有截图则拒绝导入，没声明也没截图就不落图片文件。
`GET /debug/expect/samples` 列出导入样本并支持 `category`、`q` 查询参数；`GET /debug/expect/runs/{runId}/samples/{sampleId}` 读单条（编辑回填），PUT 同一路径就地更新这一条（局部更新：只改请求里出现的字段，`category` 传 null 清回未分类；不带 imageBase64 时继承原截图）：批次身份与其余样本都不受影响。更新会写 `summary.updatedAt`，期望池按 `updatedAt or startedAt` 排序，修改立即生效且不产生同 ID 的第二条。`PUT /debug/expect/runs/{runId}/category` 整批改数据分类（含自定义分类名），只写分类字段，不重写 DSL、截图与期望项。
`DELETE /debug/expect/runs/{runId}/samples/{sampleId}` 删除单个样本，
`DELETE /debug/expect/runs/{runId}` 删除整批；删除只允许 `external-quality` 导入批次（期望与实际两种用途都算），
删掉最后一个样本时批次目录一并移除，并同步维护 `summary.json` 的样本数与尺寸提示。
`GET /debug/expect/runs/{runId}/samples/{sampleId}/input-image` 读取导入截图。导入接口同时服务两个模块，
因此 `/debug/batch/quality/import`、`/debug/batch/quality/expect` 与
`/debug/batch/runs/.../input-image` 保留为同一处理函数的兼容别名，不是两份实现，行为与限制完全一致。
对比页不轮询、不触发批跑。

对比页左侧只能选 `purpose=expect` 的导入批次（由「导入期望输出」页经上传接口或批量导入产生）。
右侧实际侧默认「本次会话调试记录」，即端到端调试与接口调试已经拿到的真实输出；也可切到已落盘来源，
在下拉里选批跑运行或「导入实际输出」产生的批次，两类来源在选项文字里用 `[批跑]`／`[导入实际]` 前缀
区分，默认优先最新导入的实际输出批次。配对规则同一套：样本 ID 同名，或两边都非空且完全一致的 Query；
实际侧选了导入批次时页面额外提示没填 Query 的样本只按 ID 配对。期望批次不能被选作实际来源。

会话来源只存在于浏览器：调试记录保存在 `sessionStorage`（上限 100 条，后端不落盘），前端按同一条
提取口径从成功调用里挖出 Query 与 GenUI DSL（`response.data.genui`，回退到 finalFrame／streamContent），
只把 `{id, title, query, genui, size}` 提交给 `compare-live`，并附带本次启用的 `dimensions`。
指纹与配对全部在后端算，与兼容的批跑来源共用 `_assemble`，避免两套口径；响应信封仍用
`actualSource: "session" | "batch"` 区分来源，会话样本的标题不链到批跑详情页。提交限制：至少一条、
最多 100 条、单条 DSL ≤2 MiB、合计 ≤8 MiB，样本 ID 必须符合 `A001`／`call-xxx` 形式且不可重复，
缺少 DSL 或声明 `2x2`／`2x4` 之外的尺寸都按 422 明确拒绝。默认不预选会话记录，由用户勾选。

配对依据是「数据 + 动作 + 图标」指纹：两侧用同一套提取逻辑从最终 GenUI 中收集数据绑定路径、
动作与图标资源，保证口径一致。尺寸不进指纹：同一组内容可以落成 2x2 或 2x4，它是渲染结果属性，只作展示。导入时显式声明的数据/动作 token 优先于自动指纹作为需求项；
图标没有显式声明，始终取 `Image` 组件的静态 `src`。匹配为确定性纯计算，不依赖模型评分。
模板把素材写成 `Image.src = {"path": "/asset/<槽位>"}` 时，`/asset/*` 属于素材槽位而不是业务数据：
指纹把它从数据维度移出、记进图标维度，并用同一条 `updateDataModel` 里 `asset` 登记的 `槽位 → 资源路径`
换成资源名（槽位没登记资源时退回槽位名），这样才与 CardSpec 的 `asset.icon_meeting` 和素材库的中文标签对齐。
图标维度只保留 `asset_capabilities.json` 里声明过的素材（比对照 `capability_labels.asset_key`：
去目录、扩展名与 `asset.` 前缀）：模板私有图片、外链图片与「槽位没登记资源」的取值一律忽略，
它们不是我们要识别的素材，留着只会以需求项身份让两侧都判缺失。能力目录不可读时不过滤，
避免把图标维度静默清空。显式填写的期望图标属于用户声明，不参与这条过滤。
另：`_iter_rows` 先整篇解析再退回逐行 JSONL，缩进过的 JSON 数组（模板文件常见形态）与 JSONL 必须给出同一指纹，
否则识别预览里看得到的数据在比对时会变成空集。

动作识别按**位置**判定，不按 `{"call","args"}` 形状判定：协议里同一形状出现在属性值位置是 FunctionCall
绑定（值函数 `formatString`、`formatNumber`、`formatDate`、`pluralize`、`size`），只有出现在事件槽里才是
动作；卡片子集只开放 `onClick` 一个事件类型（规范 §1.2 通用事件仅 onClick、组件私有事件全部排除），
因此仅 `onClick` 数组中的每个 handler 计为动作，`args` 可省略（`onClick: {"call": "x"}` 也算），
嵌套在 handler 参数内的 `call` 属于触发时一次性求值，不再另计动作（规范 §3.5 约束 9／10、§3.8、
§4.2.1.3）。数据侧统一 `${/a/b}`、`{"path":"/a/b"}`、`{{ $__dataModel.a.b }}` 三种写法为同一路径，
`updateDataModel path "/"` 的根写入不计入指纹。动作 token 为函数名加最可辨认目标标识
（`intentName` 优先，其次去模板化后的 deeplink 静态前缀、`abilityName`、`bundleName`）。

尺寸不参与「已匹配」判定：内容全部命中即记为已匹配，`2x2` 与 `2x4` 的差异只在明细表的尺寸列里展示；
不存在分数、权重或覆盖率。

数据、动作、图标三个维度可在页面上自由开关，至少启用一个。启用维度是**筛选条件**而不是评分：
期望侧在该维度下的全部需求项必须被实际指纹包含，缺少任意一项就记「未匹配」，不存在部分匹配、
覆盖率或最低匹配精度。图标取 `Image` 组件经模板化后的静态 `src`，比较时忽略目录与查询串，
只认文件名（basename），模板或数据绑定产生的动态 `src` 不计入指纹。没有启用维度需求项时记
「无筛选需求」；没有同用例的实际输出记「没有对应的实际输出」。每个期望样本只在同一条用例内选取缺失项最少的实际样本，
平局时依次优先样本 ID 相同、Query 相同（尺寸不参与）；实际侧只纳入 `success` 与 `degraded` 样本，
没有可解析 GenUI 的样本跳过并给出告警。会话来源只提交成功的调用，其尺寸取该次调试记录的卡片规格
并记为「声明」。汇总区首行固定标明「实际来源：本次会话调试记录」，并列出筛选维度与分组数。

同一实际样本可以对应多个期望样本，页面按实际样本分组：右侧一张实际卡片，左侧列出所有命中它的期望卡片，
不再把多对一当成异常分配。未被任何期望样本命中的实际样本也单独成组，左侧显示空提示。
多个期望命中同一实际样本时在汇总区给出「多对一」提示，由人工确认，不自动改分配。
页面支持按匹配层级、数据分类与 Query 筛选；筛选只影响展示，不改变匹配结果。
逐对差异分别给出期望有而实际缺、实际多出的数据、动作与图标。期望侧导入时带了截图就默认显示截图
（那是当时真实的样子），卡片上方的勾选框可切回 DSL 渲染；没有截图时只渲染 DSL。截图不参与指纹与筛选。
并排两列时左侧期望截图的显示宽度与右侧实际卡片列共用同一个上限（`--expect-side-width`），不让截图铺满
宽列后被放大；单列布局下两侧本来就是同一宽度，不另加限制。两侧卡片下方都必须展示该侧的 Query、尺寸、数据、动作与图标：
期望侧列需求项，实际侧列指纹项，缺失项标红、多出项标异色，便于逐条核对，不只放在差异栏里。
数据路径、动作与图标均附带中文标签（取自能力声明，缺失时退回内置词表或保留原文），中文只用于展示，
原文保留在标题属性中，不参与匹配。

导入时尺寸按固定优先级判定，只允许 `2x2` 与 `2x4`：显式声明值最高（声明其它值直接拒绝并说明协议只有
这两种尺寸，`4x4`／`1x2` 等一律不进入批次）；未声明时先看截图宽高比（≥1.5 判 `2x4`，0.75–1.33 判 `2x2`），
再看 DSL 证据（Design Compact 布局名 `S-*`／`W-*`、只存在于 `2x4` 的 `CardButton`／`TextBlock`、
根节点数值宽高）；证据互相冲突时判为尺寸无法确定并拒绝导入，不猜。声明值与 DSL 推断不一致时按声明保存，
只在批次 `sizeWarnings` 与告警区提示，不静默纠正。判定结果连同来源写入 `input.json`
（`size`／`sizeSource`／`derivedSize`／`declaredSize`／`sizeEvidence`／`sizeWarning`），
对比页据此区分「导入判定」与「人工声明」。

导入页可选择数据分类：预置分类（天气、电量、日程、音乐、运动、健康、待办、通用）或最长 40 字符的
自定义分类。批次级 `category` 会随 `input.json`、`result.json` 与 `summary.json` 落盘，批量清单可用
样本级 `category` 覆盖；为空表示未分类。对比响应返回本批次出现过的 `categories`，页面据此提供分类筛选，
「未分类」单独一项。期望数据画廊按批次分组展示全部导入样本，筛选框分别接收数据、动作与图标关键词
（同时匹配原始 token 与中文标签，空格分隔多个关键词时要求全部命中），并保留数据分类下拉；
展示中文数据／动作／图标标签、上传截图或 DSL 渲染，并提供删除单个样本与整批的入口；删除前必须二次确认。

导入页把来源拆成三个独立槽位：`导入 DSL`（必填）、`导入截图`（可选）、`导入 CardSpec`（可选）；
DSL 槽只认 genui DSL，放成 CardSpec 会退回并指明正确槽位。槽位是人工指定的，因此不再按内容猜格式，
只有指纹预览调用 `POST /debug/expect/detect`；识别不可用时仍可导入，指纹由后端在导入时按同一套口径重提。
选择 CardSpec 后：数据／动作／图标预览立刻给出，期望侧只在对应输入框为空时自动填充，不覆盖人工已写内容；
`Query` 还空着时用 CardSpec 顶层的 `userQuery` 补齐（两侧口径一致，后端 `cardspec_user_query` 会再补一次，
显式填写的 Query 优先）。批量有两种放法：`批量：多选 DSL／截图／CardSpec 文件`（三个槽位各自多选）与
`批量：整个文件夹（含清单）`；两者都按文件名主干（如 `Q001.genui.jsonl`／`Q001.png`）归组为同一样本，
文件夹侧在前端本地按与后端 `detect_payload` 同一套结构规则镜像判断格式，避免逐条请求，两端各有测试覆盖。
批量导入不因为一个坏文件放弃整批：每条不合格的样本连同原因列进「失败文件」清单，其余样本照常导入；
有失败文件时页面留在导入页（批次已经导入），清单里的问题修完可以再导一次。清单路径越界仍是整批硬错误。
整目录导入会自己做三件事，并全部列进页面的「自动取舍」块（不是失败，但用户要知道）：
同一主干有多张截图时取路径字典序第一张——不认目录名，目录叫什么都行；截图不参与指纹与筛选，
只作参考图并给尺寸判定当辅助证据，所以取一张即可，取用与未使用的候选都列出来；要钉死用哪张，
在目录根部放 `quality-import.json` 并写该样本的 `image` 字段（清单优先，与目录名和排序都无关）；
能被 JSON 解析但不像 genui 的文本（交付清单、渲染脚本输入等）直接忽略，不再产出「拿文件名当样本 ID」的假样本；
只有图而没有同名 DSL 的条目仍然报「缺少 genui DSL」，不会被静默丢掉。
自动识别结果按三个维度分行展示，每个 token 紧跟候选库里的中文名（素材没在能力库里声明时拿不到中文名，
只显示原始资源路径）；维度不错位：`/asset/*` 这类素材槽位归图标行，不再混进数据行。
样本 ID 在同一次导入里必须唯一：重复的那条只进失败清单并要求更换 ID；与已有批次同名时页面给出提示
（同名按最新批次生效——要修正样本就用同一个 ID 重新导入，要与旧样本并存请更换 ID），提示只提醒不阻断。
`GET /debug/expect/sample-ids?purpose=expect|actual` 只返回该侧已有样本的 ID 与批次名（不带 DSL／截图），
供导入页在提交前查重，避免为了查重拉整份样本。导入后要改数据／动作／图标：在期望数据画廊删掉该样本再重导，
或用同一个样本 ID 重新导入覆盖。
后端在生成期望指纹时优先采用 CardSpec 中的数据绑定（`writeResultTo`）、事件 handler 与资产/静态图标，
某个维度没有可用字段时回退到 DSL，显式填写的数据／动作仍然优先。画廊列表项同时返回原始
`fingerprint`（data／actions／icons），供页面按三个维度本地检索，不需要重新请求。

两侧预览复用 `CardRenderer` 与 `/debug/renderer/convert`，因此期望批次内的 Compact DSL 同样必须满足
组件类型与属性契约；使用不受支持的组件类型会让转换返回 422 并显示"暂无卡片"，属于数据问题而非匹配失败。
对比页把预览缩放固定在 130%，并为预览舞台固定行高，避免分组两栏布局下卡片被裁切。
`debug_tools/make_expect_demo.py` 只用于本地联调：向运行中的服务写入一对可删除的演示批次
（实际批跑与期望导入各若干条，覆盖同尺寸、同内容跨尺寸与筛选缺失），可验证兼容的
`GET /debug/expect/compare`；
页面本身只消费会话来源，产物落在被忽略的 `batch_output` 下，不参与正式批跑，也不作为验收数据来源。

## 真机截图

真机截图不属于任务参数，也不进入任务快照。批跑完成后，用户可在后处理流水线中选择真机截图插件，
按调试平台 `debug_agent.yaml` 配置的 ArkTS 渲染工程、DevEco 工具链和 HDC 设备串行构建、安装、启动、
截取全屏并裁切卡片；这些配置不进入微服务配置、接口请求或任务快照。
插件流水线不占用批跑单消费者、不阻塞后续生成任务，浏览器生命周期不影响执行；后端重启将活动执行标记为
中断并允许手动重试。真机截图使用统一插件状态和逐样本错误，任何配置、构建、设备或截图失败均不改变批跑
业务状态。真机截图与浏览器画廊默认没有依赖关系，用户同时选择时并行执行，互不读取或内联对方结果；
两者分别保留最新结果和历史执行。任务详情按插件展示已有结果，缺失时明确显示原因，不伪造图片。
全屏原图仅供排障。

## 组件召回分析

组件召回分析使用数据集 `evaluation/component-recall.json` 中的显式真值，不从运行时 Plan 提示或候选全集
反推。批跑启动时将真值快照到运行目录，后处理从最终 `designcompactdsl` 读取展开前组件类型。每个
`required` 组件和每个 `anyOf` 任选组各计一个召回单元；组件类型按集合去重，额外组件只展示不扣分。
已标注但没有最终 DSL 的样本记零，未标注样本跳过并排除汇总；数据集整体指标仅使用已标注样本召回率的
宏平均，并同时展示标注覆盖率。

## 本地受管微服务

批跑可连接已部署微服务，也可由调试平台按 `debug_agent.yaml` 的稳定配置和任务中的模型测试参数启动
本地微服务。受管服务只监听回环地址，每次启动自动分配空闲端口，不要求用户配置固定端口；任务切换时按
有效配置复用或重启，队列空闲后关闭。批跑并发、请求超时、Trace 路径、服务启动超时和产物校验等稳定
参数直接读取 `debug_agent.yaml`，不在创建任务页面展示；页面只提供适合比较不同模型路由、采样、思考、
重试和回退策略下后端表现的非敏感参数。密钥只从服务端环境继承，不返回浏览器、不进入任务快照或日志；
平台不得终止无法通过 PID、创建时间与启动命令共同确认身份的外部进程。

## 微服务开发调试 Trace 记录

`generateWidgetCardCompactDsl` 可复用 `enable_generation_trace_recording` 和
`generation_trace_root` 开启请求级开发调试 Trace，默认关闭。该 Trace 不属于对外接口契约，不改变
WebSocket、响应、Artifact 或普通日志中的 `retry_count` 语义，也不接入其它生成接口。

- Trace 只使用 `generation-trace-v2`，不兼容 v1 或 `model_trace.jsonl`。目录继续按合法 UID 拆为
  `<task_type>/<identifier>/<request_sequence>/<caller_retry>/`，目录内使用原子更新的 `manifest.json`、
  `trace.jsonl` 和 `artifacts/`。manifest 记录 `recording/complete/partial` 生命周期、Trace/根 Span 标识、起止时间、
  记录数、附件数和终态摘要。
- `trace.jsonl` 使用请求根 Span 和显式父子 Span，记录 Trace/Span 标识、record type、稳定 category、
  单调时钟相对偏移、耗时、状态、分层 attempt、属性、指标和附件引用。稳定 category 限定为
  `request/protocol/source/preflight/prompt/plan/model/transform/validation/repair/artifact/response/other`。
  事件序号、时间戳、附件序号由写入器统一分配，同一内容的附件按 SHA-256 去重。
- `artifacts/` 保存完整开发调试中间产物，包括 Plan 与 DSL 的完整 messages、模型 assistant 文本、提取和
  修复后的 Compact DSL、转换各阶段 A2UI、校验上下文与结果、每轮质量修复内容以及最终 Artifact 信息；
  不保存 HTTP 或 WebSocket provider 的原始包络。附件显式区分 `input/output/diagnostic/snapshot`，并记录
  MIME、SHA-256 和字节数。
- 重试统计按参数修复、接口尝试、Plan 合同、模型物理调用、模型传输重试、provider fallback、质量修复和
  校验评估分层记录。每条重试事件携带失败原因、是否继续、退避耗时和下一尝试编号。
- 路由取得合法 JSON 后尽早绑定 Trace。相同请求在接口内部重试时复用同一个 writer，不重置序号、累计
  耗时和计数；终态包含总耗时、分阶段耗时、尝试/重试汇总、错误码、Artifact URL 和摘要。WebSocket
  必须在发送 `final`/`final_error` 前完成 manifest 终结，`finally` 只保留幂等兜底。
- Trace 仅用于开发调试，启用后保存完整内容，不做脱敏或截断。UID 不符合现有目录规则时跳过记录；任何
  Trace 创建、序列化或写入失败只打印 warning，不得改变生成结果、重试策略或 Artifact 内容。

## 历史批跑修复参数覆盖

本地批跑按用户授权可覆盖失败定向修复上限为10次，首次生成不计入这10次；
产品默认按当前配置开启定向修复，上限5次；10次只适用于历史授权批跑，不是当前默认。
批跑覆盖不进入产品配置，业务请求次数、接口重试
及换模型策略不因此扩张。
