# Debug Tools React 调试平台技术方案

## 1. 目标与范围

本文维护平台架构、代码组织与关键流程；页面交互、任务执行及验收细则统一维护在
[调试平台运行规范](调试平台运行规范.md)。Debug Tools 专属变更在本目录同步文档。

### 设备渲染调试

工作台新增 `/debug/device-render`，由本机 `/debug/device/*` API 承载，两种启动模式均可用。
`device_debug` 模块负责环境检查、HDC 设备发现、已有虚拟机启动、屏幕订阅、代码转换，以及共享的
Render Project、Render Session 和 Capture Result。
工具链由 `debug_tool.yaml` 的 `platform.environment` 统一解析；
`platform.device_capture` 只保留工具链、模拟器和运行参数；ArkTS 工程固定解析到
`debug_tools/a2ui_render`。Node 优先使用 YAML 中的
`node_executable`，未配置时才查找系统 `PATH`；显式路径无效时不静默回退。
任一环境路径变量均可以 `${environment.<name>}` 形式在其它路径开头引用，
未定义、循环引用和中间插值都会明确报错。运行时不再从 DevEco 根目录在代码中拼接工具路径。
工具链是可选本机依赖：启动检查失败时记录警告，设备服务保持不可用，画廊在实际截图时严格校验。
设备接口保留环境状态查询和独立转换，执行入口统一检查服务可用性；详见运行规范“可选外部环境与启动”。
浏览器不能提交任意命令或工程路径。真机或不能确认类型的目标必须使用工程已有签名。

接口：`GET environment/targets`；`POST emulators/{id}/start`、`GET operations/{id}`；
`WS targets/{id}/screen`；`POST convert/runs`；`GET runs/{id}`、`GET runs/{id}/logs?offset=0`；
`POST runs/{id}/cancel`、`GET runs/{id}/images/{card|full}`。以上路径均以 `/debug/device/` 开头。
转换请求包含 `source/format/size`，构建请求另含 `targetId`，服务端固定任务输入与目标。
输入格式为 `auto/a2ui/compact`，尺寸为 `2x2/2x4`。标准 A2UI 保留消息内容；Compact 使用正式通用
转换器，不调用模型或执行完整云侧业务修复。转换结果可独立查看。

每设备仅一个采集器，以单调时钟按 1 秒周期采集，单次超时 5 秒，不堆积，慢订阅者只保留最新帧。
WS JSON 消息携带帧时间、序号和实际帧率，随后发送 JPEG 二进制；失败标记旧图过期。
页面隐藏、退出或暂停时断开订阅，最后一个订阅断开后回收采集器和临时截图。

构建任务串行执行，状态为 `queued/running/success/failed/cancelled/interrupted`，阶段单独记录。
在独立工程副本中写入 rawfile 并执行 debug assembleHap；签名路径按源工程基准解析，原工程不变。
部署与批量截图通过同一按目标标识建立的锁互斥。安装采用覆盖安装，失败不自动卸载应用。
后端重启将未完成任务标记中断，页面关闭不取消任务。取消只停止本任务进程，不撤销已完成安装。
输入、标准 A2UI、HAP、状态和脱敏日志保存在 Git 忽略的 `device_output` 下，任务结束清理工程副本。
本模块只验证调试渲染链路；应用启动成功不等于渲染效果、动态数据或完整协议验收通过。

页面顶部以状态栏展示渲染工程、签名、真机和模拟器可用性（不展示 DevEco 工具链汇总项），每 20 秒刷新且
不隐式启动设备。“输入与部署”提供 Compact DSL 和 A2UI 页签，按最后编辑的输入格式进行 400 毫秒
防抖转换；Compact 的转换结果显示在 A2UI 页签，并允许继续编辑。浏览器预览与设备部署使用同一转换结果。
“渲染预览”标题栏右侧提供浏览器截图、真机截图两个独立复选框，默认均显示；移除原说明文字。
浏览器画布支持滚轮缩放（向上放大、向下缩小，范围 50%–360%），缩放时不滚动页面；设备侧仅展示任务的卡片截图。
页面不展示全屏截图，也不订阅实时全屏画面；后端屏幕与图片接口保留供其它调用方使用。
profile CRUD、分辨率、等待时间和手工裁切 UI 已移除；已有本地
`device_config.yaml` 不主动删除，但不再读取。

`device-gallery` 的配置要求在线目标 `targetId`。执行开始时重新解析目标，离线或类型变化立即失败；不持久化
序列号或裁切快照。一次执行持有一个共享 Render Session，构建、安装各一次，随后按样本顺序动态推送，
并把尺寸作为 Ability 参数传入。卡片图、可选全屏图、日志和 `gallery.html` 写入该次 v2 插件目录；旧公共
截图目录及读取接口仅保留只读兼容。

`debug_tools` 是面向本地联调的统一浏览器工作台，用同一个页面串起六条链路：

1. 端到端调试：浏览器通过可配置的 Main Agent WebSocket 发送用户请求，查看 Skill 导入、Agent 回复、工具调用和产物事件。
2. 接口调试：浏览器直接连接三个正式微服务 WebSocket 接口，只把一次调用的 request 和 `final`/`final_error` 结果纳入平台共享历史。
3. 卡片渲染：在浏览器本地导入 GenUI/A2UI、Compact DSL 或 Design Compact DSL，完成解析、校验和预览。
4. 批量测试：由本地调试后端管理可重复运行的任务、单消费者队列和可选受管微服务；任务内部并发调用
   Compact DSL 接口，持久化每次执行产物并按 UID 关联生成 Trace。
5. 质量评分：显式选择 Web 批跑或导入已有 DSL、截图、Query，确认样本后评分，支持批次和单条对比。
6. 设备渲染：转换卡片代码、选择真机或模拟器，构建部署并查看设备画面与卡片截图。

平台壳不再使用 topbar、`e2e-topbar` 或 `interface-header` 作为重复标题区。页面固定为 `100dvh`，各模块在自己的面板内滚动；左侧 `navigation-rail` 的下半部显示三模块共享的接口调用历史。

后端承载自定义 Main Agent、Skill 导入、Agent 工具调用等待桥，以及本地转换、批跑、后处理和评分 API。
单次微服务调用由浏览器发起；接口调试不依赖 Agent 服务，Compact DSL 预览需要 Python 调试后端。

## 2. 总体架构

```text
浏览器 React/Vite 工作台
  ├─ /debug/end-to-end ── agentWsUrl ── 自定义 Main Agent WebSocket
  │                         └─ tool.call / tool.result：浏览器执行工具并回传 final 结果
  ├─ /debug/interface ─── toolWsBaseUrl/{operation} ── 三个正式微服务 WebSocket
  ├─ /debug/renderer ─── Python 转换 API、本地解析器、校验器与渲染器
  └─ /debug/batch ────── 任务中心 API 与单任务调度器 ── generateWidgetCardCompactDsl
                              ├─ Datasets/<dataset> / batch_output
                              ├─ 已部署后端或本地受管微服务
                              └─ workspace/traces

统一 Python 入口（python -m debug_tools）
  ├─ --mode frontend：托管 SPA、本地转换、批跑、后处理与评分 API
  └─ --mode full：托管同一 SPA，并启用 Main Agent
       ├─ Main Agent 会话、Skill 读取、模型调用和取消/重置
       ├─ 浏览器工具桥：挂起 tool.call，校验 tool.result，再恢复 Agent
       ├─ /debug/health、/debug/skills、/debug/artifact
       └─ /debug/tools/{operation} 仅保留迁移提示，不代理单次接口调用

三个微服务（示例默认 127.0.0.1:8855）
  └─ /api/v1/ws/tools/{operation}，由浏览器按配置直接连接
```

Main Agent 地址和微服务地址是两套独立配置：

| 配置 | 用途 | 默认值 |
| --- | --- | --- |
| `agentWsUrl` | Main Agent 的 WS 地址，可为相对路径或 `ws(s)://` | `/debug/e2e/ws`（后端同时兼容 `/debug/agent/ws`） |
| `toolWsBaseUrl` | 三个微服务的 WS base，平台会追加 operation 名 | `ws://127.0.0.1:8855/api/v1/ws/tools` |

`agentWsUrl` 不应被误填为微服务地址，`toolWsBaseUrl` 也不经过 Agent 后端转发。配置和固定请求参数由“连接配置”页面统一编辑，并以版本化对象保存到浏览器 `localStorage`（键：`ai-widget-debug-config:v1`；旧键会迁移一次）。

## 3. 技术栈与代码组织

### 前端

- React 18 + TypeScript + Vite；React Router 负责六个工作区路由：端到端、接口、卡片渲染、批量测试、质量评分和连接配置。
- React Context + `useReducer` 保存 `DebugConfig`、`ToolCallRecord`、当前 `CardArtifact` 和选中调用，避免模块之间通过 URL 传递大段 DSL。
- 原生 WebSocket 封装连接、状态、关闭和错误；接口调用使用 allowlist，只允许三个正式 operation。
- CSS 变量实现固定视口壳：左侧导航及共享历史、中部调试面板；长文本、列表和树在内部滚动，不因内容增加拉长页面。
- Vitest + React Testing Library 覆盖 Python repr 解析、Schema 展开、共享状态和交互。

### 后端

- Python 3.12、FastAPI、Uvicorn；`debug_tools/end_to_end_debug/backend/debug_agent/` 负责 Main Agent、Skill 读取和浏览器工具桥。
- 浏览器截图、失败样本截图和 Hvigor 构建共享同一 Node 解析与后台进程执行器；子进程继承统一的
  `NODE_HOME`、`JAVA_HOME`、`DEVECO_SDK_HOME` 和前置工具目录。Windows 使用无窗口模式，超时、
  取消与服务关闭均终止完整进程树。配置在服务启动时读取，修改后重启生效。
- `debug_tools/__main__.py` 是唯一启动脚本；命令行模式决定只创建静态应用，还是创建静态资源与 Main Agent 合并应用。
- 单次接口调试不经过后端。批量测试因需要访问本地数据集、持久化任务/队列/结果和 Trace，由后端建立
  独立微服务 WebSocket；已部署模式不管理目标服务，本地受管模式使用当前 Python 解释器启动、探活并回收
  `cloud/start_websocket_server.py`。受管服务固定绑定回环地址，且只回收具有匹配 PID、创建时间和命令身份
  的平台子进程。
- Agent 连接使用标准 dotted 消息类型；旧 `message`/`configure`/`reset` 帧仅为兼容独立调试器保留。
- `PyYAML` 作为显式运行时依赖写入 `pyproject.toml`，用于读取调试 Skill/profile 配置。

Main Agent 终端日志使用两行事件格式。只有明确成对的开始/完成事件使用方向箭头：`>>>>` 表示进入，
`<<<<` 表示返回；同一事件族颜色固定，例如 run 为蓝色、load_skill 为青色、invoke 为黄色。
没有对应开始事件的完成事件及失败、取消、初始化等独立事件使用 `[OK]`、`[ERR]`、`[WARN]`、
`[RUN]`、`[INFO]` 状态徽标，不使用方向箭头。第二行保留经过脱敏的紧凑 JSON 载荷，标题行可摘要
显示组件、状态和耗时，JSON 不再重复 `event` 字段。重定向到文件、CI 或不支持颜色的终端时自动
去除 ANSI 控制码，保证日志仍可检索和解析。

`debug_tool.yaml` 中 `platform.server.upstream_base_url` 仍作为旧配置和测试注入字段保留；浏览器直连生产路径不会使用它建立微服务连接。

### 目录

```text
debug_tools/
```

卡片渲染器保留工作台已有的 artifact 解包、输入编辑、尺寸、缩放和状态发布层，底层使用从根目录

## 4. 核心数据模型

### 4.1 `DebugConfig`

共享配置的规范字段为：

`agentWsUrl`、`toolWsBaseUrl`、`bundleName`、`protocolVersion`、`userId`、`deviceId`、`phoneType`、`appVersion`、`romVersion`、`locale`、`countryCode`、`deviceFormation`、`deviceType`（number）、`sysVer`，以及本地受管微服务的非敏感默认启动参数。分页字段仍由请求构造器按兼容默认值写入包络，但不再作为连接配置项展示。

连接配置页允许选择端到端调试和接口调试实际使用已部署微服务或本地受管微服务，默认选择已部署微服务；两条调用链必须使用同一个选择结果，不得各自维护地址。端到端调试和接口调试只在既有状态区或工具栏内显示当前选中微服务，以绿色、红色、灰色和文字分别表示可用、不可用、检查中，不增加独立状态横条。批量测试和连接配置页可展示三类后端的完整状态。连接配置页在配置内容中依次展示后端服务、本机工具链和设备环境状态，三块统一使用 `backend-status-widget settings-toolchain-status` 样式。工具链展示 Node、HDC、Hvigor、JBR 和 SDK 的实际解析结果，设备环境复用设备渲染模块的状态信息，不允许在网页中修改机器路径。进入连接配置页立即检查，之后每 10 秒自动检查，离开页面停止轮询；工具链与设备环境共用一次环境查询，不隐式启动设备。其它页面的后端状态轮询周期保持不变。

连接配置页可显式启动本地受管微服务，并将调试平台动态分配的地址保存为当前受管服务地址，复用批量测试的进程身份校验、健康检查、日志和退出回收机制；API Key、Access Key、Secret 等敏感值只从服务端环境继承，不进入浏览器配置。批量测试创建任务时默认继承连接配置中保存的受管微服务参数，任务页仍允许对本次任务单独调整。

资源根路径由渲染器内部保持 `/resources/` 默认值，不属于微服务请求配置；历史兼容别名只在迁移读取时识别，不会写回规范配置。会话 ID、交互 ID、设备时间等每次调用动态生成，不作为固定参数在三个模块中重复编辑。

### 4.2 `ToolCallRecord`

共享历史只保存一次完整接口调用，而不是每个 WebSocket 帧：

- `operation`：三个正式工具名之一；`source` 为 `interface` 或 `e2e`；
- `startedAt`、`finishedAt`、`durationMs`、`status`；
- 实际发送的 `request` 包络；
- `finalFrame`、`finalStreamContent` 和归一化的 `response`（含 `requestId`、`operation`、`status`、`errorCode`、`error`、`data`）；
- `callId`、`runId` 和错误文本（如有）。

`start`、`partial`、`command` 等中间帧不会写入共享历史。接口组件可在自身解析面板短暂展示最终帧，左栏历史只关心三个微服务调用的最终输入/输出。端到端模块的 Agent 运行轨迹仍可留在其内部检查器，但不会混入左栏调用历史。

### 4.3 `CardArtifact`

`CardArtifact` 保存来源、运行标识、GenUI、CardSpec、摘要和可选 digest。接口调试或端到端成功生成后，平台将产物放入共享状态；端到端收到只有 `artifactUrl` 的 `artifact_reference` 时由后端 artifact reader 自动下载并发送 `artifact_preview`，`mock://`、`mock_obs/` 等本地路径只允许从项目 mock 目录读取。卡片渲染模块读取当前选中调用或显式产物，不在浏览器中代理任意远程下载。

## 5. 关键流程

### 5.1 标准 dotted Agent 会话

端到端页面连接 `agentWsUrl` 后，按以下顺序通信（`protocolVersion` 当前为 `1.0`）：

1. 浏览器发送 `conversation.open`，后端返回 `conversation.ready` 和 `conversationId`。
2. 用户发送 `turn.start`，正文使用非空 `text`（同时兼容 `content`）。后端返回 `turn.status`，随后发送 `assistant.message`、`tool.call`、`tool.trace`、`artifact_preview`、`turn.completed` 或 `error`。
3. `tool.call` 由浏览器工具桥发出，至少包含 `conversationId`/`sessionId`、`turnId`/`runId`、`callId`、`name`/`functionName`、`arguments` 和 `step`。浏览器执行对应微服务调用后发送 `tool.result`，其中 `result` 必须是 JSON 对象，并带匹配的 `turnId`、`callId`。
4. 后端校验会话（若客户端提供）、调用 ID、挂起调用的 operation、可序列化性和结果大小，返回 `tool.result.accepted`、`tool.result.duplicate` 或 `tool.result.rejected`，再继续 Agent 模型循环。
5. 用户可发送 `turn.cancel` 或 `conversation.reset`。独立调试器仍可使用旧的 `message`、`cancel`、`reset` 和 `configure`，但新集成应使用 dotted 类型。

Skill 导入和工具编排仍发生在 Agent 后端；微服务请求体和 final 内容不经过后端重写。API key、模型凭证和 Skill 文件路径不下发浏览器。

首次进入端到端页面后，工作台主框架保留页面实例和 Agent 连接，主导航切换仅改变可见性。
会话、草稿与运行中的工具调用随页面实例保留，退出工作台时释放连接。范围及回归要求见
[页面切换与会话保留](调试平台运行规范.md#页面切换与会话保留)。

Main Agent 与本地受管微服务共用配置加载器，从进程环境、`cloud/config/default_config.yaml`、
`widget_service/.env`、`debug_tool.yaml` 的 `widget_backend.defaults` 和 `widget_backend.exposed`
依次覆盖；批跑单次参数仅覆盖本次受管微服务执行。配置别名、类型转换和提示词引用解析复用同一实现。
`main_agent` 仅维护 Skill、系统提示词和快捷提示，不再读取旧 `main_agent.model`。
模型调用复用微服务的通道命名及主备切换、失败重试、并发和超时语义；API key 或 URL 是否为空不参与路由。
本地配置修改后需重启端到端调试后端；已部署微服务仍使用其部署环境配置，不通过浏览器同步凭据。

`exposed` 只包含创建批跑时允许调整的版本对比参数，`defaults` 保存连接配置页可修改的其余默认参数；
两部分均使用微服务 snake_case 字段名，只有历史或外部配置命名不一致时才使用显式别名映射。

### 5.2 浏览器直连微服务

接口调试或 Agent 收到 `tool.call` 后，浏览器将 operation 追加到 `toolWsBaseUrl`：

```text
{toolWsBaseUrl}/getWidgetCapabilityOverview
{toolWsBaseUrl}/getDataCapabilitySchemas
{toolWsBaseUrl}/generateWidgetCardCompactDsl
```

浏览器发送统一请求包络（`content`、`deviceInfo`、`pagination`、`session`、`userAuth`、`utterance`、`version`、`bundleName`），参数来自共享配置和本次业务输入。浏览器持续接收服务帧，但只在 `final` 或 `final_error` 时完成调用、解析 JSON/Python repr、写入 `ToolCallRecord` 并关闭连接；中间帧既不进入左栏，也不回传给 Agent。单次调用完成、错误、断线或超时都会释放连接。

失败结果中的 `error` 保持微服务返回的原始 JSON 结构；尤其是 `error.message` 和
`error.details` 必须随 `tool.result` 原样交给 Main Agent，不能退化为仅含 `errorCode` 的概括文本。
历史 Python repr 中的 tuple（例如 Pydantic 校验路径）只转换为等价 JSON 数组，不执行输入代码。

### 5.3 卡片渲染与导入边界

Artifact 检查器已合并到卡片渲染路由，右侧提供 GenUI、CardSpec、TaskSpec、能力信息和元数据标签，以及复制、下载和源数据查看。点击左侧成功的 `generateWidgetCardCompactDsl` 调用会自动切换到卡片渲染；若 final 只返回 `artifactUrl`，前端调用 `/debug/artifact` 由后端 artifact reader 下载并解析，解析成功后同时进入右侧检查器和左侧卡片预览。已构建的静态工作台使用 `python -m debug_tools --mode frontend` 启动；需要 Main Agent 时改用 `--mode full`，两种模式都不依赖 `npm run dev`。

`CardRenderer`、`CardPreview`、`parseInput` 和 `RendererDocument` 保持原导入入口；解析结果新增 UIGraph、
warnings 和归一化 JSONL。预览交互通过 `interactionHost` 回传动作与来源组件，TextInput 修改只更新本地
DataModel；Intent、Deeplink 和 URL 均不实际执行。`/resources/` 与 `/background_assets/` 使用固定根
目录和路径越界校验，Vite 开发服务提供相同的本地资源读取语义，不开放任意远程图片代理。

`parseInput` 为异步入口，返回 `Promise<RendererDocument>`。Compact DSL 与 Design Compact DSL
统一请求 `/debug/renderer/convert`，复用 Python 转换器后解析 A2UI；已有 A2UI 和 Graph JSONL
直接解析。编辑器、批跑详情、后处理 DSL 画廊、批跑及校验失败截图共用该入口，不保留前端转换回退。
交互预览通过 AbortSignal 取消过时请求，截图页面等待转换、字体、图片及布局稳定后才标记 ready。
转换请求的 `appVersion` 优先取原产物 `TaskSpec.appVersion`，其次取同次请求 `deviceInfo.prdVer`；
裸 DSL 使用客户端版本输入框。批跑与校验历史保留每次执行自己的版本，并将其记录到截图上下文。
后端将该值传给转换器 `protocol_profile.appVersion`，沿用缺失、非法、过低版本关闭融球的规则。
修改版本时取消旧转换，避免迟到结果覆盖新预览。

下载出的 artifact 必须重新绑定到当前历史调用 ID，避免后端读取接口使用的内部 `runId` 导致前端将其
误判为其它调用。Compact DSL 历史的左侧代码框只接受 artifact 中的 `genui`（或已有的内联 DSL）；
下载期间保持为空并展示状态，失败时展示错误，不回退显示 `type='result' ...` 工具响应包络。

### 5.4 批量生成与 Trace 关联

批跑 API 只接受数据集扫描结果中的样本 ID，不接受客户端文件路径。运行 ID 和 UID 均由服务端生成；
同一样本的序号保持稳定，UID 末段表示批跑层重试序号。每次尝试独立建立 WebSocket 连接，并以
Semaphore 将并发限制在 1～16。`success/degraded` 还必须成功读取 artifact 并提取非空 `genui`
才算完成；确定性的参数错误和 unsupported 不重试。

创建任务接口在任务配置落盘后原子创建首个执行并加入持久化队列。批跑并发、批跑重试、请求超时和
Trace 根目录直接读取 `debug_tool.yaml` 的 `batch_testing`，不由浏览器提交。调度器空闲时自动开始准备和运行；已有
活动执行或等待项时，新执行保持 `queued`，详情页和任务中心显示“排队中”及队列位置。任务详情与任务中心
保留“再次执行”，用于为同一份不可变任务快照创建后续独立执行。

运行状态以原子替换方式写入 `batch_output/<runId>`。Trace importer 只根据服务端生成的 UID 从固定
`traceRoot` 解析 `<traceRoot>/<taskType>/<identifier>/<sequence>/<retry>`，只接受带 v2 manifest 的
`generation-trace-v2`，不兼容 v1、`model_trace.jsonl` 或未知 JSONL。默认等待 manifest 完成最多 5 秒；
Trace 状态使用 `complete/partial/missing/invalid`，作为独立告警而不改变生成业务状态。

每个 attempt 保存原始 `manifest.json`、`trace.jsonl`、导入摘要和稳定的 `view.json`。附件必须位于源
Trace 目录内且通过字节数与 SHA-256 校验，再按摘要写入运行级 `trace_blobs/`，跨样本和 attempt 去重。
浏览器只通过当前运行已登记的 64 位摘要读取附件，不接受本地路径。Trace 根默认读取
`debug_tool.yaml` 的 `batch_testing.trace_root`；命令行 `--trace-root` 或
`WIDGET_SERVICE_GENERATION_TRACE_ROOT` 仍可作为显式启动覆盖。

样本详情提供新标签页链接，打开 `/debug/batch/runs/{runId}/samples/{sampleId}/trace` 独立页面；刷新或直接访问
时按地址中的运行和样本标识读取详情。页面不展示工作台侧栏，使用完整视口，桌面并排展示瀑布与节点详情，
窄屏上下排列。Trace 页面使用节点树与相对时间瀑布，支持批跑 attempt 切换、名称/分类/失败/节点 attempt
筛选。节点检查器分为概览、输入、输出、诊断和原始数据；大附件通过只读摘要接口按需加载、复制和下载，
不会内联到样本详情响应。页面必须提示 Trace 含完整本地调试内容。

批跑正常完成后不自动启动后处理。后处理由 `PostprocessManager` 以独立单消费者队列调度，不占用批跑
执行队列。插件从 `debug_tools/postprocess_plugins/<pluginId>/plugin.json` 发现；清单声明
`batch-postprocess-v2`、入口脚本、版本、说明、`dependence` 依赖列表、配置 JSON Schema、产物白名单和受控展示提示。宿主自动补齐依赖并校验缺失与循环依赖；没有依赖关系的插件并行运行，存在依赖关系的插件只等待其声明的依赖完成。自定义入口在独立 Python 子进程中按样本
顺序调用 `process_sample(context)`，全部样本结束后调用可选 `process_dataset(context)`，最后调用可选
`finalize(context)` 完成截图、画廊汇总或结果回填。上下文包含只读的
运行目录、样本目录、最终 attempt 目录、插件专属输出目录、配置和直接依赖插件结果；插件返回
`status/summary/facts/artifacts`，不能返回可执行 HTML 或脚本。`facts` 只含可索引标量或字符串数组；
`artifacts` 必须引用清单声明的输出，并使用内联 JSON 或输出目录内的安全相对路径。

“开始后处理”只提交勾选项中尚无执行历史的插件。已执行插件不会随普通提交再次运行；新增插件所依赖的
已执行插件直接复用最新规范化结果。用户需要重跑时，在插件最新结果旁点击“再次运行”，平台为该插件创建
新的执行记录并保留历史结果。

每次手工启动创建 `batch_output/<runId>/postprocess/<executionId>/execution.json`，插件结果分别保存在
`plugins/<pluginId>/result.json`。逐样本结果保存到 `samples/<sampleId>/result.json`，数据集结果和自动生成的
`dashboard.json` 独立保存。插件启动后立即创建运行中看板，逐样本、数据集和收尾结果完成时原子更新看板与
结构化进度。状态为 `queued/running/completed/partial/failed/interrupted`；样本失败被隔离并继续其它样本，
收尾失败保留基础结果但将插件标记为失败并阻止依赖插件执行，不修改批跑结果。平台提供指标、表格、受控图表、热力矩阵、图片、问题列表、
JSON、代码、差异和下载渲染器，未知合法数据降级为只读 JSON。文件必须位于插件输出目录并经路径边界
校验后才可读取。批跑详情默认只在标题栏显示“后处理插件”按钮，不占用样本
工作区；点击后打开模态面板。面板在同一界面中展示插件勾选项与已选插件最新结果，不再提供执行顺序拖放
或单独的结果页。每个插件通过
`/batch/runs/:runId/postprocess/:executionId/plugins/:pluginId` 打开独立看板，支持运行中查看、搜索、筛选、表头全量排序、分页和
样本检查器，并可按时间切换该插件的历史执行。任务列表聚合展示运行中所有已执行插件。旧 v1 执行由只读适配器继续展示，新执行统一写 v2。

浏览器渲染画廊与真机截图画廊注册为两个独立内置插件，统一通过插件清单发现，并使用后处理接口排队执行。
不再提供浏览器画廊或真机截图的专用启动 API。插件产物依然通过受限只读路由访问。
浏览器画廊的隐藏截图路由读取运行与样本详情，
使用与任务详情一致的 CardRenderer 按原始卡片尺寸渲染；截图进程等待字体、图片和双帧布局稳定后，逐样本
截取 PNG。服务端将图片转成 data URI，并以原子替换写入 `batch_output/<runId>/gallery.html`，因此成品不
依赖调试服务、CDN 或旁挂资源。`gallery.json` 独立记录生成状态和错误；截图或 HTML 生成失败不修改批跑
状态，手动接口可幂等重试。浏览器画廊不读取真机截图状态或图片。画廊接口和文件读取继续复用运行 ID 校验及输出根路径边界。
渲染尺寸由共享解析器决定：最终 CardSpec `suggestSize` 优先，其次识别 query 中明确的 `2x2`/`2x4`
表达，再回退到样本保存的 `size`，最后才使用 DSL 自身声明或几何推断。普通渲染页、批跑详情预览与隐藏
截图路由不得各自维护不同的默认尺寸。

任务快照不包含真机截图选项、设备 SN、工具链或本机路径。批跑完成后立即释放批跑调度器；用户在任务中心
执行真机截图插件时，服务端使用内置 ArkTS 工程和用户当次选择的在线目标，读取最终 attempt 的 GenUI。
Render Session 按工程内容及构建输入缓存 HAP，缺少依赖时按锁文件安装，并在一次会话内只构建、安装一次。
每个样本使用唯一 `runId` 动态推送到应用沙箱，等待 `A2UI_RUN` 终态，双次确认前台后截图；外围保护失败
时有界重试。HDC debug-bundle 文件传输不可用时，样本通过 singleton Ability 参数有界分块传输，由 App
重组后写入相同沙箱目录；该回退主要用于 unsigned 模拟器，不改变后续终态和截图流程。平台严格校验 App
返回的 `cropPx` 后裁切，超时、断连和取消均回收远端临时文件与会话状态。
状态原子写入运行目录，逐样本保存成功、失败或跳过原因；后端重启把活动截图标记为中断，用户可重试失败或
缺失项，已有成功图片继续可用。截图完成后将卡片裁切图转成 data URI，原子写入
`batch_output/<runId>/device_gallery.html`。真机画廊不读取浏览器截图，不改变批跑业务状态，也不阻塞下一批生成。

设备渲染页和 `device-gallery` 配置面板均可显式启动 DevEco 本地模拟器。后端使用配置的 Emulator 启动器、
实例根目录和镜像根目录启动所选实例，按配置间隔轮询 HDC。平台优先使用实例配置中的固定端口；DevEco 6
未提供端口时，仅接受启动后唯一新上线且识别为 emulator 的目标，不会选择新上线真机或多个候选。任务终态
返回 `targetId` 和 serial，前端刷新在线
列表并自动选择，随后模拟器通过共享 Render Session 使用 unsigned HAP 截图。已运行但尚未连接 HDC 的实例
只进入等待流程，不重复拉起。启动进程提前退出或等待超时显示明确错误；路径不进入任务快照或微服务配置。
Ability 启动返回 `10106102` 屏幕锁定错误时，Render Session 仅对该错误执行有界退避重试，以承接模拟器
随后完成的异步解锁；其它启动错误不重试，锁屏持续存在时保留最后一次 HDC 错误。

浏览器渲染画廊与真机截图画廊是两个内置、可选且仅由用户手动触发的插件。两者没有依赖关系时并行执行；
分次执行时不自动等待或触发对方。两个插件各自生成只包含单一渲染路线的离线 HTML，不再组合对照。
缺少 GenUI、浏览器渲染失败或设备失败时，对应画廊显示原因占位。图片读取接口只接受已校验的运行、样本和图片种类，
不接受客户端文件路径；两条路线均将图片转为 data URI，保持离线可用。全屏图通过受限只读接口用于排障，不进入默认画廊。

## 6. 安全与可靠性

Trace 阶段视图只用于 `instrumentationVersion: 2`、`trace-view-v2` 的新批跑。默认以中文阶段分组，
树连接线与浅色父区间表达层级，实心条表达执行步骤，事件以时间点呈现；筛选保留祖先路径，支持阶段缩放。
节点内容展示实际数量和来源；小于等于 256 KiB 的首个附件自动读取，大内容按需加载，不截断正文。
运行级摘要登记表与无扩展名 blob 使用统一定位规则；加载显式区分 idle/loading/loaded/error，校验摘要，
取消过期请求，空文本属于加载成功。已有结果仅提供原始记录查看，不迁移附件。

- 调试后端默认只绑定 `127.0.0.1`；部署到其它主机时必须由反向代理、鉴权和网络策略限制访问。
- 浏览器和接口组件只接受 `ws://`/`wss://`（HTTP(S) 会转换为对应 WS）；HTTPS 页面拒绝不安全的 `ws://`，地址末尾 operation 只从固定 allowlist 生成，不接受任意路径。
- 后端保留 `/debug/tools/{operation}` 兼容入口，但不转发流量；连接后返回 `BROWSER_DIRECT_REQUIRED` 并关闭，避免误以为存在 BFF 绕行。
- 批跑读取和写入路径由服务端固定在 `debug_tools` 与配置的 Trace 根内；API 只暴露样本 ID 和服务端生成的运行 ID，拒绝目录穿越。
- Agent 浏览器工具桥默认等待 180 秒；浏览器微服务调用同样使用 180 秒总超时。收到 `final`/`final_error` 后以正常关闭码 1000 释放连接；错误、非 JSON、连接错误、服务端关闭和超时均写入失败记录，不阻塞其它模块。
- `tool.result` 的 `turnId`、`callId` 必须匹配当前挂起调用；客户端应携带当前 `conversationId`/`sessionId`（缺省时仅兼容旧客户端，显式空字符串仍拒绝）。成功结果必须携带匹配的 `operation` 和 `requestId` 或 `streamingTextId`，并且结果必须是可序列化对象且不超过 4 MiB；失败结果可用 `ok=false`、错误码或 `final_error` 表示。过期、重复、错配或过大结果会被拒绝。
- Python repr 解析采用字符扫描和 JSON 转换，禁止 `eval`；Skill 读取有 allowlist 和单资源大小上限；静态资源路径校验防止目录穿越。
- API key、Authorization、模型配置只在后端环境读取；浏览器配置页面只保存地址和测试参数。日志/展示层应继续脱敏 uid、userId、deviceId、token 等敏感值。
- 上游工具不可用时，Agent 会收到浏览器侧失败结果并结束当前调用。接口调试只需能访问配置的微服务 WS；
  Compact DSL 预览需要 Python 调试后端的转换 API，已有 A2UI 和 Graph JSONL 可在浏览器直接解析。

## 7. 验证策略

提交前执行：

1. Python：Ruff、迁移包 `compileall`、后端 HTTP/WS 集成测试和 `git diff --check`。
2. 前端：各 workspace `tsc --noEmit`、Vite build、解析器单测、React 交互单测；重点检查 `ToolCallRecord` 只在 final/final_error 写入，以及批跑选择、轮询、筛选、Trace 与预览。
3. 浏览器：桌面与移动宽度下检查导航下半部历史、设置页、固定 `100dvh`、内部滚动、键盘发送、错误提示、三类 fixture 渲染和工具服务离线提示。
4. 直连回归：验证接口调试可独立连接 `toolWsBaseUrl`；frontend 模式下验证 Compact DSL 转换与预览，
   full 模式下验证 dotted 会话、tool.call/tool.result 关联、取消、重置、断线和超时。
5. 会话回归：覆盖主导航切换往返后的消息与草稿、隐藏期间工具结果、新建会话及退出工作台清理。
