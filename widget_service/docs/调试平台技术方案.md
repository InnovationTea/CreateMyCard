# Debug Tools React 测试平台技术方案

## 1. 目标与范围

`debug_tools` 是面向本地联调的统一浏览器工作台，用同一个页面串起三条链路：

1. 端到端调试：向 Main Agent 发送用户请求，查看 Skill、工具调用、模型结果、取消和重置过程。
2. 接口调试：按正式工具协议调用三个 WebSocket 工具接口，保留原始流式帧并支持安全解析、历史回填和 Schema 子集构建。
3. 卡片渲染：在浏览器中导入 GenUI/A2UI、Compact DSL 或 Design Compact DSL，复现 `docs/index.html` 的本地预览行为。

本期只完成目录迁移、统一壳和可运行的本地调试模块；不改变生产云侧路由，不自动启动 8855 工具服务，也不接入来源分支的智能体调试协议。

## 2. 总体架构

```text
浏览器 React/Vite 工作台
  ├─ /debug/end-to-end  ── WS /debug/e2e/ws ── FastAPI Debug Agent
  ├─ /debug/interface   ── WS /debug/tools/{operation} ── BFF ── 127.0.0.1:8855
  └─ /debug/renderer    ── 本地解析器与渲染器

FastAPI 调试服务
  ├─ 静态托管 debug_tools/end_to_end_debug/backend/static
  ├─ 端到端会话生命周期、配置、取消、重置
  ├─ 工具 WebSocket 透明转发（不改写请求信封和响应帧）
  └─ /debug/health、/debug/skills 健康与 Skill 信息
```

调试服务默认监听 `127.0.0.1:8888`，工具服务仍由外部命令监听 `127.0.0.1:8855`。平台启动时只检查上游可用性，不创建或回收上游子进程。生产发布时可由反向代理将 `/debug/*` 限制在本机或开发网段。

## 3. 技术栈与代码组织

### 前端

- React 18 + TypeScript + Vite；React Router 负责三个工作区路由。
- React Context + `useReducer` 保存事件时间线和当前 CardArtifact，避免模块之间通过 URL 传递大段 DSL。
- 原生 WebSocket 封装连接、状态、断线、关闭和原始帧；不引入重量级 UI 框架。
- CSS 变量实现浅色三栏布局：左侧模块导航、中部调试面板、右侧结果检查器，底部统一事件时间线。
- Vitest + React Testing Library 覆盖 Python repr 解析、Schema 展开、状态和交互。

### 后端

- Python 3.12、FastAPI、Uvicorn、`websockets`。
- `debug_tools/end_to_end_debug/backend/debug_agent/` 是迁移后的 Agent 包，显式解析项目根、Skill 根和配置路径。
- BFF 只允许三个工具操作名；上游不可用时返回明确的关闭码和健康状态，不吞掉前端时间线信息。
- `PyYAML` 作为显式运行时依赖写入 `pyproject.toml`。

### 目录

```text
widget_service/debug_tools/
├── package.json
├── platform/                         # React/Vite 统一工作台
├── end_to_end_debug/
│   ├── backend/                      # FastAPI、BFF、迁移后的 debug_agent
│   └── frontend/                     # @widget-debug/end-to-end
├── interface_debug/frontend/         # @widget-debug/interface
└── card_renderer/frontend/           # @widget-debug/card-renderer
```

`widget_service/docs/index.html` 保留为行为对照和故障回退页面；React 渲染器从中抽取解析、数据绑定、尺寸推断、资源回退和组件绘制核心，资源根统一为 `/resources/`。

## 4. 核心数据模型

- `DebugEvent`：`channel`、方向、阶段、时间戳、耗时和原始 payload，统一呈现在底部时间线。
- `CardArtifact`：来源、运行标识、GenUI、CardSpec、摘要和可选 digest；模块间只传递用户显式导入的内容。
- `EndpointConfig`：开发环境由 Vite 代理到 8888，生产环境使用同源 `/debug/*`，避免前端写死主机和端口。
- `HistoryEntry`：接口名称、请求信封、原始帧、解析结果和来源历史 ID，支持跨接口回填。

## 5. 关键流程

### 端到端会话

1. 页面连接 `/debug/e2e/ws`，服务端发送 `session_started` 和当前 Skill/Profile。
2. 用户编辑设备上下文或 Profile，前端发送 `configure`/`reset`；输入请求发送 `message`。
3. Agent 产生的工具调用、工具结果、诊断、取消和产物事件实时写入统一时间线。
4. `artifact_preview` 进入 Artifact 检查器；用户可查看、复制或下载已经在页面中的内容。

### 工具接口 BFF

浏览器连接 `/debug/tools/{operation}` 后，BFF 建立到 `ws://127.0.0.1:8855/api/v1/ws/tools/{operation}` 的一对一连接，双向转发文本和二进制帧。`start/partial/final/final_error` 的顺序、payload 和上游关闭码保持不变；React 只在适配层增加时间线元数据。

### 卡片渲染与导入边界

渲染器识别 JSONL、A2UI、Compact DSL 和 Design Compact DSL，解析 DataModel 路径与模板表达式，并推断 2x2/2x4 画布。接口调试结果只能通过粘贴 JSONL、上传 artifact 内容或“打开生成结果”显式进入渲染器；平台不提供任意 URL 下载代理，也不在浏览器中直接请求 `artifactUrl`。

## 6. 安全与可靠性

- 后端默认只绑定回环地址；工具操作使用固定 allowlist，拒绝任意路径转发。
- Python repr 解析采用字符扫描和 JSON 转换，禁止 `eval`；静态资源路径校验防止目录穿越。
- 每条 WebSocket 有连接、超时、取消和断线边界；健康接口区分平台正常与上游不可用。
- 原始 payload 仅用于本地调试展示；生产环境应在反向代理、日志和鉴权层增加脱敏策略。

## 7. 验证策略

提交前执行：

1. Python：Ruff、迁移包 `compileall`、后端 HTTP/WS 集成测试和 `git diff --check`。
2. 前端：各 workspace `tsc --noEmit`、Vite build、解析器单测、React 交互单测。
3. 浏览器：桌面与移动宽度下检查路由、键盘发送、错误提示、三类 fixture 渲染和上游离线提示。
4. 回归：用 `docs/index.html` 对照 A2UI、Compact DSL、Design Compact fixture 的组件数量、尺寸和绑定路径。

## 8. 后续演进

- 增加可选的本地会话存档和 HAR/JSON 导出，不改变线上协议。
- 为 BFF 增加可配置的开发鉴权和连接指标；继续保持 8855 由外部进程管理。
- 若接入来源分支的 `/ws/agent/chat`，单独增加协议适配器和 feature flag，不与当前 `/debug/e2e/ws` 混用。
- 将平台静态资源纳入 CI 构建产物，并在发布包中排除 `node_modules` 和临时构建目录。
