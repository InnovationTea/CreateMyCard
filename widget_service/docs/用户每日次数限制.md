# 用户每日成功次数限制

## 职责与计次规则

Python 仅通过内部 HTTP API 查询和记录次数，不连接 MySQL，不读取数据库密码或 STS。
API 服务端由接入方实现，负责存储、唯一约束和一致性；当前两个接口及以下 JSON 是待接入契约，
不是对已部署接口的声明。`ops_metrics.py` 仅作 HTTP 调用方式参考，不改动原有指标上报。

- 默认关闭，开启后默认每个用户每天 20 次，三个生成接口的新建和编辑共享额度，查询接口不受限。
- 使用原始请求 uid 和 requestId；requestId 沿用 sessionId&interactionId 及既有兼容取值。
  不使用模型修复出来的身份。uid 或 requestId 为空时放行、不计次；上游必须保证身份可信。
- uid 和 requestId 分别进行 UTF-8 / SHA-256 小写十六进制编码。API 以两者组合唯一去重，
  不使用 recordId 或 sessionId 去重，不把日期加入唯一键。同一请求跨天、跨接口只计一次。
- 已计次请求直接放行，即使当天额度用尽；不缓存生成结果，仍允许再次生成。
- 日期使用北京时间请求进入检查时的日期；跨午夜完成仍记入入口日期，无需午夜清零。
- 在 arguments 修复前等待查询 API 返回，修复和内部重试共享本次检查。
- 只有业务 success、有有效产物且实际发送 AIWidgetEnd SUCCESS 未报错才记录。
  degraded、unchanged、失败、指令关闭、开始指令未成功、结束指令发送失败均不计次。
  后续 final 帧失败不撤销计次。发送成功不是端侧 ACK。
- 记录 API 必须等待确认，不能像运维指标上报一样后台发送；查询失败拒绝生成，
  交付后记录失败最多尝试 3 次（延迟 0、0.1、0.3 秒），最终失败仅告警，不改变已交付结果。
- 不做并发预占；不同请求可能同时通过检查而超额，崩溃和最终记录失败可能少计。

## API 接入契约

参考运维上报使用 HTTP POST、application/json 和 sessionId/body 包装。
协议、域名和端口统一使用 Settings.hag_slb_url，调用会等待响应；接口路径可配置。
此方案假设 API 在可信内网/同容器边界提供，不附加数据库凭据，不实现 API 服务端。
如后续需要跨服务认证，应另行明确认证协议，不将数据库 STS 密钥当作 HTTP 令牌。

### 共同请求体

```json
{
  "sessionId": "会话上下文标识，仅用于追踪",
  "body": {
    "recordId": "Python 在入口生成的 UUID hex",
    "uidHash": "原始 uid 的 SHA-256，64 位小写十六进制",
    "requestIdHash": "原始 requestId 的 SHA-256，64 位小写十六进制",
    "usageDate": "2026-10-23"
  }
}
```

两个接口都接收此结构；请求中不含明文 uid、明文 requestId、数据库配置。
sessionId 从任务上下文获取，缺失时使用 recordId；它不参与去重。
同一次生成后的全部记录重试使用相同 recordId、摘要和日期；同一 requestId 再次调用生成接口，
recordId 可以不同，API 仍须按 uidHash + requestIdHash 去重。

### 1. 查询快照

默认路径：`POST /genui-agent/v1/daily-usage/snapshot`。

成功返回 HTTP 200：

```json
{"success":true,"data":{"alreadyCounted":false,"usedCount":19}}
```

- alreadyCounted：该用户与 requestId 是否已有成功记录，查询范围跨所有日期，严格 Boolean。
- usedCount：该用户在 usageDate 的成功记录数量，严格非负整数，不接受字符串、浮点数或 Boolean。
- API 只读、不预占、不扣次；Python 判断 alreadyCounted 为 true 直接放行，否则比较 usedCount 与上限。
- 读写须满足成功记录返回后查询可见，不能因缓存或只读副本延迟持续返回旧计数。

### 2. 记录成功

默认路径：`POST /genui-agent/v1/daily-usage/record-success`。

完成持久化后返回 HTTP 200：

```json
{"success":true}
```

- 首次请求写入一条成功记录；重复请求不再扣次，保留首次写入的日期，并仍返回成功。
- 必须通过数据库唯一约束或等价机制实现幂等，不能简单先查再累加。
- 成功必须表示已提交持久化或已存在同一成功记录，不代表仅接收请求、发送 MQ 或入队。
- 数据库提交成功但 HTTP 响应丢失时，Python 会使用相同记录重试，API 仍应返回成功而非重复错误。
- [SQL](../sql/daily_usage.sql) 仅供 API 实现参考，Python 不执行它；数据库配置、密码和 STS 由 API 服务管理。

### 失败处理

业务失败可返回 HTTP 200 + `{"success":false}`；HTTP 非 200、超时、网络失败、非法 JSON、
缺少或类型错误的成功标志均按失败处理。HTTP 202 不视为持久化完成，不跟随重定向。
查询 data 或字段非法也视为失败，不默认补零放行；接口响应的附加字段忽略。
查询失败对主 Agent 返回 DAILY_USAGE_LIMIT_UNAVAILABLE；超限返回 DAILY_USAGE_LIMIT_EXCEEDED。
成功记录失败执行有限重试。日志不输出完整请求、响应正文或底层异常消息，只记录摘要、阶段及异常类型。

## 配置与部署

| 配置 | 默认值 / 说明 |
| --- | --- |
| enable_daily_usage_limit | false；总开关，与运维指标开关无关 |
| daily_usage_limit | 20；正整数 |
| hag_slb_url | 复用公共配置，包含 http/https 协议、域名及可选端口；开启时必须有效 |
| daily_usage_api_snapshot_path | /genui-agent/v1/daily-usage/snapshot |
| daily_usage_api_record_path | /genui-agent/v1/daily-usage/record-success |
| daily_usage_api_timeout_seconds | 3.0；单次 HTTP 操作及整体存储操作超时 |

hag_slb_url 例如 https://genui.example.test:8443，不允许携带认证信息、查询串或 fragment。
path 填以 / 开头的本地路径，不含查询串和 fragment；从域名根目录开始，替换基础 URL 原有路径。
例如上述基础地址与默认查询路径组合为 https://genui.example.test:8443/genui-agent/v1/daily-usage/snapshot。
已移除 daily_usage_api_host 和 daily_usage_api_port，不再回退 localhost 或容器 IP。
旧 daily_usage_mysql_* 配置已移除，包含数据库密码 STS 键名；旧配置不再参与执行。
绿区优先 spec / properties，蓝区回退 default_config.yaml，不合并；旧 spec 缺配置时总开关默认关闭。
沿用 Settings 环境变量规则，例如 WIDGET_SERVICE_HAG_SLB_URL。配置变更需要重启。
关闭时不创建 HTTP 客户端、不校验 hag_slb_url、不调用 API。开启时创建应用级异步 HTTP 客户端，
启动不主动请求 API，应用退出时关闭。禁用环境代理，不跟随重定向。

上线：实现并验证两个 API → 部署关闭状态代码 → 配置地址/路径 → 联调幂等、跨天和故障 → 开启。
API 未实现前保持关闭，禁止用空成功响应或固定计数模拟生产可用。
数据库历史记录的清理需考虑跨天去重，不能直接删除后声称历史请求仍可去重。

## 验证范围

测试使用 HTTP MockTransport 模拟上述 API，覆盖请求包络、严格响应校验、状态码、超时、
客户端生命周期、幂等重试、跨天及 WebSocket 调用链。只证明 Python 客户端遵守契约，
不证明尚未实现的真实 API、数据库唯一约束或读写一致性；这些必须在接入后单独联调。
