# 用户每日成功次数限制

## 计次合同

- 默认关闭，开启后默认每个用户每天 20 次，三个生成接口的新建和编辑共享额度，查询接口不受限。
- 原始报文按 content.uid、userAuth.user.userId、可严格解析的 content.arguments.uid、
  arguments.uid、payload.uid 顺序选择 uid；不使用模型修复出来的身份字段。
- requestId 复用路由现有规则：sessionId&interactionId，缺少轮次时兼容 sessionId，
  再兼容原始报文 requestId。上游应始终提供完整轮次，避免整个会话被合并计次。
- uid 或 requestId 为空时放行且不计次。只检查次数，不认证 uid；上游必须保证身份可信。
- 一张成功记录表，uid 与 requestId 分别保存 SHA-256 摘要，以两列唯一键去重。
  已计次的 requestId 直接放行，不因额度满而重复拦截；跨天及跨生成接口也不重复计次。
  不缓存或复用生成结果，重复调用仍可进入生成。
- 北京时间自然日，使用请求进入检查时的日期；23:59 进入、次日完成记入前一天。
- 仅业务 success、有有效产物且实际发出 AIWidgetEnd SUCCESS 成功才记录。
  degraded、unchanged、失败、指令关闭、开始指令未发成功、结束指令发送失败均不计次。
  成功结束指令后的 final 帧失败不撤销计次；服务端发送未报错不代表端侧 ACK。
- 检查在 arguments 修复前；修复和所有内部重试共享本次检查，不额外计次。
- 本版不做预占：不同 requestId 并发时可能超额；唯一键只保证同一 requestId 不重复计次。
- 查询失败返回 DAILY_USAGE_LIMIT_UNAVAILABLE，超限返回 DAILY_USAGE_LIMIT_EXCEEDED。
  外层插件包络不变，业务错误位于 streamContent，明确要求停止本轮自动调用。
- 交付后的计数写入最多尝试 3 次（额外 2 次），失败仅告警，不把已交付结果改为失败。
  没有交付与 MySQL 的分布式事务，崩溃、写入失败仍可能少计；不伪造成功记录。

## 配置与部署

先由数据库管理员在目标库执行 [建表脚本](../sql/daily_usage.sql)，应用不自动建表。
运行账号需要该表的 SELECT、INSERT、UPDATE 权限，勿使用 root。
依赖使用 aiomysql[rsa]，包含 MySQL 8 默认认证在非 TLS 连接下所需的 RSA 支持；
生产环境优先配置 TLS CA，RSA 认证不等于整个连接已加密。

| 配置 | 默认值 / 说明 |
| --- | --- |
| enable_daily_usage_limit | false；总开关 |
| daily_usage_limit | 20；正整数 |
| daily_usage_mysql_host | 空；开启时必填 |
| daily_usage_mysql_port | 3306 |
| daily_usage_mysql_database | 空；开启时必填 |
| daily_usage_mysql_user | 空；开启时必填 |
| daily_usage_mysql_password_sts_config_key | genui.mysql.password；STS 中保存数据库密码的键名 |
| daily_usage_mysql_ssl_ca | 空；配置 CA 路径时启用 TLS，验证主机名及证书 |
| daily_usage_mysql_pool_size | 10；每进程上限，部署时按进程和副本数评估总连接数 |
| daily_usage_mysql_timeout_seconds | 3.0；连接及单次存储操作的超时秒数 |

沿用 Settings 的环境变量规则，例如 WIDGET_SERVICE_ENABLE_DAILY_USAGE_LIMIT。
绿区优先读取 spec / properties；蓝区回退 default_config.yaml，不合并两者。
旧 spec 缺少新增配置时限额默认关闭；关闭时不创建连接池、不依赖数据库可用性。
密码仅从 `sts_config.get_sts_config(daily_usage_mysql_password_sts_config_key)` 获取；
bytes 按 UTF-8 解码，str 原样使用，不裁剪空白、不猜测 Base64，也不回退普通配置或环境变量密码。
已移除 `daily_usage_mysql_password`。STS 明确返回的空字符串仍按原值传递，不代表读取失败兜底。
STS 读取失败、返回类型非法或 UTF-8 解码失败时启动失败，异常消息不包含原始密钥或异常链。
当前蓝区 STS 适配器是 Mock；本地开启功能需要注入对应测试密钥，绿区由真实 STS 提供。
关闭功能时不读取 STS。密码在应用初始化连接池时读取，密码轮换后需重启应用。
开启但 host/database/user/STS 键名缺失时启动失败；数据库暂时不可用不影响服务启动和查询接口，
需要检查额度的生成请求失败关闭。配置生效需要重启，关闭开关可回退。
连接池由应用 lifespan 管理，空闲连接回收时间为 300 秒；不在生成期间持有连接。
日期直接使用北京时间偏移，不依赖数据库系统时区；审计时间沿用 MySQL 时间配置。

上线顺序：建表和授权 → 在 STS 配置密码 → 安装依赖及部署关闭状态代码 → 测试库验证 → 配置并开启。
不自动删除历史记录，因为删除会失去历史 requestId 的去重依据。

## 排障及验证

日志事件包括 checked、recorded、record_failed、record_exhausted、daily_usage_rejected、
daily_usage_bypass；身份日志只记录摘要。recorded 表示唯一成功记录已存在，并非每次都新增一行。
重点关注 record_exhausted（已交付但入库未确认）及 DAILY_USAGE_LIMIT_UNAVAILABLE。
数据库失败日志不输出 SQL 参数、明文 uid 或凭据。

单元与路由测试覆盖开关、边界、uid 来源、requestId 去重、跨天、重试和指令发送失败。
MySQL 集成测试使用专门的空测试库，验证建表、唯一键、按日统计和重复提交；
不得在生产库运行，也不能用 Mock 通过代替真实 MySQL 验证。

运行真实集成测试前，指向专门的本地测试实例，设置 WIDGET_TEST_MYSQL_HOST、
WIDGET_TEST_MYSQL_PORT、WIDGET_TEST_MYSQL_USER、WIDGET_TEST_MYSQL_PASSWORD。
测试会将测试密码注入 Mock STS，不调用真实 STS。测试账号需要创建/删除临时数据库的权限；
测试自动创建并清理
widget_usage_test_ 前缀的随机数据库。未设置 HOST 时集成测试自动跳过。
从 widget_service 目录运行：

```text
python -m pytest tests/test_daily_usage_mysql_integration.py -q
```
