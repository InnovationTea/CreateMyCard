# CompactDSL 融合提示词

本目录是正式 Compact DSL 链路唯一的提示词维护入口。协议身份仍是 `design-compact-dsl`，
其旧目录只保留 `protocol.json`；主提示词、编辑、修复、参数恢复和尺寸案例均不再从旧目录读取。

当前 information 使用连续语义合同，Compact DSL 仅区分基础布局组件与组件，真实模型链路已接入 Plan。
本次保底调整 DSL 提示词与选例，并澄清 Plan 提取时的展示事实与动作参数边界；不改变 Plan 的调用、
硬事实解析、事实校验和重试行为。组件软候选按真实字段类型清理，不删除事实；DSL 校验拦截进度与
同组读数明确跨对象的绑定，不改写数据或接入 JSX。

## 修改与加载

加载器为 `cloud/services/compact_prompt_loader.py`，仅依赖标准库，不依赖服务配置或模型客户端。
默认配置与协议注册表共用它；按源目录和请求尺寸缓存提示词包，启动或首次使用时读取文件并校验。

```text
prompt_source → 同源信息/组件选型规则 → Plan → 整卡参考 + 组件局部用法 → Compact DSL
```

`manifest.yaml` 使用 YAML 1.2 的 JSON 子集，由标准库解析，不新增部署依赖。
`prompts` 中每个数组的顺序是唯一拼接顺序，引用格式为 `文件#片段`。七个名称是内存中的提示词标识：
`plan`、`create`、`edit`、`repair`、`argument_repair`、`fewshot_2x2`、`fewshot_2x4`。
每种尺寸的 Few-shot 只维护一个文档，前言使用 `preamble`；2x2 使用 `example-v00` 至
`example-v32`，2x4 使用 `example-v00` 至 `example-v26`。manifest 保留逐案例索引，加载器逐片段检查完整输入/输出，不按整文件放行。
只有 `<!-- prompt:片段 -->` 与对应结束标记之间的正文发给模型；维护说明、索引、边界表、
manifest 和标记本身不发。不要把要生效的规则写到标记外。
信息模块保留连续语义合同，组件及组合公共模块的 selection 片段供 Plan 与 DSL 复用；同一提示词内
禁止重复加载同一片段，跨阶段复用不报重复。组合不新增 Compact 组件或 Card/Region 等语义协议节点。

`sizes` 控制阶段提示词按请求尺寸过滤源模块。Plan 阶段加载信息、组件选型与组合知识，不加载 Few-shot；
Plan 接受后，DSL 阶段在 `WIDGET_SERVICE_ENABLE_DESIGN_COMPACT_FEW_SHOTS=true` 时沿用按信息
结构、字段语义和动作归属选择完整案例的规则，再为尚未示范的
组件候选补充最多两种局部用法。局部组件行来自同尺寸完整案例，不带另一套根布局或数据行。
该开关默认为 `true`；设为 `false` 时不向模型追加完整案例或组件局部用法，但保留主提示词、Plan、
布局约束与 repair，并继续维护和离线校验 Few-shot 源文档。
示例字段数量不是实际容量；局部用法不替代整卡参考，更不能覆盖 Plan 必要事实。
生成、编辑、repair 与源 Token 校验共用 S-plan-guided / W-plan-guided 范围，包含同尺寸全部登记布局；
不再由业务关键词或候选字段数预先锁定骨架。每个布局自身的结构、几何与动作约束不变。
单次请求只发送一至两个结构匹配的案例，不发送整个案例库。候选缺失明确报错，不静默退回全量案例。
完整业务案例保留测量读数、睡眠明细、同级数值、设备状态、列表和动作归属等覆盖；组件案例
用于类型、语义及容量匹配的场景。两者共同维护，不以增加组件覆盖率为由替换掉必要信息。
修改规则时只编辑源模块，验证最终模型文本后发布并重启服务；没有中间文件或额外构建步骤。
部署应完整携带源目录；缺失、越界路径、重复/遗漏片段与损坏案例均明确报错。
外部配置使用 `@prompt:源目录#名称`。普通 `@file:` 仍读取原文，不能直接读取带维护说明的源模块。

## 与 Multi-step 的融合边界

吸收信息处理、单组件、组件组合、布局与编排分层的维护方式，并在 PR 416 的语义布局骨架内维护 Compact 组件。
组件在 components 中逐类验证；已接入的 Plan 独立维护信息合同。后续演进必须同时
验证 Compact 编译/校验支持，不能仅把 JSX 名称和 Props 粘进提示词。

以下能力不属于本次保底范围：JSX/dataIds 协议迁移、四轮 next、160/320 画布、
把任意格式化百分比自动转换为进度组件、冻结全部字段后禁止取舍。它们与当前 Compact 合同并不等价。
其它模块仍可能保留历史重复、覆盖和尺寸说明差异；information 已清除跨组件、视觉与布局职责的重复规则。

## 显示回归保障

七种模型文本继续由维护源确定性组装。组件合同调整属于有意的协议演进，
不再要求与迁移前文本摘要完全一致；转换测试应证明使用视觉 Recipe 的组件展开后保持对应 Few-shot 的布局与视觉属性。
案例另经 Compact 上下文校验和 A2UI 转换。这里不声称完成真实端侧截图验收或线上随机模型质量验收。
