# 宽卡信息关系（维护源）

> 维护说明不发给模型；仅 `prompt` 标记内正文参与构建。

## 边界与阅读顺序

主辅/等权与分区 → 内容变体 → `W-content-side-slots` 密度与去重。物理槽位在 layouts/2x4.md。

## 分区关系总表（维护导航，不发模型）

| 信息关系 | 分区判断 | 取舍边界 |
|---|---|---|
| 单对象多字段 | 不按字段拆数据块 | 主值、状态、事项或紧凑摘要变体 |
| 一个主焦点 + 最多两个辅助组 | `W-content-side-slots`，动作也占辅助槽 | 左右不重复路径或同义事实 |
| 两个各需完整内容区的业务 | `W-split-panels` | 每側独立密度；标题和动作归所属业务 |
| 三个 / 四个独立对象 | `W-content-side-slots` / `W-four-slots` | 固定小背板容量，不因动作增加数据块 |
| 用户明确等权比较 | 并列焦点组 | 同层级统一强调，不从中任挑 hero |

实际路由范围保持 PromptBuilder 的既有裁决，表格不是新增程序规则。

<!-- prompt:w1-density -->
**2x4 `W-content-side-slots` 内容节奏前置约束**：内容区必须先选择 Sub-140 子布局，再按其核心居中、标题单内容、标题双内容、带动作、双列、四宫格或双动作规则对齐；不得统一强制居中。固定槽列只放两个真实紧凑模块，同一路径或同一事实只能分配到一个区域。

<!-- /prompt:w1-density -->

<!-- prompt:variants -->
- 2x4 在固定外框和数据块路由不变的前提下，允许在每个骨架内部选择不同的内容变体：`value-led`（主值居中/靠上）、`status-led`（状态句为主）、`event-led`（事项标题与时间为主）、`action-led`（动作是目标）和 `dense-summary`（多指标紧凑汇总）。变体只改变内部顺序、对齐、留白和字段取舍，不新增一级区域、不跨骨架拼接。
- 2x4 多数据卡不要机械复制“标题 + 两行 14/12fp + 按钮”。每个分区先确定自己的主焦点：主值分区突出数值，状态分区突出状态句，动作分区突出动作；同一卡允许不同分区采用不同变体，但同一分区内仍遵守字号和对齐一致性。
<!-- /prompt:variants -->

<!-- prompt:zone-priority -->
- **2x4 分区差异约束**：`W-split-panels`/`W-content-side-slots` 默认采用“一主一辅”重量关系；主分区可使用 24/30fp 主读数或 16/18fp 主状态，辅分区优先使用 14/18fp 主值和 12fp 支撑信息。只有用户明确要求两项等权比较时才让两个分区使用相同主字号；`W-four-slots` 等权网格也要通过字号或颜色建立一个轻量主次，不得所有单元格完全同权。
<!-- /prompt:zone-priority -->
