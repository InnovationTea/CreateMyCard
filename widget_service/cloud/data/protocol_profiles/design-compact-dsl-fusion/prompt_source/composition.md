# 十三、整卡编排与提交检查

综合考虑以下关系，不输出额外分析：

1. **信息 → 组合。** 按对象及关系合组，分清核心、并列、辅助和动作归属；一个实例可承载多个合法事实，不把每个字段各做一个强调块，同名候选也不代表跨对象合并。
2. **组合 ↔ 布局。** 优先落实语义、类型及容量匹配的 Plan 首选；不匹配时改选合法组合、子布局或同尺寸父布局。先为全部必要动作留合法位置，再核对内容容量，不能先锁狭小槽位再删除信息。
3. **容量 → 落点。** 按完整标签、值、单位、换行及组件行高核算每区；横排逐列检查宽度，纵排累加高度与固定间距。标题和动作占高先扣，正文使用模板剩余容量；有实际工作表时结合其预算，不等待未提供的工作表。
4. **固定角色 → 真实实例。** children 按角色顺序填写；每个槽由真实内容填充，缺角色则换变体，不加空节点、不重复事实凑槽。装饰标题可在允许无标题的结构中省略；用户要求的标题不能删。
5. **绑定 → 可见性。** 从 root 逐项核对 Plan：动态事实在可见 Prop，事件有可达且归属正确的入口；同一数据不重复展示，动作参数不冒充正文，初始化数据不冒充覆盖。
6. **整体检查。** 引用、类型、表达式、素材、单位次数、全部动作、文本压力和各区预算闭合后提交。不能依赖宿主变大、缩字号、裁切或改模板几何完成布局。

Plan 含 composition 时，先按其中合法实例合组和 placements 实现；它的几何参考只用于预算。若真实内容证明计划不能成立，保留事实与动作重选合法组合。已明确的 columns/lines/density/labelLines 不能无理由换成会截断的窄列。
