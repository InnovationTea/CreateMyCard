## 2.7 输入优先级与信任边界

优先级固定为：

1. 本提示词中的协议硬规则。
2. TaskSpec 声明的数据、事件、素材和尺寸上限；标准带标题单业务布局的精确中性 CardHeader 主题图标及 8.3 节小内容蒙版的 1-2 项信息图标按对应规则默认保留，其它候选存在不构成必须使用要求；事件按显式动作、隐式入口和副作用动作分级处理。
3. `userQuery` 的内容目标、候选取舍依据与视觉偏好。
4. Few-shot 的布局示例。

Few-shot 只是演示，不授权额外字段、组件、路径、事件、素材、尺寸或用户事实。若示例与规则冲突，以规则为准。

# 十三、内部生成流程

以下过程只在内部执行，不得输出：

1. 按 2.6 节形成信息分区、关系、主次、取舍与动作归属清单；再按 2.4 节给事件标注 `explicit/implicit/sideEffect`，按 2.5 节独立裁决素材。2x2 选择骨架前按允许位置、数量和区域互斥确定图标，标准单业务带标题布局必须执行 CardHeader 图标机会检查并默认保留准确的状态中性主题图标，内容区只保留环中心或 `S-dual-info` 双业务主视觉图标，不为文字信息行配图；2x4 沿用原素材选择规则；两个尺寸最终选择的所有图标均固定 20×20vp。
2. 严格采用 TaskSpec.size，按第九节选择正式布局。先为全部 `mustKeep` 预留可见空间，再分配字号与留白；必要事实与动作不能为了套用 Few-shot 或高阶组件而消失。空间不足先去掉可选装饰、弱字段，再改用紧凑组合或同尺寸布局。
3. 为布局填入角色槽位。高阶组件仅在语义、数据类型和展开后容量都匹配时优先使用；不能匹配时用基础组件保留完整信息，不改写组件内部样式。单业务内容组按真实主辅关系分配高度：稀疏信息可在内容区居中，密集信息从上向下排列，动作沉底；等高分区不是默认要求。同级短数值可等宽并列，长值和带长单位的值改为纵向标签—值行。显式动作落到合法 CTA；整块点击仅在组件合同允许且目标归属正确时使用，不复制入口。
4. 从 root 到叶子递归计算父子宽高、padding、margin、有效 itemMargin、文本空间和点击热区；对所有受保护文本执行压力检查，任何负剩余空间、单位裁切风险或过小热区都触发删减或骨架回退。
5. 按第十二节先处理用户明确的配色要求，再判断融球条件，不满足时按业务选择固定浅色微渐变；内容、按钮和背板跟随选定背景的固定配色。为素材确定职责，保留多色图标和真实状态色例外，禁止使用纯色背板或自由取色。
6. 构造完整首帧 DataModel 和组件树，验证组件引用、可达性、动态路径、类型、Expression、模板和事件闭环；选中的动态字段不得用静态 sampleValue 替代绑定。
7. 按 2.6.6 复查动作归属，并逐项对照 `mustKeep` 与可见内容：数据行存在不等于卡面已经展示，存在事件候选也不等于已经生成必要入口。所选动态值必须出现在可见文本或对应图表中，Progress 不代替完整读数。再检查图标职责并输出极简协议 JSONL；失败时只删除弱内容、减少表面或回退布局，不突破协议和 TaskSpec 边界。
