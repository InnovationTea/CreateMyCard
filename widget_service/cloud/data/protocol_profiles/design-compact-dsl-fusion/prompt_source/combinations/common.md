# 通用组件组合（维护源）

> 维护说明不发给模型；仅 `prompt` 标记内正文参与构建。

## 边界

本文件只定义多个组件共同表达一个语义单元时的成立条件、角色关系、数量和共同排除条件。单组件
Props、字号与文本压力由 components 规定，具体骨架、槽位、尺寸、间距和对齐由 layouts 规定，颜色与
全局视觉参数由 core 规定。组合不是新的协议组件；最终仍输出当前 Compact JSONL 中已经注册的组件与容器。

## 从事实到组件组合

1. 先在内部按对象和任务目标归组，再区分核心、同级属性、短支撑、事件要素与操作。同一组件可以
   同时承载多个事实；同一类型的两个实例也可服务不同对象。软候选名称相同不代表跨对象合并。
2. 唯一短量化核心优先考虑 EmphasizedData；小卡无动作的完整单焦点可考虑 DataDisplay。普通状态、
   名称和长时间段保持文本，不能仅因需要强调就变成大数值。需要标签辨认的同级属性再考虑 TableText
   或 TopTextBottomValue，项目数与尺寸必须匹配；多记录先确保每条完整，不压缩成只有标题。
3. 真实进度与同主题 2–4 项详情可组合 ProgressLine2＋TextBlock；没有进度关系不补图，详情不足两项
   不补项。双信息槽使用 InfoBlock，动作槽使用该尺寸的按钮组件，不能把动作挂到 InfoBlock。
4. 为每项必要事实选择可见 Prop，为每项必要动作保留真实且可辨认的入口。同一数值用于可见读数
   和对应进度属于同一信息组；不要在另一分区重复一遍。时间范围、单位和指标标签不能被省略。
5. DSL 优先落实语义、类型、容量均匹配的 Plan 组件候选；不匹配时改选其它组件、组件组合或合法布局。
   Row/Column 只负责组织内容，不改变事实、绑定或事件。调整不能减少必要事实。

# 十一、多组件组合

组件组合表示多个已选组件共同表达一个完整语义单元。先依据第 2.6 节确认信息关系和动作归属，再选择
组合；只满足组件数量或外观相似不算命中。组合不产生新组件名称，也不允许跨越第九节所选骨架的槽位。

## 11.1 组合候选

| 组合 | 内容关系 | 成立条件 | 共同限制 |
|---|---|---|---|
| 标题与数量 | 标题 + 同一集合的真实数量 | 用户要求集合数量，且输入有概括该集合的真实数量字段 | 使用标题 + `Badge`；数量只表达一次，不根据可见项数推断 |
| 核心与补充 | 核心内容 + 紧密关联的短补充 | 同一主题存在明确结论与解释、限定或补充关系 | 恰好两个内容角色；两项同级时不用 |
| 核心、补充与操作 | 核心内容 + 短补充 + 直属操作 | 三者属于同一主题，操作直接作用于该主题 | 三个角色都真实存在；操作位于所属内容之后 |
| 单内容与操作 | 一个完整内容 + 直属操作 | 单个内容已能完整表达必要信息，操作直接作用于该内容 | 不为容纳操作拆散内容或补造说明 |
| 同级指标 | 两至四个可独立识别的同级指标 | 指标属于同一比较维度，且不存在主次关系 | 同字号、同字重、同对齐；每项保留自己的标签和值 |
| 双占比 | 两个同级占比 + 可选共同操作 | 两项都有可靠 current/total，使用同一尺度 | 两项分别可识别；操作必须同时作用于两者 |
| 三占比 | 三个同级占比形成一个紧凑内容组 | 三项都有可靠比例语义，且能用短标签区分 | 整组占一个内容位；不拆成三个无归属焦点 |
| 四占比 | 四个同级占比 | 四项都有可靠比例语义，且能在四个固定内容格完整表达 | 不增加标题、第五项或操作 |
| 双信息块 | 两组完整的主信息 + 辅助信息 | 两组信息同级，并且各自都能独立理解 | 每组事实只归属一个对象；有明确主结论时改用核心与补充 |
| 双操作 | 一个紧凑内容 + 两个同级操作 | 两个必要操作共同服务同一内容或整卡 | 恰好两个操作；分别属于不同对象时不得合并 |

## 11.2 成立条件

### 标题与数量

- 数量必须概括标题所指的同一集合，不能根据可见列表项数推测总数。
- 状态、类别、温度、时长、百分比和普通业务数值不是标题数量。
- 命中时使用标题组件与 `Badge` 组成同一标题单元；不得用正文组件、背景色或绝对位置仿造 Badge。
- `Badge.value` 必须来自真实数量字段；没有该字段时不根据可见列表项数推测总数。

### 核心与补充

- 核心回答用户最关心的问题，补充负责解释、限定或提供紧密关联的明细。
- 左右对象、多个设备、最高/最低、当前/目标和其它同级指标保持对等表达，不能按字段顺序或样例值大小
  任意指定核心。
- “核心、补充与操作”中的操作必须作用于这个内容组，不能借用其它对象或整卡无关入口。

### 同级指标与占比

- 同级指标中的每个值都必须与自己的标签保持一组；不得用一个大号 Hero 压过其它同级项。
- 占比只接受真实百分比、明确的 0–100 有界进度，或具有可靠 value/total 的比例。天数、次数、时间、
  温度、距离、金额等绝对量即使样例落在 0–100 也不是占比。
- 两项使用双占比，三项形成一个紧凑内容组，四项使用四占比；容量不成立时改用普通同级指标或删除
  `shouldKeep`，不得编造 total、Icon 或第五项。

### 双信息块与操作

- 双信息块中的两组信息必须同级，并分别保持完整的主信息和辅助信息；尾部 visual 仍归属所在对象。
- 操作不是信息字段。直属内容操作只有与内容存在明确归属时才形成单操作或双操作组合；用户另行明确要求的独立任务操作放入布局允许的独立动作槽，不需要补造同名数据对象。
- 同一事件只绑定一个可见入口；分别作用于不同对象的操作留在各自内容区，不合并成整卡双操作。

## 11.3 当前 Compact JSONL 落地规则

- 组合只使用第五节已经注册的组件。模型直接输出对应组件，由 Row/Column 组织需要组合的内容，不输出组合名、
  `Card`、`Region`、JSX、`composition` 或其它新字段。
- 原始数值与静态真实单位使用 `EmphasizedData.value` 与 `unit`；格式化字符串已含单位时只绑定一个完整
  显示值。标签、状态和说明不是单位，必须由对应语义组件承载。
- 组合层不重新定义语义组件内部的字号、宽度、字底或补偿公式。
- 普通同级数值不要求进度环。两项短值可在一个内容组内等宽并列，共享单位进入标题或各值下方，
  不把大数字和长单位挤进窄 Row；各列须独立通过压力预算。任一项较长时，整组改为纵向标签—值行，
  保持字号、字重和对齐一致，不靠省略单位或只缩小其中一项换空间。
- 单焦点不等于只保留一个事实。主值的状态、时间范围和用户点名明细保留独立支撑行；若有多个必需
  辅助事实，先降低主值的视觉占用，不为了大字号组件挤掉明细与按钮。
- ProgressCircle 与其它进度组件只用于满足比例条件的数据；Props、尺寸和颜色完全服从 components 与 layouts。
- 操作使用当前骨架允许的 PillButton、CircleButton、CardButton 或可点击 Row；事件只放在
  对应点击容器，Recipe 内部图标或文字节点不重复绑定。
- 固定信息槽使用 InfoBlock，外层和内部组件均不支持事件；固定操作槽使用 CardButton 并由其承载事件。
  组合不能扩大任何组件的事件能力。

## 11.4 共同排除条件

- 不为满足组合项数虚构数据、标题、单位、Icon、total 或操作，也不通过重复同一事实填槽。
- 每个事实和操作只承担一个语义角色；同一动态事实不能同时充当核心、补充和数量标记。
- 组合不能改变所选布局的一级区域、插入额外背板、交换固定槽职责或把动作移到不相关对象。独立动作槽承载的是已确认的操作目标，不等于给相邻信息对象绑定该操作。
- 当前尺寸没有合法落点时，先删除 `shouldKeep`，再按第九节更换正式骨架；不得创建未登记变体。
