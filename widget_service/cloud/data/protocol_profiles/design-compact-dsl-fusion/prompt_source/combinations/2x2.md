# 小卡组合

<!-- prompt:mapping -->
## 2x2 Group

| variant | children | 固定关系 |
|---|---|---|
| hero-support | [核心, 补充] | 同对象主辅连续纵排，2vp |
| label-value | [标签组件, 读数组件] | 同指标说明与值纵排，2vp，不拆内部单位 |
| peer-pair | [同级内容, 同级内容] | 两个等权短列，8vp，底部对齐 |
| supporting-items | 2–4个同区内容 | 阅读顺序纵排，2vp；不是逐字段强调块 |

只填写 variant 和有序 children，无几何、背景或事件；不在 Group 内嵌 InfoBlock。不能改变组件容量、图标额度或布局动作位置。

### 合组与压力检查

- 同对象多个短辅助字段优先使用一个 SecondaryBody.items；无核心的等权属性使用合法 TableText。不要把普通状态、发起人或元信息各做18/30fp焦点。
- 双列分别核算标签、分隔符及完整值。长日期、状态和温度范围放不下时使用全宽单列或合法 maxLines:2，计入新增行高；不能只改行数而不算高度。
- 主值与一项短补充在完整宽度成立时可用 peer-pair，其余事实进入布局的真实支撑角色；不为横排混合无关对象。
- 标签挤占长值时，先用单列/合法两行；仍不适配时可把必要标签和动态值合为完整 Expression，共用整行宽度，不丢标签、布尔另一种结果、日期、时分或单位。
- 同对象原字号一致的次信息可进入组件现有次文字属性，不能把14fp正文塞到12fp次文字或标题来省空间。
- 主辅不机械等高；组合占用必须在父布局剩余容量内。动作数量、四格、双信息块和图标锚点的条件与顺序以布局表为准，不用组合创造新槽。
### Group调用示意

以下Group行只能填入同区合法内容角色；实例及子节点遵循Core的结构命名，仍须补齐被引用组件，不生成第二个root。

核心与紧密补充：content_primary为核心组件，content_support为同对象短补充。

```genui
["content","Group",{"variant":"hero-support"},["content_primary","content_support"]]
```

同指标标签与读数：content_label保留必要指标名，content_value使用合法读数组件；不拆其内部单位。

```genui
["content","Group",{"variant":"label-value"},["content_label","content_value"]]
```

两项同级短内容：content_left和content_right各自完整可读，完整标签和值均能在分配列中放下，否则改合法纵排。

```genui
["content","Group",{"variant":"peer-pair"},["content_left","content_right"]]
```

同区连续多内容：需要保持独立组件职责时才用supporting-items；可合入一个SecondaryBody.items的辅助字段
优先合组，不为每个字段造强调块。下例为三项，合法数量为2–4项。

```genui
["content","Group",{"variant":"supporting-items"},["content_item_1","content_item_2","content_item_3"]]
```
