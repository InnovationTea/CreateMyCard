## 11.5 2x2 组合落地

| 正式骨架 | 可承载的组合 | 落地要求 |
|---|---|---|
| `S-center` | 单一核心内容 | 只承载一个无需标题即可理解的 `DataDisplay`，不附加补充或操作 |
| `S-title-content` | 标题 + 单内容 | 内容是一个完整语义组；有独立补充时改用标题双内容 |
| `S-title-dual-content` | 核心与补充 | 标题后依次输出核心与短补充；两个内容属于同一主题 |
| `S-quad-content` | 四占比 | 四格分别表达一个可识别的真实占比；普通四模块仍可按 layout 使用，但不属于四占比组合 |
| `S-title-content-action` | 单内容与操作 | 标题、内容、一个直属操作；操作沉底且不能省略真实内容 |
| `S-title-primary-secondary-action` | 核心、补充与操作 | 核心和补充自然撑高，操作属于同一主题；任一角色缺失时换骨架 |
| `S-title-dual-column-action` | 双占比 + 可选共同操作 | 两列各表达一个可靠比例，保持同规格；操作必须同时服务两项 |
| `S-title-anchor` | 核心、补充与独立图标操作 | 只在存在精确图标和真实事件时使用；操作归属当前主题 |
| `S-content-dual-action` | 双操作 | 一个紧凑内容后跟两个必要操作；两个操作共同服务该内容或整卡 |
| `S-dual-info` | 双信息块 | 两个对象各使用一个完整 InfoBlock；不增加总标题、第三块或独立按钮 |

### 2x2 专属约束

- 单个大数值只有在它是唯一核心焦点时才能使用 Hero；同级双指标、三状态和四占比不得从中任取一个
  放大。Hero 的字号与压力宽度按 components 执行，内容区预算按对应 layout 执行。
- 两个同级普通指标不具备可靠比例时，不生成双环；改用两条对齐的“标签—值”信息。恰好三个同级
  状态使用纵向短行，不拆成三个大号焦点。
- `S-title-dual-column-action` 的两列必须都是环形比例模块，不能一列环图、一列普通文字，也不能加入
  额外分隔线。
- `S-dual-info` 的每个 InfoBlock 只表达所属对象的主信息和辅助信息，外层和内部组件均不支持事件；
  存在必须保留的显式动作时改选可承载动作的布局。
- 倒计时、成对设备状态和融球只是业务或视觉场景，不是新的组件组合。它们先命中本表中的正式组合，
  再分别执行 layouts、components、core 的专属规则。

### 小卡完整组合自检（Plan、生成、修复共用）

- 先保留全部事实与动作，再合组；不要把四个普通辅助字段做成四个独立强调块或四个含额外间距的单项组件。
  同对象辅助字段优先放入一个合法 `SecondaryBody` 或 `TableText`，真正核心读数仍保持原字号。
- 多项并非必须双列。每列先扣完整标签与分隔符的宽度，再检查完整值；“标签+已连接/未充电”、
  日期时间及温度范围放不下时改全宽单列或 `items[].maxLines:2`，并为额外一行预留原行高。
  `metadata` 仍用其12fp，普通正文仍用14fp；不能改小字体、裁尾或只保留裸值。
- 过长的多字段句子可按事实拆成多个合法项或同字号两行，原路径和必要标签全部保留。
  主值已经显示的数值不在辅助句再次重复；目标、范围及完成度仍要可读，不能删掉其中一项冒充去重。
- 纵排不足时，先考虑“原字号主值+一项短辅助信息”在一个 Row 同行，其他辅助信息在全宽区域连续排列。
  Row 中主值、状态文字分别获得明确宽度或权重，逐项完整容纳；不让两个无权重的 matchParent 子区争宽。
  两个普通属性也可在完整宽度成立时合成同一短行，不能把不同对象无标签混在一起。
- 不把主辅内容机械等分高度；它们的整个紧凑组合承接正文剩余空间。动作仍在合法底部槽，
  标题、按钮、root边距及组件内部间距不变；只能使用所选完整变体允许的组间距，不能任意消除固定间距。
  Plan 的 remainingHeight 为负或只计裸值宽度时，重新合组、重选合法变体，不照搬该计划、不靠改权重掩盖超预算。
- 一至两项普通同级设备状态正文使用14fp `SecondaryBody supporting`，不要因状态是字符串就选12fp表格或 metadata。
  两项带“左/右”等标签的长状态，在完整双列宽度不足时使用 `columns:1` 的两个全宽行，仍为14fp。
  同一对象的短电流/电压、状态等辅助属性可以在一个完整 labelled value 表达式里合并，
  原路径、各自单位和对象归属必须保留；这种合并减少行数，不减少事实。
  原先三至四条辅助信息的 multiline 或12fp metadata仍保留原Recipe规格，不能只按role名称统一换字号。
- `TableText` 只能有2或3个条目，不存在四行变体。普通发起人、充电状态不是新强调焦点；
  只有真正主读数才用30fp数值组件，普通14fp正文不改为18fp主文而额外占一块高度。
  元信息日期时间超过一行时使用合法两行，完整日期和时分都保留；不要用一个窄列挤掉尾字。
- 没有硬标题绑定的装饰标题位，也可以承载同对象必要的12fp元信息，或用合法双行标题纳入更新时间。
  必要范围与对象名称仍完整，标题有指定事实时不能替换；14fp正文不能降到12fp标题来省空间。
  不要在空间不足时把一个普通等级、发起人或状态临时改成18/30fp焦点；先按全部事实重新合组，
  换完整合法变体并按实际Recipe占高核算，不只继续增减旧分区权重或照抄模型的估算高度。
