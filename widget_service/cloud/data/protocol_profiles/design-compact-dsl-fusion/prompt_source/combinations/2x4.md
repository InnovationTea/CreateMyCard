## 11.6 2x4 组合落地

2x4组合只用业务组件及登记的Group表达，不照抄共享示例中面向2x2的Row/Column几何。
下表旧子布局名称是选择关系的别名：A=center，B=title-content，紧凑C/宽版G=title-primary-details，
紧凑D/宽版C=title-content-action，宽版D=title-two-ratios，F=title-hero-support-action，H=four-ratios。
不把Sub名称作为组件或额外属性输出；Region只填写对应variant。

### 内容区组合

| 内容区 | 可承载的组合 | 落地要求 |
|---|---|---|
| `Sub-118-A` 核心居中 | 单一核心内容 | 一个无需局部标题即可理解的内容组件 |
| `Sub-118-B` 标题单内容 | 标题 + 单内容 | 标题后只有一个紧凑内容组 |
| `Sub-118-C` 标题双内容 | 核心与补充 | 标题、核心、短补充顺序固定，二者属于同一主题 |
| `Sub-118-D` 标题内容单按钮 | 单内容与操作 | 内容和操作属于同一对象，操作为最后一个内容区角色 |
| `Sub-140-A` 核心居中 | 单一核心内容 | 一个无需局部标题即可理解的内容组件 |
| `Sub-140-B` 标题单内容 | 标题 + 单内容 | 标题后只有一个完整内容组 |
| `Sub-140-C` 标题内容单按钮 | 单内容与操作 | 内容和一个直属操作；操作为最后一个角色 |
| `Sub-140-D` 标题双列内容可选按钮 | 双占比 + 可选共同操作 | 两列使用相同尺度和规格；操作同时服务两项 |
| `Sub-140-F` 标题主次内容单按钮 | 核心、补充与操作 | 核心、短补充和直属操作属于同一主题 |
| `Sub-140-G` 标题双内容 | 核心与补充 | 核心回答主要问题，补充解释或限定核心 |
| `Sub-140-H` 内容四宫格 | 四占比 | 四个同级真实占比；普通四模块仍可按 layout 使用，但不属于四占比组合 |

### 父布局与固定槽组合

| 父布局 | 合法组合 | 限制 |
|---|---|---|
| `W-top-bottom` | 单一主题的主体 + 明细，或同一任务的密集列表 + 短上下文 | 按语义、绑定和容量直接选择组件；密集列表可绑定所属只读详情，不承载跨对象共享操作 |
| `W-split-panels` | 两个完整内容区，或同一主题的核心与属性详情 | 两侧分别选择合法 Sub-118；操作留在所属内容区，不统一移到卡级 |
| `W-content-side-slots` | 一个完整内容区 + 双信息块、双操作或信息与操作槽 | 按角色直接选择 CardButton、InfoBlock 或同槽位合法组件组合，保持信息与动作归属 |
| `W-four-slots` | 四个固定信息或操作模块 | 每槽一个真实模块；按语义和容量直接选择组件，统一遵守组件合同 |

### 2x4 专属约束

#### Group受控组合

| variant | children | 关系与表达 |
|---|---|---|
| hero-support | `[hero, support]` | 同一对象的核心＋短补充，纵向紧密2vp，不制造两个无关核心 |
| label-value | `[标签组件, 值组件]` | 同一指标的必要说明与读数，纵向紧密2vp；单位仍由数值组件处理 |
| peer-pair | `[同级组件, 同级组件]` | 两个同级对象等宽同规格，横向8vp，双列居中 |
| title-count | `[SingleLineTitle, Badge]` | 同一集合的标题与真实数量，横向紧密4vp，组成一个标题角色 |

Group只填variant，不加背板或事件；每组恰好两项，不通过多层Group隐藏无关对象或绕过容量。
标题与数量沿用标题及Badge本身合同；环形、日程、文本块仍优先用对应语义组件，不拆成基础文本。

- 标题与同一集合的真实数量使用标题组件 + `Badge`；没有真实数量字段时不生成 Badge，也不使用正文组件仿造标题角标。
- 双占比只进入登记的双列比例内容区；三占比作为一个紧凑内容组进入单内容位；四占比只进入
  Sub-140 内容四宫格。普通状态或绝对量不能为了使用这些组合改成进度组件。
- 固定槽只承载紧凑主辅信息或操作，不承载完整业务内容。InfoBlock 只展示信息且不支持事件，CardButton
  承载所属操作；两者的 Props 和 visual 继续服从 components，不因进入组合而获得额外能力。
- 两个独立业务各自有操作时，优先使用 `W-split-panels`，让每个操作留在所属 Sub-118 内容区；只有
  两个操作共同服务同一大内容区时，才使用固定双操作槽。
- 主焦点、同行数值和数值单位的排版执行 core；组合层不按天气、电池、健康等业务名称创建专属结构。
