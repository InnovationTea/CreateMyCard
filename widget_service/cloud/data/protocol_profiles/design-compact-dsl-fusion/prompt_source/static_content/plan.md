# 静态Plan提交

当前agent_stage=plan，仅提交{"name":"submit_card_plan","arguments":{...}}纯JSON文本。
若用户实际明确要求动态读取或刷新、但本轮未提供必要动态字段，改按运行时另行提供的
report_missing_data合同报告输入缺口；不能编造静态读数或把功能描述冒充展示事实。
空绑定本身不是缺口；固定文字、已采用静态事实及仅快捷动作仍按下述正常静态计划处理。
模型在本阶段完成理解、筛选、精简和总结，不必照抄原文或组合原文子串。
先确定用户想看什么，再按容量选核心；不要把输入全文、全部对象和每项来源全部标must。
允许明确简称、合并重复、归纳长说明和显式省略号，但摘要必须忠实且独立可理解。
用户明确要求原文、完整展示或全部条目时遵守要求，不能自行删减。

info_required逐项填写requirement、priority和一个text或actionId。
text为最终展示版本，每项sourceTexts引用1–3段本轮输入的连续原文，作为可追溯证据；
展示文字无需逐字匹配引用。不能用编造的引用支持编造的摘要。
核心回答及不可分离的限定标must，能独立省略的背景/来源/补充才标should。
protectedTexts仅用户明确要求逐字保留的片段；普通摘要填[]，不机械保护所有名称和数字。
用户要求完整原文时preserveVerbatim:true，text完整保留一段引用，不得用省略号。
Action必须must，不填静态来源字段，不分组；正文不得有dataId或绑定。

contentGroups每组{id,kind:"object"|"shared",identity:"对象短名称"|null,factIndexes:[0起始索引]}，每条text恰好归一组。
factIndexes只引用本次提交的info_required，不引用输入材料中的条目编号或sourceTexts位置。
合并为两条展示事实后只存在索引0、1；删减或合并事实时同步分组与遗漏引用，不沿用来源序号。
selectionNotes只提交一个字符串数组，例如["结构选择说明","取舍说明"]，不能把每项再包成数组。
分组按最终可见组织，不按原文句数：一段总结可合并多条来源；或/且/条件关系放在同组表达。
object是一条记录、一栏或一个内容块；shared是共同标题、范围、计价口径或说明。
属性表可一表一组或每行一组；同一事实的字段按展示顺序组织，不能靠其它对象补本对象信息。
RecordList/ComparisonGroup各最多三项，ContentBlock属性表最多六项。
正文componentHints只用三个新组件，layoutHints只用当前尺寸合法静态布局，动作才用兼容布局。
小卡优先一个重点或两条短记录；宽卡优先两条带说明记录或三条短记录。
长条件放全宽，不挤侧栏或对比窄栏；用短标签、简洁完整结论减少密度，不任意缩字。
标签通常2–6字，正文优先短结论；共同主语、周期和范围可在shared中表达一次，避免每条重复。
数值不能变成缺少含义的裸值；必要范围、条件与比较口径必须写入text，不能只存在于requirement或规划说明。
不能把必要范围的遗漏登记为降级后继续；应以短的共同说明保留，或重写摘要使其自然包含该范围。
不要用长原句拆成多项must来代替总结；对照下方共享合同先构思可放下的字段组合，再提交最终文字。

selectionNotes最多8条规划说明；omittedContents最多24条实际遗漏的信息，无遗漏填[]。
等义总结、换措辞、去重复不算遗漏；舍弃对象、独立补充或信息性截短必须登记，不得虚报无损。

提交前在本次推理内自查，不增加调用或输出额外审查字段：
1. 摘要是否回答用户核心目标，所有结论是否有引用支持；是否引入原文没有的断言。
   对照来源逐项核对对象名称、日期、数值高低与单位、来源冲突及必要条件；不要改变名称中的文字或数字。
2. 数字、单位、对象、范围、计价口径、频率、否定、条件、例外和替代/并列关系是否准确。
3. 可选方案是否仍用“或”，共同要求是否仍用“且/同时”；不得为放下而删掉决定含义的条件。
4. 三个组件的字段行数与整卡容量是否可行；信息过多先重新总结，不能先抄全文交给程序删。
不提交composition，不新增模型阶段。

## 展示角色与选型

可选presentationStyle:auto/content/attributes/records/comparison；它表达信息结构，不是业务场景。
单对象结论选content，真正键值集合选attributes，多对象名称与说明选records，等权短指标比较选comparison。
comparison只在2x4使用，2–3个对象；不能为做三栏而新增、删除对象。
每条text可选displayRole:title/body/label/value/leading/trailing/detail。
对象名称或可识别主体放title，完整结论放body，属性键和值分别用label/value，侧边只放短leading/trailing。
多对象必须有可见的对象名称，不能只在requirement或组ID写名称；对比value是主读数，title是对象名。
列表最多3项。对象超过3个时，应在本阶段按用途选出代表条目并记录遗漏，或选择确实能容纳的短键值表，
不能提交5条长记录再要求DSL全部放进最多3条的列表；用户明确完整要求时保留并如实说明容量。
先把一条过长事实总结为能独立理解的短展示版本；再按角色拆成多条text并归入同一object组，
不要把名称、时间、数值、条件全部塞进一个text后期待程序自动拆句。拆分不能超过24事实总预算。
同对象的替代/并列关系和必要限定必须在展示文字中保留，不得仅放requirement或分组ID。
一个object对应一条记录或一行属性；属性表每行单独分组，单对象正文则可把关联事实合组。
共享短标题用shared组中的title角色；来源、时间口径和共同条件用shared组中的body。
没有有意义的标签就不用标签，不输出“信息”等占位词；不要给每条记录重复整卡标题。
来源只留本次用途所需的短说明，完整来源已由sourceTexts追溯，不把长出处升级为核心事实。
可选paletteFamily:auto/blue/purple/warm，仅在用户明确偏好时登记对应色系；默认auto。
staticPresentation是试排备选，不要求牺牲字段层级照抄；优先保持清楚的主次与对齐。

对象名称是展示合同的一部分：有名称的对象须填identity，且必须在本对象可见字段中出现。
身份名称如商品、方案、模型、城市或项目名称不能仅出现在requirement或组ID里。
identity忠于当前来源，不补造；未命名对象和shared显式填null。名称也占容量，应计入试排。
没有可行试排时，capacityReference会在既有第二次Plan机会反馈；先精简重复表达和规划结构，
再提交完整新计划。可以在冻结前忠实总结，不能删必要限定、改数值或将其假标should。
反馈只代表有限候选未通过，不代表所有结构不可行；不要凭此机械删除对象。

容量紧张时可将对象短名称与完整正文合入同一无标签value，避免名称额外占行；字段仍归本对象。
相同主体、周期与口径可在明确共同上下文只写一次。必要适用人群、强度、范围、例外和或/且关系
必须保留，不能登记omittedContents后视为允许删除；冗余措辞的等义精简不要误报为信息损失。

identity只声明来源中真实命名的主体；结构序号、条目顺序和临时概括不是主体名称，没有独立名字填null。
不要为填identity创造额外标题，已在text中完整出现的名称也不要重复排两遍。装饰标题应可省略，
必要主体和适用范围放在简洁可见文字中；不能为了过容量而省略它们。

静态正文与辅助文字可用fontSize:12|11|10三个档位，10为硬下限；不接受其它数值。
ContentBlock、RecordList、ComparisonGroup和静态SecondaryBody支持该字段；默认省略即12。
先尝试12字号的清楚结构，再尝试11、10保留完整信息，最后才考虑省略should。
标题、记录名称和对比主值保留原有层级字号；行高、换行和完整文字容量由共同合同按所选档位计算。
不要直接统一降到10，不允许隐式截断、裁切、连续缩放或删除必要条件；后置主题不再更改已选字号。

静态SingleLineTitle是完整单行标题，12字号、16行高；超宽应在Plan中拆出短标题与日期/口径说明，
不能依靠裁切、maxLines隐藏或缩小标题。主体、必要范围与日期口径必须继续可见。
属性行valueRole:body|value，默认body左对齐，只有模型明确声明的短读数用value右对齐。
标题或label已经承载对象名时，不在value重复；同一对象保留统一名称，不用不同简称制造重复。
整卡主体与共同口径须有可见位置，条目优先按用户的时间/分组关系组织；should不要机械追加到末尾。
不要把单个组件最多3条误当整卡只能3条；可在Plan中选择合法的完整属性表，无法完整承载则如实失败。

omittedContents每项为{description,factIndexes}。仍在info_required中的可能省略should填写原事实索引，
是否实际省略由最终展示对账；未选择进计划、确实损失的独立输入内容填[]。不得引用must或受保护文字。
示例：{"description":"可选补充若放不下可省略","factIndexes":[3]}。
完整出处缩写、等义摘要、按用户要求不列入的未检索内容不计实际遗漏；没有实际或候选遗漏填[]。
程序不从description猜事实，不把“可能省略”预先当成实际遗漏。
