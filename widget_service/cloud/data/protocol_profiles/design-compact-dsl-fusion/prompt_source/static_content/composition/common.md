# 内容组织流程

1. 按用途形成忠实、独立可理解的展示事实，保留对象、数值、单位和必要限定。
2. 按正文的信息形态选型：逐条主副记录用TextList，完整单行键值用SingleLineList，单一结论与从属说明用EmphasisText。
   两到三条平级的“对象名 + 说明/状态”记录优先TextList；对象名、主读数与趋势并存时把读数放value。
   TextList为2项时必须与SingleLineTitle标题配套使用；3项时允许无标题。
   只有短标签加短值、且可完整单行读完时才用SingleLineList，不把长说明塞入assist；
   SingleLineList必须与SingleLineTitle标题配套使用，不能只有body列表而缺少header标题。
   静态事实账本最多选入5条完整对象信息，实际展示项数以所选组件容量为准。
   标题和shared公共说明不计入对象数，但仍占用对应标题区或正文字段；任何最终渲染为正文行的shared说明、例外或提示都计入所选组件的实际条目数，
   不得因其不计对象数就在列表中额外新增一行；超过时在Plan阶段按完整对象取舍，不能只删字段留下半条对象。
   组件之间保持对象归属，不把无关事实硬凑在一起。
3. 先确定完整正文需要的记录数量，再安排标题。正文与标题均能完整容纳时保留SingleLineTitle，
   不为先保留标题而少选正文。确需三条主副记录、且共同主题可省略时，采用无标题三项TextList。
   三条短标签与短值能完整单行表达时，仍可使用带标题SingleLineList；不因条数为三就去掉标题。
   主题承载必要主体、范围或条件时，保留其可见表达，或选择可承载标题的结构。
4. 按本尺寸固定外框组合；对照完整字段与实际行数核算容量。
5. 在Plan阶段按完整文字比较合法组织，再决定信息取舍；短值可同行并列，记录可使用主副层次。
   放不下再忠实精简或换组件；接受Plan后完整落实已选事实，
   仅在程序明确授权的既有Drop阶段按事实索引删减，不用缩字、裁剪或更改固定间距掩盖问题。
