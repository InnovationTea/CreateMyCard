# 信息理解与组织

## 核心与忠实摘要

先确定用户想看什么，再按容量选核心；不要把输入全文、全部对象和每项来源全部标must。
按用户用途选择核心、合并重复、使用明确简称或总结，不要求展示原文或把原文子串拼接为摘要。
允许整理日期表达、简洁标签和显式省略号，但摘要必须忠实且独立可理解，不能截掉核心结论。
不补造事实，不改变数字、单位、对象归属、适用范围、条件、否定或“或/且”关系。
数值不能变成缺少含义的裸值；必要范围、条件与比较口径必须在最终可见文字中出现，
不能只存在于requirement或规划说明。不能把必要范围的遗漏登记为降级后继续。

核心回答及不可分离的限定标must；should只能用于可独立省略、不影响核心含义的背景、来源或补充。
必要适用人群、强度、范围、例外和或/且关系必须保留，不能假标should或登记遗漏后视为允许删除。
用户明确要求原文、完整展示或全部条目时遵守要求，不能自行删减。

## 对象与共同上下文

分组按最终可见组织，不按原文句数；同对象的替代方案与关联条件在同组表达，不能把“或”改成“且”。
相同主体、周期与口径可在明确共同上下文只写一次。标题概括共同主题，必要说明留在相关正文内，
不同对象保持顺序和归属，不把别条事实拿来补齐本条。
对象名称须可见；单主体可放整卡标题，多对象放各自条目内，不仅写内部ID；名称也占容量。
相同对象允许字段换序、增加解释性标签，仍须完整保留原值及归属。
从输入用途或内容提炼简短共同主题，帮助识别整卡；主题概括不补造对象名称、结论或适用范围。
没有真实名称的对象不另起名字；已完整出现的名称不重复排两遍，主题也不照抄正文主句。
仅作装饰的主题可在容量不足时省略，必要主体和适用范围仍须可见。条目优先按用户的时间/分组关系组织，
should不要机械追加到末尾。

## 原文要求与取舍

只有用户明确要求逐字保留才保护原文；普通摘要不机械保护所有名称和数字。
等义总结、换措辞、去重复、完整出处缩写及按用户要求不列入的未检索内容不算实际信息损失。
舍弃对象、独立补充或信息性截短须记录，不虚报无损。
来源只留本次用途所需的短说明，完整来源通过引用追溯，不把长出处升级为核心事实。

## 显式提供的静态事实

输入含“本轮卡片静态内容（用作展示的外部事实）”段时，该段提供可展示事实，段前文字只说明用途。
读数、连接结果和设备状态以已获事实为准，不将用户期待的展示或操作当作已发生结果。
已获事实足以成卡时，保留它们；其它缺少事实的独立展示期望登记实际遗漏，不为该部分报告数据缺口。
动作意图不变成静态事实，也不作为本静态路线的信息遗漏。
