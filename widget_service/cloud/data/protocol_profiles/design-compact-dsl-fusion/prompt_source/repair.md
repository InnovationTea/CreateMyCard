## 2x4语义布局修复

2x4修复继续输出Layout/Region/Group及业务组件。反馈标为expanded的几何来自模板，不是模型填写的Props；
根据定位的原语义节点修改内容组件、Group、Region.variant或Layout.layout，不输出内部生成节点，也不修改
固定宽高、边距、间距、权重或对齐。每次更换变体同步修齐其必需角色；删除获授权事实后，也要重新选择能
承载剩余内容和全部Action的合法结构，不能留下空Region或空Group。2x2仍沿用原修复表达。

Action 覆盖失败时，先检查对应按钮是否从 root 的 children 引用链可达；仅输出按钮行不等于显示入口。
优先补到现有合法动作位。没有可用动作位时，最小范围改选 Region 或父布局来承载全部真实操作，
不能给固定双槽添加第三槽、把 CardButton 放在 Region 外，或只保留不可达按钮。
已有事件及其时间、地点仍作为同一完整内容，不因补按钮退化为狭窄信息槽；不复制动作或删除事实。

展示事实缺失时，先恢复同一对象的完整信息组，再检查补齐后的容量。原布局只装入部分事实时合法，
不代表补齐后仍合法。短属性可在同组的合法 item 中完整合并；长属性按真实行数表达，不能超过
组件项目数，也不能因所有路径已绑定就接受可见截断。必要时最小范围调整组件组合或区域，
保留已正确的事实和操作，不把不同对象混到同一辅助字段；纯绑定、语法错误不因此授权重排。


修复已匹配的语义组件时，先修错误 Props、绑定形式、必要父容器与槽位预算，再考虑更换组件。
不能因一次属性错误直接退化为逐字段文本；模型仍不得直接输出 Text。必要事实、动作和对象归属不变。
属性错误只授权修改被定位的 Prop 及必要的相邻属性；未报错的绑定、事件、图标、视觉变体和色彩角色保持不变。
不能通过删除组件视觉能力来消除数值或绑定错误。`InfoBlock.visual.type:"progressCircle"` 的 `primaryText`

百分号单独写为 `unit:"%"`；不得把业务标签或百分号拼入 `primaryText`，也不得删除 `visual` 绕过校验。

合并为一个完整的 `items[].value` Expression，保留全部原始绑定，不得静态化、删除或改写成样例值。
`SecondaryBody.fontSize` 报错时，保留 items、绑定与事实，按当前行布局修正：整组单行用14，
多行用12；行高分别19和16，行间距2。改变 columns/items/maxLines 后重新核算，不删除事实来改字号。
修复范围先按本轮实际错误与请求内 repairStrategy 确定：首次仅有明确 Props、绑定或素材错误，且没有结构、容量或
必需信息错误时，保持当前合法布局/变体、事实合组、动作归属和未报错区域，仅修改定位到的
错误属性并复查相邻影响。不能因一次属性错误重选整卡骨架；不确定诊断不授权盲目重组。

`parent_layout_recompose` 重组报错组件所属的父布局并重新分配完整信息组与动作。
同根因重复且 repairStrategy 已升级到 parent_layout/full_dsl 时，按升级范围完整重组，

特别检查主读数最后的单位、百分号和状态文字。不要只保证字符串仍在绑定中而让末尾被裁切。
每个真实操作保留清晰入口；除非用户明确要求重复入口，不为满足某骨架的槽位数复制同一个动作。
文字横向放不下时，可将 SecondaryBody 改为 columns:1，并为必要长值声明 maxLines:2；
同步增加相应行预算。不得通过空值、裁切单位或省略尾部内容交付；仍放不下则换合法布局。
仅当本轮实际提供组合参考或工作表时，使用它比较原字号、原语义的完整组合与区域预算；

repairStrategy 逐层重算，不能等待不存在的工作表，也不能把软候选当成必须逐字段创建的组件实例。
同时检查当前对话中已接受 Plan 的 composition 区域分配与 factIndexes 落点。超高或截断时修复整个受影响信息组，

先保留已正确合组的事实映射：TextBlock 必须完整承载分配给它的2–4项明细，不能把这些项拆到

当 `repairStrategy.repairStrategy` 为 `compact_component` 时，表示正常布局修复和完整 DSL 重组仍未闭合，
现进入与 claw-widget 同义的无损紧凑组件替换阶段。本阶段最多连续提交两次完整 Compact DSL；两次后只迁移到
Drop、定向修复或完整 DSL 重组，不代表整条修复链路终止。严格执行：

- 保留所有用户要求的业务事实、Plan 中的 dataId、actionId、静态正文及动态绑定关系；不启用可选信息删除。
- 可将放不下的文本类组件替换为语义兼容、占位更小的已登记组件；普通文本只能使用当前合同允许的
  `EmphasisText`、`SecondaryBody` 等语义组件，不能直接输出 `Text`。
- `SecondaryBody` 只能辅助同一语义分区内的核心信息组件。诊断为孤立时，不能通过增加按钮、标题或另一个
  `SecondaryBody` 消错：正文自身是主要结论时改用 `EmphasisText`，确属辅助信息时与同区核心重新合组，
  没有可识别核心且信息等权时整体改用当前尺寸允许的表格、列表或详情组件，并重新核算布局容量。
- 仅当 `EmphasizedData` 承载的是可无损保留的短文本、状态或完整格式化字符串时，才改为
  `EmphasisText`，并把原完整可见内容迁移到 `mainText`；纯数值与单位、真实进度以及日程事件不得

- 同组多个事件继续放在一个 `EventCard.items` 中；普通规格放不下时先使用合同已有的
  `density:"compact"`，完整保留每项 title、time、location 和绑定，再改选可承载它们的合法内容区。

  2×4 仍使用 Layout/Region/Group；2×2 仍使用 Row/Column/Stack，不复制 claw-widget 的 Card 或 JSX。

当 `repairStrategy.repairStrategy` 为 `drop_optional_component` 时，表示上述无损阶段已失败，并且微服务已在
`repairStrategy.optionalDrop` 中选定本轮唯一可删的非 Action 业务展示组件。程序优先选择 should-only 组件；
没有这类候选时，指定组件可以承载 `must` 事实。本轮严格执行：

- `approvedOmissions` 是此前各轮与本轮累计批准省略的事实，后续必须保持不可见；不得换组件、改 ID、写静态文字
  或 Expression 将它们重新加入。累计省略不授权删除任何 Action。
- 只删除 `optionalDrop.componentId` 指定的一个组件，并从父级 children 移除引用；不自行改选其他组件。
- `allowedOmittedFactIndexes` 只是该组件对应的非 Action 事实索引；其余 must/should 事实与所有 Action 仍必须完整可见。
- 不自行删除第二个组件。指定组件及父级引用已删除、但布局仍不闭合时，等待微服务根据剩余 DSL
  明确指定下一轮候选；后续每轮仍只能删除当轮 `optionalDrop.componentId`。
- 按当前尺寸合法布局重排剩余完整内容，不改动态绑定，不缩字、裁切、隐藏或静态化信息。
- 若反馈指出上一轮输出与前一次提交完全相同，本轮必须删除指定组件行及其直接父级 children 引用；
  若该组件已经不存在，则保持删除并闭合剩余布局。必须输出完整 Compact DSL，禁止原样返回。

修复必须执行以下通用流程，不得把每条错误当成彼此独立的字符串替换：

1. **先恢复语义事实**：从本对话的 TaskSpec 中重新读取本轮 userQuery、字段类型、description、
   sampleValue 和候选边界。TaskSpec 是值语义的唯一依据；Few-shot、组件 id、现有字号和上一轮 DSL
   中已经写错的单位都不能反向改变字段类型或含义。
2. **再定位共同根因**：把指向同一组件、同一绑定或同一父容器的错误合并分析。优先修复最上游的绑定、
   值类型、单位归属或骨架错误，再重新判断由它引出的字号、密度、宽高和相邻节点错误；不得为了消除一条
   错误而引入重复内容、空内容、伪单位、错误标签、静态样例或新的越界。
3. **按值形态选择结构**：绑定动态字段时，只有 number/integer 才能使用 `EmphasizedData` 的量化主值与真实单位；
   已经包含单位的格式化字符串必须完整绑定到一个显示值，不得追加或拆出单位，也不得保留空单位占位；普通名称、状态、
   日期或说明文字不得伪装成数字主读数。绑定类型本来不允许当前数值组件时，按真实值语义纠正组件；
   这不是容量降级，不能把合法主读数放不下解释成值类型错误，再用更小正文绕过预算。
4. **保持需求完整**：用户明确要求且仍在候选范围内的字段不能仅为消除密度错误而删除。合法大字号结构装不下时，
   保持合法字号、角色与固定设计量，先合并可共同承载的完整事实、调整分区或选择同尺寸的完整合法骨架；
   SecondaryBody 仅按合法单行／多行规格切换，不任意缩字、缩按钮或删除必要标签和单位。未收到 `drop_optional_component` 策略时，
   不进入删事实的 drop 阶段；进入后也只能省略策略指定的非 Action 事实，
