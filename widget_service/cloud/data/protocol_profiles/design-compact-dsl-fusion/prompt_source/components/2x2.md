# 小卡组件限制（维护源）

> 维护说明不发给模型；仅 `prompt` 标记内正文参与构建。

## 边界与阅读顺序

高阶组件的 2x2 适配 → 图标允许位置和限制 → 单会议与主值组件的固定槽位。

## 高阶组件的 2x2 适配（维护导航，不发模型）

| 组件 | 合法范围 | 固定展开边界 |
|---|---|---|
| `EmphasizedData` | `S-center` 或带标题布局中的唯一核心量化值 | 使用所属内容区宽度；数值与单位保持一个主信息组，不吞并支撑信息 |
| `InfoBlock` | 仅 `S-dual-info` 的上、下 `134×63vp` 固定背板 | 1–2 行文字；可选右侧 `20×20vp` 图标；不支持事件；不封装环形 Progress |
| `TableText` | `S-title-dual-content` 的 2–3 项同级标签—值 | 标签列和值列分别对齐；每行单行；卡级标题和沉底上下文不进入组件 |
| `DataDisplay` | `S-center` 的标签、唯一核心值与短支撑文本 | 最大 `126×114vp`；不吸收动作 |
| `EventCard` | 合法布局中预算成立的单事件内容区 | 固定时间线、标题、时间与可选地点；替代手写时间线与文字列 |
| `PillButton` | 带动作布局的底部文字动作 | `126×36vp` 胶囊；可选 `20×20vp` 图标；双动作布局纵排两个 |
| `CircleButton` | `S-title-anchor` 右下锚点纯图标动作 | `36×36vp` 按钮置于 `40×40vp` 槽；必须有完整无障碍名称 |

`ProgressLine2` 在当前 2x2 Few-shot 中没有稳定实例，不建立小卡槽位。`PairedMetric` 不进入候选；
V13 保留普通双数值组合，V21 保留真实双占比的基础组件展开。

## 2x2 组件选型

| 组件 | 内容、绑定与容量 | 排除条件 |
|---|---|---|
| InfoBlock | 两个独立对象各一块；primaryText/secondaryText 两行完整短文本，stacked 变体 | 有必要动作或单对象密集信息时不能强套双信息块 |
| EmphasizedData | 一个短核心数值＋可选单位，所属内容区还可容纳必要标签或说明 | 不用于时间段、长单位读数或同级对比组 |
| TableText | items 中 2–3 项 label/value；2 行需 34vp、3 行需 52vp | 当前只用于无动作布局；有必要动作时改用基础信息组，不删动作或删项凑数量 |
| DataDisplay | label＋唯一 value＋短 supportingText，整体可占几乎整个正文区 | 仅无动作的单焦点；不承载第二指标或密集明细 |
| EventCard | 单事件 title/time/可选 location，内部时间线；动作另用按钮 | 不用于一般状态或操作本身，不为适配它省略第二事件；端侧时间线存在已知显示差异 |
| PillButton | label 与一个真实 onClick，底部文字动作；双动作使用两个实例 | 不新增候选之外的动作，不与其它入口重复同一动作 |
| CircleButton | 准确 icon＋accessibility.label＋一个 onClick，右下图标动作 | 没有准确图标或动作含义不清时不用；能容纳清楚文字动作时优先 PillButton |

小卡不推荐 ProgressLine2、TextBlock、CardButton、ProgressCircleSingle、TopTextBottomValue、SummaryList。
动作指本轮必须保留的操作，不是候选事件列表的长度。存在必要动作时，不推荐只属于无动作布局的
DataDisplay、InfoBlock 或 TableText；这些组件不能因为位于正文就自动获得带动作布局的合法槽位。
必要信息和动作先完整保留，再按最终布局预算选择组件，不因对象名称属于某个业务而锁定骨架。

**2x2 图标生成前置约束**：普通内容区生成零个 Image，不生成“每行文字配一个图标”的结构。只有环形 Progress 中心和 `S-dual-info` 两个独立对象的分区主视觉可在内容区使用 Image；两座城市的天气也属于 `S-dual-info`，每个天气分区各用 1 个合法天气图标。其余图标仅放按钮区或 CardHeader，继续遵守总数和区域互斥；L/R/盒等现有 Text 标识保留。用户必须明确要求图标本身才可例外，要求展示天气、日期、心率或动作不算。

## 2x2 高阶组件适配

通用选择条件、Props、绑定和 Compact DSL 示例见组件协议；本节只规定 2x2 的合法槽位与固定展开。
高阶组件均不带 children；仅可使用通用合同允许的根节点外部布局 Props，不覆盖内部排版。

### `EmphasizedData`

#### 合法槽位

只用于 `S-center` 或带标题布局中的唯一核心量化值，不进入 `S-dual-info`，也不用于 V13/V21 的双指标。

#### 固定展开

数值行使用 `width:"matchParent"`（参考宽126vp）：主值 `30fp/700`，可选单位 `12fp/500`，间距 `2vp`，两者底部对齐。

#### 注意事项

一个内容区只使用一个核心值。V13/V21 的两个同级指标继续使用基础 Row/Column，不抽象为新组件。

### `InfoBlock`

#### 合法槽位

只用于 `S-dual-info` 上、下两个等权背板（参考134×63vp），外框随所属槽位伸展；`variant` 省略或填写 `"stacked"`，两种写法展开相同。

#### 固定展开

主信息固定 `14fp/700`，辅助信息固定 `12fp/500`，两行由固定文字列垂直居中。可选右侧 `20×20vp` 图标；
外层和内部组件均不支持事件。

#### 注意事项

两行文字都必须保持单行。完整主值优先于冗长标签和可选图标；时间、状态被省略就表示组件不适用。
环形 Progress、完整业务区以及两个同级指标不封装为 `InfoBlock`。

### `TableText`

#### 合法槽位

只用于 `S-title-dual-content` 的 2–3 项同级标签—值。

#### 固定展开

每行宽度填满父区、高 `16vp`：标签和值用 `layoutWeight:31` 与 `layoutWeight:28` 分配宽度（参考62/56vp），均为 `10fp/500`，值右对齐；行距 `2vp`。
这里的 `10fp` 只属于转换器确定性展开的内部辅助文字，不开放为模型可写字号。

两行需要34vp、三行需要52vp。使用显式高度槽承载 TableText，父区不能靠 flexShrink 把这些行压小。
若同时有必须的动作和其它正文，改用预算成立的基础信息组，不让表格进入按钮区域。

#### 注意事项

卡级标题、沉底上下文和动作不进入表格。`ProgressLine2`、`TextBlock`、`CardButton` 当前均不用于 2x2。

### `DataDisplay`

#### 合法槽位

只用于 `S-center` 的唯一主值展示，作为 root 的唯一内容子组件。

#### 固定展开

组件宽度使用 `matchParent`，紧凑内容组高 `114vp`、内部间距 `8vp`；标签 `12fp/500`，主值 `56fp/700`、行高 `60vp`，
支撑文本 `14fp/400`，整体垂直居中。

#### 注意事项

只表达一个核心值。动作仍放在独立 `action_area`，不得传入组件。

### `EventCard`

#### 合法槽位

用于单事件的内容区，title/time/location 必须属于同一事件。带动作时使用 `S-title-content-action`
的单事件预设（日期上下文、事件内容、独立动作），或者带标题布局中预算成立的内容槽；不要求按业务根
名称判定 calendar，也不能因存在其它必要信息就删除它。多事件或容量不足时改选完整信息组合。

#### 固定展开

内容 Row 宽度填满所属区域：无地点时参考高 `34vp`，有地点时参考高 `50vp`；左侧是 `8vp` 宽时间线，右侧文字列使用 `layoutWeight:1` 承接剩余宽度；
右侧标题 `14fp/500`、时间及可选地点 `12fp/400`。标题和时间必填，地点可选。

#### 注意事项

不再手写时间线轨道或重复文字列。内容区不得出现 Image；超过一个会议时切换其它布局。

### `PillButton`

#### 合法槽位

用于带动作布局末尾的单按钮 `action_area`，或 `S-content-dual-action` 的双按钮组。动作文字必须可见；存在合法图标时可选配图标。

#### 固定展开

按钮宽度使用 `matchParent`、高度固定 `36vp`、圆角 `30vp`；`S-content-dual-action` 两个按钮垂直间距 `8vp`。单按钮优先于纯图标按钮。

#### 注意事项

同一动作只生成一个按钮。不要再使用基础 Button 或手写 Row 复制胶囊样式。

### `CircleButton`

#### 合法槽位

仅用于 `S-title-anchor` 的右下锚点。外层结构固定为 `126×40vp` 的 Row，左侧承载短辅助信息，末项是
`40×40vp`、`alignContent:"center"` 的 Stack，Stack 内唯一子节点为 `CircleButton`；外层 Row 必须是
root Column 的最后一个子节点。

#### 固定展开

组件本体固定 `36×36vp`、圆角 `18vp`，中心图标 `20×20vp`。外层 Row 固定
`justifyContent:"spaceBetween"`、`alignItems:"center"`，确保按钮位于右下操作槽。

#### 注意事项

只有底部 `PillButton` 槽无法与必需内容共同容纳、图标语义清晰且存在准确素材时使用。
`accessibility.label` 必须写完整动作名称；不得与 `PillButton` 表示同一个动作。
