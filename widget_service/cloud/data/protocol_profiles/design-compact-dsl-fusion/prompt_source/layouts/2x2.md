# 2x2 语义布局

布局固定几何以 runtime/layout-contracts-v1.json 为维护校对依据，不发给模型。仅下列标记正文参与加载。

<!-- prompt:s-layouts -->
## 9.1 2x2 固定语义布局

Layout是root，layout只选下表十种正式布局；children按有序角色填写真实组件ID。
同区业务组件可用Group合组。小卡不使用Region，不输出Row/Column/Stack或内部展开节点。
参考画布150×150vp；普通安全区126×126vp，S-dual-info为134×134vp。几何由程序展开，
不填写width、height、padding、itemMargin、layoutWeight、flexShrink、margin或对齐Props。

### 父布局与有序角色

| Layout.layout | children顺序 | 条件与参考预算 |
|---|---|---|
| S-center | [content] | 唯一无需标题即可理解的DataDisplay；双轴居中；无动作 |
| S-title-content | [title, content] | 标题＋一个完整主体；主体左对齐、贴底；无独立支撑或动作 |
| S-title-dual-content | [title, primary, support] | standard为主辅；stacked-info为同级双信息块；保留共同标题，无动作 |
| S-quad-content | [左上, 右上, 左下, 右下] | 四个真实同级短模块直接占59×59槽，横纵间距8；无标题或动作 |
| S-title-content-action | [title, content, PillButton] | 完整主体＋一个直属动作；内容左上、按钮沉底 |
| S-title-primary-secondary-action | [title, primary, support, PillButton] | 紧密主辅＋同主题操作；主辅2vp，按钮沉底 |
| S-title-dual-column-action | [title, ProgressCircle, ProgressCircle, PillButton?] | 两个同主题真实比例；等权双列；共同操作可选 |
| S-title-anchor | [title, primary, support, CircleButton] | 独立左下支撑＋精确图标操作；主内容左上、动作右下 |
| S-content-dual-action | [content, PillButton, PillButton] | 单业务紧凑信息＋两个明确操作；内容左上、按钮沉底；无标题 |
| S-dual-info | [InfoBlock, InfoBlock] | 已成立双信息块且无需共同标题；padding8、等权背板、间距8；无总标题或动作 |

纯双动作例外：已接受 Plan 只有两个动作且没有展示事实时，使用同布局的
`variant:"actions-only"`，children 为 `[PillButton, PillButton]`，两个按钮整体垂直居中。
不得为满足标准变体补造正文、状态、标题或空内容槽；存在任何展示事实时仍使用标准变体。

标题角色必须是SingleLineTitle，无图标占12vp，有图标占20vp；原数据与素材合同不变。
表中title/content等是角色，PillButton/ProgressCircle等是类型要求，不是实际组件ID。
children填写各实例的唯一ID；两个同类组件也必须使用不同ID。问号仅表示该角色可选，不输出问号、null或空槽。
单内容可以是业务组件或同区Group，不把无关对象包装为一个内容。动作缺失时改选无动作布局，
不得保留空角色。普通双指标不是双环；已成立双信息块组合时按下述登记变体承载，其它并列短内容再选peer-pair或纵排属性组件。
仅使用正式S系列布局。

### Layout属性与登记变体

- layout必填；背景沿用Core的linearGradient/backgroundColor/backgroundImage或受控design。
  融球仍遵守版本、业务和容量条件，不增加装饰节点。
- variant可省略，默认standard；除下列登记变体外不填写。
- S-content-dual-action：standard包含内容及两个按钮；actions-only仅包含两个按钮。
- S-title-content-action：standard保留标题后6vp、正文到动作8vp；dense仅将标题间距改4vp。
  direct/direct-dense/direct-tight/direct-flush对应已登记直属正文变体：标题、完整正文、36vp动作
  直属根，外层固定间距分别6/4/2/0vp，不继承标准body的8vp。不局部混用两种结构。
- S-title-primary-secondary-action：standard/dense的标题间距6/4vp；主辅2vp、正文到按钮8vp不变。
- S-title-dual-content：standard保持主上辅下；stacked-info必须是两个无visual的
  InfoBlock.variant="stacked"，每个126×50vp，中间8vp；标题后仍须通过真实高度预算。
- 已接受Plan含wholeCardActionId时，仅S-title-content或S-title-dual-content允许root.onClick承载
  该唯一只读详情的完整handler；内部无按钮或其它点击节点，正文不预留按钮高度。
  表中这两个布局的“无动作”指无独立按钮槽。标记由服务端派生，不自行补写或将其它动作挂root。
  S-center、S-dual-info、S-quad-content和2x4不开放该例外；明确按钮要求、拨号、导航、入会等仍走按钮角色。

### 关键容量与排除条件

- S-title-anchor与文字动作布局同级：仅一个显式动作、准确SVG、用户未要求按钮文案，
  且至少有一个独立左下事实时才选。没有独立支撑事实时排除 `S-title-anchor`。
  标题、动作及只在标题展示的上下文不计作支撑；左下可用SecondaryBody承载辅助事实，只要整卡
  其它位置已有核心信息组件。普通底栏40vp；纵向三项NumericRatioStack
  保留56vp高、78vp宽；右侧40×40槽居中放CircleButton。两种底栏均保留8vp区域间距。
- S-dual-info每块最多两行、可选合法visual；外层及内部无事件，不增加第三块。
  `S-title-dual-content` 的两个 `126×50vp` 槽使用stacked-info，不与普通主辅混搭。
- 双环及四格ProgressCircle的参考宽高由槽位注入，不由模型填写；比例、图标、最小环径及
  完整读数门禁不放宽。普通四模块不是四占比，不补造指标。
- root边距、标题间距、按钮36vp、全部正文行高和组件内间距先计入预算；
  弹性承载区不是无限空间。容量不足改合法组合或完整布局，不拼槽、缩字、裁切或静态化。
- 保留全部必要事实与Action；只有修复策略明确授权Drop时才删除指定信息。

### 各布局的Compact结构

下列骨架只展示结构角色；按Core的结构命名定义被引用的全部组件，不按业务改名。
若使用 `...`，它仅代表省略的属性或定义，最终输出不能包含省略号。

下列片段只展示布局层；最终输出必须补齐全部引用的业务组件行和数据行，不能直接提交这些片段。
背景Props为避免重复而省略，生成时仍按Core填写。ID只示范角色，不授权复制业务值、绑定、事件或素材。

## `S-center`：唯一核心居中

### 布局描述与限定组件

content使用一个完整DataDisplay；无需额外标题、补充或操作。

```genui
["root","Layout",{"layout":"S-center"},["content"]]
```

## `S-title-content`：标题与单内容

### 布局描述与限定组件

title为SingleLineTitle，content为一个EventCard；需要多组件共同解释同一内容时，content角色可改为Group。
主体左对齐、贴底，不把独立支撑硬塞进单内容。

```genui
["root","Layout",{"layout":"S-title-content"},["title","content"]]
```

## `S-title-dual-content`：主信息与独立支撑

### 布局描述与限定组件

title为SingleLineTitle。standard变体中primary为核心组件，support为同主题独立支撑；主上辅下，无动作。

```genui
["root","Layout",{"layout":"S-title-dual-content"},["title","primary","support"]]
```

同一卡级主题下已成立的双信息块组合使用stacked-info，可表达两个短子对象或两个同级短指标，不要求属于不同对象。
primary/support仅是槽位ID，不表示两块有业务主次；两块同规格，每块保留自己的完整标签、值与必要单位。
Layout.variant选择骨架，InfoBlock.variant选择组件规格，不能混淆；两个InfoBlock无visual。
标题和全部内容仍须满足真实预算；下例仍须补title及真实绑定，不能照抄占位文案。

```genui
["root","Layout",{"layout":"S-title-dual-content","variant":"stacked-info"},["title","primary","support"]]
["primary","InfoBlock",{"variant":"stacked","primaryText":"<第一对象主信息>","secondaryText":"<第一对象补充>","backgroundColor":"#CCFFFFFF"}]
["support","InfoBlock",{"variant":"stacked","primaryText":"<第二对象主信息>","secondaryText":"<第二对象补充>","backgroundColor":"#CCFFFFFF"}]
```

## `S-quad-content`：四个同级模块

### 布局描述与限定组件

以下四个ID分别引用一个ProgressCircle，按左上、右上、左下、右下排列；每个对象有自己的绑定与准确图标。
普通四模块也按同一角色顺序进入槽位，不为宫格补造指标。

```genui
["root","Layout",{"layout":"S-quad-content"},["top_left","top_right","bottom_left","bottom_right"]]
```

## `S-title-content-action`：单内容与一个文字动作

### 布局描述与限定组件

title为SingleLineTitle，content为EventCard，action为带真实onClick的PillButton；事件与操作归属一致。
完整内容也可以是Group，不生成额外动作包装层。

```genui
["root","Layout",{"layout":"S-title-content-action"},["title","content","action"]]
```

标准变体放不下时，可在全部事实及原组件规格不变的前提下选择登记变体。以下direct-dense是完整直属正文
结构，不是修改标准body间距；需要dense/direct/direct-tight/direct-flush时只替换合法variant。

```genui
["root","Layout",{"layout":"S-title-content-action","variant":"direct-dense"},["title","content","action"]]
```

## `S-title-primary-secondary-action`：紧密主辅与一个动作

### 布局描述与限定组件

title为SingleLineTitle，primary为EmphasizedData，support为SecondaryBody，action为PillButton。
主辅由模板连续纵排；不再把它们额外合成一个Group后仍保留两个角色。

```genui
["root","Layout",{"layout":"S-title-primary-secondary-action"},["title","primary","support","action"]]
```

三行正文需要标题间距4vp时使用dense，主辅2vp及正文到动作8vp保持不变。

```genui
["root","Layout",{"layout":"S-title-primary-secondary-action","variant":"dense"},["title","primary","support","action"]]
```

## `S-title-dual-column-action`：双比例与可选共同动作

### 布局描述与限定组件

title为SingleLineTitle，left和right分别为ProgressCircle；无动作时children只有三项。
模型不填写环形宽高，由模板注入；普通双数值不能套用此布局。

```genui
["root","Layout",{"layout":"S-title-dual-column-action"},["title","left","right"]]
```

只有真实操作同时服务两项时，追加一个PillButton；保留两个指标ID，不使用空动作或可选标记占位。

```genui
["root","Layout",{"layout":"S-title-dual-column-action"},["title","left","right","action"]]
```

## `S-title-anchor`：主内容、左下支撑与右下图标操作

### 布局描述与限定组件

title为SingleLineTitle，primary为EmphasisText，support为独立核心支撑，action为CircleButton。
不得用标题或重复的primary充当support；动作图标和真实事件必须准确。

```genui
["root","Layout",{"layout":"S-title-anchor"},["title","primary","support","action"]]
```

左下需要表达三个对象占比时，支撑角色改为NumericRatioStack，填写direction:"column"和恰好三个items；
模板自动选择原56vp底栏，普通支撑仍为40vp。不添加height、width或动作Stack。

```genui
["root","Layout",{"layout":"S-title-anchor"},["title","primary","support","action"]]
```

## `S-content-dual-action`：紧凑内容与两个文字动作

### 布局描述与限定组件

battery_summary为TableText等可完整承载紧凑内容的组件，play和favorite各为一个PillButton。
两个按钮使用各自真实事件；不额外生成SingleLineTitle或第三动作。

无内容的纯双动作使用：

```genui
["root","Layout",{"layout":"S-content-dual-action","variant":"actions-only"},["first_action","second_action"]]
```

该变体只承载 Plan 中恰好两个必要动作；有展示事实时不能使用它省略正文。

```genui
["root","Layout",{"layout":"S-content-dual-action"},["content","first_action","second_action"]]
```

## `S-dual-info`：两个同级信息单元

### 布局描述与限定组件

first和second分别引用一个InfoBlock，各保留所属信息单元完整标签、值及紧密辅助；无公共标题或按钮。
既可用于不同对象，也可用于同主题的两个同级短指标；不能将单一主值及其紧密辅助拆成两块。
可选visual只按InfoBlock合同使用，不新增第三个区域。

```genui
["root","Layout",{"layout":"S-dual-info"},["first","second"]]
```
