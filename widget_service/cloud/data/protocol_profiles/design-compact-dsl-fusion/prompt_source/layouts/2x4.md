## 9.2 2x4 固定骨架（v0.4 W 骨架 · W1→W10）

2x4 每张卡必须且只能选择一个骨架，允许在声明范围内微调，不得跨骨架拼接 region。先判断主次关系：一个明确主焦点加最多两个辅助槽优先使用 W1；没有明确主次时，再按数据块数量选择 W2-W10，2 个等权数据块使用 W9，3 个等权数据块使用 W10，4 个等权数据块使用 W8。通用约束：独立卡级标题只允许用于单数据块骨架，有则必须使用 20vp 高的 CardHeader 作为全尺寸前景 Column 首项，无则不生成标题及空槽；W8/W9/W10 严禁卡级 title、CardHeader、公共标题行及标题空槽，并统一使用 root `padding:8`；W1 及其他普通单业务骨架使用 `padding:12`，W8/W9/W10 多业务蒙版统一宽 138vp；线性进度条一律 `strokeWidth:8`；弹性沉底用包含真实内容的 `layoutWeight:1` 容器占据剩余空间（`flexShrink` 只收缩不拉伸，禁止用于沉底）；禁止 `justifyContent:"spaceBetween"` 制造三段均分（会把中部元素推离预期位置）。

### `W1-focus-aux`（左主焦点 + 右双辅助区域）

- 用于：存在一个明确主焦点，且其余必要字段、状态或动作可以压入右侧两个辅助槽。可承载单业务，也可承载“主业务 + 一个弱辅助业务”；Progress 不是选择条件。
- region：root Row 使用 `padding:12`、`itemMargin:10`，直接包含左侧 `focus_zone 136×126vp` 与右侧 `aux_column 130×126vp`。focus_zone 不加白色内容背板；aux_column 固定上下两个 `130×59vp` 背板、gap 8、白色 60% 底、圆角 12。
- focus_zone 只选一种内部变体：① value-focus：一个 `30fp/38fp` 纯数字和小单位，最多两条辅助信息；② ring-focus：一个有真实比例语义的环形 Progress 和紧邻状态；③ event-focus：最多三项事项，每项标题与时间/地点压成连续信息组；④ status-focus：一条最大 20fp 的突出状态和最多两条辅助信息。不得同时制造两个 hero。
- 左侧纵向节奏：`136×126vp` 不得把所有内容挤在顶部后留下大块无意义空白。value-focus/ring-focus 的三层信息按“顶部 12fp 上下文 + 中部 `layoutWeight:1` 主焦点并垂直居中 + 底部 12fp 支撑信息”组织，并保持左对齐。纯文字 status-focus 只有 2-4 行短文本时，全部放进同一个无 `layoutWeight` 的紧凑 Column，由 focus_zone 使用 `justifyContent:"center"` 让整组垂直居中；三行以上仍左对齐，不把第一行固定在顶部。最终可见内容只有一个主信息组、最多再加一条短辅助信息时，使用稀疏居中变体：focus_zone 与内容组都设置 `alignItems:"center"`、主值 Row 设置 `justifyContent:"center"`，相关 Text 设置 `textAlign:"center"`；数字和单位仍视为同一个主信息组。事项列表、长提醒正文和真正需要多行阅读的摘要继续左对齐。禁止仅因字段原始数量少就居中，必须按最终可见语义组判断；不使用 `spaceBetween` 生硬拉开。
- 左侧 Progress 不能替代主读数。生成线性或环形 Progress 时，必须在同一主焦点组中同时显示对应的可见数值 Text；线性 Progress 与读数上下相邻并整体居中，环形 Progress 将短百分比读数放在环心。若候选只提供含单位的 string 字段、无法可靠得到运行时 number/integer 与 `total`，不生成 Progress，直接把原始格式化值作为主读数显示；禁止只留下标题和一条无读数进度线。
- 事项容量：event-focus 展示三项时，每项只能压成一行短文本（如“09:00 · 需求评审会”）；需要标题加时间/地点两行时最多展示两项。必须展示三项时删除地点等低优先级字段，不得让第三项被画布裁切。
- 右侧每个辅助背板只承载一项指标、一组紧密相关的两行状态摘要或一个动作，最多两行文字、两个动态事实和一个可选 `20×20vp` 图标；左右耳机等天然成对信息允许用两行分别承载左右对象，每行最多两个动态事实。一个普通槽保留两个动态事实时必须分别使用两个 `maxLines:1` Text，每行各自包含完整的“短标签 + 值/状态”，不得把两个标签放第一行、两个值放第二行，也不得用 `|` 合并成一行后依赖 clip；三个以上事实先删除最低优先级项。只有一个有效状态时只保留一行，禁止以静态文案重复动态状态（例如两行都显示“未充电”），未被用户要求的 updatedAt 不用于填满槽位。带图标时固定使用 `Row -> [78vp 文字 Column, 20×20vp Image]`，Row 左右 `padding:12`、`itemMargin:8`、`justifyContent:"start"`、`alignItems:"center"`，文字 Column 垂直居中、`alignItems:"start"` 且只含一至两个 `maxLines:1` Text；Image 必须是最后一个直接子节点，固定在右侧。动作图标同样放在标签右侧，禁止 `Image -> Text`、图标在文字下方或依赖 clip 露出背板。无图标时文字区使用 106vp 宽度，Row 使用 `justifyContent:"start"`，Column 使用 `alignItems:"start"`；所有 Text 固定 `textAlign:"start"`，只允许内容组垂直居中，禁止动作文字水平居中。动作直接绑定整个背板，视觉规格仍为 `130×59vp`，不得在卡片底部另加满宽 CTA，也不得留下空辅助背板。
- 槽位优先级：userQuery 明确要求的动作先占右侧槽，再放 `mustKeep` 辅助事实，最后才考虑 `shouldKeep`。明确要求两个动作时两个槽都作为动作入口；只有一个动作时，另一槽放最相关的一项辅助事实或两行紧密摘要。字段过多时合并或删除低优先级字段，严禁为了多放一项数据增加第三个背板。
- 动作文案：一个动作槽只保留一个简短、完整的命令主标签，例如“查看日程”“蓝牙设置”“打开歌单”。第二行只允许补充真实目标或状态；禁止“蓝牙设置 / 打开设置”“收藏歌单 / 进入歌单”这类同义重复。单行足以说明动作时只保留一行并垂直居中。
- 单业务选择：一个主状态或主读数已经能回答核心问题，并且还有 2 个可归并的辅助组时，优先使用 W1。尤其是“4 项以上事实 + 显式动作”、成对设备状态、天气预警与生活指数、单日程加提醒/导航等场景，不再使用通栏文字流和满宽底部按钮。
- 数据归属：左侧可显示主业务根；右侧每个槽分别引用一个所属对象的数据或事件。不同根不能混进同一槽，动作参数与槽内数据必须同属一个对象。动作占辅助槽但不增加数据块。
- 双业务主次：两个业务的有效字段量相差至少两项、且弱业务只有 1-2 项时，按一个主焦点加弱辅助业务处理，使用 W1 而不是给弱业务分配空旷的 W9 大背板。若弱业务已有两项完整内容且两个业务各有一个明确动作，仍保留 W9，避免丢失业务入口；弱业务只有单项时仍使用 W1。若两个右侧槽都被明确动作占用，可在左侧用最多三行普通字号摘要统一回答同一个用户目标，但不得制造第二个 hero。
- 禁止：左侧白色蒙版、三列并列指标、全宽底部按钮、右侧超过两个背板、因存在多个 `/data` 根自动改成 W9。只有两个业务确实等权且都需要完整内容区时才使用 W9。

### `W2-text-flow`（单列文本流 · 沉底）

- 用于：单日程摘要、公告、说明型内容；纯文本无图形无动作，承载 3 单元。
- region：`kicker 12fp/400` 顶 + `lower Column 103 justifyContent:end`：`event 66`（主内容标题最大 18fp/500 + 正文 12fp/400 两行）+ `date 12fp/400`（贴正文下方沉底）；kicker 与标题之间大留白（上空下实）。
- 槽位：一个标题 + 一段正文（≤2 行）+ 一行元信息。
- 禁止：标题悬空居中、正文三行以上、任何背板与图形。

### `W3-ring-detail`（大环 + 说明列）

- 用于：百分比主指标（电量、完成度）+ 右侧说明，承载 1 环指标 + 3 行说明。
- region：可选 `CardHeader 20vp` + `main Row 103`：`ringArea 134`（`Stack 92`：Progress ring strokeWidth 8 + 环心纯数字 20fp/700，未拆分数值字符串最大 18fp/700）+ `info 134`（说明标题 16fp/400 / 值 14fp/400 / 状态 12fp/400，居中）。环形 Progress 本身视为所属业务主内容第一项，除可选 CardHeader 外不得在环前增加说明或强调文字。有 CardHeader 时与 main 的间距使用 2vp，确保总高不超过 126vp。
- 槽位：一个环主指标；右侧至多三行说明。
- 禁止：环径 <80、右侧第二数据域、环心空置。

### `W4-metric-triple`（三指标等分分割线）

- 用于：三并列同构指标（健康概览等）。
- region：可选 `CardHeader 20vp` + `metrics Row 84`：三列（88/96/88）+ 两条竖 `Divider 1×64` 居中；每列固定为第一行 `value_row`（纯数字 24fp/700 + 同行单位 12fp/400）和下方 `label 12fp/400`，三列对应行严格水平对齐，列内 justifyContent center；字段无法拆分数值与单位时，第一行使用最大 18fp 的完整数值字符串，不生成空单位占位。
- 槽位：恰好三个指标；每列一个数值。
- 禁止：列内行错位（三列 value_row/label 各自同水平线）、第四列、单位换行或放到数字下方。

### `W5-progress-detail`（数值 + 进度 + 双详情）

- 用于：线性进度语义（恢复度、目标完成）+ 双详情背板。
- region：可选 `CardHeader 20vp` + `body 98`：`progressSlot 45`（主数值行 20fp/700 + label 12fp/400 + `Progress linear 276×8 strokeWidth 8`）+ `details Row 45`（两背板 134×2 gap 8、圆角 10、白色 60% 底，各「标题 12fp/400 + 值 12fp/400」）。
- 槽位：一个进度主指标 + 两个详情项。
- 禁止：进度条细于 8vp、三背板、详情行高 >50。

### `W6-agenda-cta`（左侧日程焦点 + 右侧双入口）

- 用于：下一日程/单事件 + 两个真实入口。
- region：复用 W1 的横向几何，root Row `padding:12`、`itemMargin:10`；左侧 `136×126vp` 无背板区域承载日程标题、时间和一条必要上下文，右侧上下两个 `130×59vp` 白色 60% 背板分别承载一个动作并绑定各自 `onClick`。
- 槽位：左侧一个日程对象；右侧恰好两个动作。动作背板使用一个简短的 14fp/500 单行标签；可选语义准确的 20×20vp 图标时，必须使用 `Row -> [78vp 文字 Column, 20×20vp Image]`，图标固定为最后一个直接子节点并位于右侧。动作必须有注册事件。
- 禁止：满宽底部双按钮、单按钮冒充本骨架、三按钮、把事件字段挤进动作背板、标题换行。

### `W7-list-rows`（三行等高列表）

- 用于：近期日程/待办 3 行清单。
- region：可选 `CardHeader 20vp` + `list 102`：三行背板 276×28（gap 8）、圆角 8、白色 60% 底；每行文本 12fp/400，不附加装饰图标。
- 槽位：恰好三行；每行一条文本。
- 禁止：两行或四行、行内按钮、行高不一。

### `W8-quad-cells`（无标题四格）

- 用于：恰好 4 个数据块的同级展示，可来自不同业务或同类业务的不同对象实例；同一对象的多个字段不得拆格。
- region：无卡级标题；root `padding:8`，使用 `284×134vp` 的 `2×2` 网格，两行两列的横纵 itemMargin 均为 8，每个小内容蒙版固定 `138×63vp`、padding 12、borderRadius 16、白色 60% 背景，并完整遵守 8.3 节小内容蒙版的两行数据、右侧图标和数据删减规则。仅在蒙版内有 1-2 项信息且需要比例视觉时允许使用右侧 `40×40vp、strokeWidth:4` 的环形 Progress 与环心 20×20vp 图标；3 项信息时不得保留环图，否则不得为填充版面强加环图。
- action：每个小内容蒙版最多绑定 1 个属于自身数据块的 `onClick`，整块可点击；不生成 Button、action_area、动作文案或空按钮槽。root、grid、行容器及小内容蒙版内部子组件不绑定动作，仅小内容蒙版本身绑定动作，同一事件不得重复绑定。
- 槽位：恰好四个数据块，每格一个数据块；无动作时仍保持相同几何结构。
- 禁止：卡级标题、CardHeader、公共标题行、格内第三行文字、格内按钮、第五个数据块。
- 无 visual 的 `138×63vp` 小内容蒙版必须使用 Column，把一至两个 Text 作为纵向连续信息组垂直居中；禁止用 Row 将两个 Text 横向摊开。只有存在右侧 Image、环或其它合法 visual 时才使用“左文字、右 visual”的 Row。

### `W9-dual-backboards`（双业务左右背板）

- 用于：恰好两个独立业务对象的同级展示；同一对象的多个字段或多个动作不算双业务。满足时必须使用 W9，不得改选其它 2x4 骨架或自由拼接；若每侧的 `mustKeep` 超出容量，先删除 `shouldKeep` 并压缩到每侧最小充分信息，不得放到背板外或合并成公共区域。
- region：无卡级总标题；`root Row` 以 `width/height:matchParent` 填满 `300×150vp` 画布，padding 8、itemMargin 8，直接包含左右两个 `138×134vp` 同级背板。两背板均为 Column、padding 12、borderRadius 16、白色 60% 背板，内部可用空间均为 `114×110vp`。这是 2x4 双业务唯一合法的一级布局，不得套用 2x2 S4 的上下两个 `134×63vp` 结构，也不得改成上下两个全宽背板。
- 每侧按 2x2 的层级组织并独立选择内容变体；需要突出量化主值时按「对象名 + 主读数 + 必要辅助信息 + 可选底部按钮 114×36vp」排列；有必要对象名时先说明对象，再突出主值；没有突出数字时仍可按「业务标题 12fp/400 + 主内容 + 可选底部按钮」排列。有按钮时主内容使用剩余高度，每侧最多三行视觉信息。业务标题只是背板内分区标题，不使用 CardHeader。倒计时与另一个独立业务组成 W9 且倒计时侧无动作时，倒计时背板直接且只能包含三个 Text，依次为目标标题、`30fp/38fp` 纯数字、唯一一个 `12fp` 单位“天”；背板固定 `justifyContent:"spaceBetween"`、`alignItems:"center"`，三个 Text 均全宽居中，禁止嵌套内容 Column 和第四行辅助文字。数字不得再包含“天”，不得压成 `14fp` 的同行 `30天`，也不得引用另一背板的数据补充倒计时内容。
- 每个 W9 背板按 `150×150vp` 的 2x2 内容密度独立检查：内部 `12fp/400` 业务标题和底部 action 不计入信息行；使用 `30fp/38fp` 纯数字主值时，除主值/单位行外最多一条 `12fp/400` 辅助信息；纯文字或格式化主读数最多一条突出信息和两条 `12fp/400` 辅助信息；同级并行数据最多三条普通字号完整信息，不得制造多个突出焦点。普通窄行最多合并两个确实能完整显示的短事实；三个以上动态字段禁止串入同一个 Text。仍有行高时拆成独立 `12fp` 行，空间不足再删除最低优先级字段，不得移动到另一背板或背板外。多日天气的单日摘要可按下条规则合并更多同日字段。
- 稀疏分区：用户最先强调的业务承担全卡第一焦点，其背板内容组使用 `justifyContent:"center"`，主值优先使用安全的 20/24/30fp 档位，核心状态优先使用 18fp；另一背板使用 16/18fp 主信息和 12fp 必要支撑信息，不得镜像复制相同的标题、主值、辅助行模板。某侧最终只保留 1-2 项必要事实且无底部按钮时，有语义精确且状态安全的候选素材可把 `20×20vp` 业务图标放在标题右侧或主内容组右侧，文字组与图标间距固定 8vp；内容已达 3-4 行、图标会挤压必要文字或没有精确候选时保持纯文字，不留空槽。左右通过不同的信息层级形成主次，同时以内容组位置和连续留白保持视觉重量平衡。
- 多日天气在 W9 内每一天只能使用一个 `12fp/400` Text。同一天同时提供完整日期和星期时优先保留短星期并删除完整日期；随后按“星期、天气、温度、降雨”顺序压入，例如 `周四 · 多云 · 25~32℃`，后续字段只有经宽度预算确认完整可见时才追加。禁止将一天拆成三行、缩小字号或依赖裁切，禁止在日期之间插入 Divider。三天天气可使用“业务标题 + 三条天气”的四行内容预算。
- 多日天气行必须按 schema sampleValue 做 `114vp` 压力预算，温度范围必须完整显示，禁止输出只剩 `25°C/` 的残缺范围。`星期/周几 + 天气 + 温度范围` 超宽时优先压成 `周几 + 温度范围`，再超宽则只保留完整温度范围；降雨概率只在整行仍能完整显示时追加。美观和完整值优先于把所有字段硬塞进一行。
- action：每侧至多一个属于该业务的动作入口。默认使用可见 Button 或图文按钮 Row，并只把事件绑定该按钮；当 userQuery 明确说“点击卡片/点击天气区”等整块点击且没有要求可见按钮文案时，允许把唯一事件直接绑定所属背板，视为该侧已保留动作，不再重复生成按钮。root 和非动作内容不得绑定 `onClick`。只有一侧有动作时，另一侧不生成按钮或空槽；不得生成卡级 action_area。先固定左右业务数据块再放 action，禁止为按钮新增数据块或改成 W10；动作参数绑定的数据根必须与所在背板显示的数据根一致，例如引用 `/data/weather/` 的天气动作只能放进天气背板，不能放进倒计时背板。音乐动作不得放进天气背板，未被用户明确要求且无法归属当前业务的动作必须删除。
- 按钮空间：背板内动作固定 `114×36vp` 且标签保持完整单行。信息与动作竞争高度时，先删除最低优先级辅助字段，再缩短业务标题；天气详情动作优先使用“查看天气”而不是“查看天气详情”。禁止压缩按钮高度、把按钮推出背板或让动作标签出现省略号。
- W9 动作文案同样只保留一个完整命令，禁止在按钮或图文动作内追加“点击打开”“进入设置”等重复提示。数值单位本身不能说明业务含义时，必须带短标签，例如“风力 2级”，不得只显示裸露的“2级”。
- 去重：同一个候选动作在整卡只能出现一次。动作参数没有 `/data` 绑定时，按 userQuery 的业务语义选择唯一所属背板；无法明确归属时保留在用户首先强调的业务侧，不得为了左右对称复制到两个背板。
- 动作保留：userQuery 明确要求的匹配动作属于 `mustKeep`。一个动作至少保留一个，明确要求两个动作时分别保留两个；信息过多时先压缩或删除辅助字段，禁止为了多显示一项数据而完全省略“打开歌单”“拨号”等入口。
- title：所有标题必须先归属到左侧或右侧业务；没有突出数字时放入对应背板首项，有突出数字时紧邻该数字，必要对象名优先放在数字上方。地点、对象名或主题描述只要语义属于其中一个业务，就只能作为该业务标题；禁止放在两块背板上方形成卡级 title、CardHeader 或公共标题行。
- 槽位：每侧一个业务标题、一个主内容组、至多一个业务动作；两侧使用同一卡片色板和同层级排版。
- 禁止：上下双业务布局、`root Stack -> content Column -> [zone_1, zone_2]`、两个全宽 `276×59vp` 背板、卡级总标题、主辅不对等分栏、背板外动作、整卡点击、没有明确整块点击意图时绑定背板、左右业务共用按钮、第三业务。

### `W10-triple-backboards`（无标题左大右双小）

- 用于：恰好 3 个数据块；同一对象的多个字段或多个动作不增加数据块数量。用户明确强调的数据块放左侧大内容蒙版；无明确主次时按 userQuery 中的出现顺序选择左侧数据块，其余两个按出现顺序上下排列。
- region：无卡级标题；`root Row` 以 `width/height:"matchParent"` 填满 `300×150vp` 画布，padding 8、itemMargin 8，直接包含左侧 `138×134vp` 大内容蒙版和右侧 `138×134vp` Column。右侧 Column 使用 itemMargin 8，上下各放一个 `138×63vp` 小内容蒙版。三个内容蒙版均使用 padding 12、borderRadius 16、白色 60% 背景。
- 左侧大内容蒙版需要突出量化主值时按「对象名 + 主读数 + 必要辅助信息 + 可选底部 Button 114×36vp」组织；没有突出数字时仍按「业务标签 12fp/400 + 主内容 + 可选底部 Button」组织。有动作时只绑定内部按钮，大内容蒙版本身不绑定，主内容最多两行最小充分信息。右侧两个分区完整遵守 8.3 节小内容蒙版的两行数据、右侧图标和数据删减规则。
- action：左侧每个数据块至多一个可见 Button，事件只绑定按钮；右侧每个小内容蒙版至多绑定一个属于自身数据块的 `onClick`，不生成按钮或动作文案。root、右侧 Column 和非动作子组件不得绑定事件，同一事件不得重复绑定。
- 槽位：左侧一个主数据块，右侧上下各一个数据块；无动作时不保留按钮或点击空槽，几何结构不变。
- 禁止：卡级标题、CardHeader、公共标题行、左右三个等宽栏、右侧小内容蒙版内按钮、整张卡共用动作、第四个数据块。
