# 十、2x4 布局与内容区

2x4只输出Layout、Region、Group和已登记业务组件，不输出Row/Column/Stack或内部展开节点。
Layout是root；Region选择内容子布局；Group组合已有组件。尺寸、边距、间距、权重、对齐和背板由模板确定。
参考画布300×150vp，安全内容区276×126vp；参考预算用于选组件，不写成Props。

## 10.1 父布局总表

| 布局 | 适用信息关系 | 固定区域 / children顺序 | 容量与限制 |
|---|---|---|---|
| W-top-bottom | 一个主题的主体＋同级明细，或同一任务的密集列表 | `[标题?, 主体, 明细]` | 满宽276vp，明细为TextBlock/TopTextBottomValue/SummaryList，无共享按钮 |
| W-split-panels | 两个独立完整分区，或核心结论＋属性详情 | `[左Region, 右Region]` | 每区132×126vp，背板内部116×110vp；分别选择紧凑子布局，每侧最多一个直属PillButton |
| W-content-side-slots | 一个完整内容区＋两个独立紧凑信息或操作模块 | `[内容Region, 上槽, 下槽]` | 内容132×126vp，双槽各132×57vp，两个槽必填，支持整体镜像 |
| W-four-slots | 恰好四个同级、可独立表达的真实模块 | `[左上, 右上, 左下, 右下]` | 每槽132×57vp，无公共标题，不为填槽编造内容 |

父布局由信息关系和容量决定，不按业务名机械路由。先比较内容组与直属操作的归属，再比较操作数量。
两个内容组各有直属操作且紧凑区能完整承载时优先左右双区；共同服务一个场景，不等于必须把两组正文
合入一列并抽出两个公共按钮。两个操作共同服务同一个完整内容组，或是用户明确要求的独立操作时，
可以选择侧双槽；紧凑区容量不成立时仍比较其它合法布局，不强行分区。
同一对象的局部标题、主信息、辅助信息保持在连续区域；
动作位置不改变归属。内容指语义角色，不按字段数计；一个组件内的多items仍是一个内容。
紧密主辅可以用Group，不能把无关业务包装成一个内容。必要对象名称、标签、动态事实和动作不因版式省略。

## 10.2 Layout属性

| 属性 | 用法 |
|---|---|
| layout | 必选，上表四种父布局名称之一 |
| variant | 仅W-top-bottom：continuous（默认）、bottom-details、equal |
| orientation | 仅W-content-side-slots：content-left（默认）、content-right |
| linearGradient / backgroundColor / backgroundImage | 只按Core的配色和背景素材合同选择，不生成额外背景节点 |
| 第四项children | 按上表固定角色顺序填写真实组件ID；引用闭合且每个组件只引用一次 |

Layout/Region/Group不接受width、height、padding、itemMargin、layoutWeight、flexShrink、margin、
alignItems、justifyContent等几何参数，也不绑定数据或Action。业务组件不填写外部几何；继续填写组件合同
要求的内容、绑定、单位、图标、颜色、文字角色等真实Props。

## 10.3 Region子布局总表

Region只填写variant；第四项按下表角色顺序填写。父布局决定紧凑/宽版，不填写尺寸。
左右双区使用紧凑版，侧双槽内容区使用宽版。InfoBlock不进入任何Region，固定槽另行承载。

| variant | 固定角色 / children顺序 | 紧凑版116×110 | 宽版132×126 |
|---|---|---|---|
| center | `[核心内容]`，无标题、动作，双轴居中 | 支持 | 支持 |
| title-content | `[标题, 单内容]`，内容左对齐、贴底 | 支持 | 支持 |
| title-primary-details | `[标题, 主内容, 辅内容]`，上主左上、下辅贴底 | 支持 | 支持 |
| title-content-action | `[标题, 单内容, PillButton]`，内容左上，动作沉底 | 支持 | 支持 |
| title-two-ratios | `[标题, ProgressCircle, ProgressCircle, PillButton?]`，双列同规格居中 | 不支持 | 支持 |
| title-hero-support-action | `[标题, hero, support, PillButton]`，主辅紧密连续，动作沉底 | 不支持 | 支持 |
| four-ratios | `[ProgressCircle, ProgressCircle, ProgressCircle, ProgressCircle]`，无标题/动作，四环同规格居中 | 不支持 | 支持 |
| four-items | `[同级内容, 同级内容, 同级内容, 同级内容]`，无标题/动作，四格同规格居中 | 不支持 | 支持 |

标题使用SingleLineTitle；确需对象加状态/地点的双行标题可用DoubleLineTitle并计入真实占高。
标题关联真实集合数量时可用Group的title-count。局部标题必须有真实语义作用，不重复正文，不为填充版面虚构。
紧凑版主要角色间距6vp，宽版8vp；紧密主辅2vp，按钮36vp。无图标标题占12vp，有图标占20vp。
紧凑标题内容按钮的正文预算为50vp/42vp（无图标/有图标）；宽版对应62vp/54vp。
不能把完整父区高度重复分给正文和按钮。比例槽只放真实有界ProgressCircle，同级同规格、对象明确；
普通状态、绝对量或缺少可靠范围时不选择双环/四环。环、图标与完整标签全部计入槽位，不假设必然放得下。

## 10.4 W-top-bottom：上下双区

### 布局描述

标题可选，主体、明细必选，全部左对齐。省略标题不保留空槽或相邻间距。

| variant | 主体 | 明细 | 对齐 |
|---|---|---|---|
| continuous | 自然高度 | 承接剩余空间 | 主体、明细左上 |
| bottom-details | 承接剩余空间 | 自然高度 | 主体左上，明细稳定沉底 |
| equal | 伸展 | 伸展 | 两个同级且支持伸展的模块等权，各自左上 |

### 限定组件

明细只用TextBlock、TopTextBottomValue、SummaryList，不放InfoBlock或CardButton。
不增加共享按钮；真实只读密集列表可把所属详情事件绑定在列表整体，不串联副作用动作。

### 模板

```genui
["root","Layout",{"layout":"W-top-bottom","variant":"bottom-details"},["title","primary","details"]]
["title","SingleLineTitle",{"title":"<真实标题>"}]
["primary","<主体组件或Group>",{}]
["details","<TextBlock/TopTextBottomValue/SummaryList>",{}]
```

### 注意事项

标题至内容6vp，主体至明细8vp。实际文字、换行和Recipe占高须在剩余高度内闭合。
密集记录保留完整时间标识和属性，使用父区全部可用宽度、完整文本自然换行。取消重复标题和可选视觉后
仍放不下时改选合法组件/布局，不静态化、裁切或删必要信息。

## 10.5 W-split-panels：左右双区

### 布局描述

无公共标题；两区等宽、间距12vp，内容背板和8vp安全边距由模板提供，内部不重复套背板。
每侧使用紧凑Region，同级分区保持相同视觉尺度，不为对称强塞图标或虚构标题。

### 限定组件

每侧最多一个直属PillButton，只绑定按钮，不绑定父背板；InfoBlock不进入内容区。
无公共内容行、共享按钮、背板外动作或第三业务。

### 模板

```genui
["root","Layout",{"layout":"W-split-panels"},["left","right"]]
["left","Region",{"variant":"title-content-action"},["left_title","left_content","left_action"]]
["right","Region",{"variant":"title-content"},["right_title","right_content"]]
```

### 注意事项

单内容可以是一个组件或共同解释同一对象的紧密主辅Group。两个独立内容和按钮不能通过包装伪装为
单内容；确实无法在按钮上方闭合时改选更合适的父布局。

## 10.6 W-content-side-slots：完整内容区＋固定双槽

### 布局描述

一个宽版Region与上、下固定槽，横纵主要间距12vp。orientation只改变整体左右位置，children始终
按“内容、上槽、下槽”填写，不改变对象归属。

### 限定组件

两个固定槽必填，使用InfoBlock/CardButton：信息＋信息、动作＋动作、信息＋动作。
混合时InfoBlock在上，CardButton在下；动作槽整体点击，不嵌套PillButton。内容区直属操作用内部PillButton。
整个布局禁止TextBlock，包括内容区及固定槽；需要横向2–4项同级详情背板时改选上下布局的details。

### 模板

```genui
["root","Layout",{"layout":"W-content-side-slots","orientation":"content-left"},["content","upper","lower"]]
["content","Region",{"variant":"title-primary-details"},["title","primary","support"]]
["upper","InfoBlock",{"variant":"slot","primaryText":"<真实信息>","secondaryText":"<必要说明>"}]
["lower","CardButton",{"label":"<真实操作>","onClick":["<真实事件候选>"]}]
```

### 注意事项

只有一个真实槽模块时换父布局；不复制字段、保留空槽或虚构模块。标题及内容角色仍需按实际组件占高验算。
两个真实操作且只有一个完整内容组时，可让两个CardButton分别占上、下槽，内容Region选择无按钮变体。
不得用内容区已有信息的静态概览凑出InfoBlock，再把本可进入固定槽的操作放到正文；
同一操作只保留一个入口，已有两个真实固定槽模块时不增加重复按钮。

## 10.7 W-four-slots：四槽宫格

### 布局描述

恰好四个真实同级模块，横纵间距12vp，无公共标题；不要为宫格拆散连续阅读的信息。

### 限定组件

每槽一个InfoBlock、CardButton或同槽合法Group。有Action的槽必须是完整CardButton点击边界，Group不能
替代动作槽。混合信息/操作时同类组件放同列、按上到下排列；全部同类时按业务阅读顺序。

### 模板

```genui
["root","Layout",{"layout":"W-four-slots"},["top_left","top_right","bottom_left","bottom_right"]]
```

### 注意事项

不生成空槽、第五模块、格内胶囊按钮或嵌套背板；每格完整文字必须在固定槽内闭合。

## 10.8 输出前检查

- 只选择一个父布局，不跨布局拼槽；子布局支持当前父区，标题、内容和Action角色完整。
- 必要事实与Action保持原绑定、对象标签和语义归属，同一事实只展示一次。
- 完整文字、换行、Recipe占高及模板间距能放下，不裁切、缩字或省略掩盖超预算。
- 超预算改组件组合、密度或语义布局，不输出或修改内部几何节点。
