## 9.2 2x4 固定语义布局

以下是兼容参考预算，不是设备尺寸；宿主变化时保持分区关系、固定边距和组件设计值，区域自行扩展。
参考画布为 `300×150vp`。内容前景层 `padding:12`，安全内容区为 `276×126vp`。一级横向分区预算为
`132 + 12 + 132 = 276vp`；固定槽列为 `57 + 12 + 57 = 126vp`。只有 `W-top-bottom` 可以使用卡级
CardHeader；其它布局的标题必须属于具体内容区。

以下 DSL 只演示一级几何。静态文案、颜色和事件用于标明槽位；实际生成必须替换为 TaskSpec 中的真实
内容与候选，不得照抄示例业务值。

### `W-top-bottom`（上下双区）

- 适用：单个语义组连续展示标题、主体和明细；也用于同一任务的密集记录列表与短上下文。
- 区域：可选 title、可选 primary、必选 details；全部左对齐。
- 间距：title 至首个内容区 `6vp`；primary 至 details `8vp`。
- 流式关系：`continuous` 为连续自然高度；`footer` 为 details 沉底；`equal` 为 primary/details 等分。
- 限制：不使用 `InfoBlock`、`CardButton` 或卡级共享 Button。普通预设无动作；密集列表变体可将真实只读详情 `onClick` 绑定所属列表整体，不跨对象绑定、不串联动作。

密集列表变体先保留每条记录的完整时间标识和属性，使用276vp全宽，一条记录按完整文本预算自然换行。
用户分别要求日期和星期时都保留。短上下文与列表总高不得超过126vp；取消重复标题、可选图标后仍
不够时，不通过删必要字段交付。这个变体不用左右半卡，不强制把每条记录压成116vp单行。

受控内容预设：

| 预设 | 固定结构 |
|---|---|
| `neutral-footer` | 无 CardHeader；主信息左上，单条辅助信息位于下方 |
| `text-footer` | 顶部 kicker；事项内容左上；日期沉底 |
| `value-led` | 可选 CardHeader 20vp + hero 60vp + support 34vp |
| `metric-triple` | 可选 CardHeader 20vp + 三个同构指标列；列宽 88/96/88vp，Divider `1×64vp` |
| `progress-detail` | CardHeader 20vp + 4vp + progressSlot 50vp + 4vp + details 48vp；详情背板 `134×48vp` × 2；线性 Progress `276×8vp` |
| `ring-summary` | 无标题无动作时 root Column 在安全区居中放一个 ProgressCircleSingle；内部为紧凑环与右侧读数组，并非左右双父区 |
| `list-rows` | 可选 CardHeader 20vp + 三行 `276×28vp` 背板，行间距 8vp |

### `W-split-panels`（左右双区）

- 适用：两个需要完整内容区的对象，或同一主题的“核心结论 + 属性详情”。
- 尺寸与闭合：左右父区均为 `132×126vp`，间距 `12vp`；每区 `padding:8`，内部为 `116×110vp`。
- 动作：每侧至多一个所属动作，固定使用可见的 `116×36vp` Button；只绑定按钮，不绑定父背板。
- 特例：两个独立业务各有一个直属动作且均能使用 Sub-118-D 时，即使内容量不等，也保持左右双区。
- 密集正文：先扣除 `36vp` 动作和间距再核算全部文字行高；可取消重复业务标题，将对象名合入首行必要信息。例如 `70vp` 正文 + `4vp` 间距 + `36vp` 动作闭合内部高度，正文可承载三行 `18vp` 或四行 `16vp` 的普通字号短事实，不能把高度不足藏在 `layoutWeight` 中。
- 四行变体：每行 `fontSize:12,height:16,maxLines:1`，正文 `itemMargin:2`，总高 `4×16+3×2=70vp`。四行都为18vp时总高78vp，放不进70vp；从三行增为四行必须同步修改容器与行高。长文字需要换行时重新分配，不靠maxLines或clip假装能装下。
- 五项不等于五行：V17示范同对象两个短事实合为一行，其余三项各一行，仍为70vp。合并必须保留两项绑定及可辨认的标签/单位，并核算完整文字宽度；不能合并两个长状态、删掉第五项，或把五行16vp加间距共88vp塞进70vp正文。
- 限制：无卡级标题、公共内容行、公共按钮、背板外动作或第三业务。

| `title-content` | 局部标题 + `4vp` + 主体；主体左对齐并贴底 |
| `title-dual-content` | 局部标题 + `4vp` + 两个等高内容区；区间 `6vp`，主信息左上、支撑信息左下 |
| `title-content-action` | 局部标题 + `4vp` + 左上正文 + `6vp` + 底部 `116×36vp` 动作 |
| `title-dual-column-action` | 单行局部标题 + `4vp` + 两个 `54vp` 环形指标列，列间距 `8vp`；可选底部动作，前置 `6vp` |
| `content-dual-action` | `26 + 6 + 36 + 6 + 36 = 110vp` |

`title-content` 放置标题和至多三行说明。

完整内容区的底部动作必须有内层弹性承载区。下面是 `title-content-action` 的局部片段（非完整卡）：

父 Row 的等权子区，用 `layoutWeight:1,height:"matchParent"`，与另一侧共同分配剩余空间；
不能删掉 content 后把事实行和按钮直接平铺。片段文案与操作需按真实
TaskSpec 替换，完整输出仍需包含 root、全部引用、数据和真实事件。

### `W-content-side-slots`（内容区 + 固定双槽）

- 适用：一个完整内容区 + 两个真实紧凑信息或动作槽；允许整体镜像。
- 尺寸与闭合：内容区 `132×126vp`；槽列 `132×126vp`，上下槽均为 `132×57vp`，间距 `12vp`。
- 固定槽：语义及容量匹配时信息使用 `InfoBlock`、动作使用 `CardButton`；放不下完整文本时使用同槽位基础组件，保持真实角色和点击边界，不改高阶组件内部样式。
- 固定组合角色为“动作＋动作”“信息＋信息”“信息＋动作”；容量匹配时对应 `CardButton + CardButton`、`InfoBlock + InfoBlock`、`InfoBlock + CardButton`，不匹配时允许同角色的基础实现。
- 基础信息槽两行变体：上下padding为6、左右为12，两行18vp与2vp间距共38vp，不超过内部45vp。不能使用上下padding12后把38vp正文放进33vp；此规则只针对基础Column，不覆盖InfoBlock或CardButton内部Recipe。
- 动作：内容区动作使用内部 `132×36vp` Button；动作槽以整个槽为点击边界。事件只绑定所属按钮或动作槽。
- 单个独立操作：用户明确要求且事件候选精确匹配时，固定槽列先保留“信息＋动作”，不能用第二个信息背板挤掉动作。该动作可服务用户的整体任务，不要求同名数据根；不绑定旁边的信息槽或多对象root，主对象其余事实放回主内容区。
- 限制：两个固定槽必须同时存在，不复制字段、不生成空槽；固定槽不嵌套胶囊按钮。

### `W-four-slots`（四槽宫格）

- 适用：恰好四个同级、可独立表达的真实信息或动作模块。
- 尺寸与闭合：四格均为 `132×57vp`，横纵间距均为 `12vp`。
- 槽位：每格一个完整信息或动作模块；高阶组件不适合时使用同几何基础组件。四格可按业务关系自由混排，不能以四个字段占满格子而漏掉必要动作。
- 动作：`CardButton` 使用整个槽作为点击边界；`InfoBlock` 仅可绑定自身对象的一个真实动作，不能绑定无关操作。
- 对齐：无 visual 的信息槽使用 Column，将一至两个 Text 纵向居中；有 visual 时才使用左文字、右 visual 的 Row。
- 限制：无卡级标题、空槽、第五个模块、格内按钮或嵌套背板。

`shouldKeep`，再改选能承载全部 `mustKeep` 的布局；不得跨骨架拼接区域。
