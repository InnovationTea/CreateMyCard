# 模板显示与作者语法方案

本文承接本轮原位于仓库根目录 `docs/云侧方案设计.md` 的模板专项增量，统一在
`template_generation` 内维护。系统边界、公共接口、A2UI Profile 和校验策略仍遵循
[云侧方案设计](../../../../../docs/云侧方案设计.md)；本文不扩展公共协议支持范围。
详细作者语法和接入方式见 [Provider 模板接入约定](provider-template-contract.md)。

应用使用时长能力下线后，运行目录移除其 6 个模板及专属主题，并同步清理画廊和预览样例。
历史设计可通过 Git 历史查阅，不作为在线候选，也不恢复已删除的数据能力。
模板加载仍严格校验其它模板包的字段定义；不通过吞掉加载异常绕过真实错误。

## 1. 本轮边界

- 保留模板显示调整、双业务单动作布局、业务组件标记、无外层引号的 `Expr` 和编译期 `#elseif`。
- 暂缓运行时 `IF(...)` 整条链路，包括模板语法、Tersel `If`、A2UI-Compact 转换和公共 A2UI 校验支持。
  输入这些运行时组件时应明确拒绝；不静默删除分支、不读取样例值选分支，也不通过局部白名单绕过公共协议。
- 编译期条件和运行时表达式不等于运行时组件：`#if/#elseif/#else/#endif/#end`、`#Expr`、`Expr`
  继续可用，最终只能输出当前 Form Profile 已支持的组件和属性。
- 不扩展目录外的公共协议和服务入口；本轮公共校验改动仅限第 7 节的模板校验豁免，
  并在总方案同步边界。本地 HTTP 调试补丁、凭据、画廊和安装包不属于提交范围。

公共 Compact 转换器沿用基线的宽松解析职责，组件准入仍由最终 A2UI 校验执行；模板内部则在模板解析、
Tersel 解析及 Compact 归档转换阶段拒绝运行时 IF。不为提前拒绝而另外改写目录外的公共入口。

## 2. 标题与业务标记

UX 模板编译不再因正文未包含 CardSpec `title` 而自动补充标题 Text。卡片名称元信息保持不变，
仍用于预览、添加确认和卡片管理；卡内标题由模板或受信布局输入显式定义，不按 Hero 后缀、业务数量或尺寸
启用通用补标题兜底。显式标题、业务内容和动作必须保留。

正式业务模板必须在业务内容根组件的内联属性中显式声明 `_advancedComponent`，沿用业务族标记，
已有细分形态标记保持不变；带动作覆盖层的模板可将标记保留在内部业务内容容器上。
该标记只用于可信编译阶段识别业务区、保护模板内容，不触发通用补标题，输出 A2UI 前必须移除。
布局模板和动作模板不添加该标记。

## 3. 双业务单动作布局

模板路线允许受控的 `2x2` 双业务单动作组合：两个业务必须分别具备完整覆盖显式字段的 `HeroTitle`
与 `HeroContent` 模板，服务端按 `HeroTitle`、`HeroContent`、`PillAction` 的固定顺序组合，根布局为
`HeroTitleContentActionLayout`。第二层模型只能消费确定性 Search 返回的候选，不得交换、重复或嵌套位置。

`HeroContent` 是全局主题所属的主业务。Search 确定两个位置后，按该业务重新过滤主题候选；保留兼容的
已选主题，否则确定性选择该业务的可用主题，沿用版本门禁及融球候选优先规则。第二层使用同一主题契约，
`HeroTitle`、`HeroContent` 和 `PillAction` 统一应用其根样式、主辅内容色和动作色。主业务支持融球且
版本门禁开启时，可信编译器为整卡只包装一次主业务融球背景；不得改用标题业务的融球，也不放开其它多业务布局。

任一位置不能完整覆盖、没有恰好一个已批准动作，或者最终布局需要交换固定位置时，模板路线必须退出，
不得静默删减业务。该变化不授予模型调整目标尺寸的权限，也不改变公共生成入口的失败或回退策略。

天气 `WeatherOverviewHeroTitle@1` 使用高 18、间距 4、左对齐的单层紧凑 Row，以 12vp 辅助色文本依次展示
城市和天气信息；天气信息优先显示“天气现象 | 温度”。温度和现象均为可选绑定，仅有其中一个时只显示该字段，
两者都缺失时不生成后续 Text。
城市依次使用可用的城市、区县绑定、受信 `location` 或“当前城市”。所有分支只判断绑定是否存在，空样例值
仍保留动态引用，不读取样例值选分支；单字段和无字段分支不保留分隔符。配置将四个路径统一列为可选，首层不得强补
温度要求；Search 仍须完整覆盖用户显式字段。该调整不放开单业务天气卡的必需字段门禁，整卡主题仍归 HeroContent。

出行组合补充两个受控形态：无动作的“倒计时 + 后日天气”使用
`CountdownOverviewSupport@1 + WeatherOverviewDaily2TravelSupport@1`；带一个动作的出行请求使用
`CountdownOverviewTravelSupport@1 + WeatherOverviewTravelSupport@1`。天气内容沿用
`WeatherOverviewConditionHero@1` 的天气现象主视觉和无内层底板结构，并在辅助行展示温度及降雨概率；
布局将出行倒计时与天气分别放入两个等高、独立底色和圆角的 Support 胶囊槽，胶囊间距及左右内边距均为
8vp。出行闹钟动作只绑定出行倒计时胶囊，天气详情动作只绑定天气胶囊，不生成底部根动作。逐日字段只登记
`daily[2]` 与 `daily[4]` 的明确用例，不扩展为任意数组索引匹配。上述出行双业务 Support 统一采用
14vp 主标题和 10vp 副标题。

## 4. 编译期条件

Provider `.cardtpl` 的结构按 `#if data.xxx` / `#if props.xxx`、可选的多个 `#elseif`、可选 `#else`
和 `#endif` 在编译期裁剪；`#end` 是 `#endif` 的等价别名，不替代模板结束标记 `#End`。

`#elseif` 沿用 `#if` 的绑定/参数可用性条件，也支持两个直接数据绑定的 `&&`；按声明顺序只选择第一个
条件成立的分支。没有命中时选择 `#else`，没有 `#else` 时不生成该条件块的内容。空的已命中分支仍阻止
后续分支；`#elseif` 不得出现在 `#else` 之后，各分支必须通过引用边界校验。

`#if` / `#elseif` 支持 `!data.xxx` 和 `!props.xxx`，以同一可用性判定取反；
`false`、`0`、空字符串参数仍视为已提供，不属于否定分支。否定分支不能直接引用缺失字段，
对应 `#else` 可以引用。数据与参数的混合条件使用嵌套指令，不支持单个 `&`；具体语法见模板契约。

条件块支持嵌套，只判断 binding 或参数是否可用，不读取数据值。属性值通过
`#Expr(condition ? present : absent)` 按 binding 或参数是否可用确定性选择。
两类指令都必须在 CardPlan/Tersel 之前消除，不进入最终 A2UI，不输出 `If` 组件。

## 5. 运行时表达式

`Expr(...)` 表示已有 A2UI 运行时表达式，不需要外层引号。它直接引用已声明的 `data.xxx`，支持算术、
比较、逻辑、三元条件和 `size()`；字符串可用单引号或双引号，表达式内部的反引号字符串支持数据插值。
以下写法都表示空值判断后的时间拼接：

```javascript
Expr(data.start == "" ? "" : `${data.start} - ${data.end}`)
Expr(data.start == "" ? "" : data.start + " - " + data.end)
```

整个参数仍用反引号包裹的旧 ``Expr(`...`)`` 保持兼容；普通反引号文本插值和 `#Expr` 编译期选择不变。
只在模板可信编译阶段解析，不执行任意代码；未知绑定、`props`、未允许函数及非法语法均拒绝。
最终统一到已有 A2UI 表达式协议及长度、深度、数据路径限制，双引号字符串转换为协议要求的单引号。

模板解析阶段只保留绑定符号，生成 A2UI 时才映射到实际数据 path；不得读取 `sampleValue`，不在云侧计算
条件或拼接结果。数据读取和表达式求值均由端侧运行时完成，样例值为空或为零不改变生成的表达式。

## 6. 验收要求

- 标题：覆盖单业务、双业务及不同尺寸，不自动把卡片名称插入正文，保留显式标题、业务内容和动作。
- 业务标记：扫描全量正式业务模板，标记完整且与业务族一致；布局和动作模板不误标，最终 A2UI 不残留标记。
- `Expr`：覆盖直接绑定、单双引号、嵌套三元及括号、分支内反引号插值，与旧语法输出等价；普通插值及
  `#Expr` 不变。非法调用、越界引用、未闭合语法和超限表达式必须拒绝。
- `#elseif`：覆盖首个匹配、无匹配、空分支、嵌套、参数可用性、双数据条件、分支引用边界，以及
  `#endif` / `#end` 两种结束方式；非法顺序或未闭合指令必须报错，字符串中的指令文本不能被改写。
- 双业务画廊：除单业务外，必须覆盖 `HeroTitle + HeroContent + PillAction`；从正式模板派生两个独立
  数据能力的输入，经公开生成入口、Search 和第二层布局模型生成，验证固定子节点顺序、两个业务的数据引用
  和一个动作。低版本使用主业务普通主题；达到门槛且主业务支持融球时使用主业务融球主题，验证整卡主题色和
  唯一的融球背景。主业务不支持融球时不得借用标题业务背景，结果经验证后同步至端侧画廊。
- 暂缓边界：模板 `IF`、Tersel `If`、A2UI-Compact `If` 和公共 A2UI `If` 均应拒绝；有效的 `Expr` 与
  编译期条件仍可穿过模板和公共处理链，不通过读取样例值模拟组件分支。

### 运行时 IF 的后续需求（本轮不实现）

后续如重新开启，需另行评审从模板到公共转换、校验和端侧的完整支持，不能只放开模板语法。
待评审事项包括：已声明绑定或 `Expr` 条件、可省略的假分支、嵌套组件子树、两侧数据和事件边界、
`condition/childrenIf/childrenElse` 引用、虚拟节点禁止样式和事件、禁止替代 root shell、互斥分支取最大高度、
不跨分支去重，以及真假值和求值失败时的端侧行为。原有运行时 IF 说明仅作为后续需求追溯，不是当前能力承诺。

## 7. 模板内容根与对比度边界

公共 A2UI 校验根保持 `root`，非融球 `2x2` 固定布局模板为
`root → template_root → __genui_render_component__root_1`，防溢出前缀直接标记原布局骨架，
不再增加专用防溢出 Stack。单业务、双业务及各主题使用同一规则；根背景保持不变，安全边距从根节点
移到 `template_root`，骨架属性和内容不变。独立模板预览仍为 `root → template_root`；
不含单一布局骨架的旧 CardPlan shell 和非 `2x2` 产物保持原结构。融球模板仍为
`root → template_root → __genui_render_component__template_root → root_1`，
融球背景仍是 `root` 的并列子节点。保留当前融球容器的 `matchParent` 尺寸。

公共调度器确认根 `root` 的 `children` 数组直接引用实际存在且 ID 精确等于 `template_root` 的组件，
且组件 ID 无重复后，跳过整卡
`quality` 阶段，包括并列的背景、标题和动作。不按文本或前缀匹配；每次修复后重新识别标记。
不依赖 `fusionBallBackground`，非融球、融球及独立模板预览使用相同规则。
缺少模板标记、孤立标记、非直接子节点、重复 ID、普通生成及模板回退产物不自动豁免。
标记是工程约定，不是不可伪造的来源凭证；解析失败与组件引用合法性仍按原规则检查。
跳过记录 `quality_validation_skipped reason=template_root`，不视为实际质量通过或伪造分数，
也不因被跳过的检查触发质量修复。
转换前 `_collect_hero_value_errors` 也按上述有效模板标记直接返回，跳过主文字的大字号语义、
格式化主读数条件及相邻单位限制；不为模板改写普通生成的绑定、宽度或单位说明识别规则。
同一有效模板根标记还用于跳过 `semantic` 阶段的 `DISPLAY_UNIT_MISSING`，允许数值与可见单位
分属不同的固定布局容器。融球、非融球和独立模板预览均适用；普通卡片和无效标记仍检查单位缺失。
`DISPLAY_UNIT_DUPLICATED`、其它 semantic、hard、其余转换前校验及高度预算保持不变，
也不恢复运行时 IF 支持。
模板字号按评审结果保留；原有 38fp 主值统一改为 30fp、高度 40vp。
运动健康模板的 30fp 文本使用自然高度，不声明固定 height，以保持与相邻单位或说明的对齐。
独立调用对比度校验器使用同一模板根判断，符合条件整卡跳过，否则所有内容正常检查。
`has_fusion_template_root()` 保留既有方法名以兼容调用，但不再检查融球背景。

回归覆盖普通模板、融球模板、预览模板、精确标识、非模板并列节点及其它校验继续生效。

## 成对 Compact 的可选状态扩展

EarbudPairCompact 保持名称、左右耳电量为必需数据；仓电量和连接状态为可选数据。
仓电量存在时在左右电量右侧追加同样的图标与百分比；连接状态存在时放在名称右侧，间距 4vp。
缺失时省略对应节点，未连接和零电量仍正常展示。保留双按钮布局和 PR338 的非必需连接状态校验。

## 成对 Compact 的电量间距

成对 Compact 两项电量组间距为 12vp，存在盒电量时为 8vp；0% 同样视为存在。

## 耳机模糊意图的模板可行性优先

耳机第一层对模糊部位和状态含义，结合当前启用模板、输入字段及合法动作比较完整方案，
优先选能完整生成的合理解释，再按额外模板依赖较少、辅助字段较少和模板 ID 顺序消除并列。
明确部位、状态、动作和禁止项不得为命中而删除或替换；无动作候选不能凭空补按钮。
本轮仅调整耳机提示词，不改变其它业务、模板定义、检索或布局规划代码。

### 充电状态 Hero 的纵向预算

Q077、Q080 使用的 BatteryOverviewChargingProgressHero 在150vp卡片、上下各12vp内边距、36vp按钮及8vp区域间距下，业务区可用82vp。存在充电状态时，去掉数字行顶部6vp额外留白，使标题16vp、数字40vp、状态16vp及两个4vp间距合计80vp，避免状态行被父容器裁切。缺少状态时保留原6vp留白；不改变字号、按钮或主题。

### 单手机电量的 query 字段筛选与模板参考

2x2 单手机电量首层提示词注入当前启用、尺寸匹配的全部电量模板展示字段、必需输入、可选输入及缺失输入。只以 userQuery 确定必须展示的字段；其余输入保留为候选，不进入 requiredOutputFieldsByCapability，不新增协议字段。模糊概览优先采用能覆盖真实意图且输入齐全的模板解释，不能删除明确要求。模板可附带输入中存在的额外字段，不以未要求的候选字段拒绝模板。第一层不输出模板ID，最终选择与动作兜底仍由现有 Search/Planner 执行。明确禁止动作仍禁止补按钮。此规则不影响耳机和混合业务。

### 电量模板候选字段优先级

### 电量 Full 与 Hero 平等比较

没有显式动作时，有合法候选设置动作且用户未禁止交互，则同时构建无动作 Full 和 Hero+候选动作方案，按候选字段覆盖数量统一排序；无合法候选动作或禁止交互时只保留无动作 Full。不得先以存在 Full 为由淘汰 Hero。为保持二层动作契约一致，排序后仅向二层传递与首选方案动作集合相同的方案；显式动作不删除，其它业务不变。路由投影保留原候选事件 ID，不把 Planner 的同名动作区分标识（如 #1、#2）作为原始事件 ID；无动作 Full 获胜时才清空选中动作。
