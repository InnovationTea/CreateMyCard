| 分类 | 含义 | 典型处理 |
| --- | --- | --- |

完整校验顺序为：

```text
输入归一化/解析
  -> DSL 协议与 JSONL 顺序
  -> 组件字段、树和样式
  -> 表达式、绑定、事件、素材
  -> CardSpec 字段与 dataBindings
  -> DSL/CardSpec 跨文件一致性
  -> 能力有效性、布局、对比度、展示单位和美观基线
Compact DSL 则在 A2UI 转换前额外校验 TaskSpec 边界、首帧数据和高度预算。
```

未提供 CardSpec 时，DSL-only 入口允许继续进行 DSL 校验；CardSpec 专属错误不会出现在纯 DSL 报告中。

### 模板质量阶段豁免

模板生成入口显式设置 `skip_compact_dsl_validation=True`，跳过 Compact 专项校验；公共转换和
标准 A2UI artifact 校验继续执行。进入模型回退/修复后复位为 False。解析、修复和转换统一传递该标记以识别模板组件权限，无需额外解析上下文。
日程数量的时间范围与集合语义硬校验暂时停用；数据路径、类型、必要事实覆盖和布局校验仍按原流程执行。

模板编译器注入组件 ID `template_root`。公共调度器要求根 ID 为 `root`、根 `children` 数组直接
引用存在的 `template_root`，且组件 ID 无重复，即跳过整卡 `quality` 阶段并记录跳过原因。
不再要求融球背景；只有融球背景而没有模板标记时仍执行质量阶段。
不以文本、前缀或防溢出 ID 判定来源；标记不是可信来源凭证。每次调用重新识别，修复后标记消失
即恢复质量校验。Compact 的模板生成路径由编排层传入 `skip_compact_dsl_validation` 跳过校验；
普通输入仅声明 `template_root` 不能跳过本轮恢复的规则。历史主文字辅助函数保留直接调用，
不参与当前公开 Compact 入口；完整产物质量阶段的标记语义与 Compact 来源跳过分别处理。
完整产物的 `hard`、`semantic` 和解析不因质量阶段豁免而跳过，包括名称含“美观”的硬性基线；
普通生成的 Compact 绑定和整卡高度预算继续执行。独立调用对比度校验器与公共调度共用模板根整卡豁免判断。
详细规则维护在 [模板专项方案](../template_generation/docs/template-generation-design.md)。

## 2. 输入外壳与解析字段

### 2.1 `validate_card` / `validate_dsl` 输入

素材地址交付映射：模型输入与 Compact 校验保留原始素材路径，标准 A2UI 转换后才对
`Image.src` 和静态 `styles.backgroundImage` 执行 `asset_src_url_mapping` 精确替换。
`ValidationOptions.asset_src_url_mapping` 显式传入当前请求的映射；有效素材白名单同时包含
原路径及其映射地址，未入选素材的映射不放行。交付映射的允许集合为当前
`taskSpec.assetCandidates` 与系统内部素材的并集；CardButton 缺省业务图标时注入的
`resources/base/media/ic_fallback_light.svg` 不回填为模型候选，但会按同一映射配置替换为交付 URL。
URL 仍受既有域名规则限制。
动态表达式/绑定不替换，原始 DataModel 不因映射而修改。

| 字段 | 必填性 | 约束 |
| --- | --- | --- |
| `dsl` / DSL 文本参数 | 必填（对应入口） | 必须能解析为 JSONL；默认要求三行，顺序为 `createSurface`、`updateComponents`、`updateDataModel`。每行必须是 JSON object。 |
| `cardspec` | `validate_card` 中可选；纯 DSL 入口可缺省 | 字符串时必须是单个 JSON object；对象直接使用。缺失时跳过 CardSpec 专属校验。 |
| `artifact` | 可选 | 可为外层 artifact object；若存在 `artifact` 子对象且外层没有 `genui`，先解包子对象。`genui` 和 `cardSpec` 会分别作为 DSL/CardSpec 输入。 |
| `effectiveCapabilities` | 可选 | 若提供，必须是可遍历的能力对象/数组结构；用于有效能力校验，不得借此伪造未注册能力。 |

DSL 文本可包含 fenced code block；归一化后只接受 JSONL。CardSpec 文本不能混入多个 JSON 对象、Markdown 说明或 DSL 行。

## 3. GenUI DSL（A2UI Form JSONL）

### 3.1 顶层消息

每行除 `version` 外只能有一个 payload 字段；三行必须按固定顺序输出。

| 行 | 必填字段 | 可选但有约束 | 禁止值/组合 |
| --- | --- | --- | --- |
| 第 1 行 `createSurface` | `surfaceId`、`catalogId` | `styles` 可选，且只允许 `borderRadius`、`clip`；`width`/`height` 可写但仅产生冗余 warning，建议删除 | `version` 不是 `v0.9`；`catalogId` 不是 `ohos.a2ui.extended.catalog.form`；在 `createSurface.styles` 放 `backgroundColor`、`linearGradient`、`backgroundImage` 等背景字段 |
| 第 2 行 `updateComponents` | `surfaceId`、`root`、`components` | `components` 必须为数组；`root` 必须引用数组中存在的组件 id | `components` 不是数组或为空；root 不存在；消息中混入其它 payload |
| 第 3 行 `updateDataModel` | `surfaceId`、`path`、`value` | `path` 通常为 `/`；`value` 必须为非空值 | `path` 使用表达式、PathBinding 或非 JSON Pointer；`value` 为空 |

三行的 `surfaceId` 必须完全一致。结构字段 `surfaceId`、`catalogId`、`root`、`path` 不允许表达式。

### 3.2 组件通用字段

所有组件均必须包含：

| 字段 | 要求 |
| --- | --- |
| `id` | 非空字符串；在 `components[]` 中唯一。 |
| `component` | 非空字符串；只能使用允许组件：`Text`、`Image`、`Divider`、`Progress`、`Button`、`Checkbox`、`Row`、`Column`、`List`、`Stack`。 |

可选通用字段：`styles`、`onClick`、`accessibility`。出现 `styles` 时必须为 object。组件顶层不得出现协议未声明字段。

全局禁止组件字段：`theme`、`onAppear`、`onChange`、`onSelect`、`onReachStart`、`onReachEnd`。

`Button` 额外禁止顶层字段 `action`（在线 genui Form DSL 的点击行为必须使用 `onClick`；Compact DSL 的 `Button.action` 仅作为转换前兼容输入，见第 4 节）。

禁止组件类型：`TextInput`、`Toggle`、`Radio`、`CheckboxGroup`、`Select`、`NavContainer`、`Tabs`、`TabContent`、`Web`、`Grid`、`If`。

### 3.3 各组件必填字段

| 组件 | 必填字段 | 可选字段/要求 |
| --- | --- | --- |
| `Text` | `content`，非空 | 文本内容可为静态字符串或合法表达式；不得在结构字段中使用表达式。 |
| `Image` | `src`，非空 | `styles.width`、`styles.height`、`styles.objectFit` 均必须明确；素材必须通过白名单/有效能力校验。 |
| `Divider` | 无额外必填 | 仅使用协议声明的 styles。 |
| `Progress` | `value` | `value` 应为数字或合法绑定；Compact DSL 中 `total` 也要求存在且为数字/绑定，静态值需满足范围规则。 |
| `Button` | `label`，非空 | `enabled` 可选但若出现必须为布尔值或绑定；点击使用单个 `onClick` handler。 |
| `Checkbox` | 无额外必填 | `label`、`value`、`select` 可选；`select` 必须为布尔值或绑定。 |
| `Row` | `children` | `children` 为组件 id 数组，或受控模板对象；`itemMargin` 可选。 |
| `Column` | `children` | 同 `Row`；`itemMargin` 可选。 |
| `List` | `children` | `children` 为组件 id 数组或模板对象；`space` 可选。 |
| `Stack` | `children` | `children` 为组件 id 数组或模板对象。 |

`children` 数组只能包含已声明组件 id；引用不存在的 id 会报错。容器必须有实际子节点，不能用空容器充当 spacer。

模板 `children` 对象只允许以下字段：

```json
{
  "componentId": "item",
  "path": "/data/items",
  "itemVar": "item",
  "indexVar": "index"
}
```

其中 `componentId`、`path` 必填，`itemVar`、`indexVar` 可选；变量名必须是非空字符串且不能以 `$` 开头；`path` 必须是结构 JSON Pointer 并指向数组。

### 3.4 样式字段与枚举

样式只能放入 `styles`，且必须属于公共样式或当前组件样式白名单。

| 组件/范围 | 允许字段 |
| --- | --- |
| 公共 | `width`、`height`、`aspectRatio`、`constraintSize`、`margin`、`padding`、`borderRadius`、`borderWidth`、`borderColor`、`backgroundColor`、`backgroundImage`、`backgroundImageSizeWithStyle`、`linearGradient`、`layoutWeight`、`flexShrink`、`shadow`、`visibility`、`clip` |
| `Text` | `fontSize`、`fontWeight`、`fontColor`、`maxLines`、`minFontSize`、`maxFontSize`、`textAlign`、`textOverflow` |
| `Image` | `objectFit`、`aspectRatio`、`fillColor` |
| `Divider` | `strokeWidth`、`vertical`、`color` |
| `Progress` | `type`、`color`、`strokeWidth` |
| `Button` | `fontSize`、`fontWeight`、`fontColor`、`backgroundColor`、`borderRadius` |
| `Checkbox` | `selectedColor`、`shape` |
| `Row`/`Column` | `justifyContent`、`alignItems` |
| `List` | `listDirection`、`scrollBar` |
| `Stack` | `alignContent` |

主要枚举（`config/style.json` 的 `enumValues`，由 `ComponentValidator` 在最终产物
`styles` 上硬校验，错误码 `STYLE_ENUM_INVALID`；表达式取值跳过）：

- `justifyContent`: `start`、`center`、`end`、`spaceAround`、`spaceBetween`、`spaceEvenly`。
- `Row.alignItems`: `top`、`center`、`bottom`；`Column.alignItems`: `start`、`center`、`end`。
- `textAlign`: `start`、`center`、`end`、`justify`；`textOverflow`: `clip`、`ellipsis`、`marquee`、`none`。
- `objectFit`: `fill`、`contain`、`cover`、`auto`、`none`、`scaleDown` 及协议声明的位置枚举。
- `Progress.type`: `linear`、`ring`、`eclipse`、`scaleRing`、`capsule`。
- `Checkbox.shape`: `circle`、`rounded_square`；`listDirection`: `vertical`、`horizontal`；`scrollBar`: `off`、`auto`、`on`。

兼容白名单（模板链路存量产物按这些取值直出，校验放行，但新产出仍应优先协议枚举）：
`Row.alignItems` 另允许 `start`、`end`；`textAlign` 另允许 `left`、`right`。
枚举按组件类型区分：`Type.field` 键只约束对应组件，裸 `field` 键约束所有组件的同名样式。

布局和视觉约束：

- 字号只使用 `10/12/14/16/18/20/32/40`；间距只使用 `0/2/4/6/8/10/12/14/16`。
- 数值字段使用 JSON number，不要把数字写成数字字符串；间距、padding、margin 不能为负数。
- root 组件的 `styles.width`、`styles.height` 必须为 `matchParent`（若声明）；root `borderRadius` 为 `18`、`clip` 为 `true`，具体尺寸由内部布局预算承担。
- Row/Column/List 的子节点高度、margin、gap 与 padding 之和不得超过可用高度；不能依赖 clipping、flex shrink 或分布式对齐掩盖溢出。
- `Image` 必须设置明确宽、高和 `objectFit`。

### 3.5 表达式、绑定与事件

表达式必须是完整字符串包装 `{{ ... }}`，最多一个 wrapper，并包含合法 `${/absolute/json/pointer}` 引用；长度不超过 2048，括号深度不超过 20。

禁止表达式变量/运算符/关键字：`$__widthBreakpoint`、`$__colorMode`、`$context`、`===`、`!==`、`??`、`?.`、`and`、`or`、`not`。函数调用只允许已注册函数（当前配置为 `size`）。

禁止在 CardSpec、结构字段（如 `surfaceId`、`catalogId`、`root`、`path`）以及事件 `condition`、`as` 中写表达式。事件上下文 `$context` 也禁止出现。

`onClick` 必须为最多一个 handler 的数组；每个 handler 为 object，使用 `call` 与 `args`，不得出现 `condition`、`as` 等额外字段。`call` 必须来自已声明事件能力，`args` 必须符合事件参数 schema；`clickToIntent` 的 `intentName` 和 `params` 必须符合目标 intent 声明。

### 3.6 素材字段

`Image.src` 和 `styles.backgroundImage` 只能引用素材白名单、有效素材能力或批准的远程主机。禁止：

- 任意 `http://`、`https://`（仅配置的远程主机例外）；
- `data:image/`、base64、内联 SVG data URI；
- 未声明资源路径、emoji 和纯装饰堆叠。

## 4. Compact DSL

Compact DSL 是转换前的受控输入，不等同于最终 genui。每行解析为组件 tuple 或数据 tuple：

```text
[componentId, componentType, props, optionalChildren]
[absoluteJsonPointer, value]
```

### 4.1 组件行

Fusion Compact 输入只区分两类：基础布局组件 `Row`、`Column`、`Stack`，以及当前登记的其它组件。
`Button` 仅允许由 `PillButton` 等动作组件在转换阶段生成；Compact 输入不得直接提交 `Button`、`List`、
`Checkbox` 或旧版动作组件。`root` 必须是第一行组件，类型只能为 `Column` 或 `Stack`，并且
`props.width` 必须为 `matchParent`。产物至少要有一个非容器可见组件。

通用要求：

- `props` 必须是 object；组件行不得使用 `Text`/`Image` 等 wrapper 字段包装 props。
- `children` 只能放在 tuple 第四项；`Row`、`Column`、`Stack` 的 children 必须非空；其它组件不得声明 children。
- `Text.content`、`Image.src` 以及其它组件的字符串数据属性必须是字符串或 PathBinding object（`{"path":"/…"}`）。
- Compact 输入不直接接受标准 A2UI `Progress`。环形占比使用 `ProgressCircle.externalText`，线性进度使用
  `ProgressLine2`，带右侧说明的单环使用 `ProgressCircleSingle`；转换后生成的标准 A2UI `Progress`
  仍按第 3 节校验。
- 进度组件的动态比例输入只能绑定有效 number/integer 字段，不接受百分比字符串字段。
  展示字段可在能力输出定义中通过 `numericSource` 登记数值兄弟字段名，预检补齐该字段，
  模型输入投影为绝对路径；进度驱动与读数按此关系配对。静态完整百分比字面量仍按合同转换。
  不再生成 `/__display` 首帧副本，既有私有进度绑定也不得通过数值类型校验。
- `ProgressCircle.externalText` 可额外使用完整 Expression。表达式直接返回 `0–100` 数值，或以
  `+ '%'`、`+ '％'` 结尾供转换器拆分数值驱动与环外读数；`ProgressLine2.value` 和
  `ProgressCircleSingle.value` 仍不接受 Expression。
- `width`、`height`、`padding`、`fontSize` 等数字不能写成数字字符串；padding 必须是非负数字或数值 side object。
- `Image.filter` 禁止使用；应改为对比度足够的背景。
- 模型可生成的 Compact DSL 不接受 `Image`，`SingleLineTitle` 也不接受 `icon` 或 `fillColor`。素材只能通过当前组件合同登记的语义化图标属性进入；动作组件的 `icon` 由转换器按 `actionInk` 自动着色。

### 4.2 Compact DSL 动作组件

动作必须使用 `PillButton`、`CircleButton` 或 `CardButton`。三者均必须有 `onClick`，handler 必须恰好一个并且与 `TaskSpec.eventCandidates` 中的候选完全一致；尺寸和槽位由对应组件合同约束。基础 `Button` 与旧版动作组件不再作为 Compact 输入兼容语法。

### 4.3 Compact DSL 表达式和数据行

- 动态表达式必须完整占据字符串，格式为 `"{{ ${/path} }}"`，且每个引用必须是绝对 JSON Pointer。
- PathBinding 只能是 `{"path":"/absolute/path"}`；不能使用相对路径、表达式或空路径。
- 每个绑定路径必须有对应数据行；数据行路径必须被 `TaskSpec.dataModelSchema` 声明，值类型必须匹配 schema。
- `TaskSpec.dataModelSchema` 缺失或非 object 时，Compact DSL 校验失败。
- 未被任何组件引用的数据能力仅产生 warning；不会因此把合法 DSL 判为错误。

### 4.4 Compact DSL/CardSpec 高度预算

当 root 使用 `CardSpec.suggestSize` 或 `TaskSpec.size` 时，`2x2`、`2x4`、`4x2` 的参考画布高度均按 150vp 计算。Column 会扣除 padding 后检查子节点高度、margin 和 gap；超出预算直接失败。不得依赖裁剪、flex shrink 或分布式对齐隐藏溢出。

2026-10-15：2x4 语义布局生成且有来源映射的 Column，固定 `itemMargin:8` 暂不计入高度门禁；
只在校验副本中置零，同时用于参考槽位分配与递归最小高度。组件内部间距、原始 Row/Column、
2x2、padding、margin 与固定组件高度仍计入。分类为语义／布局与视觉约束，规则落在
`compact_validation/semantic/layout/geometry.py`，不修改渲染或源产物，不保证浏览器无重叠。

### 4.5 Compact DSL 横向固定内容预算（2026-10-14）

Issue #538：展开并规范化后的 Row 按参考分区内宽检查不可收缩的固定子项与后代内容，
计入 padding、margin、itemMargin／space；Column／Stack 后代横向需求取最大值。

## 5. CardSpec

### 5.1 顶层字段

CardSpec 只描述宿主标题、概述、推荐尺寸、素材域白名单和数据能力契约，不描述 DSL 组件或点击行为。

| 字段 | 必填性 | 约束 |
| --- | --- | --- |
| `title` | 必填 | 非空静态字符串；不得是表达式、PathBinding 或 `/data/...` 路径；建议不超过 8 个字符。 |
| `description` | 必填 | 非空静态字符串；同上；建议不超过 12 个字符。 |
| `suggestSize` | 必填 | 只能为已配置尺寸，当前为 `2x2` 或 `2x4`。 |
| `imageDomainWhitelist` | 可选 | 仅用于声明允许的素材域；必须与服务配置及实际素材校验一致。 |
| `dataBindings` | 可选 | 缺省表示无动态数据；出现时必须是非空数组。 |

禁止顶层字段：组件、`onClick`、`events`、`click`、`actions` 及任何其它未在协议白名单中的字段。

### 5.2 `dataBindings[]`

每项必须是 object，并包含：

| 字段 | 要求 |
| --- | --- |
| `capabilityId` | 非空，且必须能在当前能力注册表/有效能力集合中解析。 |
| `arguments` | 必填 object；字段和值必须符合能力 input schema。 |
| `writeResultTo` | 必填 JSON Pointer，且必须以 `/data/` 开头。不同 binding 的路径不得相同、互为父子或重叠覆盖。 |

`dataBindings` 不能写点击行为、组件属性或未声明的能力字段。跨文件校验还要求 `writeResultTo` 根路径在 DSL `updateDataModel` 中初始化，并且引用路径能由能力 `outputSchema` 推导。

## 6. TaskSpec（Compact DSL 校验消费字段）

TaskSpec 由生成服务构造，Compact DSL 校验只消费以下字段：

| 字段 | 必填性 | 约束 |
| --- | --- | --- |
| `size` | 可选 | 未从 CardSpec 取得尺寸时用于高度预算；使用已支持尺寸字符串。 |
| `dataModelSchema` | Compact DSL 校验必填 | 必须是 object；所有数据行和绑定路径都必须在其中声明，值类型必须匹配。 |
| `eventCandidates` | 有事件时必填 | 必须为数组；每个候选需能解析为 `{call, args}`，Compact DSL 的 handler 必须与候选精确匹配。候选也可通过 `action` 子对象承载。 |
| `assetCandidates` | 有素材时必填 | 必须为数组；Compact DSL 只能使用候选中的原始 `src`。`description` 用于判断 SVG 是否必须显式提供 `fillColor`；描述缺失时按可染色 SVG 处理。 |

TaskSpec 不得被 Compact DSL 反向扩展；校验器不会接受未声明的能力、事件或数据路径。

## 7. 禁止生成清单（跨输入类型）

以下内容无论来自模型、修复器还是手工输入，均不得进入最终产物：

- 未注册组件、禁止组件和未声明组件顶层字段；
- `theme`、`onAppear`、`onChange`、`onSelect`、`onReachStart`、`onReachEnd`；
- Form 不支持的多事件 handler、`condition`、`as`、`$context` 和未声明 call/args；
- CardSpec 中的点击行为、组件结构或表达式；
- 网络图片、内联/base64 SVG、未声明素材路径、emoji；
- 结构字段表达式、嵌套/超限表达式、未注册函数调用；
- 空容器、空必填字符串、数字字符串、负间距/尺寸、超出布局预算的结构；
- 能力注册表或 TaskSpec schema 未声明的数据路径、事件、intent 和参数；
- 互相覆盖的 `writeResultTo`，以及未在 DSL 首帧初始化的 CardSpec 数据根。
