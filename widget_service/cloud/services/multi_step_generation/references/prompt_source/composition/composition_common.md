# 卡片生成编排

信息结构决定需要表达的内容，组件决定表达粒度，布局决定可用区域和槽位。三者共同收敛，直到信息、Action 与空间同时匹配。

## 1. 保持项与可调整项

| 类型 | 内容 |
|---|---|
| 保持 | 用户目标、必须保留的事实、信息主次、必要语义配对、Action 作用范围和全部必要 Action |
| 可调整 | 不破坏语义关系的分区边界、具体组件、组件组合、静态标签、`Card.layout`、`Region.variant` 和槽位分配 |

空间不足时调整可调整项，不通过削弱保持项使当前结构成立。调整分区边界时，只能合并或拆分仍可清楚理解的内容，不拆散必要语义配对，不改变 Action 作用范围。

信息处理结果是组件与布局选择的输入。每个保持项都必须分配给一个可见内容模块；实际事实 owner、`dataIds` 与 `actionId` 的唯一性按核心生成协议执行。无法承载全部保持项的组件、组合或布局不是可行候选。

## 2. 从信息变为内容模块

- 一个字段可以形成一个单组件模块。
- 多个字段与某个组件的完整语义结构吻合时，形成一个单组件模块。
- 多个组件满足已定义组件组合的成立条件时，形成一个组合模块。组件原生 `items` 或组合组件的内部条目不重复计为父布局内容组件。
- Action 与所属内容联系紧密时，可与该内容形成同一区域；没有明确从属关系时，作为独立操作模块参与布局选择。
- 标签和值保持在同一语义位置。为重要信息保留更强的视觉表达，为同级明细选择一致的表达方式。

优先使用能够自然表达完整关系的单组件或组件组合。只有部分成立条件吻合时，不强行套用组合；没有真实信息时，不为使用组合或填满槽位而虚构内容。

## 3. 从模块到候选组件

1. 逐项读取信息处理结果，为全部保持项保留少量语义成立的组件或组合候选，不凭外观或单个样例提前锁定。
2. 一个信息分区包含多个性质时先分别映射，再判断单组件、组件原生多 item 或多组件组合何者能完整表达。
3. 数据性质不等于唯一视觉组件。空间不适配时，只在同一语义允许的候选中切换；换组件不得改变事实、信息层级、绑定或 Action 归属。
4. 次要信息优先考虑紧凑组件或尺寸变体。当前候选都不适配时先更换布局，仍不适配才报告未满足，不拼假组件或静默删除保持项。
5. 组件与槽位必须同时满足语义、当前尺寸和 layouts 合同；不手写容器或几何属性修正。

## 4. 组件与布局共同收敛

1. 依据布局总表与选择规则，用信息分区数量、内容模块数量、标题、Action 数量和固定槽需求排除无法承载的父布局。
2. 将内容模块放入语义槽位，先核对组件所属的允许集合，再选择容量和子节点顺序均匹配的内容区变体。
3. 根据槽位兼容性、组件容量、模块数量和信息层级，检查每个保持项和 Action 是否都已分配且只分配一次。
4. 组件替换后重新检查槽位，布局替换后重新检查组件语义与最小占位。容量闭合前不过早固定组件或布局。
5. 无法闭合时，依次比较同一语义下的高密度组件或组合、容量更大的已定义内容区变体、其他父布局。仍有保持项未承载的方案不得进入最终结果。

`Card.layout` 确定区域关系，`Region.variant` 确定一个内容区域内部的层级。单一核心模块使用单内容变体；核心与补充共同出现时使用主次内容变体或能完整表达关系的组件组合；内容及其直属 Action 同区展示时使用支持 Action 的变体。标题只在需要补足对象、范围或语境时使用，不与正文重复。

## 5. Action 与容量

- Action 是布局容量的一部分，不在内容排完后追加。
- 每个必要 Action 都需要一个合法操作槽。与某一信息分区明确相关的 Action 优先留在该分区；没有明确从属关系时，按当前尺寸的合法固定操作槽安排。
- 不支持 Action 的布局不能用于含 Action 的任务。当前布局缺少操作槽时更换布局，不删除 Action 或用普通文本代替按钮。
- Action 数量越多，可用于信息的空间越少，应相应选择更紧凑的组件或组合。

## 6. 容量闭合与提交复核

最终结构必须同时满足：

- 每个保持项已分配给一个可见内容模块；
- 每个 Action 已分配给一个合法操作组件；
- 每个组件符合所在槽位和内容区变体的允许范围；
- 标题、主体、明细和操作的数量及内容长度不超过槽位容量；
- 没有为套用模板产生的空槽、重复信息或无意义节点。

若全部信息无法在规范容量内同时展示，依据输入目标和信息优先级保留更重要的内容，并优先使用高密度组件表达同类明细。用户明确要求的信息和全部必要 Action 不参与这种舍弃；当前结构放不下表示结构选择无效。

提交前按 `userQuery` 逐项复核明确要求的事实：每项都能在 JSX 中定位到可见值及其真实 `dataId`，每个 Action 都能定位到一个操作组件。静态标题、相邻概括或同领域信息不能代替被要求的动态事实。

## 7. 完成结构

结构闭合后，以 `Card.layout`、`Region.slot/variant` 和业务组件提交完整 JSX，并按核心生成协议填写显示值、`dataIds`、`actionId` 与资源。语义布局负责展开固定几何；绑定只改变数据如何进入组件，不改变事实含义、组件语义或 Action 作用范围。
