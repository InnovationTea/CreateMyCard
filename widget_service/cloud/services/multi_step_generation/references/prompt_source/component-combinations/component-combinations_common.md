# 多组件组合

组件组合表示多个业务组件共同表达一个完整语义单元。本文件是两种尺寸共用的组合语义来源；具体组件形态、`Card.layout`、`Region.variant`、固定槽和尺寸示例由当前尺寸文件规定。

## 1. 组合候选

| 类型 | 组合名称 | 内容结构 | 适用场景 | 容量与约束 |
|---|---|---|---|---|
| 标题组合 | 标题与数量 | 标题 + 数量标记 | 用户要求集合数量，输入有真实数量字段，标题命名同一集合 | 作为一个标题单元；数量只绑定并表达一次 |
| 主次组合 | 核心与补充 | 核心组件 + 紧密关联明细 | 同一主题存在明确结论与解释关系 | 恰好 2 个内容模块；两个事实同级时不用 |
| 主次操作 | 核心、补充与操作 | 核心组件 + 明细组件 + Action | 核心、明细及直属 Action 同属一个主题 | 2 个内容模块 + 1 个 Action；三者都不可省略 |
| 内容操作 | 单内容与操作 | 内容组件 + Action | 一个内容模块已能完整表达必要信息，Action 直接作用于该内容 | 1 个内容模块 + 1 个 Action |
| 占比组合 | 双占比 | 2 个同级占比 + 可选共同 Action | 2 个对象使用同一占比尺度，且分别可识别 | 恰好 2 项；Action 必须同时作用于两者 |
| 占比组合 | 三占比 | 1 个三项紧凑占比组件 | 3 个对象同级、同尺度，且可由 Icon 区分 | 恰好 3 项；整体计为 1 个内容组件 |
| 占比组合 | 四占比 | 4 个同级占比 | 4 个对象使用同一占比尺度，且分别可识别 | 恰好 4 项；不增加第五项、标题或 Action |
| 信息组合 | 双信息块 | 2 组完整主辅信息 | 2 组同级信息均可独立理解 | 每组都有主文本与辅助文本；有明确主结论时不用 |
| 操作组合 | 双操作 | 2 个同级 Action | 2 个必要 Action 共同服务主内容或整卡 | 恰好 2 个 Action；不合并、不重复 |

## 2. 成立条件

### 2.1 标题与数量

- 用户明确要求该集合的数量，输入 `data[]` 有对应数量字段；不得按列表项数推测总数。
- 数量必须概括标题所指的同一集合，而不是正文中的独立核心指标。单独的核心数量不使用此组合。
- 标题与数量标记紧邻，共同占用一个标题位。下方内容仍表达各自事实。
- 状态、类别、温度、时长、百分比和普通业务数值不组成标题数量。

### 2.2 核心与补充

- 两个内容必须表达同一主题，且一个是结论或关注重点，另一个解释、限定或补充该结论。
- 两项同级时保持对等表达；不把左／右耳机、多个设备或多个同类指标随意改成主次。
- “核心、补充与操作”要求 Action 明确作用于该主题，且核心、补充与 Action 都是必要内容。

### 2.3 占比组合

- 占比项必须是同级对象的真实占比、百分比或明确的 0–100 有界进度，并使用同一尺度。
- 2 项使用双占比；3 项使用一个三项紧凑组件，不拆成 3 个零散组件；4 项使用四占比。
- 需要文本标签才能区分对象时，不使用仅靠 Icon 区分对象的占比组合。
- 双占比的可选 Action 必须同时作用于两个对象。不同作用范围的 Action 分别归入对应内容区。

### 2.4 双信息块

- 两组信息必须同级，且分别保持完整的“主信息 + 辅助信息”。
- 尾部 Icon 或进度视觉属于同一信息块，按真实语义可选；没有匹配视觉时省略。
- 存在一个明确主结论时，改用“核心与补充”，不使用双信息块。

### 2.5 内容与操作

- Action 不是信息字段。只有 Action 与内容存在明确归属时，才形成单内容或主次内容的操作组合。
- 两个同级 Action 只有在共同服务同一主内容或整卡时才形成双操作。分别作用于不同信息分区时，不合并为一个操作组合。

## 3. 共同约束

- 不为满足组合项数虚构数据、Icon、标题或 Action，也不通过重复事实填充组合。
- 组合中的每个项目只承担一个语义角色；动态事实和 Action 的唯一归属与绑定按核心生成协议执行。
- 具体组件和尺寸实现必须同时满足本文件的成立条件；只满足项数或外观不算命中组合。
