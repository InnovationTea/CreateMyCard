# 布局语义与内容骨架

只提交 `Card.layout + Region.slot/variant`。程序负责方向、尺寸、间距、对齐、安全边距、背板和固定槽，不输出 `Stack`、`Grid` 或几何 Props。

## 1. Region 内容计数

- 标题、业务内容和 Action 分别计数；按钮不计作业务内容。
- 一个业务组件无论包含多少字段、`items` 或内部元素，都只算一个内容组件。
- 每个内容组件必须是 Region 的直属业务组件；不得用容器把多个组件伪装成一个槽。
- 核心与明细由两个独立组件表达时必须使用双内容骨架；组件原生同时承载主副内容时仍算一个组件。
- 可选区域不存在时省略对应组件，不保留空槽；固定槽布局要求的槽位必须全部提交。

## 2. 内容骨架

以下名称描述信息关系，不代表某个尺寸一定提供同名 variant：

| 内容骨架 | 标题 | 业务内容 | Action | 关系 |
|---|---:|---:|---:|---|
| 核心居中 | 0 | 1 | 0 | 一个无需标题即可独立理解的 Data Display 内容 |
| 标题单内容 | 1 | 1 | 0 | 标题后只有一个主体内容 |
| 标题双内容 | 1 | 2 | 0 | 核心内容在前，紧密关联的明细在后 |
| 标题内容单按钮 | 1 | 1 | 1 | 一个主体内容和一个直属操作 |
| 标题主次内容单按钮 | 1 | 2 | 1 | 核心、明细和一个直属操作 |
| 标题双列占比 | 1 | 2 | 0–1 | 两个同级占比对象并列；操作存在时属于同组 |
| 内容四宫格 | 0 | 4 | 0 | 四个同级占比对象各占独立槽 |

标题、内容或 Action 数量不匹配时必须改选当前尺寸的其他 variant，不能临时追加区域。

## 3. 选择边界

- 布局必须同时容纳必需数据、必需 Action 和组件最小占位；不得为套用骨架虚构信息、重复事实或删除必需项。
- 标题只在骨架要求且能补充对象、范围或语境时使用。标题会重复正文时选择合法的无标题骨架。
- 同一语义分区的核心与明细保持连续；直属 Action 优先留在所属业务区域，只有当前布局规范明确提供固定操作槽时才迁移。
- 更换组件后重新检查内容组件数、标题与 Action；更换布局不得改变字段含义、绑定或 Action 归属。
- 超出容量时使用组件原生多 item、合同允许的紧凑规格或其他合法 variant；不手改几何，也不依靠截断必要事实获得通过。
