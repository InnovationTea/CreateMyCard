# 2×4 单例闭环：Q061 分区与直属操作

## 定位

旧结果覆盖了用户要求的信息和两个操作，但把两个可独立理解的内容组放在同一个左内容区，
两个直属操作放进公共右侧槽；按钮目标文字也出现不均匀换行。已接受 Plan 只推荐侧双槽和四槽，
未考虑左右双区。创建布局合同本已允许左右双区，并要求直属操作保持归属；没有 Runtime 能力缺口。

## 本次修改

只在 2×4 布局总表后的现有选择说明中明确比较顺序：先看内容组与操作归属，再看按钮数量。
共同使用场景不自动等于一个内容组；两个内容组各有直属操作、紧凑区预算成立时优先左右双区。
这仍是软偏好：真实共享操作、独立操作和预算不成立时保留其它布局，不增加自动路由或分区校验。
Plan 文档仅要求按当前尺寸布局合同比较候选，不新增字段、文本分析或硬布局约束。

## 不做的修改

- 不改原始输入、能力候选、示例库、数据样例及 Action 参数。
- 不增加这个案例或相近答案的 Few-shot，不按天气/健康或案例编号进行代码分支。
- 不改变组件 Recipe、字号、按钮尺寸、自动修复上限或既有删除兜底。
- 不把人工参考画面改写成模型输出，不将一次单例通过解释为稳定性提升。

## 验证

1. Prompt 组装验证：2×4 Plan 与 DSL 均读取该布局规则，2×2 不加载该尺寸片段。

Plan 已推荐左右双区，初稿也采用左右双区；但正文与按钮被多填到子布局，修复 6 次后
退回了混合正文＋侧双槽。反馈仅给孩子数量与“变体不支持”，未给对应角色或父区可用变体。
第二步仅补充语义编译器的错误事实：当前布局/变体需要的有序角色、紧凑/宽内容区合法变体。
不增加建议蓝图或真实字段答案；校验判定、几何、抛错顺序与绑定行为保持不变。
