# 静态 Skill 职责与加载重构实施计划

**目标：** 归位并去重静态规则，按尺寸装配同一套合同；组件、Plan Schema、试排、校验、修复预算及示例事实保持不变。

**架构：** Core、信息、组件、布局和综合流程组成创建阶段的共享合同；Plan、DSL、Repair只追加阶段要求。
静态模块在manifest中登记适用尺寸，由加载器统一验证、缓存、过滤并剥离维护元信息。动态装配保持原样。

**基线：** 主仓448b6502。另保留31ea5ec9的55条历史结果；最新主仓在独立检出运行匹配对照。

## 实施步骤

1. 冻结最新主仓的阶段Prompt、动态Prompt哈希与15例few-shot；记录规则迁移来源。
2. 将common中的协议、信息、组件、布局、执行规则细分归位，Plan字段和索引合同保留在Plan。
3. 相同规则只保留一个维护来源；原有活动记录选型、单动作title-action及完整文字保护继续保留。
4. 静态manifest登记模块及尺寸；创建阶段按阅读顺序加载，阶段追加不重新加载共享规则。
5. 加载器剥离YAML头，拒绝重复、未登记、缺失及不合法尺寸引用；只读取当前尺寸模块。
6. 容量完整合同仍由共享运行时产生，初始加载一次；Plan只补充本尺寸参考画布，避免重复发送同一规格。
7. 测试元信息隔离、尺寸过滤、阶段边界、缓存、异常、动态不变、few-shot内容不变，并运行静态及公共链路回归。
8. 同参数跑55例，使用build_gallery.mjs渲染，对比成功、降级、失败及完整请求耗时；通过后提交PR。

## 本轮不做

- 不增加组件、布局、场景示例或业务关键词；不调整priority、记录条数或should省略算法。
- 不修此前审阅发现的反馈判定、去重或动作试排缺口，以便效果变化可归因于本次装配重构。
- 不将单轮波动描述为统计意义上的性能改善。
