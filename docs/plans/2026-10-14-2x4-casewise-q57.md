# 2×4 单例闭环：日程数量与标题 Badge

基于提交 `3bb02a2`；原分支和 PR #522 保持不变，工作分支为
`codex/compact-semantic-2x4-casewise-v1`。本轮只验证 cardSpec24 的 Q057，
不修改 2×2、InfoBlock 样式、灵动布局、Plan Schema 或修复预算。

## 已确认原因

Q057 的初始反馈要求日程数量自己包含时间范围和日程含义。
Core 同时指定数量用正文，组件合同却允许标题关联数量使用 Badge。
此冲突使标题与数量无法组成合法的紧凑标题单元。
原最终结果的右上 InfoBlock 为无绑定的重复概览，不是第二个详情事件。

## 本轮修改

1. 仅在 2×4 中允许“完整统计范围与集合名称标题 + 动态数量 Badge”。
2. 展开后校验只读取同一标题 Row 的 SingleLineTitle；允许语义展开产生的
   单层标题包裹，不向祖先、其它区域或无关正文借上下文。
3. Plan 提示区分集合数量和成员详情：可使用 Badge 和 EventCard，
   不把事件标题固定推荐为卡片标题；独立统计概览保持原选型。
4. 固定双槽说明禁止以重复静态概览凑槽；两个真实操作可以占两个 CardButton。

## 验证与止损

- 用合成日程名称、数量和范围验证合法标题、错误标题、孤立 Badge、跨区标题；
  不把 Q057 原输入或参考答案加入 Prompt。
- 保留 2×2 原行为，保留无范围、无日程含义的数量报错。
- 执行相关测试、Ruff 和 diff check；仅重新生成 Q057，使用原输入与原修复预算。
- 用 Python 转换器和共享 CardRenderer 渲染旧结果及新结果，检查数量、会议标题、
  开始时间、全天状态和两个事件；不把可渲染当作校验通过。
- 若仍不好，仅针对 Q057 继续定位，不同时修改其它案例。
