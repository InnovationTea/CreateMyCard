# 结构 ID 最小优化 Implementation Plan

**Goal:** 保留原布局与组合骨架的表达自由度，只统一组件结构命名及引用，降低角色名与业务实例名不一致的风险。

**Architecture:** 已将上一版占位闭合模板保存到原实验分支的 8533e94，当前在 codex/minimal-structural-ids-20261019 修改。恢复 cffe609 的三个骨架文档，只调整其中的 ID 及相邻 ID 说明；Core 保留唯一完整结构示例并统一引用说明。两种尺寸完整 Few-shot 仅进行组件 ID 和 children 的等价重命名。不改组件选择、Plan、Runtime、校验、repair 或加载流程，不进行全量 API 推理。

**Tech Stack:** Prompt Source Markdown、pytest、Compact DSL 正式解析与转换器、Ruff。

## 执行步骤

1. 备份当前七个已修改文件到原实验分支，另建本轮分支。
2. 冻结 24 个完整 Few-shot 的输入、忽略组件 ID 的有序组件树及全部数据行摘要。
3. 新增测试：结构命名统一；ID 唯一、引用闭合、单父、全部可达；忽略命名后的输入和输出与冻结摘要一致。
4. 恢复原三份骨架内容；仅统一 Layout/Region/Group 的结构 ID 和容器 children，按需同步相邻文字中的 ID。不补齐业务叶子组件，不填业务值。
5. Core 明确按结构命名，不按业务改名；嵌套 ID 加父前缀避免重复，不改 dataId、actionId、数据路径及事件参数。Few-shot 按相同方式命名。
6. 运行新测试及现有提示词和完整 Few-shot 回归，Ruff、git diff --check；测量 Token 变化。
7. 交付修改及备份位置；不自动推送、不声称已证明真实生成收益。

## 范围边界

- Core：全局组件引用规则；各尺寸布局：布局、Region 的角色名称；组合：Group 角色名称；Few-shot：依规则示范。
- 没有引入新协议类型或属性，不对生成 DSL 做自动重命名。
- 局部模板可省略业务组件定义，但完整最终输出不可省略；唯一完整引用示范留在 Core。
- 业务描述、数据值、组件 Props、素材、用户输入和动作不因重命名而改变。
