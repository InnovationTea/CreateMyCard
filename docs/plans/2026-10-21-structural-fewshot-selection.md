# 结构Few-shot检索与双CardButton验证 Implementation Plan

**Goal:** 默认按已接受Plan检索最多4例；关闭检索时加载全部同尺寸示例；真实验证小卡双动作。

**Architecture:** 独立检索模块只读取示例、Plan和输入的结构特征，不修改生成或校验合同。
PromptBuilder在Plan接受之后注入检索结果；总开关与检索开关分离，Plan阶段不加载示例。

**Tech Stack:** Python、pytest、现有Fusion Runner、统一build_gallery.mjs。

## 实施与验收

1. 更新方案，新增结构检索单测：动作容量、事实密度、候选匹配、匿名去重、缺失值及确定性排序。
2. 从现有离线实验迁移算法；按钮容量读取layout合同，整卡点击范围读取共享合同，不复制业务路由。
3. 既有检索配置默认true；false时完整保留同尺寸全部示例，总开关false时不加载示例。
4. 用88个历史已接受Plan离线比较新旧库检索，不使用最终渲染做排名标签，不改原始输入。
5. 使用官方DeepSeek对原始Q044/Q046/Q048生成，最多每轮修复5次、失败再完整请求一轮。
   统计真实CardButton、信息/动作覆盖、尝试数与总耗时；失败需如实记录，禁止删字段换通过。
6. Ruff、相关及扩大测试、差异检查；统一渲染少量结果供审阅。检查全部暂存文件并提交独立PR。

检索评分只采用此前实验已确定权重，不依此批测试调权。没有模型通过结果前，不声称多次稳定成功。
