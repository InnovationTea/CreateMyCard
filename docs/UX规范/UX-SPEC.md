# 通用卡片 UX 规范

适用于当前通用方案的 2×2（150×150vp）和 2×4（300×150vp）卡片，规定布局、尺寸、样式、内容和动作要求。

**完整 few-shot 在另外附带的两个文件中，不在本文展开：**

- [FEWSHOT_2x2.md](FEWSHOT_2x2.md)：2×2 完整示例。
- [FEWSHOT_2x4.md](FEWSHOT_2x4.md)：2×4 完整示例。

本文与两份附件配套使用。示例文案和数据不应固定套用，实际内容以当前 TaskSpec 为准；最终视觉效果需在真机验收。

## 1. 概述与设计原则

以 150×150vp 与 300×150vp 为画布，统一信息层级、业务分区、动作和视觉细节。

- 2：卡片尺寸
- 14：布局骨架 S1–S4 / W1–W10
- 30：完整 few-shot 原例

### 业务对象先于字段数量

一个对象可以有多个指标；多个数据根也可能描述同一个目标。布局按业务对象和信息优先级理解，不把每个字段当作一项业务。

### 强调主信息，平等对待同级指标

只有明确主信息才使用突出字号。最高／最低等并行指标保持一致层级，不任意突出其中一个。

### 信息和动作都不能丢

短标签、合理分行和调整布局优先于截断。不能用裁切、假按钮或模糊单位掩盖空间不足。

## 2. 基础样式

### 画布与安全区

| 项目 | 2×2 | 2×4 |
| --- | --- | --- |
| 画布 | 150×150 | 300×150 |
| 普通根容器 padding | 12 | 12 |
| 分区骨架 padding | S4：8 | W8 / W9 / W10：8 |
| 普通安全区 | 126×126 | 276×126 |
| 分区安全区 | 134×134 | 284×134 |
| 整卡圆角 / 裁剪 | 20 / clip | 20 / clip |

单位为 vp；业务背板的内边距独立计算，不等于 root padding。例：W9 背板宽 138，内边距 12，内容宽 114。

### 字号、字重与语义

| 角色 | 字号 fp / 字重 | 语义举例 | 边界 |
| --- | --- | --- | --- |
| 标题 | 12 / 400 | 手机电量 | 常规顶部标题，不随内容数量放大 |
| 辅助信息 | 12 / 400 | 未充电 · 更新 09:00 | 不使用 10fp 强行压缩 |
| 正文 / 按钮 | 14 / 400–500 | 查看详情 | 按钮通常 14；允许范围内可降至 12 |
| 突出文字 | 16 / 18，700 | 户外跑步 | 稀疏短状态满足条件可 20 / 24；不是全局标题字号 |
| 紧凑数字 | 20 / 24，700 | 68 | 短指标、并行比较按骨架选择 |
| 主数字 | 默认 30，最大 38 / 700 | 6200 | 稀疏焦点可 32 / 38；并非所有数字都可 hero |
| 同行单位 | 12–16 / 400–500 | % · 天 · 次/分 | 紧邻数值并校正可见字底 |
| 带格式字符串 | 通常 16，最多 18 | 7小时1分 | 简单温度 / 时长 / 百分比满足专门条件可 20 / 24 |

**字号由语义和布局共同决定**

大号格式字符串的例外要求单一数据路径或简单后缀、样例单位明确、完整槽位宽度、足够文本高度（至少字号的 1.4 倍），不能直接套到小背板和环形内部。这里只记录现有分支，不新增统一放大规则。

### 间距、对齐与文本宽度

- 数字和单位通常间隔 2；文本组合间隔 2–8；大区之间 8–12，最终以骨架预算为准。
- 混合字号使用底部对齐，不使用居中对齐。转换器会对识别到的小字号文本增加有限底部补偿。
- 值和单位采用内容宽度；不能把数字 Text 拉到整行宽度，再把单位挤向另一端。
- 宽度预估按中文约 1em、数字和英文约 0.65em，并保留余量；这只是预算，不替代真机排版。
- 默认文本靠左。仅命中特定稀疏焦点或倒计时分组时居中，不能把居中传播到所有标题和列表。

## 4. 图标与图片

### 语义选择与着色边界

| 类型 | 是否改色 | 使用规则 |
| --- | --- | --- |
| 单色且允许着色的 SVG | 使用 fillColor / 主题前景 | 严格使用候选资源路径；保持 objectFit: contain、20×20、flexShrink: 0 |
| 明确不可着色的 SVG | 保留原色 | 品牌、多色、渐变或资源描述要求保留原色时，不套统一 fillColor |
| PNG / 位图 | 保留原色 | 不通过 fillColor 伪造换色 |
| 随数据变化的状态图 | 按语义选择 | 没有条件化资源能力时使用中性业务图标，不用固定晴天图代表所有天气 |
| 来源与数量 | 只用登记候选 | 不凭空拼资源路径，不用 emoji 替代；2×2 默认最多 2 个，例外按骨架 |

- 普通 2×2 的图标优先落在标题 / 按钮区；环中心、S4 右侧视觉位是专门例外。
- 2×4 小背板的图标位在右侧，文本在左侧且最多两行。图标不能挤到第三行或跑到文字下面。
- 有文字已经表达同一语义时，避免多个重复装饰图标。图标不承担唯一的信息说明。

本章不逐个陈列资源图标，仅规定选用、着色与布局要求。

## 5. 区域与组件规范

整卡由标题区、内容区、按钮区组合；各区域遵循所选骨架，不额外叠加另一套布局。

**原则共用，规格分开**

先看通用规则，再按卡片尺寸与所选骨架取值。2×4的业务面板可以继承部分2×2信息层级，但不能直接复用其宽度、安全盒和动作区域。

### 5.1 标题区

区分整卡标题、分区标题和焦点上下文。

#### 通用规则 · 2×2 / 2×4

##### 共用的是标题层级，不是标题宽度

| 项目 | 通用规范 |
| --- | --- |
| 常规标题 | 12fp / 400，单行，默认左对齐 |
| CardHeader | 固定20vp高；可用图标20×20，文字与图标间距8 |
| 角色区分 | 整卡标题、分区标题、焦点上下文分别属于对应骨架 |
| 居中条件 | 倒计时等专门结构按自身规则居中；普通标题保持左对齐 |

CardHeader 是特定组件，不代表所有顶部文字。分区标题与 W1 的焦点说明使用各自槽位。

### 5.2 内容区

对齐与数据语义通用；密度、几何和专门结构按尺寸区分。

#### 通用规则 · 2×2 / 2×4

##### 数值、单位与格式字符串

**数值紧凑成组，字底对齐**

- 同一Row的不同字号文字使用底部对齐；数字和真实单位紧邻，通常itemMargin=2，按内容确定宽度。
- 大数字行只包含纯数字与真实单位；标签、方向、状态和名称放到各自说明区。
- 格式化字符串已经包含单位时显示完整值，单位语义只表达一次。
- 当前小字号底部补偿为min(8, ceil((最大字号 − 当前字号) / 4))；仍需真机检查可见字底。
- 根据用户语义确定主辅关系；同级指标保持相同层级。密度上限与焦点尺寸分别看下方尺寸规格。

##### 进度的数据语义与时间信息

- 默认不生成Progress；字段明确表示比例且有可验证范围或真实total时才允许。
- total=100时，Progress.value=68表示68%；展示文字与数值绑定分开。环形和线性进度都需显示可见读数。
- 环大小、strokeWidth和说明容量由所选骨架决定，2×2与2×4不共用一套固定环尺寸。
- 同一天的日期与星期优先保留星期；用户明确要求日期时保留日期语义。时间范围显示完整起止信息。

#### 2×2 规格与示例

##### 普通内容区与信息密度

- 普通单业务root padding12，可用内容宽126。标题和动作占位后，内容区以layoutWeight=1承接剩余高度。
- 普通数值亚型的30/38fp主值最多搭配一条辅助行；纯文字最多一条突出信息与两条辅助行；并行信息最多三条普通信息行。
- 稀疏信息作为连续组垂直居中；真正独立的日期、来源等支撑信息可以沉底。
- 倒计时、TimelineUnit、S3、S4、Progress等专门结构按自身容量处理。

##### S2 单数字 Hero 安全盒 · 仅 2×2

- 仅匹配“顶部标题 + 中部唯一纯数字（可带单位）+ 底部单动作”的普通S2。
- 内容区宽126；hero_box固定106×58并双轴居中。数字 / 单位按38/16 → 30/14 → 24/12 → 20/12降档。
- 使用至少三位数字的压力样本并增加20%宽度余量，宽高均满足安全盒后才采用该档字号。
- 含状态、日期、第二指标、Progress等信息时，回到对应内容结构。此安全盒不套用于2×4或W9内部。

##### 专门结构：S4、单会议与进度环

| 结构 | 2×2 内容规格 |
| --- | --- |
| S4 上下双业务 | root padding8；每背板134×63；最多两条单行文字；文字82 + gap8 + 图标20 |
| S4 无图标 / 有环 | 无图标文字宽110；环视觉位44×44、stroke6，文本宽度另按剩余空间计算 |
| 单会议 TimelineUnit | 仅calendar单场会议；日期区126×16；会议标题14/700，最多两条12/400辅助 |
| S2 视觉亚型 | 环48×48、stroke6；遵循其专门底部视觉与动作结构 |

#### 2×4 规格与示例

##### W9：每个业务面板独立排版

- root padding8，左右背板各138×134，间距8；背板内部padding12，真正可用区为114×110。
- 每区独立选择内容变体。普通大数字最多一条辅助行；纯文字最多一条突出信息加两条辅助；并行数据最多三条普通信息行。仍需扣除分区标题与可选36高按钮。
- 继承的是2×2的语义层级和密度原则，不是126宽内容区，更不是106×58的S2安全盒。
- 无动作倒计时直接使用标题、纯数字、唯一单位“天”三个Text，spaceBetween分配留白并居中；另一业务独立处理。

- 右侧每板最多两行；有图标时文字78 + gap8 + 图标20，左右padding12；无图标文字宽106。
- W8 / W10的小背板另为138×63。小背板行数限制相同，但不能套用W1的130宽和59高。

## 6. 2×2 整卡布局

150×150vp。骨架说明空间结构，完整卡覆盖当前 15 个 few-shot；两者不能混为“15 种骨架”。

### 布局骨架

#### S1 单焦点 / 倒计时

**适用**

单业务、单核心信息；倒计时无动作时的专门排布。

**尺寸与排布**

标题、数值、单位形成稳定居中组。无动作倒计时主数字可38；不套 CardHeader。

**禁止 / 边界**

不要添加无关业务统计，也不要把动作版倒计时直接套入。

#### S2 标题 + 内容 + 底部区

**适用**

常规单业务，有一个动作或有意义的底部辅助信息。

**尺寸与排布**

标题20；内容layoutWeight=1；有动作时底部36。内层对齐依据内容类型，不一律居中。

**禁止 / 边界**

禁止固定高度内容吞掉按钮区；辅助信息不能无限追加。

#### S3 双动作

**适用**

同一业务两个明确动作，内容需要压紧。

**尺寸与排布**

头部40 + 间隔8 + 双按钮78 = 126；两按钮间距6。

**禁止 / 边界**

不要再额外叠加30/38大数字内容块。

## 8. 内容密度与视觉验收

### 小背板：两行与右侧图标

**文本左对齐，图标占独立右槽**

- 两行按实际视觉行统计，文案换行也计入高度预算。
- 右侧动作背板无论一行或两行，文字均左对齐，整个文字组垂直居中。
- 固定背板高度、文本列宽和右侧图标槽，确保文字与图标稳定排布。

### 稀疏与密集：用布局调节，不用空白占位

W1 少量信息的居中以内容组为单位；足够空间时辅助信息可分成两行。多场会议、列表或多指标密集内容仍保留左对齐和阅读顺序。

### 验收清单

- 尺寸正确：150×150 / 300×150，不能混用160时代的内宽。
- 根容器padding与业务背板padding分别核算；不重复留白。
- 所有被引用节点可达且不重复挂载；字段没有在转换时丢失。
- 主次符合用户语义；并行指标没有无依据的单项放大。
- 数字、单位、同排标签的可见字底对齐，数值与单位不远离。
- 单位不重复、不缺失；布尔值不是true / false直接出现在卡面。
- 内容在合法行数内；不通过拆content / bottom绕过整体密度。
- 小背板文字左对齐、最多两行，图标在右并垂直居中。
- Progress绑定数值，total语义一致，实际有进度。
- 底部按钮位置稳定，没有遮挡；图文整体对齐。
- 合法动作有明确入口；提示文字不能冒充按钮。
- 默认主题不随机变黑，双业务颜色一致，2×4白板透明度60%。
- 禁止将多个来源统计混入不相关业务区；eventCount属于日程。
- 截图检查短值、长值、三位数、多字状态、无图标和无动作。
- 浏览器预览后仍需真机验收字体字底、模糊、图标着色。
- 原例校验通过不等于视觉通过；差异与例外必须记录。
