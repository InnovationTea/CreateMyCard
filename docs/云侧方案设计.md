# AI 卡片项目云侧方案设计

## 文档定位

本文是 AI 卡片云侧方案的总入口和唯一权威方案依据，供开发者与 AI 快速理解项目目标、系统边界、主链路和关键约束。
详细字段、组件规格、配置项和测试用例按文末导航查阅，不在本文重复展开。
JSX 多步生成目录 `widget_service/cloud/services/multi_step_generation/` 当前已废弃，不作为现行方案入口。
初步了解项目及普通开发任务默认跳过该目录，仅在排查相关遗留依赖、兼容问题或用户明确要求时阅读。

方案与代码、配置或专项文档冲突时，先说明差异并与用户确认，再同步修改；不能将现有实现自动视为已批准的方案。
本文不维护 PR 合并记录、开发过程、历史实验、人员分工或逐次验收结果，旧记录也不能作为恢复已退出规则的依据。

## 方案目标与范围

用户在小艺 App 中用自然语言创建或修改桌面卡片，云侧生成 HarmonyOS A2UI Form 产物，端侧负责预览、确认添加及运行时刷新。
核心目标是：**在稳定、能力真实可用的前提下，尽可能生成美观、吸睛的卡片。**

动态能力优先覆盖天气、日历、系统设置、运动健康等一方应用和系统能力。
三方 App 数据、跨端数据或新增动态能力必须先明确方案并进入能力注册表，不能由模型自行补造。
外部静态事实可以用于卡片展示，但不能冒充动态刷新能力；完整页面、复杂表单和长报告不属于默认承载范围。

## 系统边界

| 参与方 | 核心职责 |
| --- | --- |
| App 中控 | 按 ROM/App 版本加载 Skill，提供用户与设备上下文；ROM < 7.0 不加载本 Skill |
| 主 Agent / 在线 Skill | 判断需求与支持范围，选择候选，检查权限与事实来源，调用工具并组织用户回复 |
| 微服务 | 维护能力与协议配置，裁决候选，构造运行配置与模型输入，编排生成、转换、校验、修复及产物交付 |
| A2UI 模型 | 根据已裁决上下文提交信息计划、生成 DSL，或输出编辑意图、补丁及布局候选；不裁决设备能力、不修改最终运行配置 |
| 端侧 | 执行权限工具，下载与渲染产物，确认添加，调用端侧数据能力并刷新界面 |

**在线链路的最终 DSL、CardSpec 和 artifact 均由微服务负责。主 Agent 在工具异常时也不得自行生成替代产物。**
离线 Skill 仅用于独立离线生成、兜底调试和历史视觉参考，不替代在线协议或成为在线失败后的自动回退。

### 模型与程序的实现原则

**让模型理解语义，程序负责确定性事项。** 本原则适用于创建、编辑、规划、生成、校验、修复和主题选择。
用户意图、否定与条件、内容主次、摘要取舍、对象关系及展示偏好等语义问题，由现有模型阶段理解，
并通过结构化计划或意图表达；程序消费已接受结果，负责类型与结构、协议枚举、能力与权限范围、
引用可追溯、明确原文约束、计划履约、布局容量、转换、重试预算和产物交付等可验证事项。
模型的语义判断不能扩大能力、权限或协议范围，程序的确定性检查不能宣称已证明任意摘要语义正确。

默认不使用关键词、词表、子串匹配或正则表达式推断自然语言语义，不据此重新裁决或覆盖模型已接受的
内容与意图；避免按业务名称、固定文案或样本特征增加分支。优先复用现有模型阶段及结构化合同，
不为替换词法规则默认新增模型调用。能力、字段、动作关系及错误分类优先使用正式元数据和结构化诊断。

只有必要性充分、边界明确且无法由现有结构化信息可靠替代时，才保留或新增词法匹配；明确语法的解析、
格式校验及文字换行词元识别等可以使用正则，但不得扩大为业务语义裁决。例外须在对应代码或专项文档
说明必要性、适用范围和局限，并以相关回归覆盖误命中与漏判风险；维护现有逻辑时逐步收敛此类规则。

## 端到端流程

```text
用户需求
  → 主 Agent 判断创建 / 编辑、卡片适配范围及必要歧义
  → 获取能力概述，按需加载数据定义，检查数据需求、交互动作及参数是否可满足
  → 确定本轮候选及数据权限集合，调用端侧权限工具
  → 校验并补齐外部事实，完成参数与来源检查，实际告知采用的事实
  → 紧邻生成调用前发送创建 / 编辑开始话术
  → 微服务预检 → 构造运行配置与模型输入 → 生成或编辑
  → 转换、校验、按策略修复 → 最终产物保存与交付
  → 主 Agent 处理真实结果，宿主允许时补充结果回复；端侧预览并由用户确认添加
  → 安装后由端侧独立刷新动态数据
```

主 Agent 先判断创建或编辑、卡片适配范围和当前编辑边界，再决定后续分支；不支持或仍需澄清卡片意图时停止，不提前查询外部事实。
通过上述判断且需求明确依赖外部静态内容时，主 Agent 应在能力与权限流程前查询、清洗并完整告知；已有相关结果直接复用。可能由动态能力覆盖的展示项先完成能力与来源判断，仅剩余必要外部内容在权限阶段后按既有步骤处理。
纯视觉、文案和尺寸编辑从有效来源继承未修改的数据、事件及素材，不重新查询能力概述或数据定义，但仍检查继承数据的权限；修改已有数据参数时，重新查询概述与完整数据定义，再检查权限。
权限阶段后的来源步骤只处理剩余内容，补查按相关性串行执行，不重复查询或播报，也不新增权限前搜索分支。
生成前停止时不发送开始话术；普通对话、明确不支持或仍需澄清卡片意图时，不提前调用卡片工具或外部来源。

生成接口调用前是必要告知的最后时点，不能依赖调用后仍有自然语言回复机会。
已知的能力拒答、权限引导、必要澄清、替代确认、次要缺失、使用限制及采用事实均按原流程在调用前实际告知；
需要用户回答时等待，拒绝或不支持时停止，不为展示卡片而继续调用。纯静态内容创建须在开始话术前
告知内容保留制作时的信息、不会自动更新；仅快捷动作卡不适用，同一任务条件未变不重复。
已知信息不留到结果回复，但生成成功、生成中实际省略、工程失败及编辑模型返回的澄清不能提前断言。

核心动态需求在能力概述阶段检查一次，完整数据定义返回后再次检查；交互需求同时核对事件语义、完整模板、动态参数和依赖字段。
核心内容不可满足时停止；仅次要内容缺失且核心用途仍成立时，告知移除后继续；替代会改变主要用途时先确认。
必要业务信息缺失或有歧义时，主 Agent 先向用户追问一个最小必要问题并等待，不得自行推测或带着
未解决的问题进入权限、开始话术及生成。例如个人事件倒计时缺少日期时，先询问日期。
当前任务已明确的信息不重复询问；客观事实仍可按既有来源流程核实，默认值和示例不能替代用户事实。

## 主 Agent 调工具接口

在线固定链路由三个微服务工具和一个端工具组成，外部事实来源按运行时可用工具发现。
在线 Skill 的 `SKILL.md` 集中维护可独立执行的流程、关键参数、权限与结果判定及固定回复；
参考文件按需提供补充示例，不承载仅在额外读取后才能获得的必要门禁。能力范围与具体限制以本轮工具返回为准，
Skill 不重复维护版本能力清单或组件渲染实现。
工具调用以当前运行时 schema 为唯一入参依据；设备与用户上下文由工具层携带，不能从示例补造。
正式调用通过 `invoke` 指定工具名与匹配的 `bundleName`，并携带当前 Skill 名；业务参数不再套 `params` 外层。
`invoke.arguments` 必须直接为 JSON 对象，不能传 JSON 字符串；数据绑定中的 `arguments` 也必须为对象。
Compact 入口在请求校验前提供一次确定性参数恢复：严格解码已字符串化的业务对象，失败后才使用
受限 JSON 标点修复；仅在登记的对象位置解码，不递归解释普通展示文字。外层传输包络仍严格解析。
恢复不得改写业务值、重排数组、丢弃候选或改变创建／编辑模式；括号修复必须保持可证明的容器边界，
同层业务字段冲突时拒绝恢复，用户、设备和关联信息以原传输上下文为准，不由修复结果覆盖。
事件只兼容无冲突的 actionTemplate→action 结构映射及已登记的旧动态参数结构；固定动作值必须匹配
注册模板，非法或缺失动态值不得用模板默认值替代。未知字段及无效候选保留到校验并报错，不静默过滤。
机械恢复通过后仍执行请求校验和生成预检；无法确定性恢复时沿用既有提醒和独立开关控制的模型恢复，
模型仅恢复结构，已解析字段和数组项原样锁定，不能增删业务值。原文存在歧义或内容已丢失时拒绝恢复。
确定性恢复不调用模型、不增加重试额度；记录恢复方式和诊断，独立于模型恢复与 DSL 质量修复计数。
该通道默认执行，不受模型参数恢复开关控制；编辑恢复保留省略、空数组和显式空值的差异，
完整业务预检仍在原来源读取及继承之后执行，不借恢复清空动态绑定或自动切换为创建。
传输层使用 WebSocket 插件协议，主 Agent 消费最终业务内容，不自行解析或构造底层传输帧。

| 工具 | 用途与关键边界 |
| --- | --- |
| `getWidgetCapabilityOverview` | 返回当前用户实际可用的数据能力概述、事件和素材候选，以及本地不可用的数据能力 ID |
| `getDataCapabilitySchemas` | 按本轮已选数据能力按需加载完整输入与输出定义，不重新查询设备安装状态 |
| `RequestDataPermission` | 端侧判断本轮最终数据能力集合的权限，无数据能力时跳过 |
| `generateWidgetCardCompactDsl` | 创建与编辑共用的正式生成入口，返回业务状态、产物地址、摘要和实际有效能力 |

### RequestDataPermission

权限集合使用本轮最终数据能力 ID 去重构造；集合或绑定变化后重新检查。
本轮实际采用的能力若明确要求告知手动设置、连接条件或设备兼容限制，主 Agent 必须在生成开始话术前
实际发送对应使用提醒，说明必要操作或条件及不满足时的影响；不能仅写入内部计划、请求或卡片文案。
权限检查通过不证明这些使用前提已满足。提醒与权限裁决分别处理，不替代授权、不新增等待用户确认步骤，
也不绕过已有拒绝、待授权或不支持门禁；同一任务已告知且条件未变时不重复提醒。固定话术见在线 Skill。
纯视觉编辑也应从当前会话的有效结果或完整候选链恢复权限集合，无法可靠恢复时终止，不能由主 Agent 下载原产物猜测。
权限调用必须等到正常结果或明确异常结论后才进入后续来源与生成步骤，等待期间不改变待检查的数据集合。

- 正常返回时，只有 `stateOfPermission` 为 Boolean `true`、`nonAuthStatus` 缺失或为空数组，且权限项未明确拒绝时才继续。
- `stateOfPermission` 或任一权限项 `authorized` 为 Boolean `false`，立即终止生成。
- `nonAuthStatus` 非空时停止，按返回的名称与设置路径引导手动授权；正常返回结果缺失、结构或类型非法时也停止。
- 仅当错误精确为“不能传入空的dataCapabilityIds，请重新调用工具”时，复用本轮已确定的非空集合重试一次；重试未取得合法权限结果则终止。
- 首次调用的工具不可用、invoke 抛错、超时、传输或工具执行失败，且没有正常权限结果时，按既有默认开启策略继续来源处理和生成；不伪造授权结果，也不宣称已获授权。上述空 ID 错误的重试失败不适用此例外。

### 生成请求与结果

- `dataCapabilityIds` 仅用于加载数据定义及端侧权限检查；生成请求使用完整的 `candidateDataBindings` 和 `candidateEventCandidates`。生成入口与统一分发入口对显式传入的 `dataCapabilityIds`、`eventCapabilityIds` 均返回参数错误，包括空数组或空值，不静默忽略或据此进入静态生成；沿用现有 `INVALID_ARGUMENTS` 错误码。
- 生成请求及固定结构的候选、动作对象拒绝未声明字段，按既有参数错误通道返回字段位置与原因。`bundleName`、`functionName`、`skillName`、`requestId` 是已登记的工具元数据，在生成入口及统一分发入口剥离，不进入模型输入；实际操作由 WebSocket 路径或统一入口的 `operation` 决定，不采信透传的 `functionName`、`skillName`，请求关联仍由现有包络解析规则确定。该兼容仅作用于请求顶层，不授权同名业务参数。能力调用参数按注册 Schema 校验，有明确属性定义的对象默认拒绝额外字段，只有 Schema 显式开放的扩展项例外；不改变传输包络及设备元数据的兼容规则。
- 请求校验与生成预检的内部错误对象在 `error.details` 中保留阶段、是否可修正重试、字段路径、约束和修正说明；对主 Agent 使用下述简版投影，不返回原始参数值。只有明确可修正且允许重试的参数错误可在主 Agent 既有调用预算内重试；内部模型、产物校验、上传、超时及来源错误不提供猜测性的改参建议，也不授权切换创建或动态转静态。业务 failed/unsupported 同样提供停止指引；编辑澄清仍使用 `editFeedback`。
  纠错指引面向主 Agent 的工具调用：issues.path 用于定位错误，修正目标是下一次 invoke.arguments
  的完整业务对象，不要求主 Agent 构造 WebSocket content、顶层镜像、设备或会话包络。按完整字段
  层级及错误类别说明预期结构、取值来源和修正动作；数据参数与动作参数中的同名业务键不得被当作
  工具字段。候选误用定义结构时，指导核对本轮概述及完整 Schema，只保留工具要求的 ID 和执行参数，
  不整体照搬定义元数据、不根据名字或 URI 猜 ID。修正外层结构后仍须复核该项全部必填和下层参数，
  保留需求、模式、来源、尺寸约束及其它合法候选；不得仅提交字段补丁或通过清空候选规避错误。
  反馈只返回脱敏错误类别、类型、合同约束和来源，不回显实际参数、原始异常上下文或自定义异常中的值；
  本项仅增强指引，不改变校验准入、权限门禁、自动恢复范围及既有调用预算。
  普通日志与内部错误对象保留错误码、阶段、类型、约束、修正说明和全部已发现问题。插件外层
  errorCode、errorMessage、streamInfo 及成功响应保持原样；失败／不支持结果的 streamContent
  改为直接序列化简版 JSON，不再附加文字前缀或嵌套旧业务消息。简版仅含 message、retryable、
  requiredActions、agentInstruction、issues；issues 每项仅含 path、message，必要约束与修正方法
  合并到该项 message，有实际非阻断调整时可附加同形状 warnings。不得附带内部阶段、模型调用标志、
  原始参数、冗余元数据或完整诊断对象。停止结果不展示模型修复过程，只说明失败原因及停止动作。
  单项说明按已确认的错误类别组织，不机械拼接原因、expected 和 repairInstruction。未声明字段
  直接指出字段名并说明移除；已登记的包裹层、事件 ID 和动作模板错位须说明迁移目标，不丢弃
  实际业务值。类型、枚举和范围错误直接给出有效约束，移除重复的泛化修正句；必要的静态值、
  数值范围、模板固定值、权限或核心需求边界仍须保留，不猜测未知字段的替代名称。
  真实主 Agent 读取顶层重试控制和逐项说明，兼容旧版 error.details；不以简版缺少 status 或错误码
  判定为传输异常。此变更仅影响主 Agent 展示，内部错误码、准入及重试裁决保持不变。
  通用编排要求由在线 Skill 维护，响应按实际场景提示：绑定相关纠错才提醒
  复查权限，结构错误才提醒检查下层字段，有 warnings 时才说明非阻断影响；新建必填字段不夹带
  编辑继承说明，停止类反馈不夹带重调建议。此精简不删除必要约束或改变任何控制字段和调用预算。
  基于实际请求区分字段未传、显式 null、
  空字符串和错误类型；不能仅从模型默认值推断用户传了 null。当前阶段未检查或被外层错误遮蔽的内容
  不声明为通过，warnings 表示非阻断调整，不授权删去核心需求。内部参数恢复错误可附带已确认且脱敏的
  语法、结构或业务校验诊断；恢复耗尽仍明确停止，附带诊断不重新授予重试权限，不回传原始异常或参数值。
  内部可选 diagnostic 中的 issues.path 相对于解码后的业务对象，仅保留问题位置、原因、预期约束和来源，

  核心能力不可用、权限被拒或缺少必要业务值时沿既有停止或澄清流程，不承诺补齐后必定成功。
  此错误不触发微服务整轮重试、DSL 修复或产物保存；报告非法时沿原 Plan 修复预算处理，不能从普通
  Plan 校验失败推导补参许可。静态文字、固定事实与仅动作卡片无需数据能力，空绑定本身不构成缺口。
  编辑不开放该报告，不能借补参增加或替换原数据集合；接口不新增请求字段，不由微服务静默补能力。
- `userQuery` 表达本轮有效需求及采用的完整静态事实，不包含已移除或未经确认替代的功能。
- 数据候选必须来自本轮概述，业务参数符合本轮输入定义；写入路径合法且互不冲突。

  主 Agent 必须将本轮目标显式传入 `size`，不能仅写在 `userQuery`、继承旧值或被默认值、模型建议覆盖。

- `sourceArtifactUrl` 缺失表示创建，提供有效来源表示编辑；创建时不传空字符串代替缺失。
- 返回状态分为 `success`（完整成功）、`degraded`（部分满足）、`unsupported`（能力或协议不支持）、`failed`（工程失败），不能混用。
  编辑额外支持 `needs_clarification`（需澄清）和 `unchanged`（无需修改），不形成新产物或更新来源。

- 实际省略的信息通过可选 `omittedRequirements` 返回给主 Agent，仅用于部分满足说明，不授权补做生成；无省略时不输出该字段。

创建 `2x2` 单业务天气或单条日程卡时，目标唯一、参数可唯一对应、未禁止点击且没有其它必要动作的，

不补按钮或制造用户显式要求；显式按钮要求、列表多目标、`2x4` 和副作用动作不适用，编辑也不借此新增动作。

### 用户每日生成次数

三个生成接口的新建和编辑共享每日成功次数，查询接口不受限；功能默认关闭，上限默认 20。
Python 不直连数据库，通过内部 HTTP API 查询及记录成功次数，持久化和唯一约束由 API 服务实现。
查询和记录请求均使用 HMAC-SHA256 鉴权：AK 使用 `hag_osms_ak`，SK 从 STS 的
`hag.osms.sk` 读取，对 `x-ts` 的 UTF-8 字节签名并 Base64 编码到 `x-sign`，
同时发送 `x-access-key`。`x-ts` 使用 Unix 毫秒时间戳字符串。
每次请求重新生成签名；密钥读取或签名失败不发送请求，
查询失败按本次关闭限额处理，交付后记录失败直接降级；日志不输出密钥或签名。
开启后在 arguments 修复之前等待 API 返回成功记录快照，以原始请求的 uid 和 requestId 去重；
requestId 沿用 sessionId&interactionId 及现有兼容取值，不采用模型修复出的用户标识。
uid 或 requestId 为空时放行且不计次；上游须保证用户标识可信、同一轮重复调用的 requestId 稳定。
`daily_usage_uid_whitelist` 为用户 ID 的 SHA-256 十六进制摘要的英文逗号分隔字符串，默认空；
请求原始 uid 按 UTF-8 编码后计算 SHA-256，与完整摘要匹配，不接受明文 ID 或子串匹配。
配置各项去除首尾空白并统一为小写，空项和重复项不影响匹配；原始 uid 不改大小写或空白，
与每日次数 API 的 uidHash 计算规则一致。沿用入口原始 uid 的取值优先级，
在参数修复前判断；命中后不查询次数 API，生成成功也不计次，不受已有使用次数影响。
日志记录 `reason=uid_whitelist` 和不计次结论，不打印白名单或原始用户 ID；非白名单保持原限额逻辑。
每个用户每天最多一条汇总记录，唯一键为 uid 摘要 + usageDate，普通 TEXT 字段保存当天已计次的 requestId 摘要。
摘要为固定 64 位小写十六进制，以英文逗号分隔；Java 使用 String 接收，不依赖数据库 JSON 类型或函数。
此为 2026-10-23 确认口径，取代原需求草案中的跨天去重约定。
Java 在事务内锁定当天汇总行，解析字符串并精确去重，将新字符串和实际条目数一起更新后提交。
禁止无锁读改写；持久化字符串损坏或次数不一致时明确失败，不能清空历史记录后继续计次。
仅当天去重：同一用户当天已经计过次的 requestId 不受当天上限重复拦截；次日同一 requestId 可重新计次。
不复用生成结果。查询和记录接口的请求字段保持不变，列表字符串仅由 API 服务端维护，Python 不传整份列表。
仅业务 success、有有效产物、实际发送 AIWidgetEnd SUCCESS 未报错时记录一次，degraded 不计次。
指令关闭、开始指令未成功、结束指令发送失败及生成失败不计次；成功结束指令之后 final 帧发送失败不撤销计次。
日期使用北京时间的请求入口日期，跨午夜不改归属；按日期查询，无需午夜清零。
查询、放行及超限日志记录 remaining_count=max(limit-used_count,0)，表示查询快照时的剩余次数。
当前写入响应没有计数，不根据旧快照推算写入后的剩余次数。
API 服务须保证重复写入不重复计次，不做并发预占，允许不同请求同时通过检查时超额。
查询 API 超时、鉴权失败、网络异常或返回非法快照时，当前请求放行且不再计次；
客户端初始化失败或不可用也按本次关闭限额处理，不阻断服务启动或生成，不修改全局开关。
后续请求重新检查额度，仅正常响应明确超限时拦截。
超限与兼容保留的不可用错误话术分别取 Settings.daily_usage_limit_exceeded_message、
Settings.daily_usage_limit_unavailable_message。默认超限提示“今日 AI 卡片生成次数已达上限，请明天再尝试。”；
不可用提示统一为“本次卡片生成失败，请稍后重试。”，不向用户解释内部次数检查故障。
错误正文使用对应配置，主 Agent 提示要求向用户回复该话术并停止本轮自动调用，不包含更换请求标识的说明。
交付后记录 API 仅尝试一次，失败告警后继续最终响应，不重试、不改变已交付结果。
查询与记录分别受 daily_usage_api_timeout_seconds 限制（默认 3 秒），超时后降级；
同步 STS 签名在线程中执行，避免阻塞事件循环。请求取消继续传播，不当作 API 故障吞掉。
记录成功必须表示持久化已完成或已有该成功记录，不能只表示消息入队；不能保证崩溃场景精确计次。
每日次数通过 `ops_metrics.report_ops_metrics` 异步上报，沿用 sessionId 和
`ai_widget_data_huashan_enable` 开关。每次实际超限拦截上报 `dailyUsageLimitExceeded: 1`，
同一 requestId 再次被拦截也再次上报；每次写入 API 确认成功上报 `dailyUsageDeductSuccess: 1`，
包括幂等写入确认成功，不要求区分本次新增计次，因此该指标不等同于数据库实际新增次数。
前置查询命中已计次时不写入、不打成功点；白名单、限额关闭、身份缺失、查询故障放行以及写入失败均不打这两个点。
两类打点的 body 只包含对应指标和值 1，不附带 uidHash、原始 uid 或 requestId。
次数查询与写入 API 继续使用原有 uidHash 计次及去重，不受打点字段调整影响。
调度及网络上报失败不改变限额判断或已交付的生成结果。
上报不保证送达、不新增补偿重试；Java 打点接收服务只需支持两个新增指标字段，由接入方同步实现。
服务端发送成功不代表端侧确认收到。详细配置、SQL 和上线步骤见
[每日次数使用说明](../widget_service/docs/用户每日次数限制.md)。

## 能力裁决与数据真实性

数据能力、事件能力、素材能力分开注册，以 App/ROM 版本区间选择完整快照。
版本区间、默认回退和安装过滤范围通过集中配置维护；区间未命中时只有开启默认回退才可使用默认快照。
已发布能力快照不原地修改；新增能力必须同步方案、注册表、校验及测试。
协议 profile 由请求显式值或服务配置选择，版本对应关系由模型侧记录维护，微服务不从设备版本或原卡自动推导新协议。

能力概述阶段通过 IDS 查询已安装应用，只对配置范围内的依赖包名做精确匹配。
当前不据此判断包版本、provider、intent 或数据权限；生成阶段不重新查询 IDS，只检查注册状态、参数、路径和结构。
IDS 的 mock 与远程模式互不兜底，mock 缺失或非法不触发远程查询；概述只对配置范围内的依赖包做安装过滤。
IDS 远程查询按时间窗口进行指数退避，不再使用 `ids_request_retry_count` 限制次数。
`ids_request_retry_budget_seconds` 默认 10 秒，从首次远程尝试前开始计时，包含请求、签名刷新和等待；0 表示只请求一次。
`ids_request_retry_initial_delay_seconds` 默认 0.5 秒，`ids_request_retry_backoff_multiplier` 默认 2，
失败后的间隔依次为 0.5、1、2、4…秒；间隔必须大于 0，倍数必须大于 1，各配置必须为有限数值。
使用单调时钟判断窗口；若完整等待后已到或超过截止时间，不再等待或发起该次重试。
已发出的最后一次请求允许跨过窗口完成，成功仍采用结果；失败不再重试，因此总耗时可能超过配置窗口。
超时、连接失败、HTTP 408/429/5xx、响应无法解析为 JSON 对象时重试；其他 HTTP 错误及未配置地址不重试。
保持原 requestId 和查询正文，每次重试重新生成签名；单次请求仍使用原超时配置。
失败耗尽后仍返回空安装应用列表，不改用 mock；日志记录尝试次数、重试安排、恢复成功或终止原因。
主 Agent 只能从本轮概述选择数据候选，不能用历史缓存或静态事实补足缺失的核心动态能力。

天气云朵的选择偏好仅维护在对应素材的概述与完整说明中：普通天气或天气详情优先
`asset.ic_weather_monochrome`，随主题染成白色或黑色；`asset.ic_weather_color` 仅在用户明确要求
彩色云朵、蓝色渐变云朵或保留该云朵原色时选择，背景颜色偏好不构成选择理由。
这是模型候选选择指引，不强制替换已传入素材，不改变其它彩色图标的选择或原色保护规则。
后置主题另执行确定性资源门禁：最终前景实际使用 `ic_weather_color.svg` 或其登记的交付URL时，
整卡排除所有图片背景，包括主体图、抽象图和单图准入例外；模型返回图片ID也不能绕过。
仅列为候选、未挂载组件或文字提及不触发；单色云朵和其它图标继续按既有规则匹配图片。
命中后沿用合格普通主题与既有降级策略，不更换图标、不改变前景，Trace记录排除证据。

每项展示数据都须有可追溯来源：本轮可用动态能力、用户明确提供的静态值，或本轮已校验并采用的外部事实。
模型、生成工具、历史产物和示例不能承担查询或补齐真实业务事实的职责；首帧样例不代表用户实时数据。

### 动态数据与点击能力边界

下述分类用于理解支持边界，不是永久白名单；设备安装依赖和版本过滤后的本轮概述、完整 Schema
及事件模板决定实际可用性。候选选择、数据与动作的区分规则见 [在线 Skill](../skills/harmony-card-generation-online/SKILL.md)。

数据覆盖天气、日历、倒数日、蓝牙耳机、本机电池、运动健康、日期、应用耗电与当日使用排行、通话和备忘录。
不得仅凭能力名称扩展范围：天气限国内区县及声明预报天数，运动汇总不代表实时心率，电池状态不代表最大容量，日期输出不保证秒级时钟。
天气预报按端侧刷新时的日期解释：`forecastDays` 表示从明天起返回的预报天数，不是目标日期偏移；
`daily[0]` 对应明天、`daily[1]` 对应后天，不包含今天。明天预报使用 `forecastDays: 1` 和第 0 项，
日期、星期、天气及气温均引用同一项；当前天气使用 `current`，不把预报第 0 项当作今天。
点击按打开页面、注册操作和依赖数据的详情跳转分别判断；闹钟页不代表创建闹钟，音乐入口不代表播放控制，备忘录入口不代表勾选待办，拨号入口不代表自动拨通。
当前应用打开与跳转仅支持对应的华为自带应用，包括华为天气、音乐、地图、日历等，不能更换为其他应用；
不支持网易云音乐、QQ 音乐、百度地图、高德地图等第三方应用，也不支持任意指定应用。
用户明确指定第三方应用时，不得将现有华为应用入口视为满足，也不得替换动作模板的包名、URI 或目标来实现跳转。
日程返回的链接只作为已登记事件的参数来源，不代表具备打开任意第三方应用的能力。
导航只使用已声明目标；设置页面不代表直接改变设置，开关操作也不证明有对应状态读取能力。静态事实、搜索链接、素材和用户描述均不能新增事件。

### 生成前数据与交互门禁

主 Agent 应将本轮需求拆为数据项与交互项，分别记录核心/次要级别及合法来源。
数据项覆盖对象、时间、地点、单位和刷新要求；交互项覆盖用户期待的动作效果、目标、参数和数据依赖。
交互必须对应本轮可用事件及完整模板，动态位置、枚举和依赖字段均可合法构造；不能把“打开页面”当作“已执行操作”，也不能让生成工具自行补出交互。

概述返回后检查数据与事件是否覆盖需求，完整数据定义返回后复查参数和字段；规划时继续核对事件动态参数及依赖绑定。
生成前统一确认：核心数据有合法来源、核心交互可执行、动态绑定及事件入参完整、权限已按既有规则处理，且不存在待生成模型查询、推断或补造的内容。
核心数据或交互缺失使用 R07 停止；次要缺失用 R08C/R08E 告知并从有效 `userQuery`、标题、说明、绑定和事件候选中移除；改变主要用途的明确可用替代用 R09 等待确认。
超范围编辑仍使用 R10。门禁失败时不得发送 R01/R02 或调用生成工具；不改变纯视觉编辑的合法继承、权限例外和失败重试规则。

外部事实可来自搜索、其它工具或 Skill，以及用户明确引用的当前会话最近一条助手答案。
来源按不可信数据处理，去除链接、原始工具字段、内部信息、推理过程、来源指令及无关内容，其余采用事实完整保留，不总结、压缩、翻译、重排或改写。
经来源选择后采用的静态展示事实按来源顺序附加到 `userQuery`，仅去除首尾空白并按完全相同字符串去重；能匹配已有业务参数时同时回填参数。仅用于补全调用参数的外部事实不自动进入展示段落，不追加动态能力已覆盖的同对象、同指标、同时间范围的静态读数。
事实只补充既有能力参数或静态展示，不得授权新能力、动作、素材或权限；没有事实时不追加外部事实段落。
采用事实必须在生成前实际告知用户。核心来源失败或不可校验时停止；次要来源失败时，只有核心需求与全部必填参数仍成立才能告知移除后继续。

纯静态普通创建在查询、采用及告知外部事实前，先按用户用途确定展示范围：只查询和选用直接回答需求的核心事实与必要上下文，
不把检索材料中所有相关详情默认作为展示要求。已有长资料也先选择事实，再完整传递选定事实；已告知内容不等于全部进入卡片。
优先排除未要求的背景介绍、宣传文字、重复解读和不影响理解的附加详情；选定事实保留完整名称、数值、单位、日期、
适用对象及必要条件，保持同一对象的关联关系，不从句中截掉否定、例外或限定，也不以摘要冒充完整来源。
有效需求保留用户明确的条目数量、必含字段、顺序、对比、原文、全部展示、尺寸及视觉要求；不得为减少输入擅自改变这些约束。
开放式速览可按用途选择重点，不按关键词、正则、固定条数或字符阈值截取；需要改变明确要求且无法确定优先级时，
生成前用 R05 确认一个展示重点并等待，不把已取得的事实说成不可获取，也不承诺缩减后一定可生成。
这一步只缩小输入事实范围，选定事实仍按原顺序完整传入，展示摘要和实际容量裁决仍由静态 Plan 与布局校验负责。
动态、混合动态及编辑保持原事实传递规则；不新增请求字段、模型阶段或容量失败反馈。

## 关键契约与端侧刷新

| 契约 | 定位 |
| --- | --- |
| `CardSpec` | 微服务生成的端侧运行配置，包含静态展示元信息、建议尺寸、数据绑定和写入路径；不承载点击事件 |
| `TaskSpec` | 微服务构造的模型输入，包含有效需求、尺寸、投影数据结构、事件及素材候选；不让模型自行挑选未裁决能力 |
| `genui` | 最终标准 A2UI：依次为 `createSurface`、`updateComponents`、`updateDataModel` 的三行 JSONL，surface 一致 |
| `artifact` | 完整交付文件，以具名 Markdown 代码块保存运行配置、标准 DSL、模型上下文、候选计划和版本等信息 |

模型输入数据结构直接投影自能力输出定义及写入路径，不设置另一套运行时字段重命名层。
能力输出的展示文字叶子可用 `numericSource` 显式登记同一对象内的数值兄弟字段名；注册表加载时
检查该字段真实存在且为 number/integer，不按名称、描述或样例推断关系。预检通过后，微服务
在构造模型输入前为已选展示字段补齐该数值字段，保留字段顺序、去重及原始请求，不新增能力、
调用或权限。数组关系只补齐同一下标对象，不跨对象取值；字段级权限不得因补齐而扩大。
补齐字段及投影后的绝对数值来源记录在有效上下文和日志中，仅供图形驱动，不新增必显事实。
进度图形绑定必须指向有效数值字段，展示文字与驱动值必须符合已登记的同对象同指标关系。
缺少合法数值来源时应改用完整文字；用户明确要求图形而无法满足时按现有失败或不支持流程处理。
当模型把已登记 `numericSource` 的格式化文字误绑到进度主值时，校验反馈必须给出展示路径、
目标数值路径和可执行修法；修复只替换数值绑定并分离静态单位，保留原进度视觉、素材和其它合法属性。
禁止将动态格式化文本按首帧解析后写入私有数据树作为进度来源；这种副本没有运行时依赖，
不能随端侧刷新。直接绑定、模型修复、模板转换及最终产物均不得用此方式绕过数值类型检查。
静态字面量可按组件合同转换；动态文本转数值只有在未来正式登记并实现端侧重算协议后才可开放。
必要的事件参数字段也须进入生成上下文；动态表达式、单位、动作与素材使用位置受协议和校验约束。
动态值不能因存在样例而改为静态文案，不能在能力输出路径下新增未授权字段；图表驱动值与可见读数必须属于同一对象和指标。
单位按能力声明展示：未带单位时补且只补一次，已带单位时不重复追加。表达式单位校验只将动态字段
相邻的拼接字面量归属给该字段，允许单位后跟空白或标点分隔符，不新增业务文案后缀名单；
静态标题、名称或其它独立文案中出现相同单位字符时不得计为重复，
例如“2天1晚”不属于后续倒计时字段的“天”。标题、说明及按钮文案不得承诺有效需求与候选之外的功能。
写入路径必须位于 `/data/...`，不能相同、互为父子或相互覆盖；静态卡可不含数据绑定，最终尺寸仍按需求裁决。
Form 事件仅使用 `onClick`、单个 handler，不引入 `condition`、`as` 或 `$context`；动态绑定只出现在协议允许的位置。
EventCard 可在 `items[].onClick` 声明对应记录的详情入口，转换后仅由该条目的外层区域承载；
未声明点击的历史组件保持原展开。详情优先与对应日程区域合一，不重复生成同用途按钮；明确要求独立按钮时保留按钮。
入会、导航等独立操作仍沿用动作按钮，受限的单对象整卡点击保持原规则。
条目点击必须完整匹配本轮候选，且展示绑定和详情参数属于同一数组记录；不从标题或样例值猜测归属。
同一事件 ID 对应多个不同参数时，Plan 使用本轮候选序号派生的内部引用区分实例，不能覆盖为最后一个；
该引用只用于规划与履约，公开能力 ID、请求及端侧 handler 不变。候选不自动成为必选动作，
选入的条目动作仍须完整履约，不因已有独立按钮而豁免。此扩展不改变容量、主题、重试预算或其它组件。
模型源图片只来自有效素材或用户明确提供的本地资源，禁止网络图、内联/base64 SVG 和未声明路径。
CardSpec 不替代运行时 DataModel；TaskSpec 顶层不扩展非协议字段，样例须脱敏，不能将标题、说明或整套视觉规则塞入其中。
新增组件、属性或表达式能力须先有协议、转换与校验支持，再写入提示词，不能仅通过提示词扩展协议。

artifact 先写 `cardspec`、再写 `genui`，解析按块名识别；当前可编辑产物采用 `widget-artifact-v2`。
完整候选计划用于编辑继承，不能替代本轮最终配置与裁决。产物及关键配置必须记录版本；主 Agent 可见接口不暴露版本元信息。
版本、来源摘要及诊断信息供追溯使用，
产物摘要不是端侧下载文件完整性校验契约；元数据不记录完整永久来源 URL。

端侧最小依赖为 `genui + CardSpec`，不依赖云侧模型上下文进行刷新：

```text
读取数据绑定与刷新计划
  → 调用端侧数据能力，取得符合输出定义的结果
  → 以 writeResultTo 为 path、能力返回值为 value 构造 updateDataModel
  → 注入对应 surface，由数据绑定触发组件重渲染
```

运行时刷新不要求再次调用生成云服务，也不重新生成组件树或改写下发契约。

## 生成方案

### Fusion 主链路

静态创建的阶段输出先检查形状及类型，再进入兼容归一化；错误阶段的 Plan 对象不能从内部数组提取成
DSL，非法组件类型必须作为转换错误进入既有修复流程，不得泄漏为未捕获的程序异常。
Plan 修复保持与首次规划相同的忠实摘要权限，并一次反馈可独立检查的结构问题及准确路径；分组索引
只引用本次提交的展示事实，不引用来源条目，不由程序猜测或重排。JSON 错误提供解析位置，不猜补内容。
有限静态试排在当前语义组件与固定标题/内容区内组合，保留展示文字、对象归属与顺序；
候选通过相同覆盖、完整文字及空间校验，使用组件固定文字规格，再考虑合法的可选省略。
没有候选、候选均失败及已证明的合同冲突分别反馈，不以有限搜索失败宣称需求全局无解。
上述优化不新增模型阶段、业务识别、公开字段或重试次数，不放宽组件数量、文字保护与宽高门禁。

Plan 的非容量结构修复只处理可证明无歧义的封装：完整 JSON 外的单侧代码围栏可以移除；
误放顶层的已知 Plan 参数只在单调用、无重名冲突时移入 arguments，之后仍执行本轮完整字段和语义校验。
内部 JSON 标点、未知字段、多调用及冲突值不猜修，反馈错误位置、短上下文和字段应在的路径。
静态分组失败沿用原 Plan 修复预算，附本次提交的事实索引、分组归属及省略声明账本，
使模型同时修正事实、分组和省略记录；程序不根据自由文字省略说明删除事实或推测对象归属。
账本区分待修错误与主链路已确定性恢复的提交：Action 移出正文组、冲突文字移除和无效省略授权撤销
仅记恢复说明，不再列为阻断问题；剩余文字仍须满足唯一分组。来源引用要求沿用本轮静态来源合同，
不把无显式事实段且无原文保护时的缺引用 warning 重新升级为错误。Plan 省略声明不等于后段受控 Drop 授权。
重复展示优先无损去重和信息组内修复；仅当诊断明确同一事实占据多个必填展示槽时，允许调整这些槽
所在的必要父布局，重新分配已有独立事实或采用合同允许的组合。不得清空必填槽、虚构事实或无条件
重建整卡；没有必填槽冲突的普通重复继续保持局部修复。所有候选仍执行完整覆盖、动作、组件及容量校验。
当同一事实同时出现在 InfoBlock 必填文本与其它组件时，修复建议优先保留 InfoBlock 的完整展示，
从其它组件删除可合法移除的重复属性或条目，不把 InfoBlock 改绑到另一项已展示事实。
删除不得破坏组件最少项数、必填属性或父槽合同，也不得连带删除独有信息；没有合法删除位置时，
仍按既有范围重组必要信息组或父布局。本项只补充修复指导，重复展示继续按 error 处理。
小卡双动作骨架的固定约束必须由两项不同的真实必要动作支持，不能仅凭 layoutHints 锁定；
事实不满足时移除错误的双动作候选，不复制动作或替模型指定其它骨架。合法双动作计划保持原行为。

普通 Compact 创建通过 `enable_static_content_generation_policy` 启用开域静态策略，默认开启。
仅预检通过且原始/有效数据和事件候选均为空的普通创建进入；Action、动态、编辑请求保持原能力型路线。
静态内容为制作时快照，不支持Action或动态绑定，不静默移除请求动作后进入静态。

静态Skill按Core、信息、组件、固定外框、综合流程及阶段合同分工；Common加当前尺寸加载一次，
维护用YAML不发给模型。Plan、DSL、Repair沿用已有消息历史与调用预算。
Plan省略声明的全部事实索引可可靠映射、但因must或原文保护而撤销删除授权时，仅保留诊断警告；
不将该声明转成已确认的最终遗漏。实际损失仍由最终覆盖核对报告；索引无效或归属不明的旧保守反馈不变。
模型在Plan内理解、忠实总结、确定对象归属及主次，提交最终展示文字、连续来源引用、对象名、
contentGroups与真实遗漏；程序核对来源、原文保护、对象归属、展示覆盖及容量，不证明摘要真实性。
首次Plan上下文必须同时给出当前尺寸可用的静态正文组件、标题组合与真实条目上限。模型在首次提交前
先按信息形态选定一种正文结构，再将对象条目、是否保留公共标题及公共正文说明纳入同一容量预算；
任何最终渲染为正文行的内容（包括shared公共说明、例外和提示）均计入该组件的实际条目数，
不得因其在Plan中不计object组数而在DSL中额外新增一行；
“静态正文最多五个对象组”只是账本上限，不代替TextList、SingleLineList、ComparisonGroup及
EmphasisText的具体承载上限。超出选定组件的容量时，应在首次Plan内按priority取舍完整低优先级对象并
记录遗漏，不等到冻结前重规划才首次告知真实容量。冻结前重规划仍作为容量估算、文字宽度或完整性校验失败时的安全兜底。
若userQuery含“本轮卡片静态内容（用作展示的外部事实）”段落，来源引用限于该段，
段前需求只用于确定用途，不反推未获设备状态、读数或动作。已有事实可以成卡而其它独立展示期望
缺少事实时，保留已获事实，将未支持的独立内容以factIndexes:[]记入omittedContents，不为该部分报告数据缺口。
没有显式事实段时沿用本轮输入来源合同；来源可追溯不等于摘要语义正确。

普通静态Plan首次提交结构合法后，冻结前使用原有第二次Plan机会复核原始事实源与实际可见文字，
并合并已有容量细化反馈；仍最多两次Plan调用，不增加第三次或新模型阶段。原先一次接受的请求
会多一次实际Plan调用，Trace单独登记。复核按同一对象的名称与全部展示字段共同判断，
requirement、sourceTexts或规划说明有某信息不代表该信息已经展示；必要地点、日期、数值单位、
范围、条件、否定及替代关系不能通过摘要悄然弱化。
内部复核返回decision（keep/correct）、sourceFidelity（preserved/needs_correction）、findings及
修正时的完整correctedPlan。keep仅允许preserved且无问题证据，直接沿用原解析结果，避免抄写变更。
复核消息只保留当前系统合同，将首份提交作为待检查数据放入复核请求，不继续携带前一轮
要求直接输出submit_card_plan的用户指令与assistant示范；原输入、有效事实源和首份计划仍完整提供。
needs_correction在输出Schema中要求至少一条问题证据；解析失败保留现有失败行为，并在普通日志
记录具体复核异常，不仅写Trace。不新增复核调用或将格式错误视为通过。
Plan来源引用失败的既有修复消息明确提供当前有效事实段；标题同样只能从该来源引用，
不能用事实段外的制作指令充当事实。程序不自动补引文、不放宽来源门禁。
动态修复中重复事实、缺失动作与容量指导独立组合，不能由互斥分支遮住另一类错误。
动作交接沿用候选实例映射，列明完整参数及允许承载：仅合法日程详情可进入EventCard条目，
其它独立操作使用按钮，已接受的整卡点击仍由root承载。不改动作、布局或覆盖校验。
needs_correction必须列原输入可追溯的sourceText、原事实索引（原Plan全漏项允许空索引）及问题；
复核findings使用factIndexes引用首份归一化计划，完全漏项使用[]；修正版的omittedContents
继续使用factRefs引用组内稳定事实标识。提示、复核Schema与解析器须区分这两种引用结构。
修正版仍通过原Plan来源、分组、保护、遗漏与试排合同。复核格式错误、矛盾或超时不当作通过。
若correctedPlan违反Plan合同，或复核前Plan已有可行试排而correctedPlan没有可行容量候选，
直接丢弃correctedPlan并沿用复核前的合法Plan，不区分preserved或needs_correction。该回退只防止
复核将已可排版计划改为不可排版计划，不代表原Plan的语义完整性已获证明；仍执行后续DSL生成、

当前诊断能定位到某条文字或条目时，容量证据按已接受分组关联到本轮仍可见的事实，只在这些事实
内先选should、再选低顺位must；不以删除其它未溢出条目代替修复。累计已批准索引参与下一轮映射，
每轮从当前源重新定位，不沿用删减前的位置。不能证明归属时不猜测对象或借同值事实授权删除。
每次仍只批准一条事实，保留本组其余名称和字段、保护原文及至少一个正文对象；确实损失的信息
按既有流程记录降级。候选已移除后才能推进下一次授权。
静态容量修复有一个重新定位例外：旧候选的全部事实在当前源中已按原对象完整可见，且不属于本轮
确切容量影响范围时，可撤销这些事实后续允许省略的资格，再从当前受影响事实选择唯一候选；
这不是累加新的无关删减许可。当前仍缺失、仅部分恢复或归属不明的授权不得撤销，其它已批准的
实际遗漏继续保留。此前各轮的授权、实际遗漏及Trace审计不改写；曾经遗漏后完整恢复的事实按
当前覆盖状态处理，不要求再次删除已经放下的内容。该重定位不增加修复次数或重置原预算。
静态接口容量恢复沿用已经计算的保留与省略事实清单，将其完整传给下一轮Plan；关闭运行时组合
上下文不关闭这份恢复账本。模型可以重选分组与合法组件，但保留清单的text和priority仍须原样
落实，不能重新加入省略清单，也不能以普通摘要规则改写已冻结事实。首次Plan和动态恢复提示
保持原样；不增加调用或放宽恢复Plan的事实匹配。
恢复账本还须区分实际文字缺失与归组失败：完整已接受文字仍存在于任一单条可达展示内时，即使
当前对象映射失败，也继续列为必须保留的信息，交恢复Plan重组，不登记为可排除内容。不跨不同
条目拼接碎片，不借孤立节点证明存在，不改变原对象归属或通过判定；解析失败保持原异常语义，
不得推定为实际缺失。同值在其它对象内完整出现时保守保留，宁可继续修复，也不扩大删减许可。
有界试排先保留原能通过的候选；首选形态不可行时再尝试其它现有合法形态及组件内部公共说明落点。
原有候选之后，可将已存在的公共标题与公共说明按声明顺序完整合放在现有SingleLineTitle中，
正文对象和事实保持不变；没有公共标题但存在shared/body原文时，可将该原文放在同一独立标题槽，
不编造标题或适用范围。多对象候选不再把公共说明轮流拼进某一对象字段；单对象副文承载保持。
此候选仅用于失败后的有限试排，仍须通过
完整文字承载、语义归属和Artifact布局检查。标题超宽即放弃，不截断、缩字或改变组件合同。
显式展示形态优先于旧componentHints建议，实际DSL仍执行完整组件与容量校验。不得伪造标签、
拆残事实、改写文字或变更组件UX以制造可行候选；有限试排失败不等同于全局无解。
新增恢复候选额外复用组件实际宽度与固定文字规格检查全文承载，不能利用原组件的省略号行为制造
无损恢复假象。该检查只在候选试排作用域生效，原候选、已成功源和正常组件展开样式保持不变。
Plan试排对原合同允许省略号的合法候选也执行一次完整文字承载诊断，将被隐藏的宽度或行数压力
作为软反馈交给原有剩余Plan机会；仍返回原合法候选，不新增发布门禁、不改正式省略号UX、不据此
授权删除或自动替换布局。反馈需明确区分“组件合同允许省略”与“完整信息尚未显示”，不能把空错误
误当作全文已排下。已完整承载的原候选与正常转换结果保持不变，最终仍按原输入及真机验收。
若原合法候选仅因省略号隐藏完整文字，且未省略事实，可额外试一次既有单行列表的同对象连续行：
每行沿用该组原identity及一条完整text，不拆句、不猜标签、不换组、不改变文字规格，公共信息仅
使用原有合法标题位置。该候选须通过既有对象续行映射、全文宽高与完整覆盖；仅通过后在Plan试排
中替代会裁省的参考。已完整显示的原候选仍优先，无法完整承载时保留旧候选及压力反馈，不放宽
原省略号合同，也不把受控试排失败升级成新增发布门禁。最终成功DSL不因此自动重写。
参考画布仅用于开发验算，不推断真实宿主尺寸。转换后主题保持文字与前景结构，统一渲染用于视觉检查。
详细合同见[静态语义组件方案](静态语义组件与固定内容区方案.md)。

能力型路线中，由Runtime Recipe明确标记的EmphasisText.main固定强调主文，其单行宽度检查
复用既有组合规划文字估计，避免已确认的大字硬裁仍按更窄估计放行；不依靠组件ID、业务文案或
机型猜测角色。普通Text、SummaryList等其余文字继续原保守估计，不把强调主文的压力模型推广到
所有字体。未知宽度、未知绑定仍不猜测；静态组件继续自己的实际规格与省略号合同。估计只作为
参考区域内的容量诊断，不等同于端侧字体像素测量。
已定位到固定单行强调文本超宽时，沿现有容量修复链反馈完整原文、原字号及宽度；允许在原文字
完整边界使用同字号的合法组件分行，并在必要父布局内选择原已登记的容纳方式，保留其余事实、
绑定及动作。不能给固定单行组件添加不支持的多行属性，或只改间距。
2x4能力型路线的EmphasisText主文超宽且尚无secondaryText时，可建议模型重排同对象主次字段：
仅当原输入已有可承担核心语义的名称或状态，且用户与已接受Plan未要求原值保持大字强调时，
允许把完整原mainText移入secondaryText，以已有名称或状态作为18fp mainText；不得编造结论、
覆盖已有次文本或丢失原值、绑定与Action。次文本沿用12fp单行Recipe并继续执行完整宽高校验；
没有合法主文本来源或仍放不下时，继续使用同字号分行或合法布局重组。2x2原显示规格保护不变。
程序不自动猜测字符串的语义切分、不生成重排DSL，也不增加调用或删除授权；重新生成后仍须通过
全部组件、事实、动作和容量检查。原成功未触发此诊断的修复路由保持不变。

### 模板及其它路由

- `FullIconActionLayout` 仅允许完整模板 ID 命中视觉验收白名单的 Full 模板，与一个语义匹配的
  `IconAction` 组合。白名单以同版本布局、动作和业务模板的真机截图及检查记录为依据；失败、
  未验收及仅支持宽卡的模板不得入选。用户可基于已有截图人工确认纳入，覆盖初审结论；须记录确认
  来源、日期及原始重叠/边界观测，不将人工确认记为告警消失。模板或布局源变化后须重新验收。
  Planner、二层候选和编译入口
  使用同一准入条件；无合格候选时保留原有其它布局及不匹配处理，不删减用户内容或补造动作。
  专项验收生成器仍须枚举全部 Full 模板，不能用白名单过滤待检查对象。
- `2x4` 的 Hero/Full 与单个 Compact 组合采用两个独立合同：`WideHeroCompactLayout`
  的 children 顺序固定为 Hero、Compact、PillAction，左列上下排列 Hero 和唯一按钮，右列垂直居中显示
  Compact；按钮必须来自已批准的 Hero 业务动作。`WideFullCompactLayout` 的 children 固定为 Full、
  Compact，左列完整展示 Full，右列垂直居中显示 Compact，不接受动作。缺失按钮的 Hero + Compact
  必须拒绝；无动作请求只能选择字段覆盖完整的 Full 组合，不得补造动作或仅改名冒充 Full。
  此修订不改变其它已登记宽卡组合的独立合同。Planner、二层候选、编译校验和画廊应一致遵守。
- 普通 Compact 创建可按配置先尝试受控模板；模板模块只负责源 DSL，不负责能力裁决、最终配置、完整产物校验或保存。
- 模板二层输出完成编译及图片后处理后，按当前版本能力清单传入的素材说明清理图标染色：
  明确要求保留原色、禁止染色或禁止 `fillColor` 的素材，移除 Image 顶层及 styles 中的 `fillColor`，
  包括嵌套组件；沿用位图去色规则，可染色 SVG、动态素材绑定、数据、动作和其它样式保持不变。
  该处理位于模板返回及公共格式转换之前，不新增模型调用或校验重试，并记录普通日志中的清理数量。
- 模板图片在定稿 A2UI 生成后接入公共图片匹配及后处理，不新增 LLM 调用，不重新编译或改动前景布局。
  模板和 Fusion 从同一份 `data/post_layout_themes.json` 发现图片；取消逐图业务模板/骨架映射与独立准入规则。
  两条链路只负责将定稿转换为受信内容事实，公共算法统一裁决业务、行数、布局、特殊规则、图标排除、
  优先级及同级随机分配。新图使用已支持的规则时，只增加公共图集配置，无需修改模板或维护第二份图片清单。
  模板预选保留原有字符串颜色判断，兼容逻辑限定在模板内部；不依赖 Fusion 已移除的原文解析接口，
  不将原文直接传给接收结构化偏好的新接口，也不改变融合的偏好理解流程。
  模板适配根据实际 A2UI 树和编译器记录提取主区、标题、背板及主题样式归属；缺少证据时拒绝图片，不按文案或像素猜测。
  单子节点包装仅在对齐约束等价时展开，顶部占位分析保留原始纵向锚定；上下主区不套用左右双辅助背板条件，
  唯一确认的标题可在主区定位时排除，仍保留其交付节点；不能唯一确定主区时继续拒绝。
  公共后处理统一使用登记配色、背板材质、图片加载兜底和 OBS 交付，保留原色图标与显式自有颜色。
  模板布局按既有例外移除背板时，同步撤销该容器的主题背板标记及背景色归属；图片后处理不得重建
  已移除的外层底板。内部业务面板、按钮、进度环轨道及其它样式归属保持不变。
  不改变原内容、绑定、动作及几何；图片应用或地址映射失败时保留原模板结果。外层仅通过生成器门面登记已选素材，
  用于原有完整产物校验和编辑恢复，不接触模板内部实现、不传递主题标志，也不执行图片地址替换。
  图片背景与原 `template_root` 保持根节点下的兄弟关系，复用既有模板质量和单位缺失豁免；
  不为通过图片主题校验拆改业务模板；图片仅替换背景层和主题材质，保留根节点及完整模板内容树。
  旧模板的文本左对齐枚举仅在只读准入事实中等价适配，交付前景不改对齐、边距、容器或业务文案。
  固定布局模板展开深度上限由 9 放宽为 10，支持原始双耳机组合；其它编译预算及公共协议、数据、事件、素材检查保持不变。
  图片主题专项回归保留在本地验证，不提交独立测试目录；CI 沿用既有工作流和路由测试。
- 模板不匹配、内部策略耗尽、适配失败，或模板返回后的公共处理与校验失败时，从原始有效需求重新进入 Fusion Plan。
  不带入失败模板的裁剪结果、错误上下文或校验豁免；外层不再调用模板，不占用 Fusion 修复额度。保存或上传失败不触发重生成。
  该回退不依赖质量修复开关，也不转入已废弃的 JSX 路径；模板内部重试策略保持独立，成功结果复用已完成的转换与校验。
- 独立 `generateWidgetCardTerseDslNested2` 创建仍为严格模板入口，不匹配时失败，不自动切 Fusion；
  来源编辑走统一编辑路线，不实例化或调用模板。关闭新编辑及受限字段编辑开关时仍拒绝该入口编辑。
- 标准 A2UI 和单步新建兜底保留独立路由或配置边界，不能根据共享处理器名称推断实际来源。
  单步新建兜底独立默认关闭，仅开启且融合实际完成至少 5 次质量修复仍失败、满足条件时额外生成一次，不再自修复或递归兜底。
  该路线复用独立冻结的单步提示词与转换器，只接收原始有效需求与候选，不带失败 DSL、Fusion Plan 或修复历史，不套用 Fusion 专项门禁，末尾交接公共主题并完成完整产物校验。
  鉴权、模型网络、能力前置、来源读取和存储失败均不触发单步新建兜底，模板专用入口也不接入。

### 布局与后置主题

Fusion 固定先完成无颜色布局的生成、重组、转换及校验，再冻结布局并选择主题。
布局阶段保留语义样式角色，不提前写入实际颜色；主题阶段统一解析角色、填色并按配置执行完整产物校验，交付不能残留角色引用。
主题失败从同一份布局定稿尝试兜底主题，不通过改布局、删内容、缩字或修改动作提高主题命中率。
程序先筛选合格主题，模型只从候选 ID 选择，不能自由输出色值或选择未准入主题；用户明确颜色要求优先。
最终前景结构须保持不变，主题阶段失败不触发布局模型重试；主题配置集中维护于 `data/post_layout_themes.json`。
图片总开关默认开启，合格图片优先，不以随机抽样决定是否使用图片；图片不命中时沿用普通主题与融球的原有准入规则。
`2x4` 不提供融球候选，无合格图片时使用浅色纯色渐变；`2x2` 仍须满足业务、版本、单内容组、事实与动作数量等门禁才可选择融球。
模板、历史 JSX 及原卡编辑遵循各自流程，不能因同用 Compact 入口而误入 Fusion 去色和重绘。

视觉约束保护必要事实、单位、关键文字及点击热区；修复优先调整合法组合与布局，不能用静态化动态值或无授权删事实消除溢出。
只有既定修复策略可授权事实省略，全部已接受 Action、handler、动作素材与动作槽始终受硬校验保护；warning 本身不授权额外删减。
`2x2` 已接受 Plan 恰好只有一个 Action，且至多包含一个明确标题事实时，`S-title-content-action` 可显式使用
`title-action` 变体：根语义 children 固定为 `[SingleLineTitle, PillButton]`，程序展开标题和沉底动作，
不设置正文槽。标题事实必须标记 `displayRole: title` 或首选 `SingleLineTitle`；该例外只解决纯入口卡的结构表达，
标题和唯一 Action 仍须完整保留；存在任一正文或 dataId 展示事实时必须使用原 `[title, content, PillButton]`
结构，不得借此省略已接受事实。

云侧不知道 `matchParent` 对应的真实卡片宽高，不能硬编码机型或按 `2x2/2x4` 猜测实际像素尺寸。
背景使用自适应尺寸与归一化区域；图片来源受控，按当前定稿业务、正文行数及结构进行准入，
不以未知像素尺寸承诺避让安全。开发渲染必须显式提供测试视口，结果不等于真机显示或线上避让通过。
区域自适应是参考几何到 `matchParent/layoutWeight` 关系的等价编译，承载区随父区分配，字号、图标、行高与组内间距等固定设计量不整体缩放。
源布局仍须先通过参考预算检查，不能指望更大的未知宿主消除溢出；未知区域不当作已匹配，也不承诺任意更小容器可完整容纳。
图片扩宽属于独立、默认关闭且当前无可用素材的实验，不是普通主题或模型自行改变卡片尺寸的授权。

### 图片与前景配色

## 多轮编辑

编辑继续使用正式生成接口。主 Agent 只提交本轮修改需求、有效来源及必要显式参数，不下载原产物、不拼接历史 DSL。
微服务读取并检查来源，继承省略的字段与候选，再按本轮上下文重新校验。
候选数组缺失表示继承，显式数组表示替换整个类别，空数组表示清空；这是请求表达语义，不代表当前编辑支持相应变更。
当前版本不支持删除部分或全部数据，已有参数调整须保留相同数据能力及写入路径；用户明确修改的公开参数应显式提交。

语义编辑默认开启，独立于首次生成编排：以已展开、已应用主题的原卡建立内容与行为保护基线，
先解析编辑意图，再按接受的范围执行属性补丁或布局编辑。用户 query 不设修改动词、颜色名称、
数字或多目标正则门禁；模型输出仍检查结构、类型、协议枚举、原值及实际修改范围。
支持尺寸 2x2/2x4、颜色、相对或绝对字号、局部样式及整体视觉风格；修改尺寸必须重新布局并同步
运行配置，不以根宽高、背景透明度或整卡等比缩放冒充尺寸适配。未知真实宿主尺寸不作几何保证。
局部编辑允许计划明确列出的容器、背景层等必要联动；其它区域、原有可见事实、动态表达式、单位、
动作及业务素材受保护。纯视觉编辑不得删除业务信息或新增数据、动作和素材。
属性补丁与布局候选都在不可变原卡副本上执行，每次修复仍针对同一原卡；模型不能直接修改运行配置。
编辑结构检查覆盖容器与业务节点，禁止重复引用、多父节点、循环和缺失引用；列表模板按单条结构引用
检查，不展开运行时数据。原可见节点必须保持可达，新建容器不得孤立；来源已有重复挂载或循环时明确
按来源结构错误失败，不自动复制或展开修复。原有未变的孤立节点保留兼容口径。
原有动态样式及对象内部的动态子字段必须在原位置原样保留，不依赖模型是否登记目标；不得新增、移动、
删除或静态化绑定。含动态子字段的对象允许修改获准的静态兄弟字段，不能整体改写动态部分。
编辑字段值规则独立维护并同时注入模型合同，仅作用于本轮新增或修改的属性；未修改的历史兼容属性
保留。阴影、尺寸约束、布尔值、边距和圆角等均检查类型、结构及范围；约束只比较可确定的同单位数值，
不猜测宿主或跨单位换算。编辑专项规则不接入首次生成的公共校验流水线。
编辑从入口强制排除模板、JSX、Fusion 创建和自动主题重绘，失败或重试也不切创建。
完整产物协议、能力与内容保护校验强制执行；编辑不套用首次生成 Recipe、固定字号和布局偏好。
模板根标记不授权编辑质量豁免，历史未改变的质量问题保留 warning；新增或恶化的确定性低可读性
仍阻断，经验性视觉建议不触发修复。编辑专用校验统一归入 `card_validation/edit_validation/`：
`artifact.py` 负责产物与履约检查，`structure.py` 负责引用结构，`styles.py` 负责动态样式保护与字段值；
三者仅由编辑合同和编排调用，复用公共产物校验，不加入首次生成流水线，也不复制 Compact 规则。
固定高度承载区也检查子文字变化；放大字号造成的新增或加重高度不足必须修复，不能因父容器未变而跳过。
有最小字号时按可缩小到的下界检查，否则使用字号下界；历史未恶化的高度不足不借本轮编辑强制整改。
编辑提示词独立维护于 `data/protocol_profiles/semantic-widget-edit/`，按意图、执行、协议、视觉原则、
示例及修复分文件加载；不读取首次生成 Fusion、模板或冻结的 `widget-edit` 创建资源。
协议说明参考《鸿蒙桌面卡片A2UI协议完整规范》，实际可编辑字段与枚举由现有校验配置及编辑维度
规则生成并注入，两者交集决定本轮权限；完整协议允许但编辑尚未开放的属性只保留原值。
意图可登记明确属性目标 `expectations`：精确值、增大、减小、保持原值或移除；精确要求与明确
相对要求应登记，模糊整体风格不编造数值承诺。程序验证目标范围、静态属性和比较条件，并在最终
产物检查履约；不满足的无需修改结论须修复，执行未履约不得保存。此机制不解析用户 query 的正则，
也不构成独立语义判官，仍需评测模型是否完整理解和登记了用户要求。
提示词指导配色角色、字体与多层承载联动、长文案及尺寸重排，附编辑样例但不复用创建骨架。
只提供当前原卡与本轮要求，无法从当前卡确定的历史恢复请求应澄清，不猜测历史值。
编辑意图和执行质量修复使用独立有界预算，默认各最多两次；不支持、需澄清和无需修改直接结束，
分别返回 unsupported、needs_clarification、unchanged。后两者仅用于编辑，通过 editFeedback 给主 Agent
提供必要问题或说明，不返回新地址、不更新编辑来源，端侧以非成功结束关闭等待。
success/degraded 仍要求新的完整产物地址。编辑质量失败不触发接口整轮重跑；模型传输重试保留独立策略。

编辑模型响应兼容单个完整的 JSON、JSONL、genui 或无语言标记代码围栏，仅移除完整外包装，
不截取夹杂说明的片段、不补齐缺失括号、不改写内容；后续严格 JSON、重复键和编辑合同校验保持执行。
编辑来源读取、阶段开始、实际修复预算、每次校验结果、修复是否继续及最终失败原因须同时写入普通业务日志，
不依赖开发 Trace 开关。日志按单行结构化 JSON 记录诊断，不记录完整原卡、提示词或签名来源地址。

编辑总开关独立控制；关闭语义编辑后恢复受限字段或既有编辑路由，首次生成开关及默认行为不变。
受限字段回滚路线同样不使用 query 正则：修改语义由模型理解，原话引用仅供审计，不再作为词法授权。
该路线仍只接受原有五类字段，保留摘要、原值、字段类型和动态绑定保护；尺寸和整体样式继续由语义编辑负责。
在线 Skill 的范围门禁仍独立生效，
新增、删除部分或全部数据、跨数据能力替换、修改事件或素材候选时按 R10 停止，不自动转为创建。
不能把请求继承规则或旧编辑方案中的广义能力当作当前字段补丁已支持范围。

来源仅允许完整、可编辑的有效产物。读取或校验失败时明确失败，不静默转创建；每次成功编辑保存新对象与来源摘要链，不覆盖原产物。
来源下载的 mock 与远程模式互不兜底。远程读取复用公共下载方法，限制超时与大小且不跟随重定向；
来源仓库不做 URL 范围白名单裁决，调用方与部署网络必须保证来源可信，URL 不直接传给生成模型。
动态引用授权仍由完整产物的有效能力校验检查，不能依赖旧首帧值或整段字符串搜索判断授权；该校验不授权删除数据绑定。

## 校验与重试

校验贯穿请求、Compact 源、转换结果与完整产物；转换是必需步骤，关闭完整产物校验也不能保存未转换源 DSL。

- **生成前：** 检查请求结构、能力注册、业务参数、写入路径冲突、事件与素材范围，失败时不调用生成模型。
- **Compact 源：** 按语法与语义分类检查组件、表达式、绑定、信息完整性、动作归属和布局预算；复用公共合同与运行时。
- **完整产物：** 检查标准协议、运行配置、跨文件一致性、动态引用授权、有效能力与最终主题等约束。
- **修复反馈：** 区分错误事实、硬约束和可选建议，可靠定位原文；展开节点无法映射时不编造源位置。
  建议不能放宽规则或授权额外删减，修复结果必须复检。

`PillButton` 与 `CardButton` 的可见 `label` 最多6个非空白字符。Plan 继续保留完整 Action 语义和必要目标，
Compact DSL 仅把按钮可见文案压缩为简洁的“动作+必要目标”，例如“一键导航去公司”改为“导航去公司”；
不得删改 `onClick` 的调用、参数或真实目标。超限属于语义／展示的阻断错误，进入既有 DSL 质量修复循环，
只重写报错按钮文案，不重新生成 Plan，也不增加 `planContractAttempts` 或 `planContractRetries`。
该次模型调用仍计入既有质量修复预算，并在修复后重新执行全部校验。

错误按路由策略处理，warning 保留诊断但不进入质量修复错误列表。
Compact 路线中仍为 error 的问题按修复或失败处理；既定 warning 与受控事实降级不能误判为阻断错误。
标准 A2UI 入口保留校验错误可记录而不阻断保存的兼容行为，不能混用。
完整产物校验与各类重试开关独立，实际执行范围和预算须核对本轮生效配置，不能把仓库默认值当作线上配置。
Compact 创建在转换成功后、主题选择前执行公共单位校验；完整产物校验开启时复用其中的结果，关闭时仍执行单位专项检查。
单位错误进入现有质量修复循环，warning 不消耗修复预算；模板豁免与主题最终检查沿用现有边界，不新增重试层级。
程序不为修复单位覆盖日期等业务内容，也不新增组件属性；由模型在已支持的组件合同内组织展示。
在既有单位检查适用范围内，所有声明单位的缺失和重复统一按 error 处理，包括百分比；不按单位符号降低严重等级。
单位后跟空白或标点分隔时仍按实际声明识别，避免将已有单位误报为缺失。
自动去重只删除可安全移除的独立纯单位片段；带业务文案的字符串保留，由既有质量修复流程处理。
接口整轮重试将生成流程抛出的 `ValueError` 视为可重试异常，预算耗尽后继续抛出最后一次异常。

### 信息覆盖与容量修复

首次 DSL 对已接受 Plan 的 `must/should` 事实均执行硬覆盖检查；每个必显动态事实在可见信息位置恰好展示一次，数据行和事件参数不算展示，同指标图形驱动值不额外计数。
同一个可达 `EmphasizedData` 中合法静态 `value` 与 `unit` 共同显示的读数，按该组件内的完整文字
核对 Plan 覆盖，避免数值和单位分字段导致误报缺失；不跨组件拼接，不改写数字或单位，不把动态表达式
及不可达节点算作静态文字。实际布局、单位、绑定和重复检查仍沿原链路执行。
事实覆盖严格度由 `enable_drop_plan_fact_validation` 独立控制：默认关闭，动态与静态内容的第一次 DSL
均严格检查；进入第一次模型修复后，缺失的非 Action 展示事实降为 warning，同一静态分组缺失不得再由
Compact 专项校验重复升级为 error；同一请求进入容量恢复的第二轮接口时继续使用 warning，
不因接口轮次重置已消耗的一次硬覆盖检查；
开启时继续硬校验，仅豁免程序明确批准删除的事实。实际缺失均须记录并返回 `degraded`，不清空已接受 Plan。
进入 Drop 后仍沿用同一严格度：开关默认关闭时，修复过程中未获批的非 Action 事实缺失也记为 warning，
不再触发新一轮质量修复；它们仍须记录为未授权降级，不因为 warning 而追加新的删除授权。
开关开启时，Drop 阶段仍仅豁免当轮及累计明确批准的非 Action 事实。
动态绑定、标题角色及布局等其它门禁不随事实缺失政策放宽，已展示的动态事实也不能通过重复展示或静态化规避检查。
已接受 Plan 包含三个或更多不同 Action 时，候选 DSL 若已从 root 可达地保留至少两个
不同的合法动作按钮，且其 handler 均与候选完整匹配、没有额外未匹配或重复动作的按钮，第三个及
后续未落位 Action 的 Plan 覆盖缺失降为 warning；对应未落位动作的素材分配不再重复产生阻断错误。
仅有一个按钮、按钮不可达、重复同一动作、存在未匹配按钮、handler 或参数不匹配时不适用该容量降级，继续按 error 处理。

重复展示的确定性修复仅面向已被原覆盖检查判定重复的独立展示项，保留唯一展示及其完整标签、单位、绑定和动作。
不按业务或相同样值去重，不改混合表达式、图形与读数组合，也不删除仍含独有信息的组件。
候选必须复跑原 Plan 覆盖、组件、树结构及布局校验，完整通过才采用；否则保留原稿和准确的重复位置交原模型修复。
没有重复错误的成功输出不进入该修复，不新增调用或重试额度，不把去重作为容量降级。

动作入口只复用现有检查与模型重试链路，独立记录 `duplicateActions`，不自动删除按钮或调整布局变体。
仅检查从 root 可达、唯一关联已接受 Plan Action 的独立按钮；以完整 `onClick` 数组（包含顺序、
参数类型和值、动态绑定）判定相同执行动作，不按按钮文案、样值或候选匹配的宽松归一化去重。
不同开关值、不同参数、不同绑定、附带其它动作、列表项上下文和父子点击不自动合并。
固定槽中的重复按钮不能直接删槽、清空事件或用重复内容填槽；结构化反馈标记真实父角色，
由现有修复轮次调整必要父布局及已有信息分配，保留全部独立事实与动作。
重复动作始终是展示错误，不因缺失事实降为 warning，也不能进入容量 Drop；不增加调用或重试预算。
保留原稿和准确诊断，模型返回修复结果后仍通过原完整校验；既有数据重复的确定性修复保持不变。

修复先处理局部属性、绑定与素材；已证明结构或容量无解时升级共同父区或完整布局，不能把非法区域冻结，也不因重复错误提前结束修复。
当候选卡片的可见业务正文只有 `SecondaryBody` 等普通标签—值文本、因缺少核心信息组件而失败时，
修复策略可建议把同一对象内 2–3 项同级、等权、无事件／比例／强调语义的短文本改用 `TableText`，
由其承担核心信息角色。两项按 `38vp`、三项按 `52vp` 核算；超出容量的事实仍须放入其它合法内容角色，
仅能按 `optionalDrop` 或 `approvedOmissions` 的明确授权省略，不得为了改用表格自行丢失事实。
普通流程前三次修复仍失败时，自第四次起可由程序锁定一个非 Action 展示组件执行有界删除：优先仅含 `should` 的组件，无此候选且仍无法闭合时才允许承载 `must` 的组件。
当纵向高度诊断能精确确定 `SecondaryBody` 所在父区域的可用高度时，修复上下文按实际列数、展开后行高和行间距计算当前最多可保留的行与条目，并将超出部分标记为 `doesNotFit`。该证据本身不授权丢失信息；进入 Drop 后优先只授权删除这些条目，先 `should`、后低顺位 `must`，不直接删除整个混合信息组件。任何删减后整卡必须仍保留至少一个核心信息组件；不满足时不产生 Drop 候选。
若当前候选因引用错误导致核心组件暂时不可达，但源 DSL 仍定义了可恢复的核心组件，Drop 可以只从
root 当前可达的辅助信息中选择候选，同时把已定义核心列为保护节点并要求本轮重新挂载至少一个；
不可达节点不参与删除候选。源 DSL 完全没有核心组件定义时仍禁止 Drop，不以标题、动作或辅助信息替代核心。
三行 `TableText` 是当前唯一核心组件且容量失败时，可以通过条目级 Drop 删除一行并保留合法的
两行核心组件；仍须先选 `should`，无可用 `should` 时才允许删除低顺位 `must`，不得一次删除整个表格。
`TableText.items` 超过组件合同允许的三项时，该组件合同错误同时作为确定的信息组合超限信号，
修复编排直接进入条目级 Drop，不再反复执行普通组件属性修复。每轮只授权删除一个可追溯到 Plan 的
非 Action 条目，先 `should`、后低顺位 `must`，逐轮删至三项；保留其余条目、绑定、父级引用和至少一个
核心信息组件。该路由只消费既有 `TableText` 合同诊断，不改变 2–3 项合同、校验归属或 Action 保护规则。
接口整轮重试的容量恢复只针对已确定的布局容量或结构失败，新一轮不复用失败 DSL。
动态链路第二轮不再调用模型重新生成 Plan；服务从第一轮已接受 Plan 中确定性构造 Recovery Plan：
以最后一次失败 DSL 的可见事实为恢复边界，保留其中全部可见事实和全部
Action；构造 Recovery Plan 时不根据第一轮 `capacityFits.doesNotFit` 预先删除仍可见的事实。
第二轮 DSL 生成后如仍有容量、结构或上述 `TableText` 明确组合超限，再由当前轮诊断和有界 Drop
产生新的删减授权。
第一轮最终已经缺失并记录为 warning 的非 Action
事实不再加入第二轮 Plan；累计 `approvedOmissions`
继续保留为省略依据。Recovery Plan 保留事实的 requirement、priority、componentHints 和合法素材分配，
删除旧 composition 及 compositionNotes，并直接进入第二轮 Compact DSL 生成。无法安全构造时才回退到常规 Plan 流程。
静态链路仍由模型重新组织第二轮 Plan，但恢复边界只排除原策略允许省略且最终确实缺失的事实：
`should` 沿用既有可选规则，`must` 必须出现在修复跟踪器当前的正式删减授权中。
未授权而被失败 DSL 遗漏的 `must` 仍列为必保留事实，不得把模型擅自遗漏转换成禁止恢复的指令。
已经重新完整展示的授权事实也继续保留；所有 Action 保留，授权历史和实际遗漏分别记录。
该修订只影响静态失败后的接口恢复上下文，不改变动态恢复、成功产物、组件合同及调用预算。
第二轮只能重新选择信息合组、组件和布局，不得恢复已排除事实、修改保留事实优先级
或删除任何 Action。恢复模式可提前进入受控 Drop：优先选择仅含 `should` 的候选；没有此类候选且容量仍
无法闭合时，允许选择承载 `must` 的低损失候选。
恢复 Plan 结构合法但有限试排仍失败时，剩余 Plan 提交继续使用显式恢复上下文，保持固定的
`text/priority` 及排除清单，只调整展示角色、同对象分槽、分组与组件布局；不再附加普通规划的
“重新总结、不要原样重复过长计划”指令。该修订只统一恢复阶段的反馈，不新增模型调用或删减权限。
每轮只能删除程序明确批准的非 Action 组件或条目，
删减后仍须保留至少一个核心信息组件；未获授权的保留事实不得由模型自行删除。
这些是生成阶段的明确降级例外，不授权主 Agent 提前删去核心需求；候选、实际缺失及累计授权范围必须记录，Action 始终不可删除。

接口重试保留处理结果的完整issues及severity，事实省略warning可作为此前容量失败的证据，但warning自身不触发容量恢复。
问题主分类仍只读取阻断错误；除上述“已有两个合法按钮”的明确容量降级外，存在Action缺失或
重复展示硬错误时，即使同时有容量错误或省略warning也不按容量恢复处理。普通重复展示保持局部删重：
只删除校验定位的重复可见引用，保留其中一个现有展示；每次修复后重复超额数量应下降，未下降时继续
在同一范围修复，不得复制或新增该动态绑定。只有同一事实存在至少两个不同必填展示槽的明确诊断时，
修复范围才允许扩至必要父布局，重新分配已有事实及合法组合；仍禁止无条件整卡重建、删除独有事实或动作。
该传递修正不改变校验规则、失败响应或重试预算。

静态原始DSL已通过语法和组件类型检查，但仍有分组覆盖错误时，不让该错误掩盖可独立确认的
组件展开容量错误：复用原展开器做一次诊断，合并既有结构化容量错误，原覆盖错误仍然阻断。
只合并能按原规则映射的容量诊断，其它转换错误保留原文及异常原因，不猜测无效组件的几何；动态链路及无原始错误的
成功路径保持原顺序。联合反馈交给既有修复路由，既有无损重排与逐次Drop授权范围、预算均不改变。

静态源因缺少已接受公共说明而失败、原无标题且正文结构本身可解析时，既有成功试排候选仍优先。
所有既有候选失败后，可以额外核验一个只补齐原计划公共文字至既有标题槽的候选；原正文组件、
属性、事实、字号和顺序不变，不猜测或改写公共文字。候选须通过同一完整校验；若仅剩真实容量错误、
原覆盖错误已消除，可把该失败候选及其同源诊断一起交给下一次既有模型修复，而非继续返回漏信息的原稿。
该交接不算生成成功、不直接授权删减，原模型响应和程序候选分别留痕；仍缺事实、存在其它错误或
无法可靠补齐时保持原稿。后续省略仍须满足当前候选的原有无损尝试与逐条 Drop 条件，不借用其它源的容量证据。

`2x2` 外层重组与 `2x4` 紧凑搜索是受控的有界确定性修复，不新增模型调用或占用模型修复额度；候选必须通过对应完整校验与 Plan 检查，无解保留原稿及诊断。
纵向高度对 `2x2` 和 `2x4` 整棵子树均保留 `2vp` 数值容差；最小占用及可用高度
已确定且超过容差时，统一产生 `COMPACT_LAYOUT_HEIGHT_OVERFLOW` error，进入修复与逐轮复检。
根节点、权重、可压缩间距、裁切、收缩或分布对齐均不能作为高度降级依据；溢出容差配置只保留
横向 warning 阈值。横向溢出仍按版本化容差及来源条件分级，文字宽度检查不借用几何容差，
经验容差不保证真机无裁切。
模板 Compact 专项校验豁免仅由编译成功后的服务上下文授权，不由 DSL 中的节点 ID 或标记决定；公共转换和按配置执行的完整产物校验仍保留，回退模型时复位豁免。

### 模型与重试边界

主 Agent 对同一任务的生成工具调用必须串行，每次等待最终业务结果，最多 3 次总调用（含首次，最多重试 2 次）。
一旦返回 `success/degraded`，本任务立即结束生成调用，不得为了美化、确认、补回复或补 URL 再调；
即使成功结果缺少合法新 URL，也只按异常回复并保留旧来源。用户后续明确提出的新创建或编辑需求另算任务。
仅当结构合法的简版错误反馈明确 `retryable=true`、未要求 STOP/NOTIFY_USER，且提供了可执行修正信息时，才允许修正参数后再次调用；
旧版响应还须明确为 `failed`，修正依据及停止条件不变；不要求简版包含已移除的状态或错误码字段。
不能虚构修复字段或从笼统错误码猜修法。相同错误重复、无新修正信息、达到上限时按 R14 终止。
`unsupported`、编辑的 `needs_clarification/unchanged`、非法结果、工具异常、超时或调用状态不确定均不重试。
重试仍沿用本轮 create/edit 与原有效来源，不继承失败响应中的 URL；每次重新校验参数、尺寸、数据来源和权限，
数据集合或 binding 变化时复查权限，禁止绕过编辑边界。R01/R02 仅首次生成前发送，重试不重复开始话术。
本规则仅约束主 Agent 再次调用生成工具，不修改微服务内部模型修复与接口整轮重试的独立预算。

模型调用失败重试、主备切换、Plan 重试、DSL 质量修复、参数恢复及接口整轮重试分别编排，不能混为一次统一重试或无限循环。
物理调用共享应用生命周期的连接、并发限制、排队和执行超时；传输层不另行叠加重试。
模型后端由服务配置决定，调用方不能覆盖；模型异常、转换失败、质量失败与存储失败需分别记录。

## 降级与端侧交付

生成前因能力缺失调整需求时，只允许在核心目标仍成立的前提下移除次要内容；核心不可满足时停止并按不支持处理。
生成阶段的信息省略仅适用上节明确的修复政策并报告 `degraded`，不能把该例外用于提前删除核心需求或静默降级。
工程异常按失败处理，任何阶段均不伪造动态数据、动作、权限或素材。

微服务保存完整 artifact，经上传适配器取得地址，由生成工具内部通道交给端侧。
实现提示：当前仓库上传适配器为本地模拟实现，不改变方案的完整产物 OBS 交付目标；不能凭返回 URL 判定真实 OBS 已接通。
端侧负责预览和用户确认添加，云侧生成成功不等于已添加或真机视觉验收通过。

主 Agent 继续按真实业务结果处理状态、重试及编辑来源；宿主允许生成后文本回复时，实际发送适用的结果话术，
说明生成用途、修改内容或部分满足情况。必要前置告知不能依赖该回复，宿主未提供后续回复机会不视为已告知结果。
仅生成后才能确定的失败、实际省略及编辑澄清，其用户可见交付仍需宿主联调确认；Skill 不保证文本送达，
不新增输出通道，也不为补回复重新调用生成接口。
不原样透传业务 message，不重复搜索数据值，不提前承诺动态能力或声称已添加桌面；候选和有效能力也不证明最终 DSL 实际采用了对应展示。
产物 URL 仅保留在内部工具轨迹供后续编辑使用，不出现在用户可见回复或固定结果标记中。
不支持时使用固定边界话术，不附加相近场景建议；生成失败仅在上述重试条件内继续，否则停止，不提供替代产物。
固定回复正文与组合规则集中维护在在线 Skill 的回复规范。
