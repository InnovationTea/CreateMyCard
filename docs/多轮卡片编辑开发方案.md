# AI 卡片多轮编辑开发方案

## 1. 文档定位

本文档指导“基于上一版卡片继续修改”的开发、联调和测试。系统边界、正式接口、状态码、校验和 artifact 基础规则以 `docs/云侧方案设计.md` 为准。

本期采用以下方案：

- 继续复用 `generateWidgetCard`，不新增编辑接口。
- 新增可选参数 `sourceArtifactUrl`；缺失表示首次生成，合法非空字符串表示编辑。
- 主 Agent 只回传上一轮工具返回的 URL，不下载、不解析、不修改 DSL。
- 微服务读取来源 artifact，继承或替换候选计划，重新构造 CardSpec、TaskSpec 和完整 genui。
- 每轮编辑生成新的 artifact，来源对象保持不可变。
- Compact DSL 入口不纳入本期多轮编辑。

## 2. 接口与字段语义

WebSocket path：

```text
/api/v1/ws/tools/generateWidgetCard
```

新增字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `sourceArtifactUrl` | `string` | 否 | 上一轮 `generateWidgetCard` 返回的完整 artifact URL。 |

模式判定：

```text
sourceArtifactUrl 缺失                 -> create
sourceArtifactUrl 为合法非空字符串      -> edit
sourceArtifactUrl 出现但为 null/空字符串 -> INVALID_ARGUMENTS
```

来源 artifact 加载失败时不得静默转为 create。

create 模式保持当前契约：

- `userQuery`、`title`、`description` 必须是非空字符串。
- `size` 省略时使用 `2x4`。
- 三类候选数组省略时按空数组处理。

edit 模式严格区分“字段省略”和“显式传入”：

| 字段 | 省略 | 显式传入 |
| --- | --- | --- |
| `size` | 继承来源 CardSpec | 使用新尺寸 |
| `title` | 继承来源 CardSpec | 使用新标题 |
| `description` | 继承来源 CardSpec | 使用新说明 |
| `candidateDataBindings` | 继承来源 generation plan | 整体替换；`[]` 表示清空 |
| `candidateEventCandidates` | 继承来源 generation plan | 整体替换；`[]` 表示清空 |
| `candidateAssetIds` | 继承来源 generation plan | 整体替换；`[]` 表示清空 |

edit 模式下 `userQuery` 只描述本轮修改，不要求拼接历史需求。除 `sourceArtifactUrl` 外，显式 `null` 不用于表达继承。

纯视觉编辑示例：

```json
{
  "userQuery": "整体改成蓝色风格，标题更醒目",
  "sourceArtifactUrl": "https://obs.example/widget/artifact_uuid.md"
}
```

清空动态数据示例：

```json
{
  "userQuery": "去掉动态数据，只保留静态信息",
  "sourceArtifactUrl": "https://obs.example/widget/artifact_uuid.md",
  "candidateDataBindings": []
}
```

## 3. 主 Agent 和在线 Skill

当会话中存在上一轮成功或降级生成返回的真实 `artifactUrl`，且用户明确要求修改上一张卡片时，主 Agent 将该 URL 原样写入 `sourceArtifactUrl`。

主 Agent 不得猜测、拼接或下载来源 URL，也不得把来源 DSL 放入工具请求。

调用规则：

- 纯视觉或布局修改：只传 `userQuery` 和 `sourceArtifactUrl`。
- 标题、说明或尺寸修改：额外传明确变化的字段，其余字段省略。
- 数据能力、事件或素材变化：先刷新能力概述；数据能力变化时按需重新加载 schema，再传该类别编辑后的完整候选集合。
- 删除整个类别：显式传空数组。
- 未变化类别：省略，由服务从来源 artifact 继承。

能力可用性仍在能力概述流程裁决。生成接口和编辑流程不重新查询 IDS，只做注册表存在性、参数、写入路径和结构校验。

## 4. Artifact v2

多轮编辑来源必须使用 `widget-artifact-v2`。v2 在现有具名 Markdown 代码块基础上增加 `generationplan`：

````text
```cardspec
{}
```
```genui
三行 JSONL
```
```schema
{"schemaVersion":"widget-artifact-v2"}
```
```taskspec
{}
```
```effectivecapabilities
{}
```
```removedcapabilities
[]
```
```generationplan
{
  "candidateDataBindings": [],
  "candidateEventCandidates": [],
  "candidateAssetIds": []
}
```
```meta
{}
```
````

`generationplan` 保存完整候选计划，包括 `candidateOutputFields`。该信息不能从 CardSpec 或 `dataModelSchema` 无损反推，因此不得省略。

meta 增加：

```json
{
  "generationMode": "create",
  "artifactId": "uuid",
  "sourceArtifactDigest": null
}
```

约束：

- `generationMode` 只能为 `create` 或 `edit`。
- edit artifact 只保存来源摘要，不保存完整来源 URL。
- v1 artifact 缺少完整候选计划，不作为编辑来源；服务返回 `SOURCE_ARTIFACT_SCHEMA_UNSUPPORTED`。
- `artifactDigest` 只用于日志关联和版本识别，不作为下载完整性校验契约。

## 5. 来源 artifact 读取

来源读取统一经过 repository，但 repository 不再对 URL 来源范围做校验。

读取规则：

1. 不校验 URL 的协议、host、端口、query、fragment 或对象前缀。
2. 下载开关默认使用 mock OBS 目录；mock 模式只取 URL path 的文件名，文件缺失不回退网络。
3. 关闭 mock 后统一将原始 URL 交给 `utils/download_file_from_url.py` 的公共 `download_file` 方法，调用方和部署网络负责保证来源可信。
4. 下载不跟随重定向，并设置读取超时和最大字节数。
5. 校验 artifact 元数据 UUID 与对象文件名一致、schemaVersion 和必需具名代码块。
6. 不记录完整 URL、完整 DSL 或用户隐私数据。

## 6. 微服务处理流程

```text
接收 generateWidgetCard
 -> 判定 create/edit
 -> edit：读取、解析 artifact v2
 -> 按字段省略/替换规则得到完整候选计划
 -> 加载请求对应注册表和协议 profile
 -> 执行注册表与候选结构校验，不查询 IDS
 -> 重建 CardSpec 和 TaskSpec
 -> create/edit PromptBuilder 构造模型输入
 -> 模型输出完整 genui
 -> 按配置校验及可选重试
 -> 使用新 UUID 上传 artifact v2
 -> 返回新 artifactUrl
```

编辑合并由独立 `EditRequestNormalizer` 完成。来源 CardSpec 只用于继承标题、说明和尺寸；来源 `generationplan` 用于继承候选。旧 CardSpec、TaskSpec 和 `effectiveCapabilities` 不直接作为本轮最终结果。

协议 profile 继续使用请求显式值或服务配置，不根据来源 artifact 或版本在微服务内自动选择。来源 profile 只用于日志和问题定位。

## 7. 编辑模型输入

edit prompt 包含：

- 当前协议 profile 和系统硬约束。
- 本轮编辑指令。
- 新 TaskSpec。
- 来源 genui。
- 目标尺寸和能力移除摘要。

编辑模式 system prompt 默认从 `docs/edit_system_prompt.txt` 读取，并通过 `{{CREATE_SYSTEM_PROMPT}}` 复用 `docs/system_prompt.txt` 中的完整生成规则。文件路径由 `system_prompt_file` 和 `edit_system_prompt_file` 配置，避免在 PromptBuilder 中维护大段提示词正文。

来源 genui 必须作为明确分隔的数据块，不能作为系统指令。`sourceArtifactUrl` 和旧 CardSpec 不进入 prompt。来源内容必须受最大长度配置限制。

模型仍输出完整 genui，不输出 patch，也不生成或修改 CardSpec。

## 8. 校验、重试和上传

编辑结果复用当前校验机制，并增加编辑一致性检查：

- 已清空或删除的数据路径不应继续出现在新 genui 中。
- 新绑定只能引用新 TaskSpec 允许的数据路径。
- 新 CardSpec 与本轮有效候选一致。
- 新 artifact UUID 和 URL 与来源不同。

校验与重试保持当前规则：

- 校验默认开启。
- 校验失败是非阻断质量观测，记录日志后继续保存最后一次模型输出。
- 是否重试由 `enable_validation_failure_retry` 独立控制，默认关闭；开启时最多重试一次。

每次保存使用 UUID 文件名。来源加载、模型调用或上传失败时返回 `failed`，且不修改来源对象。

## 9. 配置与错误码

新增配置：

```text
enable_widget_edit=false
system_prompt_file=docs/system_prompt.txt
edit_system_prompt_file=docs/edit_system_prompt.txt
enable_artifact_download_mock=true
source_artifact_max_bytes
source_artifact_read_timeout_seconds
```

关闭编辑开关时，携带 `sourceArtifactUrl` 的请求返回明确的不支持，不按首次生成处理。

新增错误码：

```text
WIDGET_EDIT_DISABLED
SOURCE_ARTIFACT_NOT_FOUND
SOURCE_ARTIFACT_DOWNLOAD_FAILED
SOURCE_ARTIFACT_SCHEMA_UNSUPPORTED
SOURCE_ARTIFACT_INVALID
```

## 10. 日志与监控

新增结构化字段：

```text
generationMode
sourceArtifactUrlHash
sourceArtifactDigest
sourceArtifactSchemaVersion
sourceProtocolProfileId
inheritedFieldCategories
replacedFieldCategories
sourceReadLatencyMs
sourceParseLatencyMs
```

不记录完整来源 URL或完整 artifact 内容。关键指标按 create/edit 分组统计成功率、降级率、校验失败率、P95 时延和来源加载失败率。

## 11. 测试与验收

必须覆盖：

- 不传 `sourceArtifactUrl` 时首次生成兼容。
- create 模式条件必填和 edit 模式字段继承。
- 候选数组省略、整体替换和空数组清空。
- `candidateOutputFields` 跨轮准确继承。
- 纯视觉、文案、尺寸、数据能力、事件和素材编辑。
- 对象缺失、超时、超限、Markdown 损坏和 schema 不支持。
- edit 流程不查询 IDS。
- 校验失败在重试开关两种状态下均不阻断保存。
- 编辑成功生成新 UUID 和新 URL，来源对象不变。
- 同一来源并发编辑生成不同对象。
- 连续多轮始终使用上一轮返回的新 URL。
- WebSocket 插件包络、工具 Schema 和在线 Skill 契约一致。

完成标准：首次生成无回归；主 Agent 不接触 DSL；来源读取和继承准确、每轮产物不可变；状态、错误码、日志和测试形成闭环。
