# 开域静态内容卡片产品需求 PRD

## 产品目标

支持用户通过自然语言，将演唱会信息、节假日安排、个人计划等内容制作成桌面卡片。小艺可结合网络搜索、用户个性化记忆（UG）及用户提供的信息，整理与当前需求相关的内容，生成便于随时查看的卡片。

“静态”指卡片保存制作时采用的内容，添加后不自动更新。

## 场景价值

- **减少重复查找：** 将搜索结果或对话中需要反复查看的信息放到桌面，减少翻聊天记录、重新搜索的操作。
- **扩大卡片适用场景：** 覆盖演出、假期、旅行、纪念日等多样化主题，满足用户临时、个性化的信息展示需求。
- **降低制作成本：** 用户用一句话表达需求，小艺结合已知偏好和相关信息完成整理，无需手动填写和排版。

## 典型场景

以下均为需求示例，不代表真实活动或日期信息。

| 场景 | 用户表达示例 | 卡片展示内容 | 用户价值 |
| --- | --- | --- | --- |
| 演唱会速览 | “帮我查一下某歌手在上海的演唱会，做成桌面卡片。” | 演出名称、日期、时间、场馆 | 出发前随时查看关键信息 |
| 节假日安排 | “把今年国庆的放假和调休安排做成卡片。” | 对应年份的假期区间、调休工作日 | 方便安排休假与出行 |
| 个性化活动 | “按我喜欢的音乐风格，找一场本地演出做成卡片。” | 符合偏好的演出及时间、地点；有多个合适选项时先确认 | 减少重复描述偏好和筛选的成本 |
| 旅行计划 | “把刚才确认的周末行程做成卡片。” | 出行日期、目的地、已确认的行程安排 | 集中查看个人计划 |
| 个人纪念日 | “做一张我们的结婚纪念日卡片，日期是六月十八日。” | 纪念日名称、日期及用户指定的文字 | 承载个性化纪念与情感表达 |

## 核心需求

1. **自然语言创建：** 支持直接提出卡片需求，也支持将当前对话中已确认的内容制作成卡片。
2. **按需获取信息：** 用户未提供的客观信息可通过网络搜索补充；缺少影响结果的关键信息时，进行必要追问。
3. **结合个性化记忆：** 使用与当前需求相关的兴趣、偏好和个人信息辅助选择内容，用户本次明确表达优先于历史记忆。不得将兴趣推断为已购票、已预约等个人事实。
4. **制作前告知内容：** 向用户说明本次采用的事实；存在歧义或信息冲突时先澄清，关键信息无法确认时说明原因。
5. **生成与预览：** 将关键信息组织为清晰、美观、易读的卡片，供用户预览并确认添加到桌面。

## 产品边界

- 本期聚焦静态信息展示，不承诺实时票务、余票、价格、活动变更通知或自动刷新。
- 日期和安排须明确适用年份、地区或场次，避免将不同对象的信息混用。
- 告知用户卡片内容不会自动更新；现实信息发生变化时，用户可重新制作。
- 仅使用与本次需求相关的个性化信息，不将无关个人记忆展示到桌面。
- 本期不包含自动购票、预约、支付，以及随时间变化的倒计时。

## 验收要点

- 演唱会、节假日及用户提供的个人计划，均可在信息充分时完成卡片预览与添加。
- 卡片中的名称、日期、时间和地点等与本次采用的信息一致，不补造事实。
- 个性化记忆可辅助内容选择，用户本次指定的对象和偏好能够覆盖历史记忆。
- 信息不足或冲突时能够澄清；添加后保持制作时的内容，不让用户误以为会自动更新。
