# 静态标题必需合同与单行列表验证

## 确认的问题

原提示词规定两项TextList及SingleLineList应带标题，但静态外框只有“header存在时检查其类型”，
没有检查必需标题是否缺失。上一批55条中，Q007/Q027的两项TextList与Q022/Q033/Q049/Q052
的SingleLineList都缺标题，却交付了产物。这属于Prompt/Runtime合同没有落实，不能解释为全部容量不足。

用户2026-10-31确认：只有三项TextList可以无标题，其余静态正文形态均须标题，包括EmphasisText。
四项ComparisonGroup旧满高背板不能原样带标题，因此退出本轮生成选型；四个对象保留后改选能带标题的合法结构。
旧背板尺寸、文字规格、单行宽度和整树空间检查不放宽，也不为了标题直接删掉一个对象。

## 实现边界

- Information拥有忠实主题概括；Plan负责有来源的shared/title，除三项TextList外标题标must。
- Components与Composition维护可选形态；Layouts维护根header/body结构，只有三项TextList使用body单槽。
- `requires_static_header`集中登记标题要求；静态展开在根可达children中核对header，校验与最终转换共用。
- 只定义孤立标题不算满足。空标题和错误组件类型继续由原检查拒绝，不增加公开协议字段或诊断码。
- 缺标题属于结构修复，不当作空间超限，不授权Drop正文。
- 原公共标题修复允许识别该精确结构诊断；仍只从已接受Plan的缺失公共原文构造候选，正文不变，
  不猜标题、不从测试编号生成业务文字，候选仍完整重验。
- 少量旧测试夹具原本省略标题，已补齐明确的标题/Plan角色以继续测试原本的覆盖、容量、复核和恢复行为；
  新增缺标题、孤立标题、强调文本和不授权Drop的反例。没有跳过测试或放宽原信息断言。

## 三项单行列表确实能带标题

显式150vp高参考画布：上下安全区各12，标题16，标题正文间距6，剩余正文104。
三个32vp背板加两个4vp间距也是104。2×2与2×4均通过实际生产转换、布局及Artifact校验；
参考背板宽仍为126/284，右值字重与原样式保持。文字横向装不下仍须反馈，不能仅凭纵向预算判定可用。
该结论是开发参考画布验算，不把150或300硬编码成真实宿主尺寸，也不代表端侧真机验收。
