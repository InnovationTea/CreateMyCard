# 卡片对比度校验方案演进记录

## 1. 文档目的

本文记录卡片对比度校验从初始实现到当前微服务实现的变化、问题定位、设计决策和验证结果，作为后续维护 `widget_service` 卡片校验链路的参考。

本文记录的是可复用的工程判断和验证证据，不记录内部逐步思维链。方案细节以 `docs/云侧方案设计.md` 为准。

## 2. 背景与场景

项目中的卡片背景主要有三类：

1. 普通场景：根节点下使用普通内容分支（典型标记为 `root_0`），文字通常通过父级 `backgroundColor` 或显式渐变获得背景。
2. 显式渐变场景：根组件直接使用 `linearGradient` 或 `radialGradient`。
3. 融球场景：根节点下存在 `fusionBallBackground`，背景由多个装饰组件、透明层和玻璃层叠加，内容位于另一个兄弟分支。

其中第三类场景不能简单沿父子链路推导文字最终所在位置的背景像素。

## 3. 初始方案与问题

微服务原有校验器位于：

```text
widget_service/cloud/services/card_validation/contrast_validator.py
```

原始处理流程是：

1. 从白色默认背景开始。
2. 沿组件父子关系递归。
3. 读取当前节点的 `backgroundColor`、`linearGradient` 或 `radialGradient`。
4. 对文字颜色和背景候选颜色计算对比度。
5. 对比度低于 `4.5:1` 时报告 `VISUAL.CONTRAST`；低于 `3.0:1` 时为 `error`，否则为 `warning`。

这个算法对普通父子背景结构有效，但对融球场景存在结构性误判：

```text
root（透明）
├── fusionBallBackground（实际装饰背景）
└── __genui_render_component__root（实际内容）
```

校验器沿内容分支递归时不会把兄弟节点 `fusionBallBackground` 合成到内容背景中，透明 root 又会保留白色默认背景。因此白色文字可能被错误计算为对白色背景：

```text
错误结果：1.00:1
实际含义：白色文字 vs 白色默认背景
并非：端侧真实渲染后的最终背景对比度
```

## 4. 方案演进

### 4.1 第一阶段：尝试从离线美学校验器调整渐变规则

最初曾在离线美学校验器中尝试将渐变背景的低对比度从阻塞错误降为渲染复核 warning。但该路径不属于用户指定的微服务在线校验链路，且不能解决融球场景的兄弟背景合成问题。

该路径已回退，当前不作为微服务方案的一部分。

### 4.2 第二阶段：在微服务侧区分显式渐变

在微服务 `contrast_validator.py` 中增加了对显式 `linearGradient` / `radialGradient` 的识别：

- 普通背景仍按严格规则处理。
- 显式渐变低于推荐值时改为渲染复核 warning。
- 诊断中保留静态计算出的对比度值。

这一阶段可以解决显式渐变的“最差 stop 直接阻塞”问题，但仍不能识别由多个兄弟装饰组件组成的融球背景。

### 4.3 当前阶段：通过结构标记识别普通场景和融球场景

根据卡片结构约定，在根节点 children 中使用两个标记区分场景：

```python
_NORMAL_ROOT_ID = "root_0"
_FUSION_BACKGROUND_ID = "fusionBallBackground"
```

判定规则：

```text
存在 fusionBallBackground，且不存在 root_0 -> 融球场景
存在 root_0 -> 普通场景
同时存在两者 -> 优先普通场景，避免误将普通内容分支降级
```

融球场景下，文字对比度处理为：

- 不使用白色默认背景计算伪造的 `1.00:1` 结果。
- 不直接报告阻塞级对比度 error。
- 为每个可见文字输出 `VISUAL.CONTRAST` warning。
- `actual` 标记为：

```json
{
  "scene": "fusionBall",
  "requiresRenderReview": true
}
```

- 提示端侧真实渲染后确认文字区域可读性。

普通场景和显式渐变场景仍保留原有严格/渐变分级逻辑。

## 5. 前后行为对比

| 场景 | 修改前 | 当前行为 |
|---|---|---|
| 普通纯色背景 | 按父级背景严格计算 | 保持严格计算 |
| 普通低对比度文字 | `<3.0:1` 报 error | 保持 error |
| 普通中等对比度文字 | `3.0:1～4.5:1` 报 warning | 保持 warning |
| 显式 `linearGradient` | 可能因最差 stop 直接 error | 降为渲染复核 warning |
| `fusionBallBackground` 兄弟背景 | 可能错误计算为 `1.00:1` error | 识别融球场景，改为渲染复核 warning |
| 融球背景无法静态闭合 | 使用默认白色背景继续计算 | 明确标记 `requiresRenderReview` |

## 6. 代码改动

### 微服务实现

文件：

[widget_service/cloud/services/card_validation/contrast_validator.py](../widget_service/cloud/services/card_validation/contrast_validator.py)

主要改动：

- 增加 `root_0` 和 `fusionBallBackground` 场景标记。
- 在 `validate()` 中根据 root children 判定场景。
- 将场景标记传递到递归 `_walk()`。
- 融球场景文字输出渲染复核 warning，不执行错误的默认背景对比度计算。
- 显式渐变场景保留静态比值，但将低于推荐值的结果降为 warning。
- 普通场景保留 `<3.0:1` error、`3.0:1～4.5:1` warning 的严格规则。

### 测试实现

文件：

[widget_service/tests/test_contrast_validator.py](../widget_service/tests/test_contrast_validator.py)

新增/调整测试：

- 增加融球场景识别测试。
- 验证融球场景生成 warning 而不是 error。
- 验证融球诊断包含 `scene=fusionBall` 和 `requiresRenderReview=true`。
- 更新显式渐变低对比度测试，预期从 error 调整为 warning。

## 7. 实测结果

### 7.1 融球日程卡片

文件：

[template/widget_meeting/meeting.jsonl](../template/widget_meeting/meeting.jsonl)

微服务校验结果：

```text
errors: 2
warnings: 5
contrast errors: 0
contrast warnings: 5
```

5 个文字组件均被识别为融球场景并要求端侧渲染复核。剩余 2 个 error 是 root 固定宽高问题，不是对比度问题：

```text
root.styles.width = 160       -> 要求 "matchParent"
root.styles.height = 160      -> 要求 "matchParent"
```

### 7.2 融球睡眠卡片

微服务校验结果：

```text

```

5 个文字组件均被识别为融球场景并要求端侧渲染复核。剩余 2 个 error 同样是 root 固定宽高问题。

### 7.3 显式渐变卡片

文件：

[template/widget_health/health_sport.jsonl](../template/widget_health/health_sport.jsonl)

微服务校验结果：

```text
errors: 2
warnings: 5

```

5 个文字组件进入显式渐变的渲染复核 warning，静态计算值分别包括 `1.75:1` 和 `2.52:1`。剩余 2 个 error 是 root 宽高未使用 `matchParent`。

### 7.4 普通场景错误颜色测试

通过普通结构（包含 `root_0`，不包含 `fusionBallBackground`）在内存中构造了三组错误颜色：

| 背景色 | 文字色 | 对比度 | 结果 |
|---|---|---:|---|
| `#FFFFFFFF` | `#FFFFFFFF` | `1.00:1` | error |
| `#FF000000` | `#FF111111` | `1.11:1` | error |
| `#FF1D3A6A` | `#FF777777` | `2.51:1` | error |

这证明普通场景仍未被融球降级逻辑放宽。

## 8. 当前边界与后续工作

当前方案是结构感知的安全降级方案，不是完整的像素级渲染模拟。原因是 DSL 目前没有提供可靠的组件实际 bounds、层叠顺序和背景覆盖区域信息。

后续如果能获得布局计算结果或端侧截图，可进一步实现：

1. 根据组件矩形和渐变方向进行空间采样。
2. 计算文本区域的最小值、P10 值、中位数和低对比度面积比例。
3. 按 `FAIL / REVIEW / ADVISORY` 三级输出诊断。
4. 对关键主数字使用更严格的最低阈值。
5. 对辅助文本和半透明白色进行角色分级。

在获得这些上下文前，不应把融球场景的默认白色背景计算结果当作真实对比度，也不应为了消除 warning 擅自修改卡片颜色。
