## 实施结果

普通 Fusion 创建入口接入请求级静态策略，首期同时实现 ContentBlock、RecordList、ComparisonGroup，
新增静态文档布局及独立范围。Plan、DSL、repair 共用原对话历史和预算，无额外摘要模型阶段。
新组件确定性展开为既有端侧基础组件；旧 TextBlock、SummaryList、动态组件、旧布局和默认提示词保持原合同。

原始候选及有效数据绑定均为空、预检成功、非编辑、非单步的普通创建才允许进入静态策略。
当前开关已开启供本地手动批跑；重启后须以进程配置和请求 Trace 确认，不以文件值代替运行证据。
本次只处理本地联调服务；真机与线上部署另行验收。

静态保护包括原文引用、连续片段提取、完整数字词、对象分组、受保护片段及原文模式、完整文字容量，
并在主题后复核前景冻结和文字可达性。仅程序明确授权的 should 可以有界省略；
同一组件混有 must 时只授权对应事实，不删除整个组件。正常精简不作为降级，实际省略沿用 degraded 反馈。

缺少资源、上下文、明确宽度或完整文字容量时失败；不以截断、缩字、删核心或删除动作交付。
新结构暂不进入未适配的确定性搜索，保留原稿并复用现有校验和模型修复。

## 校验归属与未完成范围

来源检查归 `semantic/cross_file.py`，对象局部覆盖归 `semantic/static_content.py`，完整文字容量归
`semantic/layout/text_capacity.py`；组件与角色形状归共享展开及布局编译。修复建议放在现有配置，
规则目录和唯一归属清单同步更新。API 只衔接执行及诊断格式化，不复制完整度量或分组判断。

本次完成源码层面的首期闭环，尚未完成 HarmonyOS 真机和正式 UX 验收，默认开关保持关闭。
语义判断仍依赖同一次 Plan 提取；引用存在、受保护文字和组内覆盖不能证明模型没有遗漏最初的用户核心需求。
不支持任意自由摘要、未登记的日期单位转换、2x2 对比、四栏、自动扩尺寸、翻页、多卡及混合动态套用静态策略。

### 修复内容与职责

- 英文名称：规范排版分隔时保留ASCII词元边界，避免把Charlie Puth与后续英文粘连。
  身份名称按完整字段检查，不能从重排词或部分读数拼凑；逐字要求和同对象保护不变。
- compact：展开与正式运行匹配共用静态合同的gap/compactGap；试排显式使用guided布局范围。
  未接受任意间距值，也未修改动态布局合同。
- 标题：静态SingleLineTitle按12字号、16行高、单行完整文字和图标扣宽展开。
  超长原稿拒绝；属性表可用既有body字段完整承载共享上下文，不截字、缩标题或隐藏内容。
  原动态标题配方及动态转换路径保持不变。
- 降级对账：新静态工具提交omittedContents条目为{description,factIndexes}。
  非空引用只允许无保护should，并跟随去重索引映射，实际省略由最终覆盖决定。
  空引用表示模型未入计划的实际输入损失；历史字符串保守兼容，不做文本语义清洗。
  新在线提交拒绝自由字符串，历史解析仍支持；端到端用例验证恢复后不降级、确实缺失仍降级。
- 美观：属性显式valueRole选择正文左对齐/短读数右对齐；元数据不参与文字覆盖。
  有限候选去除已在标题呈现的同字字段；通用断行禁止闭标点孤立行首、开标点留在行尾。
