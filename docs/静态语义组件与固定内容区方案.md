# 静态语义组件与固定内容区

## 已确认范围

### 2026-10-30 组件更新（覆盖下方历史实施记录中的旧外观）

- 静态SingleLineTitle字重400，仍12fp/16vp。动态标题不变。
- SingleLineList的1–3项由Runtime自动加背板，高32、圆角8、左右内边距12，右值12fp/700。
  三项占满剩余高度均匀分布；1/2项以4间距整组靠下。超过三项保持无背板紧凑形式。
  小卡左右安全区12；宽卡背板左右8，标题仍12。显式参考画布150/300宽时背板126/284宽。
  正式产物仍按宿主横向空间自适应，不把参考画布当机型尺寸。
- TextList自动按可见顺序加编号Badge，高16、10fp/500、圆角8、左右内边距6、编号与正文间距8。
  编号不属于输入事实，不改变对象分组；宽度预算先扣编号，原有文字省略与完整右值规则不变。
- EmphasisText主文本左上，支持secondaryText、bottomText两段辅助。只有一个非空辅助时统一左下；
  两个非空时secondaryText紧随主文，bottomText左下。可选辅助的缺省、null、空白均为空；其它类型拒绝。
  字号和原有行数上限不变，上下块最小间距6，须共同通过总高度校验。
- 样式由Runtime固定；模型只增加bottomText语义字段。它参与同一对象的事实覆盖、精确容量反馈与主题保真。
- 外框的水平安全区由标题和正文各自包装层提供；根保留上下12及6间距，校验采用同一受控展开合同。

静态路线使用固定标题区与内容区，标题左上，正文按本次组件对齐合同排列。模型选择内容组件并填写语义字段，
Runtime 统一拥有字体、行高、间距、分割线、背板及几何。静态不支持 Action；携带事件候选的请求
仍按既有能力型路线处理，不静默删除动作。动态路线不改。

## 组件合同

- SingleLineTitle：title、可选合法 icon。
- TextList：2–3 项 primaryText、secondaryText、可选 value；按 v16 4.8 固定分割线；
  2项必须与 SingleLineTitle 标题配套使用，3项时允许无标题；
  主副文字单行省略，有 value 时为右侧完整值预留宽度，无 value 时使用整行宽度。
- SingleLineList：text、assist；1–3项使用固定高背板，更多项按 v16 4.9 固定4vp行距；
  必须与SingleLineTitle标题配套使用；替代TableText。
- ComparisonGroup：仅宽卡 2–4 对象；2–3项横排时必须与 SingleLineTitle 标题配套使用，
  primaryText保留完整换行，secondaryText最多两行且超出省略；
  4项仅在无公共标题时按2×2宫格占满正文区，其 primaryText、secondaryText 固定单行且超宽省略。
- EmphasisText：mainText与可选secondaryText、bottomText；使用18fp/12fp、18vp/16vp，
  mainText最多两行，辅助各最多三行并在超出时省略，位置和整体高度按本次更新执行。
- 独立 SecondaryBody 退出静态合同；辅助说明只使用组件已有语义字段。

固定根保留 Compact 的 Layout 行作为传输外框，但仅允许本尺寸一个 ID，无变体。
children为header?、body；标题优先保留，正文按组件合同排列。主题与主体名称放标题，不占强调位置。
单主体名称可通过标题履约，多对象名称仍须在各自条目内可见；这不授权其它数据跨对象补齐。
每种组件按原有对象分组核对最终展示，不以其它对象补本对象。

SingleLineList只承载左右文字都能完整单行展示的短记录。任一侧文字超出时，
无损容量修复优先切换为TextList；含标题的TextList最多两项。仍无法容纳时，
状态机按既有时机进入受控Drop，每轮只授权删除一条未保护事实，并保证整卡仍有至少一个正文对象。

## 2026-10-28 历史实施与验证

- 工作分支：codex/static-semantic-components-20261028；原e4497adb版本保留。
- 支持标题、带分割线文本列表、单行列表、宽卡对比、强调文本及其内部副文本。
- 独立SecondaryBody、TableText、ContentBlock、RecordList及静态Action退出模型合同。
- 强调文本沿用动态字体、行高和主副间距；静态完整文字通过测量换行，每段上限两行。
- 主题/主体名称优先进入header；唯一主体可通过标题保留名称，多主体仍逐条核对，不跨对象借值。
- 标题、组件、输入事实与内容组织的边界分别归Layouts、Components、Information与Composition。
- 文字样式、分割线、背板、固定安全区由Runtime生成；根内容左下对齐，父外框没有模型可选变体。
- 生成阶段沿用5次修复、最多两轮；空间修复一次仍失败可进入现有受控Drop，每次仅删除明确批准事实。
  提前Drop只针对容量错误，引用缺失等结构错误仍先修复引用。
  优先should，必要时使用原有低顺位must兜底；保护片段与最后正文对象持续保留，损失返回degraded。
